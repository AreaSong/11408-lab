# code/boss/ · 综合 MiniMachine

> 在 MiniMachine 中的角色：**整机**。把四门课的部件装成一台真能运行的机器：MM32 CPU 执行用户程序，宿主机上的 C 内核管理进程、内存和文件，多台机器联网。
> boss 只有**一个关卡工程** `boss/00-minimachine/`（程序基名 `minimachine`），分 14 个阶段往上长。**指令集规格见 [ISA.md](ISA.md)**；**各阶段的产出、小步骤、通过标准见 [LEVELS.md](LEVELS.md)**，开始或推进某个阶段时再读对应小节；大纲映射见 `COVERAGE.md`。

## 本科目约定
- **一个工程、按阶段长大**：`answer/` 与每次尝试 `mine/<日期-说明>/` 都是整台机器，按子系统分目录（`src/common`、`asm`、`cpu`、`mem`、`mmu`、`kernel`、`fs`、`dev`、`net`、`user`）。每个阶段有题面 `00-minimachine/stages/NN-<主题>/TASK.md` 和测试 `tests/stage-NN/`；做完第 N 阶段，阶段 00~N 的测试全部通过（回归）
- **前置关卡学完才开**：每个阶段的前置关卡写在 `00-minimachine/DEPS` 的「阶段 NN 前置」注释和下方进度表最后一列。前置没学完（对应科目进度表里不是 ✅）就不开这个阶段，平时仍以 66 关为主线。阶段按序号依次开，后一个依赖前一个
- **`.stage`**：尝试目录里的 `.stage` 记当前学到第几阶段（`./lab.sh new boss 00` 写 `00`），测试只登记到这一阶段；开下一阶段时把它改成下一个阶段号，再在 CLion 重新加载 CMake。尝试里的阶段单元测试不进 Build All，由 ctest 的 `minimachine_<x>_sNN_test::build` 按需编译（当前阶段没写完时它失败，不影响其他科目的构建）
- **公共头文件只增不改**：每个阶段 `TASK.md` 列出的头文件与函数签名就是题面，阶段单元测试只通过它们调用。后面的阶段可以改前面阶段的代码，但已发布阶段的公共头文件只增不改
- **前面阶段没写完**：优先 `./lab.sh borrow boss <尝试> <子系统> [NN]`，从标签 `boss-stage-NN`（缺省为 `.stage` 的上一阶段）借入 `src/<子系统>/`，记在 `.borrowed`；跳得多时用 `./lab.sh new boss 00 <说明> --from-stage NN` 以该阶段的参考实现为底起新尝试。只能借比当前阶段早的
- **谁写代码**：`answer/` 由 AI 按 `.cursor/plans/answers.md` 与 `answers-boss.md` 每轮写一个阶段；用户学到时，由 AI 按 [TEACHING.md](../TEACHING.md) 的档位带着在 `mine/` 里组装，流程和普通关卡一样（定档、手推、组装、反讲）
- **打标签**：每个阶段的参考实现写完后，由用户审阅并提交，再打标签 `git tag -a boss-stage-NN -m "MiniMachine 阶段 NN 参考实现"`。用户提交后说「打标签」时 AI 可以代打：先核对 `git status --porcelain code/boss` 为空、HEAD 已包含该阶段（`stages/NN-*/` 与 `tests/stage-NN/` 已提交），且该标签还不存在，再打标签；**AI 只打标签，不代提交、不推送**
- **带学防剧透（学第 N 阶段时）**：开场只读 `stages/NN-*/TASK.md`、`00-minimachine/NOTES.md`、尝试的 `.stage`/`.borrowed`；定档后要看参考实现，一律用 `git show boss-stage-NN:code/boss/00-minimachine/<路径>`，或 `git worktree add /tmp/mm-ref-NN boss-stage-NN` 只读检出（用完 `git worktree remove /tmp/mm-ref-NN`）。**禁止**读工作区（HEAD）里的 `answer/`、`ANSWER.md` 和序号大于 N 的 `stages/`、`tests/stage-*`；**禁止**整仓 `git checkout <标签>`（会回退用户其他科目的进度与 `mine/`）
- **默认「🟢 先学会模式」**：日常只要求本阶段的核心机制接进整机、阶段单元测试和自己的 `test.c` 跑通，再做 1 次总反讲；完整的考试视角 trace、命令脚本主程序和综合大题场景属于「🔵 规范化代码模式」（取消 `CMakeLists.txt` 里主程序的注释，`tests/stage-NN/*.in` 用例才会跑）
- **多机测试单进程仿真**：多台机器、交换机、路由器的测试一律在一个进程里用模拟时钟仿真，保证可重复；真实 UDP 互联只做演示，记在 `stages/13-showcase/EXPERIMENTS.md`
- **选做的两种标签**：「选开（考纲内）」是考纲里有、关卡已练、整机里不是必需的部件，做成可选模式或旁路实验；「选做拓展」只用于大纲外的内容（RAID 不在 2027 大纲，归在阶段 08 的选做拓展）。两种都不进必做路径，定义与清单见 `LEVELS.md` 贯穿设计第 5 节
- **Cache 一致性按 408/王道口径**：多核模式用写直达加监听失效（选开，考纲内）；MESI 只作选做拓展里的进阶提示，不写进必做或选开的实现
- **用户程序两种形态**：MM32 机器码程序（汇编器产出）和宿主用户程序（Nachos 式的 C 函数，只能经系统调用进内核，在系统调用处让出 CPU）

## 口径约定与易错点（AI 引导时重点核对）
- **ISA.md 是唯一规格**：实现中要增补端口、系统调用号、控制寄存器时，先改 `ISA.md` 再写代码，并在该阶段的 `ANSWER.md` 里写明改了哪一节
- 按字节编址、小端、指令定长 4 字节；**相对寻址和转移目标用的是已经加 4 的 PC**，位移单位是字节（不是 2014 年那种「× 4」）
- 标志位口径同 `co/02`：减法的 CF 是「补码加法的进位取反」（借位），OF 是最高位进位异或次高位进位；`LD`、`MOV`、跳转不改标志
- 断点：故障存**本条**地址（重新执行），陷阱和外中断存**下一条**；终止不返回。缺页是能修复的故障，除法错、非法指令、越权是内核修不好的故障
- 中断隐指令只做「关中断、保存 PC 和 PSW、进内核态、按向量送入口」；**通用寄存器和屏蔽字由内核保存**；多重中断要先把 EPC、EPSW 存进内存再开中断
- 外中断只在指令结束时采样；屏蔽字 IMR 中 1 表示屏蔽；屏蔽字决定处理优先级，硬件按 IRQ 编号决定响应优先级
- 节拍模式是多周期（单总线做不成单周期），每拍内总线只能有一个输出；流水线默认「前半拍写、后半拍读」、开转发、预测不转移
- 两级页表 10/10/12，页目录正好一页；页表项地址 = 页表始址 + 页号 × 4；TLB 不带进程标识，切换 PTBR 后必须 `TLBFLUSH`
- **已发布阶段的公共头文件只增不改**；前面的阶段在机器结构体里留函数指针表给后面注册。`src/` 按子系统分目录、文件带前缀（`cpu_`、`mem_`、`mmu_`、`k_`、`fs_`、`dev_`、`net_`、`app_`），源码带目录包含（`#include "cpu/cpu_alu.h"`）；basename 不得与 `deps/` 里的文件同名
- 数据结构通过整机唯一的 `DEPS` 复用 `lib/`；各关的机制模块不直接链接，由 boss 重写成整机部件，并在该阶段 `ANSWER.md` 标出对应关卡和差异。`lib/12` 与 `lib/13` 的 `graph.c` 重名，不能同时链接
- 网络时延按模拟时钟算，不用宿主机真实时间，保证 `tests/` 可重复；带宽的 k/M/G 是 10³/10⁶/10⁹，存储容量的 K/M/G 是 2¹⁰/2²⁰/2³⁰
- 所有算式带单位；场景脚本复现的真题年份和题号由用户核实，AI 不凭记忆编造
