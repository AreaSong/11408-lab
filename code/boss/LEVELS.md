# MiniMachine · 阶段详情

> 把 66 关学到的东西装成一台真能运行的机器：32 位 CPU（MM32，规格见 [ISA.md](ISA.md)）执行用户程序，宿主机上的 C 内核管理进程、内存和文件，两台机器通过 UDP 联网。
> 考查范围以 **2027 年 408 统考大纲**为准，具体约定以王道为准；大纲条目到阶段的逐条映射见 `COVERAGE.md`。
> 每个阶段不超过 6 个小步骤。**前置关卡都学完才开**，平时学习仍以 66 关为主线，boss 不挤占闯关时间。

## 贯穿全程的设计

### 1. 一个工程，按阶段长大
- boss 只有一个关卡工程 `boss/00-minimachine/`（程序基名 `minimachine`）：`answer/` 与每次尝试 `mine/<日期-说明>/` 都是**整台机器**的源码，按子系统分目录（`src/common`、`asm`、`cpu`、`mem`、`mmu`、`kernel`、`fs`、`dev`、`net`、`user`），子系统与阶段的对应见该关 `ANSWER.md` 的子系统地图。
- 14 个阶段按序号往上叠：每个阶段一份题面 `stages/NN-<主题>/TASK.md`（讲解 `ANSWER.md` 写到该阶段时再加）+ 一组测试 `tests/stage-NN/`；做完第 N 阶段，阶段 00~N 的测试要全部通过（回归）。尝试里的 `.stage` 记当前学到第几阶段，测试只登记到这一阶段。
- **公共头文件 = 题面**：每个阶段的 `TASK.md` 列出必须提供的头文件与函数签名，阶段单元测试（`tests/stage-NN/*.c`）只通过它们调用。后面的阶段可以改前面阶段的代码，但**已发布阶段的公共头文件只增不改**。前面的阶段要给后面留接口：机器结构体里放函数指针表（如访存、中断检测、系统调用分派、设备列表），后面的阶段注册自己的实现。
- 命名防重名：`src/` 文件带子系统前缀（`cpu_alu.c`、`k_sched.c`、`net_ip.c`），源码里一律带目录包含（`#include "cpu/cpu_alu.h"`）；`deps/` 是平铺的（`#include "hash.h"`），`src/` 下任何文件的 basename 都不得与 `deps/` 里的文件同名，C 全局符号统一带子系统前缀（`mm_`、`cpu_`、`k_`…），不与 lib 函数撞名。
- boss 的 `CMakeLists.txt` 是例外：用 `file(GLOB_RECURSE … src/*.c)` 收源码并设好 `LAB_CORE_SRC`，逐阶段加文件、借用子系统时都不用改 CMake。
- 数据结构直接通过整机唯一的 `DEPS` 复用 `lib/` 的代码，从阶段 00 起 `deps/` 里就有全部要用的数据结构；各关的机制模块（如 `co/06` 的 Cache 模拟器）是为单关出题设计的，接口不适合整机，由 boss 重写成整机部件，并在该阶段的 `ANSWER.md` 里写明对应关卡和差异。
- 参考实现每发布一个阶段打一个 git 标签 `boss-stage-NN`：前面阶段没写完时，用 `./lab.sh borrow` 从标签借一个子系统，或 `./lab.sh new boss 00 <说明> --from-stage NN` 以某阶段的参考实现为底起新尝试；带学时只从标签读参考实现，防止剧透后面的阶段（流程见 `boss/AGENTS.md`）。
- 回归稳定：某阶段引入的 trace 格式发布后不变；新部件默认关闭或透明（如没有 Cache 时直通主存），早期用例的 `.out` 不因后续阶段改变；迫不得已要改时，在该阶段 `ANSWER.md`「回归变更」里写明并同步旧 `.out`。

### 2. 考试视角 trace
- 每个机制都能按王道表格的格式打印过程：节拍微操作、时空图、地址翻译每一步、甘特图、置换表、Work/Finish、cwnd 变化……
- 机器本身就是**综合大题推演器**：把真题参数配进去、跑一段程序，打印的过程要和标准答案逐步对得上。
- 与单关一样，默认「🟢 先学会模式」下只要求核心机制跑通并用 `test.c` 断言；完整 trace 和命令行壳子属于「🔵 规范化代码模式」。

### 3. 用户程序的两种形态
- **MM32 程序**：用阶段 00 的汇编器写成机器码，在 MM32 CPU 上逐条执行。测试程序、PV 进程、shell 都是这种。
- **宿主用户程序**（Nachos 式）：一段宿主机的 C 函数，作为 MiniMachine 的一个进程被调度，所有 I/O 都必须经系统调用接口进内核，不能直接碰内核数据。它只在系统调用处让出 CPU（协作式）。`grep`、`sort`、`zip`、`curl` 这类算法较重的工具用这种形态，方便复用 `lib/` 的 C 代码。

### 4. 多台机器
- **测试一律在单进程内仿真**：一个宿主进程里用同一个模拟时钟驱动多台 MiniMachine 以及交换机、路由器、NAT、DNS 服务器节点（命令脚本里用 `node add …` 之类的命令搭拓扑），线路就是节点之间的内存队列。这样结果完全可重复，能写进 `tests/`。
- 线路的带宽、距离、误码率可配置，时延按模拟时钟计算，不依赖宿主机的真实时间；误码与丢帧用固定种子的伪随机数。
- **真实 UDP 互联只做演示**：每台 MiniMachine 作为宿主机上的一个独立进程，网卡把帧装进 UDP 数据报发给另一台，一条 UDP「连接」就是一根网线。它依赖本机环境和调度时序，不进 `tests/`，命令和本机输出记在 `stages/13-showcase/EXPERIMENTS.md`。

### 5. 选做的两种标签
- **「选开（考纲内）」**：2027 年大纲里有、对应关卡已经练过，但整机里不是必需的部件，做成可选模式或旁路实验（如段式与段页式、管程、多处理机调度、多处理器 Cache 一致性、微程序控存、双发射超标量、DRAM 刷新停顿、VLAN、PPP、SDN、BGP、组播、移动 IP、IPv6、FTP、P2P、进程间通信、RAID、红黑树管理虚拟内存区间）。不进入必做路径，不做不影响考研覆盖。
  - **例外：RAID** 尚未在任何关卡里练过，首次练习就在阶段 08（fs-disk）的选开项。
- **「选做拓展」**：只用于大纲外的内容（如 CFS、写时复制、日志文件系统、硬件浮点指令、MESI 协议、静态链接器），不进入必做路径，也不会考。

## 各阶段详情

### 00 · 指令集、汇编器与节拍模式
- **产出**：MM32 汇编器（源程序 → 装入映像 + 符号表 + 列表文件）与反汇编器；CPU 的节拍模式执行器：取指、译码、执行，按拍打印微操作和控制信号，统计每类指令的拍数和 CPI
- **小步骤**：① 编码与译码：按 `ISA.md` 第 3、4 节写编码和译码，机器码 → 反汇编 → 再汇编要得到同一个字；列表文件里的机器码和手算的对上 ② 两遍汇编：第一遍收集标号地址，第二遍生成机器码；展开 `li`、`la`、`push`、`pop`、`ret` 等伪指令；相对位移 = 标号 −（本条地址 + 4） ③ 寄存器、PSW 和 32 位 ALU：加减、逻辑、移位、乘除和四个标志，CF 与 OF 的口径对照 `co/02`（减法的 CF 是借位） ④ 寻址方式：立即、直接、间接、寄存器间接、基址、变址、相对，算 EA 并数取操作数的访存次数；按字节编址、小端存取、字访问对齐检查 ⑤ 节拍模式：取指 4 拍加各类指令的执行拍，trace 打印微操作，检查同一拍只有一个部件向内总线输出 ⑥ 端到端：数组求和与带栈帧的函数调用两个程序，汇编、装入、运行，打印最后的寄存器和内存
- **通过标准**：真题考法在 MM32 上复现：给汇编写机器码或给机器码反推指令、转移目标地址（PC 先加 4）、某条指令执行后的标志位与有符号/无符号比较的结果、某种寻址方式的 EA 与访存次数、一条指令的微操作序列与拍数
- **选做拓展**：浮点指令 `FADD`/`FSUB`/`FMUL`/`FDIV`，按 IEEE 754 单精度实现（对应 `co/04`；考纲要求的浮点运算已由用户态软浮点子程序覆盖）；可重定位目标文件加一个简单的静态链接器（两个源文件分别汇编再链接，对应 `os/00` 的链接；考纲要求的重定位已由 05 的 `exec` 装入覆盖）
- **选开（考纲内）**：用微程序控制器（控存里的微指令）代替硬布线产生控制信号（`co/10` 第 ② 步已练）
- **前置关卡**：`co/01-encoding`、`co/02-adder`、`co/03-mul-div`、`co/04-ieee754`、`co/08-isa-x86`、`co/09-mini-cpu`

### 01 · 异常、中断与系统调用
- **产出**：向量表、中断隐指令、`IRET`、特权检查与用户态/内核态切换；宿主内核入口（Nachos 式，C 函数处理向量）；最小内核：控制台的 `exit`、`write`、`read` 系统调用，时钟中断
- **小步骤**：① 特权级：PSW 的 U 位，用户态执行特权指令产生特权违例故障；trace 打印每次模式切换 ② 内部异常：除法错、非法指令、地址未对齐、溢出陷阱、断点；断点按「故障存本条、陷阱存下一条」写进 EPC ③ 外中断：时钟 IRQ0、终端 IRQ3；每条指令结束时才采样；IF 与屏蔽字 IMR，NMI 不看 IF；同时有多个请求时编号小的先响应 ④ 宿主入口区与向量表：C 内核按向量号注册处理函数；`SYSCALL` 走 8 号向量，实现 `exit`、`write`、`read` ⑤ 多重中断：服务程序先保存 EPC、EPSW 和屏蔽字再开中断，按屏蔽字 trace 打印 CPU 的执行序列（复现 `co/13` 的屏蔽字题） ⑥ 用户态 hello：用户程序调用 `write` 打印，trace 打印「传参 → `SYSCALL` → 服务程序 → `IRET`」四步，并标出每一步由硬件还是操作系统完成
- **通过标准**：某事件属于故障、陷阱、终止还是外中断，断点存哪条、能否屏蔽、何时响应；系统调用的执行顺序和各步的执行者；哪些指令是特权指令；给定屏蔽字后中断服务程序的执行顺序
- **选做拓展**：把某个向量改成真正的 MM32 处理程序，用汇编写时钟中断服务程序；单步调试器（TF 位加 `BRK`，支持 `step`、`break` 命令）
- **选开（考纲内）**：陷入-模拟式虚拟机：客户内核在用户态跑，特权指令陷入后由管理程序模拟（`os/01` 第 ⑤ 步的 MM32 版）
- **前置关卡**：`co/10-controller-interrupt`、`os/00-syscall`；阶段 00

### 02 · 五段流水线
- **产出**：流水线执行模式：IF、ID、EX、MEM、WB 五段，打印时空图；检测三种冒险，转发、阻塞、冲刷；统计总周期、CPI、MIPS；同一程序在节拍模式和流水线模式下的最终状态一致
- **小步骤**：① 段间寄存器与理想流水：无相关的指令序列，验证总周期 = k + n − 1 ② 数据冒险：检测 RAW，不转发时按「前半拍写、后半拍读」阻塞 ③ 转发，以及转发消不掉的 load-use ④ 控制冒险：预测不转移、EX 段判定、猜错冲刷；可切换为阻塞到 MEM 结束 ⑤ 结构冒险与精确异常：打开「统一存储器」开关观察 MEM 与 IF 相撞；流水线里的缺页、除法错、系统调用按程序顺序处理，后续指令冲刷 ⑥ 对比：同一程序在两种模式下的周期数，算加速比、吞吐率、效率，按给定主频算执行时间和 MIPS（`co/00` 的公式）
- **通过标准**：时空图；哪些指令之间有数据相关、各阻塞几拍、总共多少个时钟周期；把 `co/11` 的真题指令序列改写成 MM32 汇编后，周期数与标准答案一致；CPI、MIPS、加速比的计算
- **选做拓展**：延迟槽；2 位饱和计数器的动态分支预测，比较预测准确率
- **选开（考纲内）**：双发射超标量，观察 CPI 小于 1（`co/11` 卡片、`co/12` 已练）
- **前置关卡**：`co/00-performance`、`co/11-pipeline`；阶段 01

### 03 · 主存与 Cache
- **产出**：主存模块（可配置容量、存取周期、多体低位交叉或高位交叉）；Cache（直接映射、组相联、全相联；LRU、FIFO、随机替换；写回加写分配、写直达加非写分配），指令 Cache 与数据 Cache 分开；CPU 访存都经过 Cache，统计命中率和平均访问时间
- **小步骤**：① 主存：按字节编址、小端；用若干片存储芯片拼出主存，打印每片的地址范围和片选 ② 多体交叉：连续访问时低位交叉的流水时间与带宽，和高位交叉对比 ③ Cache 地址划分（标记 | 组号 | 块内偏移）与查找，三种映射方式可配 ④ 替换算法与写策略：脏位、写回时机；按配置算 Cache 总容量（含标记位、有效位、脏位、替换控制位） ⑤ 接入 CPU：节拍模式下命中 1 拍、缺失按主存周期和块大小计；流水线模式下缺失时阻塞 ⑥ 在整机上复现 `co/06` 的第 ⑥ 步：MM32 程序按行、按列对二维数组求和，打印两种顺序的命中率和平均访问时间
- **通过标准**：主存地址各字段的位数、Cache 总容量、给定数组访问顺序的命中率、平均访问时间、交叉存储器连续访问的时间、存储器扩展的芯片数与地址范围
- **选做拓展**：两级 Cache；硬件预取；进阶可看 MESI
- **选开（考纲内）**：多处理器 Cache 一致性：两颗 MM32 核共享主存，写直达加监听失效，复现 `co/12` 的伪共享；DRAM 刷新造成的访存停顿（`co/05` 第 ① 步已练）
- **前置关卡**：`co/05-memory`、`co/06-cache`；阶段 02

### 04 · TLB 与两级页表
- **产出**：MMU：TLB（全相联或组相联）加两级页表（10/10/12）的硬件遍历，硬件维护 A、D 位；缺页、越权故障进内核；地址翻译 trace：虚拟地址拆分 → TLB → 页目录项 → 页表项 → 物理地址 → Cache → 主存，每一步打印地址和命中情况
- **小步骤**：① 虚拟地址拆分与页表项格式（`ISA.md` 第 7 节） ② 页表遍历：页目录项地址 = PTBR + DIR × 4，页表项地址 = 页表始址 + PAGE × 4 ③ TLB：查找、装入、替换，进程切换后 `TLBFLUSH` ④ 权限检查与故障：P = 0 产生缺页，W、U 不符产生越权，写 BADVA，EPC 存本条，处理完重新执行（此时内核先用「装入时全部映射好」的最简做法） ⑤ 有效访问时间：区分 TLB 命中、页表命中、缺页三条路径，统计 EAT（`os/10` 第 ④ 步） ⑥ 复现综合题：内核按题目给的页表内容建表，用户程序访问题中的地址，trace 与标准答案逐步对照
- **通过标准**：给定虚拟地址、页表和 TLB 内容，求物理地址以及是否命中 TLB、Cache、是否缺页；页表项的地址；页表共占多少页、顶级页表不超过一页；EAT
- **选做拓展**：带进程标识（ASID）的 TLB，切换进程不必全刷；4 MB 大页（10/22 划分）；反置页表
- **选开（考纲内）**：段式与段页式翻译模式（`os/10` 第 ⑤ 步已练）
- **前置关卡**：`co/07-vm-translate`、`os/10-paging`；阶段 03

### 05 · 进程与调度
- **产出**：宿主 C 内核的进程管理：PCB、五状态转换、上下文切换（R0~R7、PC、PSW、PTBR）、`fork`（复制地址空间）、`exec`（装入汇编器产出的映像）、`wait`、`exit`；调度算法运行时可切换（FCFS、SJF/SRTN、HRRN、优先级、RR、多级反馈队列），时钟中断驱动抢占；甘特图 trace

### 09 · 总线、DMA 与 I/O 软件

### 10 · 链路层：网线、成帧与交换机

### 11 · 网络层：IP、ARP、NAT 与路由

| 首次用到的阶段 | 用途 | 复用的关卡与文件 |
|---|---|---|
| 阶段 05 | 就绪队列、多级反馈队列各级 | `lib/04-queue` 的 `cycq.h`、`cycq.c` |
| 阶段 05 | `sleep` 定时器 | `lib/09-heap-huffman-ufset` 的 `heap.h`、`heap.c`（阶段 13 的 `zip` 要用的 `huff.h`、`huff.c` 也写在这一行） |
| 阶段 07 | 伙伴系统空闲链、LRU 的使用顺序 | `lib/02-linked-list` 的 `dlist.h`、`dlist.c` |
| 阶段 07 | LRU 判断页在不在、TLB 之外的页查找 | `lib/16-hash` 的 `hash.h`、`hash.c`、`chain.c`、`open.c` |
| 阶段 08 | 大目录的文件名索引 | `lib/15-btree` 的 `bp.h`、`bp.c`、`limit.h`、`limit.c` |
| 阶段 10 | 链路层发送窗口 | `lib/04-queue`（阶段 05 已引入） |
| 阶段 11 | OSPF 的 Dijkstra | `lib/13-graph-app` 的 `graph.h`、`graph.c`、`path.h`、`path.c` |
| 阶段 11 | IP 首部校验和 | `net/01-encap-parse` 的 `checksum.h`、`checksum.c`、`bytes.h`、`bytes.c` |
| 阶段 13 | `grep` | `lib/06-string-kmp` 的 `match.h`、`match.c`、`nexttab.h`、`nexttab.c` |
| 阶段 13 | `sort` | `lib/19-external-sort` 的 `repl.h`、`repl.c`、`loser.h`、`loser.c`、`balance.h`、`balance.c`、`ext.h` |
| 阶段 13 | `zip` | `lib/09-heap-huffman-ufset` 的 `huff.h`、`huff.c`（阶段 05 已引入） |
| 选开 | 虚拟内存区间（VMA） | `lib/11-rbtree`（做阶段 07 的选开时再加进 `DEPS`，加前先确认文件名与已有文件不重名） |
| 选做 | CFS 调度 | `lib/11-rbtree`（做阶段 05 的拓展时再加进 `DEPS`） |

同一关卡在 `DEPS` 里只写一行，要用的文件都列在这一行。上面这些文件放在一起已验证可以一起编译链接、零 warning、没有重名符号。死锁检测用的有向图找环（`lib/12`）因为和 `lib/13` 的 `graph.c` 重名，不链接，在阶段 06 里按其思路重写。
