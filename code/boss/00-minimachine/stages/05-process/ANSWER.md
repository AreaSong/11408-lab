## 思路

没写 `proc on` 时，`k_step` 是空的，系统调用仍走阶段 01 的栈保存。`exit` 还是结束整台机器。时钟中断也还是阶段 01 的屏蔽字服务。所以旧用例不用改。

`proc on` 之后，内核给初始程序建一份页表，再放一个闲逛进程。闲逛进程号是 0，指令是一条跳向自己的 `jmp`，不进就绪队列，也不进平均。用户进程从 1 号起。代码页按装入时的物理地址做恒等映射，至少覆盖 `00001000H` 那一页。栈页在虚拟地址 `7FFFE000H`，SP 设成 `7FFFF000H`，向低地址长。`00000000H` 那一页不映射。页目录从 `00080000H` 起，往上分配，停在内核栈 `000E0000H` 之前。

切换时把 R0～R7、PC、PSW 放进 PCB，改 PTBR，再 `mmu_flush`。TLB 没有进程标识，不刷就会用到上一个进程的页框。系统调用返回靠 `IRET` 恢复 PC 和 PSW，通用寄存器要内核自己写回。时钟中断也一样：时间片到了先入队，再选下一个，然后让 `IRET` 回到新进程。

`fork` 把父进程已经映射的用户页逐页复制。子进程 R0 = 0，父进程 R0 = 子进程号，两边的 PC 都是系统调用的下一条。父进程不让出 CPU，除非当前算法会因新进程抢占。两次 `fork` 再各写一个字符，一共 4 个进程写 4 次。`exec` 按 `keep` 登记的名字换掉地址空间，PC 改到新映像的入口。`wait` 有僵尸子进程就收掉；没有就阻塞，等子进程 `exit` 把它唤醒。`sleep` 把到期时刻推进小根堆，自己阻塞。闲逛进程每条指令之后看堆顶，到点了就把人放回就绪队列。

调度计算器不跑指令，时间就是题目里的单位。同一时刻先让新到达的进程入队，再把时间片用完的进程放到队尾。这是王道对 RR 的约定。SJF 不抢占。SRTN 和抢占式优先级只在严格更短、严格更高时抢走正在跑的进程，相等就继续。HRRN 的响应比用交叉相乘，等待为 0 时大家的比都是 1，于是退回先来先服务。多级反馈队列新进程进第 0 级。时间片用完才降级；这一拍已经运行完，就按结束处理，不再降。被更高队列抢走时放回本队列队尾，下次重新拿满时间片。2019-27 的第二级不是翻倍的时间片，而是按剩余 CPU 选短的。

真机上的抢占只在节拍模式做。`policy rr 周期` 把时钟周期设成这个数，IRQ0 到来就当作时间片到了。FCFS、SJF、HRRN、非抢占优先级不看这个中断。流水线打开时不改进程，避免段间寄存器还指着上一个进程。

## 和关卡的差异

| 关卡 | 整机里怎么用 |
|---|---|
| `os/02` | 五状态的边和它一样：阻塞不能直接运行，就绪不能直接阻塞。撤销可以从创建、就绪、运行、阻塞收走。`exit` 只从运行发生 |
| `os/04` | 选人规则、平局、甘特图和三个平均分数与那一关相同。那一关当时没有循环队列，这里 FCFS 和 RR 的就绪队列用 `lib/04` 的 `cycq`。切换开销这一关固定为 0，例题本身也是 0 |
| `os/05` | 多级反馈队列的降级、同一时刻先接纳再降级、被抢占不降级，都在 `k_mlfq.c`，每一级一个循环队列。真机上的 `policy mlfq` 先按一级时间片轮转，2019-27 的两级差别用 `sched fb2` 对 |
| `lib/04` | 循环队列牺牲一格，只存进程号。容量 16 时最多 15 个，本阶段进程不超过 8 个 |
| `lib/09` | 小根堆下标从 1 起。堆里不存指针，用「时刻 × 16 + 进程号」把两个数合成一个键 |

## 易错点

- 2023 年第 29 题 P3 的 CPU 时间是 13ms。写成 15ms 时，平均周转不是 61。P1 的周转是 115，等待是 55，响应时间是 0：它在 0 时刻就上了 CPU，中间被抢占的时间算等待，不算响应。
- 2019 年第 27 题 Q1 时间片是 10，Q2 按剩余时间选短进程，不是再给一个 20 的时间片。平均等待是 15，不是 10。输出里的 q0 就是题目的 Q1。
- RR 在时刻 2 的队列是先到的 P2，然后才是时间片用完的 P1。把顺序倒过来，后面的完成时刻都会错。
- 响应比都是 1/1 时，HRRN 先跑先来的长进程。SJF 才先跑短的。`P1(0,10)` 和 `P2(0,2)` 同时到达，HRRN 的第一段是 P1，SJF 的第一段是 P2。
- 时间片用完回到就绪，不是阻塞。阻塞是 `wait`、`sleep` 这种自己等事件。
- 就绪不能直接阻塞，阻塞不能直接运行。唤醒只到就绪，还要再调度一次才运行。
- `fork` 的打印次数看的是有几个进程会执行到那条输出，不看谁先跑。两次 `fork` 都不判断返回值，四个进程都会写。
- 切换必须清 TLB。只改 PTBR、不清 TLB，子进程会沿用父进程的页框。

## 概念卡片参考

### 卡片一：五种状态

| 从 | 到 | 怎么发生 |
|---|---|---|
| 创建 | 就绪 | 接纳 |
| 就绪 | 运行 | 调度 |
| 运行 | 就绪 | 时间片用完，或被抢占 |
| 运行 | 阻塞 | 自己等 I/O、等子进程、`sleep` |
| 阻塞 | 就绪 | 唤醒 |
| 运行 | 终止 | 自己 `exit` |

### 卡片二：什么时候调度

| 事件 | 谁会因此换人 |
|---|---|
| 运行结束、自己阻塞 | 所有算法 |
| 时间片用完 | 时间片轮转、多级反馈队列 |
| 来了严格更合适的进程 | SRTN、抢占式优先级；多级反馈队列里是更高的那一级有人 |

调度了不一定换人。队列里只有自己时，时间片到了再选中的还是自己，甘特图连在一起。

### 卡片三：上下文里有什么

R0～R7、PC、PSW、PTBR。硬件在中断隐指令里只保存 EPC 和 EPSW，通用寄存器和页表基址是内核保存的。换了 PTBR 还要清空 TLB。
