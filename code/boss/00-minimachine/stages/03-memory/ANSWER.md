## 思路

主存还是阶段 00 那块小端字节数组。芯片和多体是计算器：考试问的是片选范围和连续访问要多少纳秒，不改变 CPU 每拍的微操作。低位交叉的模块号按题目给出的地址单位取模。2015 年那一串就是地址 mod 4。连续的字另算时间：m×τ ≥ T 时低位是 T+(n−1)τ，否则按每个模块的空闲时刻排；高位交叉这些字都挤在同一个模块里，时间是 n×T。带宽的 M 是 10⁶。

Cache 的地址划分和 `co/06` 同一条公式。块号 = 地址 / 块字节，组号 = 块号 mod 组数，标记是块号剩下的高位。全相联没有组号。直接映射的组号就是行号。

行里存着这一块的副本。读命中从行里取。读缺失先把脏行写回，再从主存把整块填进来。写回的写命中只改行，脏位置 1。写直达的写，无论命中还是写分配之后，都马上改主存，记一次「当时写主存」，但命中不再加拍。非写分配的写缺失绕过 Cache，只写主存里的那一个字。

空行优先，所以随机替换在组被占满之前不会抽签。LRU 用越大越新的时间戳，命中和装入都更新。FIFO 只在装入时更新。牺牲的是时间戳最小的那一行。随机替换用固定种子的线性同余，两次一样的种子换掉同一路。

总容量 = 行数 × (标记 + 有效位 + 脏位 + 替换位 + 块字节 × 8)。有效位总是 1。脏位只在写回时为 1。替换位只在 LRU 或 FIFO、并且路数大于 1 时是 log2(路数)。这些位不在主存地址里。存储容量的 K 是 2¹⁰。能整除 1024 时结果用 K 位，否则能整除 8 时用字节。2010 年因此是 532 B，2015 年因此是 148 K 位。

接到 CPU 上之后，原来的访存拍仍然是查 Cache 的那 1 拍。缺失额外的拍加进 `m->cycles`，节拍模式不另起一行微操作。流水线把同一拍的指令缺失和数据缺失，分开时取较大值，共用一块时相加，加进流水线周期。所以开了 Cache 之后，「阻塞」里会含这些拍，报告再单列一行。关着的时候这个数是 0，阶段 02 的报告一个字都不改。

平均访问时间按每一侧 Cache 自己的访问次数来除，不用流水线重叠之后的那个数：

平均访问时间 = (访问次数 + 这一侧的缺失额外拍) / 访问次数

数组按行优先。按列只改访问次序。两次都从空 Cache 开始。2010 年一行 256 个 int 是 1024 B = 16 个块，16 mod 8 = 0，同一列挤进同一行，直接映射一次都不中。按行每 16 个 int 缺 1 次，命中率 15/16。

单元测试里的 MM32 程序把这个比例缩小：4 行、块 64 B，一行 64 个 int 正好 4 个块，4 mod 4 = 0。按行仍是每块 16 个 int 里中 15 个，128 次访问命中 120 次。按列 128 次全缺。求和用寄存器，数据 Cache 里只有数组那一次 `ld`。

`mm_raw_read` / `mm_raw_write` 不进 Cache。装入映像、向量表用的就是这条路，所以打开 Cache 之前写好的主存，第一次读仍是缺失。已经注册的访存钩子优先于 Cache，阶段 04 的 MMU 可以插在前面。

## 易错点

1. **有效位要算，脏位和替换位看题目。** 2010 年说不考虑一致性维护和替换位，脏位和 LRU 是 0，有效位还在。8 × (64 B + 20/8 B) = 532 B。2015 年写回，1024 行 × (18+1+1) 位标记阵列，再加 1024 × 16 B，一共 148 K 位。漏掉有效位或脏位会落到 146 K、147 K。
2. **组号是 log2(组数)，不是 log2(路数)。** 2020 年 512 行 8 路，组数 64，组号 6 位。LRU 的 3 位在行里，不在 32 位地址里。地址是标记 20 + 组号 6 + 块内偏移 6。写直达没有脏位。
3. **行号 = 块号 mod 行数，直接映射时块号 = 地址 / 块大小。** a[0][31] 的地址是 320+31×4 = 444，444/64 = 6。a[1][1] 是 320+257×4 = 1348，1348/64 = 21，21 mod 8 = 5。
4. **按列会整列打在同一行上。** 一行的字节数 / 块大小如果能被组数整除，下一行就把上一行换掉。块里其余元素来不及再用。按行则是每块只缺一次。
5. **2015 年的冲突看间隔，不是只看模。** 8008 和 8004 都在模块 0，但隔了 4 次发射，4 体刚好轮完。8004 和 8000 只隔 1 次，前一次还没做完。
6. **模块不够时低位交叉也会停。** 4 体、200 ns、50 ns，连续 4 个字是 350 ns。2 体时 m×τ < T，低位变成 450 ns，高位仍是 800 ns。
7. **命中的 1 拍已经在原来的访存拍里。** 再加 1 拍，`practice-hit` 的时钟就不是 66。一次缺失是 5 × (16/4) = 20 拍。指令缺 1 次、数据缺 1 次，一共多 40 拍。
8. **写回没换出之前，主存数组还是旧的。** `dmem` 走 `mm_read`，能看见 Cache 里的新值。直接看字节数组要等这一行被换出。`mm_reset` 丢掉 Cache，不把脏行写回。

## 概念卡片参考答案

### 卡片一：三种映射

| | 直接映射 | 组相联 | 全相联 |
|---|---|---|---|
| 主存块能进哪 | 唯一的一行 | 唯一的一组，组内任意一行 | 任意一行 |
| 地址 | 标记、行号、块内偏移 | 标记、组号、块内偏移 | 标记、块内偏移 |
| 替换 | 没有选择 | 组内 LRU、FIFO 或随机 | 全部行里选 |

路数从 1 加到行数，就是从直接映射过渡到全相联。命中只比标记，还要看有效位。

### 卡片二：写策略

| | 写直达 | 写回 |
|---|---|---|
| 写命中 | Cache 和主存一起改 | 只改 Cache，脏位置 1 |
| 换出 | 不用写回 | 脏了才把整块写回 |
| 脏位 | 没有 | 有 |
| 常配的写缺失 | 非写分配 | 写分配 |

读缺失与写分配无关，仍然调块。

### 卡片三：平均访问时间

命中时间是 1 个 CPU 时钟周期。缺失额外时间 = 主存传一个字的周期 × 块内字数；写回脏块再加一次。平均访问时间 = 命中时间 + 缺失率 × 缺失额外时间。报告里写成 (访问次数 + 额外拍) / 访问次数，和这个式子相同。
