## 思路

计数器的「读、加、写」是三条指令。时钟中断只在指令结束时采样，所以 `TSL` 和 `XCHG` 自己不会被从中间切开，普通的加 1 会。`k_race_run` 把这个画面收成：不加锁时两个人读到同一个旧值，结果停在 n；加锁时一个人做完再换人，结果是 2n。真机上把时间片设成 1 个时钟周期，两个进程轮流执行下一条指令。单元测试里不加锁的计数小于 8，`TSL` 和 `XCHG` 都得到 8。共享靠 `share`：这一页在 `fork` 时不复制，父子的虚拟地址落到同一个页框。

系统调用的隐指令已经把 IF 清掉，处理函数返回前不会再被 IRQ0 打断。P 和 V 改队列就发生在这段里，所以内核临界区不用再写一条 `DI`。`k_kernel_if` 把进入内核之前的 PSW 按隐指令的方式清掉 IF、U、TF，用来核对这一点。

记录型信号量的值可以为负。P 先减，减完为负就按先来先服务进队并阻塞；V 先加，加完仍不大于 0 就叫醒队头。值不为负时队列是空的，为负时等待人数等于相反数。`sem_free` 在还有人等的时候拒绝。

银行家和化简是两张表。银行家的 Need 是以后最多还要的，回答「这次给了会不会走进不安全状态」。化简看的是此刻的申请边，回答「现在是不是已经互相等死」。当前申请全是 0 时，每个人都能被消去，系统却可以很不安全：`practice-unsafe` 把这两件事放在一起。一类资源有多份时，等待图里有环也不等于死锁。`practice-cycle` 里 P2 不再申请，先还回一份，环就断了。只有一份实例时，有环才和死锁是一回事。

安全性算法每次取下标最小的可运行进程，所以打印出来的那条是唯一的，不是唯一存在的。2012 年编号最小的是 P1 P2 P0 P3 P4，选项 D 是另一条，两条都安全，一共 66 条。申请的三关是：超过自己的 Need 就出错，超过现在的 Available 就等待，都过了才试分配。试分配不安全就整次作废，不改原来的表。

解除只在还占着资源的进程里挑。手里是空的人被划掉也不还资源。代价相同取编号更小的，王道没有规定并列时选谁，这样输出才只有一种。

经典 PV 的步进器一次只走一条 P、V 或临界区。生产者-消费者的 empty 初值是 1，做两次，生产和消费都是 2。把互斥 P 放在同步 P 前面，消费者拿着互斥量去等 full，生产者等互斥量，等待图成环。哲学家都先拿左边时，五根筷子各被一个人握住，右边都等着。room 初值是 4，至少有一个人进不了房间，那根空着的筷子能让里面的人吃完。读者优先时，第一个读者才去 P 写锁，两个读者可以同时在读区里，写者要等他们都离开。

真机上的生产者-消费者用系统调用：父进程做消费者，先等 full，子进程放一个 7 再 V(full)，父进程读出来，退出码是 7。故意写反的那一份不退出，两个用户进程都停在阻塞，闲逛进程在跑，两个信号量的值都是负的。

## 易错点

- 2012 年第 27 题，编号最小的安全序列不是选项 D。D 的 P3 P4 P2 P1 P0 单独拿去 `order` 是安全的。A 的第一步 P0 就要 7 个 R3，可用只有 3。Need 是最大需求减已分配：P0 是 (2,3,7)，不是有的转载印的 (2,2,7)。安全序列一共 66 条。
- 2011 年第 27 题走到 P1、P4 之后 Work 是 (2,2,2)，P2 和 P3 都还要 3 个 R2。没有安全序列。
- 2018 年第 26 题只有 P3 的尚需是 1。P3 手里本来是 0，还回来之后可用仍是 1，P1 和 P2 都还要 2。
- 2022 年第 26 题先只有 P0，还回之后是 (3,3,3)，P1 和 P2 都能接上。两条里编号最小的是 P0 P1 P2。
- 2014 年第 24 题不能按最大的那个需求去套 `3×(5−1)+1`。三人还差的是 1+1+1，再加 1 台，最少是 10。2009 年第 25 题问的是可能死锁的最小 K，是 4，不是保证不死锁的最多进程数 3。
- 2016 年第 25 题里 p4 是孤立结点。已经成环的是另外三个，所以至少 3 个。p4 若也去申请，死锁集合会变成 4 个，题目问的是至少。
- 值是 0 的信号量没有人等。值为负才表示有人在队列里，人数是相反数。把 0 理解成「有一个空位正在被等」会把 P/V 写反。
- 申请超过 Available 是等待，还没做安全性检查。超过 Need 是出错。试分配之后不安全才叫拒绝。这三句不是一回事。
- 不安全不等于已经死锁。申请全是 0 时化简能做完，他们一旦把 Need 都要满，银行家会说不安全。
- 多份实例时，有环只说明可能死锁。`practice-cycle` 是 `cycle=yes` 而且 `deadlock=no`。
- 撤销时跳过不占资源的人。`practice-recover` 的第二组里，P0 的代价是 1 但两手空空，撤销的是代价 100、占着那一个资源的 P1。
- 互斥 P 放在同步 P 前面，消费者会拿着互斥量去等空缓冲区。生产者再来拿互斥量，两边都过不去。

## 概念卡片参考

### 卡片一：记录型信号量

P 先把值减 1。减完大于等于 0，进程继续，临界区里的资源算它占着。减完小于 0，进程进队并阻塞，此时它还不占有资源。V 先加 1。加完仍小于等于 0，说明刚才有人在等，叫醒队头；加完大于 0，没有人等。所以等待人数是 `max(-value, 0)`。

### 卡片二：三种做法

| 做法 | 什么时候动手 | 要不要最大需求 |
|---|---|---|
| 预防 | 事先拆掉四个条件里的一个 | 不要 |
| 避免 | 每次申请时用银行家守住安全状态 | 要 |
| 检测 | 分配时不拦，事后化简 | 不要，只看当前申请 |

银行家回答不了「现在是不是已经死锁」。检测回答不了「以后按最大需求走会不会死」。

### 卡片三：申请的三关

1. 申请超过 Need：进程在改口，出错，不分配。
2. 申请超过 Available：资源不够，等待。这还不是不安全。
3. 两关都过：Available 减、Allocation 加、Need 减，再跑安全性算法。安全就答应，不安全就把这次假装作废。
