## 思路

五段每拍流一次。没有冒险时，第 i 条的 IF 在第 i 拍，WB 在第 i+4 拍。n 条提交完的最后一拍是 n+4，也就是 5+n−1。

寄存器堆按 ISA：WB 前半拍写，ID 后半拍读。关掉转发时，消费者要停在 ID，直到生产者走到 WB 的那一拍，所以相邻写后读停 2 拍，隔一条停 1 拍。2012 年写过「同一拍不能又读又写」，那会再多 1 拍；MM32 没有这句，不做成开关。

转发开着的时候，ALU 结果在 EX 段末就有，下一条 EX 能直接用，停 0 拍。load 的数要到 MEM 段末才从存储器出来，下一条若在 EX 就要用，必须再停 1 拍，然后从 WB 转过去。store 要写进存储器的那个数可以晚到 MEM 才读，所以紧跟在 ALU 或 load 后面的 store 自己不必为这个数再停。

控制冒险两条路：

- 预测不转移。PC 先按顺序加 4。分支在 EX 段末才知道。猜对就继续；猜错就把 IF 和 ID 里的两条冲掉，目标从下一拍开始取，惩罚 2 拍
- 阻塞到 MEM 结束。分支还在 IF、ID、EX 时不取下一条。它进入 MEM 的那一拍才取正确的下一条，所以下一条的 IF 比正常晚 3 拍。分支自己若还因数据多停了几拍，那几拍算在分支头上，不再加进这 3 拍

结构冒险只在统一存储器、而且 MEM 段真的访存时出现。运算指令的 MEM 不碰存储器，不抢 IF。

异常记在发现它的那条指令上，结果不写回。等它走到 WB，比它新的指令全部冲掉，再做阶段 01 的隐指令。这样除法错后面的 `st` 来得及在写内存之前被取消。外中断要等一条指令正常写回之后才采样，断点是下一条。`HLT` 一进流水线就不再预取，避免把后面的空字当成 `nop` 做掉。

三个性能数都用提交条数 n 和流水线总周期 T。主频 f 的单位是 Hz，题目里的 `freq` 用 MHz：

- CPI = T / n
- 吞吐率 TP = n 条 / T 个时钟周期
- 效率 E = (n×5) / (5×T) = n/T
- 执行时间 = T / f
- MIPS = f / (CPI × 10⁶) = 主频的 MHz 数 / CPI
- 加速比 S = 节拍模式的时钟周期 / 流水线的时钟周期

`compare` 把同一份映像装入两次。节拍模式的周期含每条指令的微操作；流水线的周期是五段的拍。两边的寄存器、内存、PSW、停机原因和控制台必须一样。时钟中断按周期累计，两种模式拍数不同，触发次数会不一样，所以对照程序不要开定时器。

真题序列的改写：`2014-44` 的 `bne R2, R6` 改成 `jr r2`。R6 在这段里没有被写，写后读只在 R2 上，所以停的拍数不变，但 `jr` 一定会跳。脚本把 r2 配成下一轮 `shl` 的地址，跳过去的就是 I7。`2023-19` 的 `beq t2, s3` 同样改成 `jr r3`，r3 里放着 `addi` 的地址，所以 I4 仍会执行，只是晚 3 拍才取到。

## 易错点

1. **关转发是停 2 拍，不是 3 拍。** 前半拍写、后半拍读，相邻写后读在 WB 那一拍就能读到。用 3 拍去画，2014 的总周期不是 22。
2. **转发消不掉紧挨着的 load-use。** ALU 后面的运算停 0 拍；load 后面要在 EX 用这个数的指令停 1 拍。store 的数据不算这一类。
3. **前一条停在 ID，后一条的 IF 会重复。** 这是按序发射。2014 的 I5 就是这样，它自己和谁都没有写后读。
4. **控制阻塞 3 拍不要再加到分支自己的数据阻塞上。** 2023 的 beq 先为 load-use 停 1 拍，下一条再晚 3 拍，一共多 4 拍，理想 8，实际 12。
5. **预测不转移猜错冲 2 条，猜对冲 0 条。** 无条件 `jmp` 总会猜错。
6. **结构冒险不是每条指令的 MEM 都访存。** 四条里只有第一条 load 会在第 4 拍和第 4 条的 IF 相撞，所以只多 1 拍。
7. **精确异常在 WB 才处理。** 除法错和后面的 store 同时在流水线里时，store 还没写，WB 先把后面冲掉。缺页也一样，而且更老的除法错先到 WB，缺页不会再发生。
8. **`统计` 的时钟和流水线「实际」不是同一个数。** 中断隐指令的 5 拍加进机器计数器，不加进五段的 T。没有中断时两个数一样。分类行里的「拍」在流水线模式是提交了几条，总周期看上面的结果行。

## 小步骤对应的代码

| 步骤 | 函数 | 在做什么 |
|---|---|---|
| ① | `cpu_pipe_run`、`record` | 空流水线先放进第一条，之后每拍记录 IF 到 WB。n 条的 WB 在第 n+4 拍 |
| ② | `id_stall`、`raw_stall`（`forward = 0`） | 生产者还没到 WB 就让 ID 再停一拍 |
| ③ | `raw_stall`（`forward = 1`）、`pipe_gpr` | EX 段的 ALU 结果可以转；load 还在 EX 且消费者在 EX 要用，就停 |
| ④ | `flow`、`branch_block` | 预测失败冲掉 IF 和 ID；阻塞模式等分支离开 EX 再取 |
| ⑤ | `struct_block`、`divert_exc`、`try_irq` | 统一存储器让 IF 让路；故障到 WB 才交付；外中断在成功写回之后 |
| ⑥ | `cpu_pipe_report`、`cpu_pipe_compare` | T、CPI、TP、E、执行时间、MIPS，以及节拍周期 / 流水线周期 |
