# 408 代码区

> 最终 Boss：**MiniMachine**——用 C 从下往上搭一台玩具计算机：CPU → 存储 → 操作系统 → 网络。

## 目录

| 目录 | 科目 | 说明 |
|---|---|---|
| `lib/` | 数据结构 | 手写的通用库（线性表、栈、队列、哈希、树、图……），供其他关卡复用 |
| `co/` | 计算机组成原理 | 数据表示、Cache、迷你 CPU、地址翻译…… |
| `os/` | 操作系统 | 进程调度、PV 同步、死锁、页面置换、文件系统、磁盘调度…… |
| `net/` | 计算机网络 | 分层封装、子网与路由、滑动窗口、TCP 拥塞控制…… |
| `boss/` | 综合 | 把各科模块接起来，完成 MiniMachine |

## 关卡约定

- **命名**：`序号-主题`，序号即学习顺序，例如 `co/06-cache/`；66 关的目录已全部建好；`example/00-rotate/` 是一道完整的样板题
- **每个关卡目录**（以 `lib/02-linked-list/` 为例）：

  ```
  02-linked-list/
  ├── TASK.md          题目：做什么、输入输出格式、真题题面（不含答案）
  ├── ANSWER.md        答案讲解：思路、三段式、易错点，做完再看
  ├── NOTES.md         我的复盘和概念卡片
  ├── DEPS             （可选）本关复用的其他关卡
  ├── tests/           真题数据 <用例>.in/.out，答案和每次尝试共用
  ├── CMakeLists.txt   lab.sh 生成，收录下面的各个项目
  ├── answer/          标准答案（一个完整的 CLion 项目）
  └── mine/                我的所有尝试（平时为空，用到时才建；每个子目录都是独立的 CLion 项目）
      ├── 2026-11-01-first/           【情况 1】正常写 / 空白重写(-rewrite)：我自己用 ./lab.sh 建
      │   ├── .mode                   记录教学方式（m0~m3），lab.sh 自动生成
      │   ├── .done                   （运行 ./lab.sh done 后出现）标记本次已完成，供后续关卡复用
      │   ├── CMakeLists.txt          跑关卡层的 ../../tests/
      │   ├── main.c                  主程序入口（读输入前用 prompt("请输入…") 提示）
      │   ├── test.c                  单元测试入口
      │   ├── src/                    本关核心代码（我写）
      │   └── deps/                   lab.sh 复制进来的 test.h、prompt.h 和依赖关卡代码，不手改
      │
      ├── 2026-11-03-first-blank/     【情况 2】挖空(-blank) / 找 bug(-bug)：选定后由 AI 调用 lab.sh 建并备好作业
      │   ├── .mode / CMakeLists.txt / main.c / test.c / deps/
      │   └── src/                    -blank：AI 写好能编译的骨架，关键行留 /* TODO(你)：… */ 给我填
      │                               -bug：  AI 写好埋了 1~3 个 bug 的代码，我定位修好（修好后把 diff 记进 NOTES.md）
      │
      └── 2026-11-20-review-variant/  【情况 3】变式题(-variant)：选定后由 AI 调用 lab.sh 建并出题
          ├── VARIANT.md              ★ AI 写：改了原题什么条件、新的输入输出格式和样例
          ├── tests/                  ★ 变式题专属测试目录（只跑这里的 .in/.out，不跑原题测试）
          ├── CMakeLists.txt          最后一行指向本目录的 ./tests/check.cmake
          └── main.c / test.c / src/  我按 VARIANT.md 编写
  ```

## 日常怎么跟 AI 说（提示词速查）

> 规则已写进 `AGENTS.md`（每次新对话自动加载），直接说自然语言即可；完整教学与练习细则见 [TEACHING.md](TEACHING.md)。

| 我想做什么 | 我对 AI 说 | AI 会怎么做 |
|---|---|---|
| **开始学某一关**（最常用） | `学 lib 01` 或 `开始 co 00` | 先读进度表、题目、我的 NOTES 和随笔，问我这关什么程度，并推荐教学档位（M0~M3）与练习形式 |
| **零基础手把手 + 挖空** | `学 lib 02，用 M0 领读` | 当场调用 `lab.sh` 建好 `-blank` 尝试并填入挖空骨架，按「①学什么 → ②怎么做 → ③怎么在 CLion 跑起来」一步步带我 |
| **让我找 bug** | `学 lib 01，给我出个找 bug 练习` | 当场调用 `lab.sh` 建好 `-bug` 尝试并写入埋了 bug 的代码（若只练单道题会自动精简无关文件），修好后帮我把 diff 归档进 `NOTES.md` |
| **给我出变式题** | `复习 lib 00，给我出一道变式题` | 当场调用 `lab.sh` 建好 `-variant` 尝试，写好 `VARIANT.md` 题面与专属 `tests/`，我来写代码 |
| **某一步卡壳了** | `卡住了` | 先诊断我是概念、设计、C 语法还是调试卡住 → 只针对这一点降一档帮我 → 解决后回原档 |
| **调整引导深浅** | `降一档` / `升一档` | 立刻切换教学档位（如 M1 引导 ↔ M0 领读 / M2 项目指导 / M3 独立挑战） |
| **今天时间少** | `今天只有 20 分钟` | 进入轻量模式：不写新代码，只带我做「预测 → 运行」、反讲或整理对比卡片 |
| **练选择题手推 / 费曼反讲** | `来个预测练习` / `我给你反讲一遍` | 给我输入让我手推每步 trace 再跑程序对照；或扮“不懂的学生”追问我原理 |
| **写完交作业** | `写完了，帮我审查` | 跑测试 → 代码审查 → 更新进度表的「档位」「最近一次」 → 提醒我 `done` 和归档随笔 |

## 怎么用 CLion 与 `lab.sh`

1. **打开项目**：直接用 CLion 打开顶层 `code/` 文件夹即可。
   - **默认是智能加载模式（`mine`）**：左侧文件树能看到全部 66 关；右上角运行下拉框**自动只加载我已经建过 `mine/` 尝试的关卡**（那 50 多关还没学的标准答案不会塞进来添乱）。因此**我学过的任何一关，在左边随便点开 `main.c` 行号旁都有绿色 `▶` 按钮可以直接运行**，不用敲命令切换。
2. **新建一次尝试**：
   - **我自己从头写（正常写 / `-rewrite` 空白重写）**：在 `code/` 下运行 `./lab.sh` 选「新建尝试」（或 `./lab.sh new lib 02`），建出来的项目已经能编译运行，文件名和答案一致；
   - **需要 AI 先出作业（`-blank` 挖空 / `-bug` 找 bug / `-variant` 变式题）**：平时不预建，等我在对话里跟 AI 选定后，AI 会当场调用 `./lab.sh new` 建好这次尝试并把挖空骨架、问题代码或变式题面备好（也可以我自己先用 `./lab.sh` 建好再让 AI 填）。
3. **加载与运行**：新建或删除尝试后，在 CLion 里点 **`File → Reload CMake Project`**，右上角下拉框选程序运行或调试：`linked_list_first` 是我的主程序，`linked_list_first_test` 是单元测试，带 `_answer` 的是标准答案。
4. **跑测试**：下拉框选「All CTest」点运行；终端可用 `ctest -R '^linked_list_first'` 只跑某次尝试（变式题只跑它自己目录里的 `tests/`）。
5. **标记完成**：写完并通过测试后，用 `./lab.sh done` 标记完成（`-bug` 和 `-variant` 练习不能标记）：之后依赖本关的关卡（比如用到栈的二叉树）复制的就是我写的代码，没标记就一直用答案。

`lab.sh` 不带参数是交互菜单；也可以直接用子命令（`<尝试>` 写目录名或 `list` 里显示的编号）：

| 命令 | 作用 |
|---|---|
| `./lab.sh new lib 02 [说明] [--mode m0..m3] [--drill blank\|bug\|rewrite\|variant]` | 新建尝试项目（选教学方式与练习形式），并在 `NOTES.md` 追加小节；说明缺省依次为 first、review、review2…… |
| `./lab.sh list [lib] [02]` | 查看各关的尝试次数，或某关每次尝试的方式、练习、文件与完成标记 |
| `./lab.sh rename lib 02 <尝试> <新说明>` | 改说明（日期和练习后缀不变），程序名和 `NOTES.md` 小节标题一起改 |
| `./lab.sh delete lib 02 <尝试>` | 确认后删除尝试，`NOTES.md` 的复盘保留 |
| `./lab.sh done` / `undone lib 02 <尝试>` | 标记完成 / 取消标记（`-bug` / `-variant` 不能标记），并更新依赖本关的各次尝试的 `deps/` |
| `./lab.sh review [lib]` | 查看已学关卡的档位、距今天数与复习建议 |
| `./lab.sh focus [mine \| all \| lib 02]` | 查看或切换 CLion 加载范围（默认 `mine`：自动加载已建过尝试的关卡，随便点哪关都能直接运行） |
| `./lab.sh sync [lib] [02]` | 重新生成关卡配置、测试脚本和各项目的 `deps/`（改了 `DEPS` 或答案后用） |

在 `src/` 里新增 `.c` 文件后，要在项目的 `CMakeLists.txt` 里把它加到 `add_executable` 的文件列表中（和 CLion 原生项目一样）。
- **考查范围**：以 2027 年 408 统考大纲为准，各科 `LEVELS.md` 末尾有逐条的大纲覆盖对照

## 每关的闭环

0. **定档与建尝试**：开始一关时 AI 先问这关我掌握到什么程度，推荐教学方式（M0 领读 / M1 引导 / M2 项目指导 / M3 独立挑战）和练习形式，再由我用 `./lab.sh` 新建尝试，详见 [TEACHING.md](TEACHING.md)
1. **学**：读王道对应章节，明确考纲采用的模型与约定
2. **设计**：先在纸上画数据结构和状态流转
3. **编码**：100~300 行，能跑通即可
4. **真题验证**：2~3 道真题数据输入，输出必须与答案一致
5. **复盘**：把踩过的坑和本关的概念卡片写进 `NOTES.md`
