# 教学方式

> 一句话：整套体系由 **「2 种学习模式（🟢 先学会［永远默认，像刷力扣/写考卷一样只专注核心理论与纯粹算法］ vs 🔵 规范化代码［按需开启，写完整工程壳子跑 `ctest`］）」 × 「4 种学习档位（M0~M3，AI 帮得一档比一档少）」 × 「7 种练习形式」** 三个正交维度组成。**所有尝试按需实时创建，平时绝不提前预建。**
> **何时读本文件**：每关开场定档时、用户说「规范化 / 升一档 / 降一档 / 卡住了 / 复习 / 只有 20 分钟 / 填练习代码 / 出变式题」时。其余时间不必读。

## 一、学习者的三个状态维度

| 方向 | 取值 | 用途 |
|---|---|---|
| **① 掌握度**（记入进度表「档位」列） | L0 没接触 · L1 看过书有印象 · L2 懂概念但写不出 · L3 能写但慢、要查 · L4 能空手写出且真题一次过 | 决定用哪一档教学档位（M0~M3） |
| **② 周期阶段** | 首学 → 巩固（学完 ≤ 1 周）→ 复习（隔几周）→ 冲刺（考前刷真题） | 决定做新关还是复习组合 |
| **③ 临时状态** | 卡住了 / 时间少或状态差 / 写完了 | 插入短流程，不改档位 |

## 二、2 种学习模式（顶层维度：无论选 M0~M3 哪一档，默认永远是「🟢 先学会模式」）

> **核心原则**：无论是零基础（M0）还是到后面自己限时刷题（M3），**默认一律采用「🟢 先学会模式」**——就像刷力扣（LeetCode）或写 408 考卷一样，直奔理论与最纯粹的核心算法函数，绝不写一大堆工程防御、`trace` 日志或 `scanf/printf` 命令行壳子；只有当用户主动要求时，才切换为「🔵 规范化代码模式」。

| 环节 | 🟢 先学会模式（永远默认 · 刷力扣/写考卷风） | 🔵 规范化代码模式（有需要时再切换 · 工业工程风） |
|---|---|---|
| **定位与节奏** | • 搞懂 408 理论与算法思想，直接写**最纯粹的核心函数**<br>• **单考点 15 分钟微循环**：每关拆成独立小考点，逐个走完「讲透→反讲→写核心函数→记随笔」小闭环，绝不一口气灌输整关 | 训练工业级 C 语言工程规范，完成整套项目壳子并跑通 `ctest` 入库供后续科目复用 |
| **1. 学与反讲** | • **零工程废话**：只讲 408 理论、物理画面与核心逻辑，不提 `trace`、防溢出等<br>• **反讲过关（硬门槛 + 考卷三段式）**：每学完一个考点，**必须由用户用自己的话给 AI 反讲明白**；遇到算法/真题时，顺带口述考卷第 (1) 问**「基本设计思想」**与第 (3) 问**「时空复杂度」**（练考场保底步骤分） | 讲本关工程接口约定（`.h/.c` 暴露规则、指针传出参数、`FILE *trace` 格式、边界错误码） |
| **2. 编码（兼容两类题型）** | • **算法手写型（`lib` 为主）**：像刷力扣一样只写王道 / 408 考卷标准的 **10~15 行最直白代码**（无 `trace`、无防溢出、无工程辅助结构体）<br>• **机制推演型（`co/os/net` 及树图查找）**：**先拿真题数据手推一遍状态表** → 只写模拟器最核心的 **1 个状态转移函数**<br>• **外围壳子空着不管**：`main.c`、`moves.c` 等保持初始 `return 0;` 占位，不删也不写 | • **写完整工程实现**：给所有函数加上判空、防溢出、`trace` 过程打印与辅助结构体<br>• **填满外围驱动壳子**：实现 `main.c`、`moves.c`、`median.c` 等命令行交互与格式对齐 |
| **3. 真题与验证** | • **真题**：按 408 考卷要求完成纯粹三段式（设计思想 + 纯净核心代码 + 复杂度）或手推过程表<br>• **验证**：只用 `test.c` 的简单断言（`CHECK_EQ`）测核心函数返回值是否与手推/标准答案一致 | • **验证**：跑通关卡层全套 `ctest`（`.in / .out` 字符级严格比对，零 warning） |
| **4. 通关与 `done` 解耦** | • **只更进度表，不跑 `lab.sh done`**：通关后直接更新科目 `AGENTS.md` 进度表（标 `✅` 与 `L1~L4`），**不运行 `./lab.sh done`**——让后续关卡的 `deps/` 自动沿用官方完整的 `answer/src`，避免因极简考卷版缺少工程接口而导致跨关编译报错 | • **工程组件入库**：全套 `ctest` 跑绿后，运行 `./lab.sh done` 将你写的完整工程代码正式替换进后续关卡的 `deps/` |

## 三、4 种学习档位（M0 ~ M3，在任一学习模式下决定 AI 帮多少）

无论当前处于默认的「🟢 先学会模式」还是「🔵 规范化代码模式」，都按掌握度选这 4 档：

| 档位 | 适用 | AI 做什么（默认在「🟢 先学会模式」下） | AI 不做什么 | 用户产出 |
|---|---|---|---|---|
| **M0 🐣 领读**（零基础手把手） | L0 | 1. **学+反讲**：用生活例子+简单数字讲透理论 → **你反讲给 AI 听，讲明白才过**<br>2. **语法扫盲**：提前把要用到的陌生 C 语法用 3 行小例子单独讲懂<br>3. **编码（防打字员）**：只给函数头和中文步骤注释（每次 2~3 行），手把手带你写出最直白的核心函数并用 `test.c` 验通 | **不贴整段现成代码让你当打字员照抄**；不混入工程规范废话 | 理解透彻的反讲笔记 + 亲手写出的纯粹核心代码 + 概念卡片 |
| **M1 🧭 引导** | L1~L2 | 苏格拉底式提问，一次只给一个提示；先让你反讲原理并说清算法思路，再直接写纯粹核心函数 | 不给代码 | 自己写的纯粹核心实现 |
| **M2 🏗️ 项目指导** | L2~L3 | 只给考纲目标、验收标准和约束；由你自己拆步骤写核心函数与真题；只在设计完成、编码完成两个节点做评审 | 你不开口就不提示 | 核心实现 + 自己写的设计说明（写进 NOTES） |
| **M3 🎯 独立挑战** | L3~L4 | **像刷力扣/考场实战一样**：只给题目和建议时限，直接写最纯粹的算法函数（无需写任何工程壳子）；完成后按考卷满分标准评价正确性、边界与复杂度 | 全程不帮 | 限时独立完成的核心算法实现 |

> **若切换到「🔵 规范化代码模式」**：M0~M3 的辅助程度不变，但编码目标从“只写纯粹核心函数”升级为“写满 `.h/.c` 工程防御、`trace` 打印与 `main.c` 外围壳子并跑通全套 `ctest`”（在 M0 下，冗长的 `fprintf(trace, ...)` 与 `scanf/printf` 格式字符串由 AI 直接给准并帮核对空格）。

### 各档在「每关闭环」里怎么走

| 步骤（按单考点微循环逐个推进） | M0 | M1 | M2 | M3 |
|---|---|---|---|---|
| 1 学与反讲 | AI 讲透单点理论与例子 → **你反讲给 AI 听（含考卷设计思想，讲明白才过）** | AI 指章节，你读并**反讲核心原理与设计思想** | 你自己读，AI 只说明考纲约定 | 跳过，或自查 |
| 2 设计 / 手推 | AI 带你做 3 行 C 语法扫盲 + 梳理步骤（机制题先手推真题表），你复述 | 你说清思路（机制题先手推），AI 追问 | 你写设计说明，AI 评审 | 你自己做 |
| 3 编码 | 按中文步骤注释每次写 2~3 行纯粹核心代码 + 跑 `test.c` | 你直接写纯粹核心代码，卡住时给一个提示 | 你写，到节点时审查 | 你限时直接写纯粹核心算法 |
| 4 真题验证 | AI 带着手推一遍 → 写纯粹考卷代码 + 口述时空复杂度 | 你写并测返回值，AI 解读差异 | 你跑 | 你跑，AI 按考卷三段式评分 |
| 5 复盘 | 归档 `Lab随笔.md` 至 `NOTES.md` 与概念卡片，更新进度表（`L0~L4`；默认不跑 `lab.sh done`） | ← | ← | ← |

### 升档 / 降档
- **降档**：同一个点连续卡住 3 次（或用户说「降一档」），就只针对**这个点**降一档帮忙，解决后回到原档
- **升档**：连续几步都顺畅、没要提示，AI 建议升一档；用户同意才升
- 结束时的「档位」记的是掌握度 L0~L4，不是用的哪一档模式

### 复习组合（周期阶段 ② 用）

先看进度表里的档位和「最近一次」，再按阶段挑 2~3 种练习：

| 阶段 | 推荐组合 | 判定 |
|---|---|---|
| 巩固（学完 ≤ 1 周） | 预测 → 运行 + 反讲 | 能顺利完成就保持档位 |
| 复习（隔几周） | 空白重写（`-rewrite`）+ 变式题（`-variant`） | 重写卡住就降一档，用对应模式补一遍 |
| 冲刺（考前） | 找 bug（`-bug`）+ 限时真题（M3） | 一次通过则定为 L4 |

## 四、7 种练习形式（任何一档都能叠加）

| 形式 | 是否建尝试 | 做法 | 对应 408 题型 |
|---|---|---|---|
| **挖空补全** `-blank` | 是 | AI 在用户建好的尝试里写能编译的骨架、挖掉关键行，用户补上 | 算法大题中的关键代码 |
| **找 bug** `-bug` | 是 | AI 按本关易错点和用户 NOTES 里真实犯过的错，写一份埋了 1~3 个 bug 的代码，用户定位并修好 | 易错点、边界条件 |
| **空白重写** `-rewrite` | 是 | 不看任何资料限时重写，再和上次的尝试对比 | 检验是否真的掌握 |
| **变式题** `-variant` | 是 | 改参数或条件（如换一种循环队列判满方式、换一种页面置换算法），AI 出题面与测试，用户写代码 | 真题的变形 |
| **预测 → 运行** | 否（对话） | 运行 trace 前先手推每一步的状态，写下来，再跑程序对照 | 选择题（手推过程） |
| **反讲**（费曼法） | 否（对话） | 用户讲原理，AI 扮演“什么都不懂的学生”追问到底 | 概念辨析、简答 |
| **对比卡片** | 否（写 NOTES） | 用表格对比容易混的概念，写进 NOTES 的概念卡片 | 定义、分类 |

## 五、新建尝试与分工约定（方案 A：按「谁先动手」区分，绝不提前预建）

> **铁律**：
> 1. **绝不提前预建**：没学到某关、或用户还没在对话里拍板选定方式之前，AI 绝不创建任何 `mine/` 目录。
> 2. **4 档主模式（M0~M3 正常写）与 `-rewrite` 空白重写**：全部使用 `./lab.sh new` 生成的**干净空模板项目**（M0 领读也不例外，绝不默认绑定 `-blank` 挖空，也绝不往 `mine/` 里预填代码文件）。用户自己运行 `./lab.sh` 创建（若用户选了 M0 领读且尚未建目录，AI 可跑一次 `./lab.sh new <科目> <关卡号> --mode m0` 建好空项目，但**严禁修改或预填里面的 `.c`/`.h` 文件**）。
> 3. **需要 AI 先出作业的 3 种专项练习（`-blank` 挖空 / `-bug` 找 bug / `-variant` 变式题）**：**仅当用户明确说出要做这 3 种练习之一时**，AI 才当场调用 `./lab.sh new <科目> <关卡号> --mode m× --drill <练习>` 创建该次尝试，并写入挖空骨架 / bug 代码 / 变式题面与测试（若用户已自建了该尝试，则直接填入）。

### `./lab.sh` 怎么用
- **交互菜单**：运行 `./lab.sh` → 选 `1) 新建尝试` → 选科目和关卡 → 选教学方式（M0~M3，默认 M1）→ 选练习形式（默认 `1) 正常写`；可选挖空 / 找 bug / 空白重写 / 变式）→ 填说明 → 确认
- **命令行**：`./lab.sh new <科目> <关卡号> [说明] [--mode m0|m1|m2|m3] [--drill none|blank|bug|rewrite|variant]`
  - 例：`./lab.sh new lib 02 --mode m0`（生成干净空项目 `mine/<日期>-first/`，记录 `.mode` 为 `m0`）
  - 例：`./lab.sh new lib 02 --mode m2 --drill variant`（生成 `mine/<日期>-review-variant/`）
- **记录位置**：教学方式记在尝试目录的 `.mode` 文件里（`m0`~`m3`）；练习形式就是说明的后缀（`-blank` / `-bug` / `-rewrite` / `-variant`，无后缀表示正常写）；`NOTES.md` 对应小节的第一行会自动写上 `- 方式：… · 练习：…`
- **CLion 加载范围（`./lab.sh focus`）与复习看板（`./lab.sh review`）**：
  - `./lab.sh focus mine`（**默认智能模式**）：顶层 `code/CMakeLists.txt` 自动只加载**已建过 `mine/` 尝试的关卡**（及 `example/`），未学关卡的 200+ 个标准答案目标不加载；用户在 CLion 里随便点开任何学过的关卡都能直接点 `▶` 运行
  - `./lab.sh focus <科目> <关卡号>`：单关极简模式，只加载指定的那 1 关
  - `./lab.sh focus all`：全量模式，加载全部 66 关
  - `./lab.sh review [科目]`：汇总四门课进度表里已开始/已通过的关卡，按进行中优先、档位从低到高、距今天数从久到近排序，并给出复习建议

### 每种练习誰建目录、谁写什么

| 练习形式 | 谁调 `lab.sh new`（均在定档后按需创建） | AI 往里写 | 用户写 | 测试跑哪份 | 能 `done` 吗 |
|---|---|---|---|---|---|
| 正常写 | **用户自己** | — | 全部代码 | 关卡层 `tests/` | ✅ |
| 空白重写 `-rewrite` | **用户自己** | — | 全部，不看资料限时写 | 关卡层 `tests/` | ✅ |
| 挖空 `-blank` | **AI 当场建并填好**（用户自建亦可） | **能编译**的骨架，关键行留 `/* TODO(你)：… */` | 填空处 | 关卡层 `tests/` | ✅（填完通过后） |
| 找 bug `-bug` | **AI 当场建并填好**（用户自建亦可） | 埋了 1~3 个 bug 的完整代码 | 定位并修复 | 关卡层 `tests/` | ❌ 代码主体是 AI 写的 |
| 变式 `-variant` | **AI 当场建并填好**（用户自建亦可） | `VARIANT.md`（改了什么条件、输入输出、样例）和本尝试 `tests/*.in/.out` | 全部代码 | **只跑本尝试自己的 `tests/`** | ❌ 解的是另一道题 |

### AI 出作业（`-blank` / `-bug` / `-variant`）时的细则
1. 必须先经用户在对话中确认选定该练习（或用户已自建了带该后缀的尝试）；严禁写入正常写或 `-rewrite` 的尝试目录
2. `-blank` / `-bug` 中每个由 AI 写的代码文件，开头加注释：`/* AI 生成的练习代码（挖空 / 找 bug），见 code/TEACHING.md */`
3. `-blank` 的挖空处统一写成 `/* TODO(你)：<这里要做什么> */`，函数先返回占位值，保证未填前也能编译通过
4. `-bug` 不提前告诉用户有几个 bug、在哪；用户卡住时一次只给一个范围提示。**修复通过后**，复盘阶段由 AI 将「原 bug 代码 vs 修复后代码」的关键 diff 贴入 `NOTES.md` 对应尝试小节中留痕，以免日后忘记当初埋的坑在哪
5. `-variant` 只写 `VARIANT.md` 和该尝试自己的 `tests/*.in/.out`，不碰 `src/`、`main.c`、`test.c`；测试数据至少 2 组（含边界），AI 先用草稿或手算核对 `.out` 正确再写入
6. **单点出题精简**：当一关有多个可执行程序（如 `lib/01` 含 `main`、`test`、`moves`、`median`、`majority`），而本次 `-bug` 或 `-variant` 只针对其中某一个小步骤或单道真题时，AI 在生成作业时一并删掉该次尝试里无关的空入口 `.c` 文件，并精简该尝试的 `CMakeLists.txt`（只保留本次要练的那个 `add_executable`），避免其他无关空程序在跑测试时满屏报 `FAIL`
7. 作业写入完成后，提醒用户在 CLion 里点击 `Reload CMake Project` 即可开始做题
8. 复习选关时，用户可运行 `./lab.sh review [科目]` 查看四门课已学关卡的档位、距今天数与复习建议；CLion 默认按 `mine` 智能模式只加载建过尝试的关卡（可用 `./lab.sh focus` 查看或切换）

## 六、临时短流程（状态 ③）

| 触发 | 流程 |
|---|---|
| 「卡住了」 | **卡壳诊断**：先问清是哪类卡点：概念 / 设计 / C 语法 / 调试 → 只针对这一点降一档帮忙 → 解决后回到原档 |
| 「只有 20 分钟」「今天状态差」 | **轻量模式**：只做预测题、反讲或对比卡片，不开新的编码 |
| 「写完了」 | **审查与归档**：跑 `test.c` 断言（规范化模式下跑 `ctest`）→ 代码与复杂度审查 → 归档 `Lab随笔.md` 至 `NOTES.md` 并更新进度表（仅在「🔵 规范化代码模式」且非 `-bug`/`-variant` 时额外提醒运行 `./lab.sh done`） |

## 七、开场询问模板（短平快：≤ 15 行，定档前严禁剧透）
