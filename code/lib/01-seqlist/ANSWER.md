## 思路

### 顺序表里元素怎么搬家

插入位序 i 时，下标 i−1 到 length−1 上的元素各向后一格，腾出 `data[i-1]`。必须从后往前搬：从前往后的话，`data[j] = data[j-1]` 会先把后面还没搬走的值盖掉。搬家次数是 `length - i + 1`。插在表尾（i = length+1）时一次都不用搬。

删除位序 i 时，下标 i 到 length−1 上的元素各向前一格，次数是 `length - i`。删最后一个元素时次数是 0。

平均次数把每个合法位置都算进去，而且认为这些位置等可能：

| 操作 | 位置 | 位序 i 的搬家次数 | 总和 | 平均 |
|---|---|---|---|---|
| 插入 | 1 … n+1，共 n+1 个 | n−i+1 | 0+1+…+n = n(n+1)/2 | n/2 |
| 删除 | 1 … n，共 n 个 | n−i | 0+1+…+(n−1) = n(n−1)/2 | (n−1)/2 |

`moves.c` 不是把公式再算一遍，而是真的对每个位置调用插入和删除，把函数数出来的次数加总，再和公式比。n = 5 时插入 15 次搬家、6 个位置，15/6 = 2.5 = 5/2；删除 10 次搬家、5 个位置，10/5 = 2 = 4/2。

### 扩容

`length == capacity` 时先 `realloc` 到两倍，再搬家。初始容量是 4，不是王道示例里的 `InitSize`，加倍规则一样：这样插入第 5 个元素就能在输出里看到 `grow 4 -> 8`。删除不把容量缩回去。

扩容若发生了内存复制，那是整表拷贝，不是插入定义里的“元素后移”。本关统计的 `moves` 只数后移或前移的赋值。

### 2011-42 中位数

两个序列各长 n，合并后长 2n。按题面，中位数是第 ⌈2n/2⌉ = 第 n 个（从 1 数），也就是较小的那个，不是两个中间值的平均数。题面例子合并后是 (2, 4, 6, 8, 11, 13, 15, 17, 19, 20)，第 5 个是 11。

维持 A、B 各一段，并且两段始终等长。每轮取两段下标中点（`(左+右)/2`，偏左）：

- 两个中点的值相等：它就是合并后的中位数，直接返回
- A 的中点更小：合并后的中位数落在 A 的右半和 B 的左半，另一半丢掉
- A 的中点更大：对称，留 A 的左半和 B 的右半

丢掉的个数必须相同，段长的奇偶决定中点留不留：

- 奇数：中点左右元素一样多，两边都留中点
- 偶数：下标中点是靠左的那个，较小的一侧要把这个中点一起丢掉，两边丢掉的个数才一样

缩到各剩一个元素时，较小者就是第 n 个。每轮段长减半，时间 O(log n)；只用几个下标，空间 O(1)。

归并着数到第 n 个也是对的，时间 O(n)、空间 O(1)，但题面要求时间和空间都尽可能高效，这一档拿不到时间上的最优分。先合并进一个长度 2n 的数组再取第 n 个，还多花 O(n) 空间。

### 2013-41 主元素

主元素是出现次数严格大于 n/2 的值，有则只有一个。从左向右维持一个候选和净票数：相同就加 1，不同就减 1；减到 0 时，当前这个元素改当新候选，计数记为 1（它自己算新一轮的第一票）。

主元素若存在，和别的值两两抵消后仍有剩余，最后留下的候选只能是它。没有主元素时也会留下某个候选，所以必须再扫一遍，数出真实次数，严格大于 n/2 才返回，否则返回 −1。两遍都是 O(n)，只用几个变量，空间 O(1)。

题面给了 0 ≤ ai < n，也可以开一个长度 n 的计数数组，时间同样 O(n)，空间 O(n)，最优性比 O(1) 空间略低。双重循环是 O(n²)。

## 易错点

1. **位序和数组下标差 1**。插入位序 i 写到 `data[i-1]`。循环写成 `for (j = length; j >= i; j--)` 时，`j` 是下标，`i` 是位序，两边单位不同，但这个写法正好让搬家次数等于 `length - i + 1`。
2. **插入平均是 n/2，分母是 n+1 个位置**。漏掉表尾那个移动 0 次的位置，总和仍是 n(n+1)/2，除以 n 会得到 (n+1)/2。删除没有“插到表尾”这种多出来的位置，平均才是 (n−1)/2。
3. **从后往前搬**。顺序表插入的覆盖问题是顺序存储带来的，链表没有这一步。
4. **扩容的复制不算进 moves，删除不缩容**。`practice-grow` 里插第 5 个元素时先出现 `grow 4 -> 8`，`moves` 仍是 0；删掉元素后 `cap` 还是 8。
5. **按值查找失败返回 0，主元素失败返回 −1**。位序 0 本来就不合法，可以拿来表示“没找到”。主元素的值域包含 0，`practice-zero` 的答案就是 0，不能再用 0 当失败。
6. **恰好一半不是主元素**。n = 8 时出现 4 次，`4 > 8/2` 不成立。判定写成 `times >= n/2` 会把这组判成有主元素。`times > n/2` 和 `times * 2 > n` 对整数等价。
7. **候选必须再验证**。2013-41 的第二个例子扫完候选是 5，但 5 只出现 4 次。不验证就会输出 5，而题面答案是 −1。
8. **中位数是第 n 个，不是两个中间值的平均**。题面例子若算 (11+13)/2 = 12，和定义不符。
9. **偶数段的中点要丢掉较小的那一侧**。奇数段两边都留中点。2011-42 的第三轮段长是 2：A 的中点 11 大于 B 的中点 8，应留下 `A[0..0]` 和 `B[4..4]`，答案 11。这一轮若也按奇数规则两边都留中点，会得到 8。王道用 `(s1+d1) % 2 == 0` 表示元素个数为奇数（首尾下标同奇偶）；本关直接看段长 `len % 2`，两种判断等价。
10. **两段必须一直等长**。丢掉的个数不同，下一轮的中点就不再对应全局的第 n 个。
11. **王道的引用在 C 里是指针**。`bool ListInsert(SqList &L, int i, ElemType e)` 写成 `seqlist_insert(SeqList *L, int i, int e, ...)`；需要带回被删元素时用 `int *out`，调用处传 `&value`。只读的查找传 `const SeqList *`。

## 2011-42 三段式

**1. 设计思想**

比较两段等长区间的中位数 a 和 b。a = b 时，a 就是两段合并后的中位数。a < b 时，丢掉 A 中较小的一半和 B 中较大的一半（丢掉的个数相同，段长为奇数时保留中点，为偶数时较小一侧连中点一起丢）；a > b 时对称。重复到各剩一个元素，较小者即为所求。这样每轮问题规模减半。

**2. 算法实现**

卷面不需要 trace。带过程打印的版本在 `answer/src/two_median.c`，分支和下述代码一致。实现里的中点写成 `s + (e - s) / 2`，下标非负时与 `(s + e) / 2` 相同，只是避免两个大下标相加溢出。

```c
int median(int A[], int B[], int n) {
    int s1 = 0, e1 = n - 1, s2 = 0, e2 = n - 1;
    while (s1 < e1 || s2 < e2) {
        int m1 = (s1 + e1) / 2;
        int m2 = (s2 + e2) / 2;
        int len = e1 - s1 + 1;                 /* 两段等长，看 A 的长度即可 */
        if (A[m1] == B[m2]) return A[m1];      /* 中点相等，即为中位数 */
        if (A[m1] < B[m2]) {                   /* 留 A 的右半、B 的左半 */
            if (len % 2 == 0) { s1 = m1 + 1; e2 = m2; }
            else              { s1 = m1;     e2 = m2; }
        } else {                               /* 留 A 的左半、B 的右半 */
            if (len % 2 == 0) { e1 = m1; s2 = m2 + 1; }
            else              { e1 = m1; s2 = m2; }
        }
    }
    return A[s1] < B[s2] ? A[s1] : B[s2];
}
```

题面例子的过程：

| 轮 | 段长 | 比较 | 保留 |
|---|---|---|---|
| 1 | 5，奇 | 15 > 6 | A[0..2]，B[2..4] |
| 2 | 3，奇 | 13 > 8 | A[0..1]，B[3..4] |
| 3 | 2，偶 | 11 > 8 | A[0..0]，B[4..4] |
| | | | min(11, 20) = 11 |

**3. 复杂度**

- 时间：每轮段长减半，O(log n)
- 空间：只用一组区间端点，O(1)

## 2013-41 三段式

**1. 设计思想**

从前向后扫描，用一个候选和计数器做抵消：遇到候选就加 1，遇到别的值就减 1，计数减到 0 时把当前元素换成新候选并把计数记为 1。若主元素存在，抵消结束后候选必是它。再扫描一次统计候选的真实出现次数，严格大于 n/2 则输出该候选，否则输出 −1。

**2. 算法实现**

带过程打印的版本在 `answer/src/majority_element.c`。

```c
int majority(int A[], int n) {
    int c = A[0], count = 1;
    for (int i = 1; i < n; i++) {
        if (A[i] == c) {
            count++;
        } else {
            count--;
            if (count == 0) {          /* 旧候选被抵消完，当前元素开新一轮 */
                c = A[i];
                count = 1;
            }
        }
    }
    int times = 0;
    for (int i = 0; i < n; i++) {
        if (A[i] == c) times++;
    }
    if (times > n / 2) return c;       /* 严格过半；0 也可能是主元素 */
    return -1;
}
```

**3. 复杂度**

- 时间：两遍扫描，O(n)
- 空间：只用候选、计数和次数，O(1)

## 概念卡片参考答案

### 卡片一：静态顺序表 vs 动态顺序表

| | 静态顺序表 | 动态顺序表 |
|---|---|---|
| 容量 | 编译期定死，`data[MaxSize]` | `malloc` 一块连续空间，`capacity` 记录当前容量 |
| 表满再插入 | 直接失败 | `realloc` 加倍后再插入 |
| 按位存取 | O(1) | 仍是 O(1)，因为还是连续存放 |
| 删除之后 | 容量不变 | 本关也不缩容，空槽留给以后的插入 |

区别在哪：两者都是顺序存储，逻辑关系都靠物理相邻来体现。变的只是“这块连续空间能不能在运行时变大”。扩容之后地址可能变，所以保存的是 `data` 指针，用下标访问，不把某个元素的地址长期留在外面。

### 卡片二：插入、删除的平均移动次数

见上面的对照表。插入平均 n/2，删除平均 (n−1)/2，都是 O(n)。按位读取是 O(1)，按值查找是 O(n)。这组数字是顺序表和后面链表对比的那一半：顺序表读得快，改结构要搬元素。
