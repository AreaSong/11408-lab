## 思路

### 假溢出，所以把数组接成环

顺序队列如果 `front` 和 `rear` 只增不减，出队空出来的格子在数组前头，`rear` 却已经顶到末尾。数组里还有空位，新元素却进不去，这叫假溢出。栈没有这个问题，因为进栈和出栈在同一端，指针会退回来。

把最后一格的下一格规定成下标 0，指针移动改成取模，空位就能再用。主程序容量 8，`practice-wrap` 里先入队 1 到 6，再出队三次，`front` 停在 3。接着入队 7、8、9：8 写在下标 7，9 写在下标 0。此时 `front = 3`，`rear = 1`，格子是

```text
[9 _ _ 4 5 6 7 8]
```

`rear` 指着下标 1 那个 `_`，那是下一空位，不是队尾。队尾元素 9 在下标 0，也就是 `(rear - 1 + 8) % 8`。`ok tail e=9 index=0 rear=1` 就是在核对这件事。

### 牺牲一个单元：front == rear 只表示空

成环以后，入队 8 个再让 `rear` 走一圈，`front` 和 `rear` 又重合了，和空队列长得一样。王道的做法是少用一格：`rear` 的下一格已经是队头，就宣布队满，那一格永远空着。

```c
空：front == rear
满：(rear + 1) % cap == front
个数：(rear - front + cap) % cap
```

先加 `cap` 再取模，是因为绕回后 `rear - front` 是负数。C 的 `%` 对负数的余数仍是负的，不能写成 `(rear - front) % cap`。`practice-wrap` 的最后一行是 `(1 - 3 + 8) % 8 = 6`，直接相减会得到 −2。

容量 8 时最多 7 个。`practice-full` 入队 1 到 7 之后 `full=1`，格子是 `[1 2 3 4 5 6 7 _]`，剩下的 `_` 就在 `rear = 7`。第 8 个被拒绝，队列不变。弹出 1 之后 `front` 变成 1，下标 7 不再是“必须留下的那一格”，9 可以写进去，新的空位转到下标 0。满的时候，那个 `_` 的下标就是 `rear`。

`cap` 至少是 2。`cap` 为 1 时，`(rear + 1) % 1` 永远是 0，队空和队满会同时成立。

入队是先写入 `rear` 指的空位，再把 `rear` 前进。这和“指针指向元素”的顺序栈相反：那里要先移动指针再写。这里 `rear` 已经指着空位，所以先写。

### size 和 tag：把空位也用上

三只队列的指针语句相同。差别是：重合的时候到底算空还是算满。

| | 队空 | 队满 | 最多 |
|---|---|---|---|
| 牺牲一格 | `front == rear` | `(rear + 1) % cap == front` | `cap - 1` |
| size | `size == 0` | `size == cap` | `cap` |
| tag | `front == rear && tag == 0` | `front == rear && tag == 1` | `cap` |

`tag` 记的是最近一次成功操作，不是“只在指针碰上时才看一眼”。入队成功置 1，出队成功置 0。初值必须是 0，否则空队列满足队满，第一个元素进不去。

`practice-fill` 用长度 4。前三个元素三只队列一样。第 4 个：

```text
sacrifice fail full front=0 rear=3
size front=0->0 rear=3->0 count=4 full=1
tag front=0->0 rear=3->0 tag=1->1 count=4 full=1 raw=0
```

size 和 tag 的 `front` 与 `rear` 都是 0，格子是 `[1 2 3 4]`，没有 `_`。`raw` 照搬牺牲单元的公式，得到 0，真实个数是 4。公式在“放满且 `front == rear`”时失效，所以 size 直接读 `size`，tag 在指针相等时改看 `tag`：相等且 `tag == 1` 就是 `cap` 个，相等且 `tag == 0` 就是 0 个。

再出队三次，牺牲单元已经空了，size 和 tag 里还剩 4。第四次出队只有它们能弹出 4。从这一步起，三只队列里的元素不再相同。判满条件不同，拒绝的时机就不同，后面的状态会岔开。

`practice-wrap` 里长度仍是 4。出队一次再入队，`rear` 从 3 绕回 0，牺牲单元已经满（3 个），size 和 tag 还能再进第 4 个，写到下标 0，`front` 和 `rear` 重新变成 1。满队列的 `cells` 是 `[5 2 3 4]`，`raw` 又是 0。

### 2011：rear 指向队尾元素，初值就不是 0

2011-3 把约定换了：队列非空时 `front` 和 `rear` 都指向元素。入队要先把 `rear` 前进，再写入，否则会盖住原来的队尾。

第一个元素要落在 `A[0]`。入队只改 `rear`，所以 `front` 一开始就是 0。写入前先执行 `rear = (rear + 1) % n`，结果要等于 0，因此 `rear` 的初值是 `n - 1`。`init 6` 打印 `front=0 rear=5`，接着 `rear=5->0 index=0`。`init 8` 是 `rear=7`。选项 B。

`n = 1` 时队空和队满又会撞在一起，程序直接 `fail n=1`。题干的 n 是一般长度。

这套指向如果仍牺牲一个单元，条件都要往后错一格：

```text
空：(rear + 1) % cap == front
满：(rear + 2) % cap == front
非空个数：(rear - front + cap) % cap + 1
```

队空时那个“加 1”的公式会得到 `cap`，必须先判空。`elem 6 0 5` 就是初始状态，`empty=1 count=0`。`elem 6 0 0` 是刚写入 `A[0]` 之后，个数是 1。`elem 5 0 3` 有 4 个元素，已经满。`elem 8 3 1` 是绕回之后的满队列，个数 7，不是 `(1 - 3) % 8`。

主程序不要改用这套。本关默认仍是“`rear` 指向下一空位”。看到题目先确认 `rear` 指着元素还是指着空位，再套公式。

### 链队列：头结点省掉的是入队，不是最后一次出队

队头删除、队尾插入，单链表要在两端都是 O(1)，就得同时留下 `front` 和 `rear`。王道的链队列带头结点：两个指针一开始都指向头结点，判空是 `front == rear`，和循环队列的空条件是同一句话。

入队两句对空队列也成立，因为 `rear` 这时就是头结点：

```c
rear->next = s;
rear = s;
```

出队删的是 `front->next`，不是头结点。队列里只剩这一个数据结点时，`rear` 正指着它。`free` 之后如果还让 `rear` 留在那里，下一次入队会往已释放的内存里写，而且 `front != rear`，判空会说队列不是空的。所以要加一句：

```c
if (p == rear) rear = front;
```

`practice-last` 里弹出 7 时打印 `last=1 rear=head`，紧接着入队 8 仍然成功。弹出 8 而队列里还有 9 时是 `last=0 rear=9`，`rear` 不用动。

队头元素是 `front->next->data`。头结点不存数据。链队列没有固定的队满，`malloc` 失败才插不进去。

### 双端队列：受限的是动作，不是某一端的名字

普通队列是一端只进、另一端只出。双端队列两端都能进能出。408 常考的是只放松一半：

- **输出受限**：两端都能入队，只能从一端出队。本关把出队固定在左端
- **输入受限**：只能从一端入队，两端都能出队。本关把入队固定在右端

2010 和 2021 的题面都是输出受限，而且做法是先把输入序列全部插入，再从左端出完。2010 写了“依次入此队列后再进行出队”。2021 没有这七个字，公开解答仍是先插完再出。`batch` 就是这个模型。第一个数从哪一端进，得到的队列一样；程序固定从右端进，所以成功的路径里第一行总是 `enq right e=1`。后面每个数先试右端，再试左端，找到一条能对上的就停。别的插法也可能得到同一条序列，测试对的是这一条固定路径。

2010 的 a 到 e 是 1 到 5。

| 选项 | 序列 | 程序里的入队 | 结果 |
|---|---|---|---|
| A | b a c d e | 1 右，2 左，3、4、5 右，得到 `[2 1 3 4 5]` | 可以 |
| B | d b a c e | 1 右，2 左，3 右，4 左，5 右，得到 `[4 2 1 3 5]` | 可以 |
| D | e c b a d | 1 右，2 左，3 左，4 右，5 左，得到 `[5 3 2 1 4]` | 可以 |
| C | d b c a e | 没有一种两端插入能把 c 插进已经挨着的 b 和 a 中间 | 不可以 |

1 刚进队，2 只能加在它的某一侧，所以 1 和 2 在最终序列里必须相邻。C 是 `4 2 3 1 5`，2 和 1 中间隔着 3。这只是否定了 C，不能反过来：1 和 2 相邻的序列也不见得插得出来。`1 2 4 3` 就是 1、2 相邻、但 4 插不进 2 和 3 之间。选 C。

2021 同样先插完再出。A、B、C 的路径在 `tests/deque/2021-2.out` 里，D 是 `4 1 3 2 5`，`legal=0`。1 和 2 被 3 隔开，两端插入做不到。选 D。

交替入队、出队比“全部进完再出”多。输出受限的交替模型里，左端正好是下一个要输出的数就先出队，否则先试右端入队，再试左端。`enum 3` 的六个排列都能由交替得到，`batch` 却只有 4 条。少掉的 `1 3 2` 和 `2 3 1` 必须在中途出队：例如先出 1，再把 3 从左端压到 2 前面，才能得到 `1 3 2`。

n = 4 的 24 个排列里，分类是：

| 类 | 条数 | 序列 |
|---|---|---|
| 两种交替都能得到 | 21 | `enum` 的 `both` |
| 只有输入受限 | 1 | `4 1 3 2` |
| 只有输出受限 | 1 | `4 2 1 3` |
| 两种都不能 | 1 | `4 2 3 1` |
| 其中先全部入队再出队 | 8 | 包含在上面两类里 |

`4 1 3 2` 的输入受限过程：1 到 4 从右端进入，右端弹出 4，左端弹出 1，右端弹出 3，再弹出 2。输出受限做不到：4 先出来，说明 1、2、3 都还在队里，而且 4 是从左端入的。剩下的队要让下一个输出是 1，左端只能是 1，此时队列只能是 `[1 2 3]`。弹出 1 之后左端是 2，不是 3。

`4 2 1 3` 正好相反。输入受限在弹出 4 之后队里是 `[1 2 3]`，2 在中间，出不来。输出受限可以：1 右、2 左、3 右、4 左，得到 `[4 2 1 3]`，再从左端出完。这条也在 `batch` 里。

`4 2 3 1` 两种都不行。输入受限同样卡在弹出 4 之后的 `[1 2 3]`。输出受限要让 2 紧跟在 4 后面，剩下的队列只能是 `[2 1 3]`；弹出 2 之后左端是 1，不是 3。

2021 的 D 用 `batch` 和交替的输出受限都不行，用输入受限却行：右端弹出 4 之后队是 `[1 2 3]`，左端出 1，右端出 3，再出 2，最后入 5 再出。所以“不可能”必须先看清受限的是输入还是输出，以及能不能中途出队。这两道题都是输出受限，而且是先入完再出。

### 2014：队空和队满要同时对

`end1` 就是 `front`，`end2` 就是 `rear`。最多 `M - 1` 个，仍是牺牲一个单元。两端都能进出，并不改变判满公式：从队头入队是先把 `front` 退一格再写入，从队尾出队是先把 `rear` 退一格再读。退格写成 `(i - 1 + cap) % cap`。C 里 `(-1) % cap` 是负数。

满的条件两端共用。只剩 `rear` 那一格是空的时候，从队尾写会用掉它，从队头写用的是它的前一格，也就是同一格。`practice-both` 在长度为 6 时放进 5 个元素，`front = 5`，`rear = 4`，格子是 `[1 3 4 5 _ 9]`，`_` 的下标就是 `rear`。这时从哪一端入队都被拒绝。个数仍是 `(4 - 5 + 6) % 6 = 5`。

四个选项用 `M = 6` 的两个状态就能分开：

| 状态 | 真实 | A | B | C | D |
|---|---|---|---|---|---|
| 空，`end1 = end2 = 0` | 空 | 对 | 对 | 把空当成非空 | 把空当成非空 |
| 满，`end1 = 0`，`end2 = 5` | 满，5 个 | 对 | 没看成满 | 队满这一条对 | 把满当成空 |

D 的“队空”其实是 A 的“队满”：`end1 == (end2 + 1) % M`。所以满队列上 D 打印 `empty=1`。B 的队满用了 `mod (M - 1)`，`end2 = 5` 时不等于 `(0 + 1) % 5`。

`end1 = 2`、`end2 = 4` 时队列里只有 2 个元素，四个选项的空、满都是 0，`match` 全是 1。只看一个没满也没空的状态，分不出对错。要选在所有状态下都对的那一条，空和满都得试。两条都对的只有 A。

## 易错点

1. **先看 rear 指着谁**。本关默认指着下一空位，队尾元素在 `(rear - 1 + cap) % cap`。`practice-wrap` 里 `rear = 1`，下标 1 是 `_`，队尾 9 在下标 0。2011 改成指向队尾元素，初值、入队顺序和个数公式全部跟着变。
2. **个数要先加 cap 再取模**。绕回后 `rear - front` 是负的。`(1 - 3 + 8) % 8 = 6`。写成 `(rear - front) % cap`，C 会得到负数。
3. **牺牲一个单元最多 cap - 1 个**。容量 8 时第 8 个进不去，留下的 `_` 下标就是 `rear`。判满写成 `front == rear` 会和队空撞车。`cap` 为 1 时两种条件同时成立，本关不允许。
4. **size、tag 队满时公式得到 0**。`practice-fill` 的 `raw=0` 旁边 `count=4`。个数要读 `size`，或者在 `front == rear` 时改看 `tag`。指针语句和牺牲单元相同，能放的个数不同，拒绝之后两边的队列就岔开了。
5. **tag 的初值是 0，而且每次成功操作都改**。初值写成 1，空队列会被当成满。只在指针碰上时才改，下一次就不知道上一拍是入队还是出队。
6. **2011 的 rear 初值是 n - 1，front 是 0**。入队先移动再写，第一个元素才落在 `A[0]`。非空个数要再加 1；队空时这个公式得到 `cap`，不能用。选项 A、D 让两个初值相等，空和满分不开。
7. **链队列删最后一个结点要让 rear 回到头结点**。头结点只省掉入队时对空队列的分支。漏了 `rear = front`，下一次入队会写到已经 `free` 的结点上，`practice-last` 里 7 弹出后再入队 8 就会坏。
8. **2010、2021 是先全部入队再出队**。1 和 2 必须相邻，这只是否定条件。2010 的 C、2021 的 D 都是 1 和 2 被隔开，所以失败；2010 的 D 虽然以 e 开头，1 和 2 仍然相邻，是可以的。相邻也不保证做得到，`1 2 4 3` 就插不出 4。`batch` 的第一条固定 `enq right e=1`，因为第一个数从哪边进都一样。
9. **输入受限和输出受限得到的序列不同**。n = 4 时，只有输入受限能得到 `4 1 3 2`，只有输出受限能得到 `4 2 1 3`，`4 2 3 1` 都不行。2021 的 D 用输入受限可以，用输出受限不行。题目问的是输出受限。
10. **交替出队比全部入完再出更多**。n = 3 有 6 个排列，`batch` 只有 4 个。`1 3 2` 必须先把 1 出队，再把 3 插到左端。
11. **2014 要空、满两个状态一起看**。空队列上 B 也对，满队列上 C 的队满也对，只占用一部分时四个选项可能全对。D 把队满条件当成了队空，满队列上它会说 `empty=1`。只有 A 两边都对。
12. **指针后退要先加 cap**。从队头入队是 `front = (front - 1 + cap) % cap`，然后再写。`practice-both` 里第一次从队头入队，`front` 从 0 退到 5，9 落在最后一格。

## 概念卡片参考

- **缓冲区**：2009-1 的打印缓冲区。主机按产生顺序写入，打印机按同一顺序取出，谁也不能插到已经写入的数据中间。这是队列，不是栈。栈会把后写入的先打出来。
- **层次遍历**：二叉树一层一层向外扩。当前层的结点先入队，出队时把它的孩子排到队尾，孩子就自然落到下一层。后面第 07 关用的就是这只队列。
- **BFS**：图从起点一圈一圈向外走，和层次遍历是同一件事。先遇到的顶点先扩展，扩展到的新顶点排到队尾。用栈就会变成 DFS。
- **和第 03 关的差别**：栈是后进先出，递归、括号、表达式用它。队列是先进先出，等待、缓冲、按层扩展用它。共享的只是“操作发生在端点”；端点有几个、哪一端允许进或出，决定它是栈、队列还是双端队列。
