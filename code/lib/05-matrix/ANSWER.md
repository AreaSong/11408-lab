# lib/05 · 多维数组与特殊矩阵 · 答案讲解

> 题目见同目录的 `TASK.md`；本文件是答案讲解，做完再看。答案代码在 `answer/` 项目里。
>
> 王道第 3 章。内存是一维的，多维数组要排成一列才能放下。地址能由下标用同一个式子算出来，所以取任意一个元素的时间都一样，这就是随机存取。特殊矩阵的下标映射也是这种式子，只是「前面有几个元素」不再是整行，而是一行比一行短。稀疏矩阵没有式子，位置只好存进三元组。

## 思路

### 先数前面有几个元素

行优先时，元素 `A[i][j]` 前面是若干整行，再加上本行里它左边的那些。一行走完要跨过的个数就是列数，所以乘的是列数。列优先把行和列对调：跨过的是整列，乘的是行数。

下标的起点藏在下界里。范围 `[lo, hi]` 的长度是 `hi - lo + 1`，这一维上的步数是 `下标 - lo`。`practice-row` 里同一个 3 行 4 列的数组：

```text
at i=1 j=2 passed=1 each=4 inner=2 offset=1*4+2=6 loc=1000+6*2=1012
at i=2 j=3 passed=1 each=4 inner=2 offset=1*4+2=6 loc=1000+6*2=1012
```

第一行的数组从 0 起，第二行从 1 起。`(1, 2)` 和 `(2, 3)` 是同一个元素，偏移都是 6。从 0 起的 `(2, 3)` 则是另一格，偏移 `2*4+3 = 11`，地址 1022。少减一次下界，问的就变成了旁边那个元素。

列优先的 `(1, 2)` 是 `passed=2 each=3 inner=1`，地址 1014。和行优先的 1012 差一个元素。最后一个元素两边相同：`A[0..3][0..4]` 共 20 个，`A[3][4]` 的偏移是 19，首地址 1000、每个元素 4 个单元时地址是 1076。可以用它检查公式有没有把行列乘反。

三维仍是这句话。行优先先跨面，再跨面里的行，最后是行内。`A[0..2][0..3][0..4]` 求 `(2, 1, 3)`：

```text
offset=2*20+1*5+3=48
loc=200+48*2=296
```

一个面有 `4*5 = 20` 个元素，一行有 5 个。列优先时最左边的下标变化最快，要从 `k` 往回数：`passed=3 face=12 mid=1 line=3 inner=2`，偏移 41，地址 282。下标改成从 1 开始的 `(3, 2, 4)`，减完下界仍是 48。

`scan2`、`scan3` 按这个次序把偏移和 0、1、2、… 比。`mismatch=0` 表示公式和真实铺法一致。负下界也走这里：`A[-1..1][2..4]` 是 3×3，行优先的 `(0, 3)` 偏移是 `(0-(-1))*3 + (3-2) = 4`。

### 2021-3：先求列数，答案是 300

题面不给列数。`A[0][0]` 在 100，`A[3][3]` 在 220，每个元素 1 个单元：

```text
diff=(220-100)/1=120
eq=(3-0)*cols+(3-0)=120
cols=39
query i=5 j=5 offset=5*39+5=200 loc=100+(200-0)*1=300
```

`A[3][3]` 前面有 3 个整行，还有本行的 3 个，所以是 `3*cols + 3 = 120`，列数是 39。再套到 `A[5][5]`：`5*39 + 5 = 200`，地址 300。选项 B。

两个点都在 `i = j` 上，地址差的比例碰巧是 3∶2，`220 + 120/3*2` 也能得到 300。问的若是 `A[5][0]`，这个比例就不能用。稳妥的做法是先解出列数。`120/3 = 40` 把本行的 3 个也当成了整行。用 39 却只加 5 个整行、不加行内的 5，得到的是 `A[5][0]` 的地址 295，那是选项 A。

### 特殊矩阵：前面的行一次比一次短

矩阵下标从 1 开始，压缩数组从 0 开始。`index = prefix + inner`。对称矩阵的另一半先交换下标，再套存下来的那一半。三角矩阵的另一半全是同一个常数，下标固定是 `n(n+1)/2`，这些位置不再各占一格。

| 种类 | 存哪些 | 长度 | prefix | inner |
|---|---|---|---|---|
| `lower` | `i ≥ j`，按行 | `n(n+1)/2` | `i(i-1)/2` | `j-1` |
| `upper-row` | `i ≤ j`，按行 | `n(n+1)/2` | `(i-1)(2n-i+2)/2` | `j-i` |
| `upper-col` | `i ≤ j`，按列 | `n(n+1)/2` | `j(j-1)/2` | `i-1` |
| `tri-lower` / `tri-upper` | 同上，另一半是常数 | 再加 1 | 常数区的 prefix 就是那个下标 | 0 |
| `band` | `\|i-j\| ≤ 1`，按行 | `3n-2` | `3i-4` | `j-i+1` |

下三角第 `i` 行之前有 `1+2+…+(i-1) = i(i-1)/2` 个。上三角按行时，第 `i` 行存 `n-i+1` 个，前面是首项 `n`、末项 `n-i+2`、共 `i-1` 项的等差数列。上三角按列时，第 `j` 列存 `j` 个（行号 1 到 `j`），前面是 `1+…+(j-1)`。

`practice-tri` 把对称和三角放在同一个位置上。4 阶、`(1, 3)`：

```text
k tri-lower ... swap=0 const=1 prefix=10 inner=0 index=10
k lower     ... si=3 sj=1 swap=1 const=0 prefix=3 inner=0 index=3
```

三角矩阵这里是常数，下标 10，数组长度 11。对称矩阵换成 `(3, 1)`，下标 3，就是下三角第 3 行第 1 个。两种矩阵的下三角公式相同，差在落在另一半时怎么办。

### 2018-3、2020-1、2016-4

2018 存的是 12 阶上三角，按行，问 `m(6, 6)`。它就在上三角上，不用交换。前 5 行有 `12+11+10+9+8 = 50` 个，`m(6, 6)` 是第 6 行的第一个，`inner = 0`，下标 50。它是第 51 个元素，C 语言下标是 50。选项 A。选项 B 的 51 把「第 51 个」直接当成了下标。

2020 按列存 10 阶上三角，问 `m(7, 2)`。`7 > 2`，这一格不在存下来的那一半里。对称矩阵先换成 `m(2, 7)`：

```text
k upper-col n=10 i=7 j=2 si=2 sj=7 swap=1 const=0 prefix=21 inner=1 index=22
```

前 6 列有 `1+2+3+4+5+6 = 21` 个。第 7 列按行号 1、2、… 存放，`m(1, 7)` 在前，`m(2, 7)` 的 `inner = 1`，下标 22。选项 C。前面那 22 个元素占的是下标 0 到 21；把「第 23 个元素」报成下标，就是选项 D 的 23。

2016 是 100 阶三对角，问 `m(30, 30)`。第 1 行 2 个，第 2 行到第 29 行各 3 个，共 `2+3*28 = 86`。第 30 行的三个元素是 `m(30, 29)`、`m(30, 30)`、`m(30, 31)`，对角线在中间，`inner = 1`。下标 `86+1 = 87`，也就是 `2*30+30-3`。选项 B。

```text
k band n=100 i=30 j=30 si=30 sj=30 swap=0 const=0 prefix=86 inner=1 index=87
bandk n=100 k=87 i=30 j=30 back=87
```

漏掉行内的 `m(30, 29)`，会停在 86，那是选项 A。数组若从 1 开始，公式是 `2*i+j-2`，得到 88，那是选项 C。`prefix = 3*i-4` 在第 1 行是 −1，行内偏移又多 1，加起来仍是 `2*i+j-3`。`practice-tri` 里 `k band n=5 i=1 j=1` 的 `prefix=-1 inner=1 index=0`。首行、末行不用再写一套公式。

反过来，`i = (k+1)/3 + 1`，`j = k - 2*i + 3`。`k = 0` 必须得到 `(1, 1)`；少写那个 `+1`，行号会变成 0。`bandk` 再用正向公式算回 `k`，对不上就拒绝。100 阶一共 `3*100-2 = 298` 个非零元，下标 0 到 297。教材里若数组是 `B[1..298]`，把这里的下标加 1。`A[66][65]` 的 0 起点下标是 194，从 1 数就是 195。

### 铺开以后再信公式

`verify` 做两件事。先按真正的存储次序走：下三角是 `i` 从 1 到 `n`、`j` 从 1 到 `i`；上三角按行是 `j` 从 `i` 到 `n`；上三角按列是先固定列。走出来的序号必须等于公式的 `k`。再把 `n×n` 的每个位置查回去：对称的镜像要落到交换后的那一格，三角的常数区要落到同一个下标，三对角带外必须报 `absent=1`。

4 阶下三角的前两行：

```text
store i=1 j=1 seq=0 k=0
store i=2 j=1 seq=1 k=1
store i=2 j=2 seq=2 k=2
check i=1 j=2 absent=0 si=2 sj=1 swap=1 const=0 k=1
```

`(1, 2)` 和 `(2, 1)` 共用下标 1。5 阶三对角铺出来是 13 格，`store` 的顺序就是 `(1,1) (1,2) (2,1) … (5,4) (5,5)`，末格 `seq=12 k=12`。`(1, 3)` 打 `absent=1`。3 阶下三角矩阵的常数下标是 6，`ordered=6 stored=7`，上三角三个位置的 `k` 都是 6。12 阶上三角有 78 个元素，`n > 5` 时只留汇总：`verify ok ordered=78 stored=78 checked=144`。

### 三元组：位置没有式子，就连位置一起存

规律压缩仍然是 O(1)，因为下标映射是一次算术。稀疏矩阵的非零元散落着，没有这种式子。三元组记下 `(行, 列, 值)`，并且按行优先排好。王道的表从下标 1 开始用，`data[0]` 空着。

2023-3 问除了三元组还要保存什么。行数和列数要留，含有非零元的行数、列数不用另存。`init` 打出 `keep=rows,cols` 和 `drop=nonzero_rows,nonzero_cols`。有了规模才能区分两件事：下标越界，以及表里没有、所以值是 0。

```text
get i=1 j=1 val=5 scans=1
get i=2 j=2 val=0 scans=1
fail get range i=4 j=1
```

`(2, 2)` 不在表里，值是 0，但这一次已经看过表了。`(4, 1)` 超出 3 行，直接拒绝。`scans` 是看过的三元组个数。表按行排好，行号已经超过目标就可以停，最坏仍要看完所有非零元。随机存取在这里没有了。

追加必须保持行优先。`practice-order` 先写了 `(2, 2)`，再写 `(1, 1)` 会被拒绝，表还是只有那一个元素。零元不进表。

### 转置：普通的按列找，快速的一次定位

转置是把 `(行, 列)` 换成 `(列, 行)`。新表还要按行优先，也就是按原矩阵的列号从小到大。

普通转置对每一个列号把整张表扫一遍。三元组按行排，同一列并不挨在一起，不能扫到就停。6×7、8 个非零元时 `slow visits=56`，即 `7*8`。

快速转置先准备两份辅助信息。`num` 是每一列有几个非零元。`cpot[1] = 1`，后面 `cpot[c] = cpot[c-1] + num[c-1]`，表示这一列第一个非零元在新表里的下标。表从 1 开始，所以第一项是 1，不是 0。放的时候用 `cpot[列]` 当位置，放完加 1。原表只看一遍。

严蔚敏教材那张 6×7 的矩阵：

```text
num 2 2 2 1 0 1 0
cpot 1 3 5 7 8 8 9
cpot_after 3 5 7 8 8 9 9
```

第 5 列、第 7 列是空的，`num` 为 0，`cpot` 和下一个相同。`visits=22`，即数 `num` 的 8 次、求 `cpot` 的 6 次加法、安放的 8 次。列数记为 `nu`、非零元个数记为 `tu` 时，普通转置是 O(`nu * tu`)，快速转置是 O(`nu + tu`)。空列多的时候，快速转置省下的就是那些重复扫描。

转置结果两条路相同。原 `(1, 2, 12)` 变成新表里的 `(2, 1, 12)`，排在第 1 列的两个元素后面，下标是 3。

## 易错点

1. **行优先乘列数，列优先乘行数。** 跨过一整行，跳过的是这一行里的元素个数，那是列数。最后一个元素两种次序的偏移都是「总个数 − 1」，可以用来检查有没有乘反。
2. **下标起点写在下界里。** 从 0 的 `(1, 2)` 和从 1 的 `(2, 3)` 在 3×4 的数组里是同一格，偏移 6，地址 1012。从 0 的 `(2, 3)` 是 1022。每维都要减自己的下界，负下界也一样。
3. **2021 的 120 要写成 `3*cols + 3`。** 列数是 39。只加 5 个整行得到 295，那是 `A[5][0]`。三个点都满足 `i = j` 时，用地址差的比例也能凑出 300，换一个不在对角线上的点就不成立。
4. **对称矩阵先看它在不在存下来的那一半。** 2020 的 `m(7, 2)` 要换成 `m(2, 7)` 再代按列的公式，下标 22。三角矩阵在这个位置不交换，直接去常数那一格。4 阶时前者下标 3，后者下标 10。
5. **2018 的 50 是下标，51 是「第几个」。** 前 5 行 50 个元素占下标 0 到 49，`m(6, 6)` 在 50。C 语言数组从 0 开始，题面写的就是这种数组。
6. **2016 的对角线不是该行的第一个。** 第 30 行先存 `m(30, 29)`。漏掉它得到 86。公式改成从 1 计数会得到 88。`3*i-4` 在第 1 行是 −1，和行内多出来的 1 抵消，首行不用单写。
7. **三对角反推要先加 1 再除以 3。** `i = (k+1)/3 + 1`。`k = 0` 对应 `(1, 1)`。从 1 开始的数组把下标加 1，`A[66][65]` 是 195，数组长度仍是 `3n-2`。
8. **三元组的 0 和越界是两件事。** 表里没有就是 0，下标超出行数、列数才是越界。所以必须保存矩阵的行数和列数。含非零元的行数、列数可以从表里数出来，2023 不要求另存。
9. **`cpot` 从 1 起，空列的 `num` 是 0。** `data[0]` 不用。第一列的起始下标写成 0，后面全部错一位。第 5 列为空时，`cpot` 的 8 会连续出现两次。
10. **快速转置的 `visits` 把三段都算进去。** 数 `num`、推 `cpot`、安放。6×7 的例子是 `8 + 6 + 8 = 22`。普通转置是 `7*8 = 56`，因为它对每一列都重扫整张表。

## 概念卡片参考

- **三元组表**：顺序表，每个非零元三个字段，另加行数、列数、非零元个数。适合非零元的个数和位置变化不大的矩阵。转置可以做到 O(`列数 + 非零元个数`)。按下标取值要扫描，插入删除要移动表项。
- **十字链表**：每个非零元是一个结点，除了行、列、值，还有 `right` 和 `down`。`right` 指向同一行的下一个非零元，`down` 指向同一列的下一个。每一行、每一列各有头结点，头结点可以合成一个数组来管。非零元经常插入、删除时用它，改的是指针。沿一行或一列走很直接。按下标取值仍要沿链表找，结点里还多两个指针。
- **压缩以后失去什么**：对称矩阵、三角矩阵、三对角矩阵仍然是 O(1)，失去的是另一半各自取不同的值。对称的另一半必须等于镜像，三角的另一半必须是同一个常数，三对角的带外没有格子。三元组失去的是随机存取。大约每个非零元三个单元，非零元接近「行数 × 列数 / 3」时，光是三个字段就和原矩阵一样大，再加上行数、列数、个数，反而不省。十字链表把插入删除换成改指针，空间和实现都更重，取值的时间也不是常数。
- **和稠密数组的差别**：稠密数组的地址是下标的线性函数，各维长度一定，这个系数就是常数，所以任一元素的时间相同。压缩公式仍是线性函数。三元组的位置存在表里，时间随非零元个数变化。
