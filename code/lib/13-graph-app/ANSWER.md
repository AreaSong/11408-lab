## 思路

### Prim 扫顶点，Kruskal 扫边

Prim 手里始终是一棵树。`low[v]` 是 v 连到这棵树的最便宜的边，`from[v]` 是树里的那一头。起点的 `low` 写成 0，表示它已经在树里。每一轮在还没进来的顶点里找 `low` 最小的，编号小的优先。选中之后，用这个新顶点去松弛树外的顶点。

松弛用的是严格小于。权值一样时不改 `from`，原来的那条边留着。选点的时候再扫一遍树，把同样短的另一端打在 `alt` 上。选择题说「可能」，`via` 和 `alt` 都算。王道筛选、Dijkstra 更新写的也是 `<`，不是 `<=`。

`tests/2015-6` 的顶点：V1=0，V2=1，V3=2，V4=3。边是 0-3 权 5，以及三条权 8：0-2、1-2、2-3。从 3 开始：

- 第 1 轮只能选 0，边是 3-0，权 5。这就是 (V1, V4)
- 第 2 轮选 2，`via 3` 是 (V3, V4)，`alt 0` 是 (V1, V3)。顶点 1 的 `low` 还是 `inf`，(V2, V3) 还挨不着这棵树
- 第 3 轮才把 1 从 2 拉进来

所以 Prim 第 2 次可能是 (V1, V3) 或 (V3, V4)，不会是 (V2, V3)。

Kruskal 先把边放进第 09 关的小根堆。`2015-6.in` 故意先输入三条权 8 的边，最后才输入权 5 的边；`sort` 仍是 `0-3:5 0-2:8 1-2:8 2-3:8`。同一档权值在加入任何一条之前，先打 `open`：此刻两端还不在同一个集合里的边。权 8 那一档的 `open` 是 `0-2 1-2 2-3`，三条都不成环。换一种并列次序，第 2 条可以是其中任何一条，包括 (V2, V3)。这条不在 Prim 第 2 轮的 `via`/`alt` 里。选 C。

程序自己的并列次序是端点编号，所以它真正 `add` 的第 2 条是 0-2，也就是 (V1, V3)。看这道题要看 `open`，不要只看 `add`。收够 n−1 条就停，2-3 没有变成 `skip`，它只是没轮到。

两棵树的边集不同，代价都是 21。代价看的是权值之和，不看边集。

不连通时 Prim 打 `round k stop`，`span no`。Kruskal 能加的边加完，`span no`，`cost` 是森林的权。

堆的上限是 32 条边。无向完全图 n=8 有 28 条，放得下；n=9 有 36 条，`kruskal` 打 `fail heap`。真题的图比这小。

### 四句最小生成树，用三张小图就够

`practice-mst` 对应 2012 年第 8 题，答案是仅Ⅰ。

三个顶点、三条边权都是 1：

- Prim 从 0 得到边 0-1、0-2，从 1 得到 0-1、1-2。树不一样，代价都是 2。Ⅲ 不成立。Ⅰ 成立：代价是权值之和，并列时树可以有好几棵，和不变
- 边 1-2 的权也是最小的那一档，但它不在「从 0 长出来的那棵」里，所以「一定出现在所有最小生成树中」不成立。Ⅱ 不成立
- Kruskal 这张图得到的也是 0-1、0-2，和 Prim 从 0 的结果相同。Ⅳ 说「总不相同」，不成立

再看权值互不相同的 0-1 权 1、1-2 权 3、0-2 权 4。Prim 和 Kruskal 都留下 0-1 和 1-2，代价都是 4。更重的 0-2 收够两条就不再看。这是Ⅳ的直接反例。

四个顶点的环，边权全是 1。Kruskal 留下 0-1、0-3、1-2，没有 2-3。从 2 做 Dijkstra，`dist[3]` 是 1，走的就是那条没进生成树的边。生成树上 2 到 3 要绕 2-1-0-3，长度 3。所以权值全是 1 时，Prim 和 Kruskal 仍然不一定给出最短路径。2023 年第 6 题只有广度优先一定可以：边权都是 1 时，最短路径长度就是边数，BFS 一层层扩正好按边数来。选 B，仅Ⅲ。本关不重写 BFS，上一关已经有。

### Dijkstra 读的是第 k 轮，不是最后一轮

源点先放进集合，`dist` 是源点的直接出边，没有边就是 `inf`，`path` 里写源点。然后做 n−1 轮：在没确定的顶点里找 `dist` 最小的（一样小就取编号小的），确定它，再用它的出边松弛。已经确定的顶点不再改。

`hist[0]` 是初始，`hist[k]` 是第 k 轮松弛完的 `dist`。`round` 那一行的 `dist=` 是选中时的旧值。

2021 年第 8 题，顶点 k 对应程序里的 k−1。源点是 0（试卷上的 1）。

| 时机 | 程序里的 dist | 试卷上顶点 2、3、4、5 |
|---|---|---|
| 初始 | 0, 26, 3, inf, 6 | 26, 3, ∞, 6 |
| 第 1 轮确定 2（试卷上的 3），2→1 把 26 改成 25 | 0, 25, 3, inf, 6 | 25, 3, ∞, 6 |
| 第 2 轮确定 4（试卷上的 5） | 0, 21, 3, 14, 6 | 21, 3, 14, 6 |
| 全部跑完 | 0, 15, 3, 14, 6 | 15, 3, 14, 6 |

题目问的是求出第二条之后，是第 2 轮那一行，选 C。选项 D 的 15 是后来确定试卷上的顶点 4 时，用 4→2 权 1 把 21 改成 15 的最终结果。多做一轮就会掉进 D。选项 B 的 25 是第 1 轮才有的数，那时顶点 4 的距离还是 `inf`，不是 14。

最终到顶点 1 的路径是 `0>4>3>1`，长度 6+8+1=15。

2016 年第 8 题的弧，按解析表里的路径还原：0→4 权 4，0→1 权 5，1→2 权 2，4→5 权 5，4→3 权 7。确定次序是 4、1、2、5、3，换成试卷编号就是 5、2、3、6、4。选 B。

第 1 轮确定 4 的同时，4→3 和 4→5 已经把距离写成 11 和 9。有的转载在第 1 列把顶点 4、6 写成 ∞，把 11 和 9 放到第 2 列。那和「选中 5 之后立刻松弛」不一致。选择次序不受这个错位影响，仍然是 B。

负权时 Dijkstra 会错，程序先打 `warn neg` 再照旧算，用来和 Floyd 对照。`practice-neg`：0→1 权 4，0→2 权 5，2→1 权 −3。正确的 0 到 1 是 0→2→1，长度 2。Dijkstra 第 1 轮就确定了 1，距离锁在 4，后面不再改。Floyd 得到 2。

2009 年第 41 题的方法不是 Dijkstra。它只从当前这一步的终点，挑一条最近的、还没走过的边，不会回头看源点的其他分支。`practice-greedy` 里 0→1 权 1，1→2 权 100，0→3 权 2，3→2 权 1。那种方法从 0 走到 1，再走到 2，长度 101。Dijkstra 第 1 轮也会先确定 1，并把 2 临时写成 101；第 2 轮确定的是距离更小的 3，再把 2 改成 3。路径是 `0>3>2`。所以第 1 轮的 101 只是中间值，不是最终答案。

### Floyd 用每个顶点当一次跳板

`dist[i][j]` 初值就是边权，自己到自己是 0。对 k = 0 .. n−1，对所有 i、j：若 `dist[i][k] + dist[k][j]` 严格小于 `dist[i][j]`，就改距离，并把 `path[i][j]` 改成 `path[k][j]`，也就是 j 的新前驱。某一端还是 `inf` 就不加，避免把「没有路」加出一个数。

`practice-floyd` 里 0→2 原来是 8。k=0 没有更短的。k=1 时 0→1→2 是 3+2=5，前驱从 0 改成 1。k=2 不再变。

负环会把某个 `dist[i][i]` 压成负数。0→1 权 1、1→0 权 −2：k=0 时 1 绕回自己得到 −1，k=1 时 0 绕回自己得到 −1。`negcycle yes`。出现负环之后，矩阵里的数不能再当成最短路。

Floyd 允许负权边，时间是 O(n³)，一次求出所有点对。Dijkstra 要求非负权，教科书实现是 O(n²)，一次只求出一个源点。把每个顶点当一次源点可以凑出所有点对，那是 O(n³)，而且仍然不能有负权。

### 拓扑序列唯一，当且仅当每一步只有一个候选

入度先数好。每一步把入度为 0 的顶点收集起来，取编号最小的输出，再把它的出边删掉（后继入度减 1）。候选有两个以上，`unique` 就是 no。没有候选、顶点还没排完，就是环：环上的顶点入度永远减不到 0。

2010 年第 8 题，a..e 对应 0..4。测试用的弧是 0→4、0→1、0→2、1→2、4→3、2→3。`topo-all` 给出 3 条：

```text
0 1 2 4 3    a b c e d
0 1 4 2 3    a b e c d
0 4 1 2 3    a e b c d
```

选 B。去掉 0→2 再数，仍然是这 3 条：c 的另一条入边 1→2 还在，a 出去之后 c 的入度不会马上变成 0。两种复原的答案一样。`0 4 2 1 3` 把 c 排在 b 前面，`topo-check` 是 no。

`practice-cycle` 里 0→1→2 每一步只有一个候选，`unique yes`。0↔1 一个顶点都排不出来，`order -`，`cycle yes`，`unique no`。

2024 年第 41 题的 `uniquely` 就是这件事：

1. 设计思想：对邻接矩阵做拓扑排序。每一轮找入度为 0 的顶点。若某一轮多于一个，不唯一，返回 0。若某一轮一个都没有、顶点还没排完，图中有环，拓扑序列不存在，也返回 0。n 个顶点都是「轮到时只有一个」，返回 1。
2. 代码：见 `src/topo.c` 的 `topo_run`。入度用矩阵的一列来数；输出时取编号最小，只是为了让序列固定，判断「是不是只有一个」与取哪一个无关。

邻接矩阵上，数入度和每一轮扫描都是 O(n)，一共 n 轮，时间 O(n²)，额外空间 O(n)。2016 年第 7 题问的是邻接表，每个顶点进一次队列、每条弧看一次，是 O(n+e)，选 B。换存储结构，复杂度跟着变。

### 关键路径是最长的那条，不是边最多的那条

事件的最早发生时间 `ve` 沿拓扑正序取最大：没有前驱的事件是 0，其余是「前驱的 ve + 活动时间」里的最大者。工期 `len` 是最大的 `ve`。最晚发生时间 `vl` 沿拓扑逆序取最小：没有后继的事件等于工期，其余是「后继的 vl − 活动时间」里的最小者。权必须非负，否则「先写成 0 再取最大」会把一条负的真实路径盖住。负权直接 `fail neg`。

活动 u→v 的最早开始 `e = ve[u]`，最晚开始 `l = vl[v] − w`，`slack = l − e`。`slack` 为 0 才在某条关键路径上。

`practice-aoe` 的活动和 2013 年第 9 题的路径用的是同一套名字，时间是自编的：

| 活动 | 边 | 权 |
|---|---|---|
| b | 0→1 | 3 |
| a（不在那三条路径上） | 0→3 | 1 |
| d | 1→2 | 2 |
| f | 1→4 | 4 |
| c | 2→3 | 2 |
| e | 2→4 | 2 |
| g | 3→5 | 3 |
| h | 4→5 | 3 |

三条路径长度都是 10：

```text
b d c g    0>1>2>3>5
b d e h    0>1>2>4>5
b f h      0>1>4>5
```

`ve` 和 `vl` 都是 `0 3 5 7 7 10`。0→3 的 slack 是 6，不是关键活动。其余 7 条边都是关键活动。三条路径的公共边只有 0→1，所以 `alone` 只有它。

2013 年问的是「同时加快选项里的那几项」。这一组必须打中每一条关键路径：

- c 和 e 打不中 b-f-h
- d 和 c 也打不中 b-f-h
- f 和 d：f 打中第三条，d 打中前两条
- f 和 h 打不中 b-d-c-g

选 C。只缩短 `alone` 里的 b，三条都会变短；b 不在选项里。

2020 年第 8 题：关键路径按权值之和，不按边数，A 错、B 对。把任意一条关键活动加长，那一条关键路径变得更长，工期跟着变长，C 说「不会延长」是错的。`practice-aoe` 里把 d 的权从 2 改成 3，工期从 10 变成 11。只缩短一条不在所有关键路径上的活动，另外的关键路径长度不变，工期不变：把 d 的权改成 1，b-f-h 仍是 10。D 错。把 `alone` 的 b 从 3 改成 2，三条一起变成 9，工期才下降。

## 易错点

1. **第 k 轮和最终的 dist 不是一回事。** 2021 年的 21 在第 2 轮，15 是跑完以后。题目说「求出第二条最短路径后」。
2. **并列边看 `open` 和 `alt`，不要只看程序选中的那条。** 2015 年 Kruskal 实际加入的第 2 条是 (V1, V3)，但 `open` 里还有 (V2, V3)。后者才是「Kruskal 可能、Prim 不可能」。
3. **严格小于才更新。** 写成 `<=` 会把 `from` 换成后看到的那条，`alt` 就空了，2015 年 Prim 的第 2 条会从 (V3, V4) 变成 (V1, V3)。两条仍然都「可能」，但和测试约定的 `via` 对不上。
4. **Dijkstra 确定之后不再改。** 负权边靠这个规则算错。Floyd 可以有负权；对角变成负数是负环，不是「自己到自己还有一条路」。
5. **无穷不要用 `INT_MAX`，也不要印成 `-`。** 加一条正权会溢出。负权印出来是 `-3`，和表示「没有边」的 `-` 分不开，所以没有边印 `inf`。
6. **拓扑不唯一，不是「图上看着有分支」。** 分支可以被后面的边卡死，每一步仍然只有一个入度为 0 的顶点。有环则序列不存在，2024 年的函数要返回 0，不能返回 1。
7. **邻接表的拓扑是 O(n+e)，邻接矩阵是 O(n²)。** 2016 年第 7 题写的是邻接表。
8. **缩短一条关键活动，工期不一定变短。** 它必须在每一条关键路径上，也就是 `alone`。加长任意一条关键活动，工期一定会变长。关键路径比的是权值之和。
9. **权值全是 1，最小生成树仍不一定是最短路径树。** 环上去掉任意一条边都是最小生成树，被去掉的那条边两端在树上要绕远。
10. **顶点从 0 起。** 试卷上的顶点 1 是程序里的 0，字母 a 也是 0。并查集内部再加 1，不要把这两次平移叠在输入上。
11. **2012 年第 7 题、2020 年第 7 题的图没有完整边表。** 前者公开答案是 C（f, d, e），后者是 A，并且 (d, f) 因为成环被丢掉。这里不编一套权值冒充原图。

## 概念卡片

### Prim 和 Kruskal

| | Prim | Kruskal |
|---|---|---|
| 每次看什么 | 离当前这棵树最近的顶点 | 全体边里最轻、又不把两头连进同一棵树的边 |
| 中间长什么样 | 始终一棵树 | 一片森林，最后才并成一棵 |
| 判环 | 顶点已经在树里就不再进 | 并查集里两端同根 |
| 时间 | 矩阵扫描 O(n²)，和边数无关，稠图合适 | 堆排序 O(e log e)，稀图合适 |
| 负权边 | 可以。它不依赖「没有负权」 | 可以 |
| 不连通 | 从起点只长出一棵，`span no` | 得到生成森林，`span no` |
| 权值相同 | 树可以不同，代价相同 | 同左。`open` 列出这一档里都能当「下一条」的边 |

最小生成树的代价唯一。树本身在权值并列时不唯一。最轻的那一档若有好几条而且彼此成环，总有一条不在某一棵最小生成树里。

### Dijkstra 和 Floyd

| | Dijkstra | Floyd |
|---|---|---|
| 求什么 | 一个源点到其余各点 | 所有点对 |
| 负权边 | 不行。确定过的顶点不再改，负权会把更短的路挡在后面 | 可以 |
| 负环 | 没有定义 | 对角线上出现负数 |
| 时间 | 教科书是 O(n²)。堆优化不是选择题要模拟的那一版 | O(n³) |
| 过程怎么读 | 第 k 轮松弛完的 `dist`，不是最终数组 | `k` 用完之后的整张矩阵 |

最短路径一定是简单路径。有负环时可以无限绕，最短路不再有意义。

### 拓扑排序和关键路径

- 有向无环图才有拓扑序列。排不完就是有环。序列不唯一，当且仅当某一步入度为 0 的顶点多于一个。
- 栈或队列都能暂存入度为 0 的顶点，得到的具体序列可以不同，都合法。本关固定取编号最小，是为了和测试对上。
- AOE 网用边表示活动、用顶点表示事件。AOV 网用顶点表示活动。关键路径是源点到汇点权值之和最大的路径，也是工程的最短工期。
- 关键活动是 slack 为 0 的活动。单独缩短它能缩短工期，当且仅当它在所有关键路径上。一组活动一起缩短能缩短工期，当且仅当每一条关键路径至少含有其中一条。
