## 运行目标

`answer/` 不是独立项目，而是 `code/` 大项目里的一个单元：含 `main` 的 `.c` 各自是一个程序，出现在 CLion 右上角的运行目标下拉框里；其余文件被这些程序调用，不单独运行。

| 下拉框里的运行目标 | 入口文件 | 作用 |

| `lib00_answer_max_test` | `max_test.c` | 用 `test.h` 的宏测 `max_find`，全部通过时退出码为 0 |
| `lib00_answer_max_io` | `max_io.c` | 先读个数 n，再读 n 个整数，打印最大值；直接运行会等你从键盘输入（如 `5` 回车 `3 9 -2 7 9` 回车） |

## 思路

### test.h 的设计
- **失败不中断**：`CHECK` 失败只记一笔、打印 `文件:行号: CHECK 失败：表达式`，继续跑后面的检查，一次运行就能看到所有错误；最后 `return TEST_SUMMARY();` 根据有没有失败返回 1 或 0，CTest 据此判定。
- **`#cond` 字符串化**：宏参数前加 `#` 会变成字符串字面量，所以能把出错的表达式原样打印出来——这是必须用宏、不能用函数的原因；`__FILE__`、`__LINE__` 同理，函数里拿到的是函数自己所在的行。
- **`CHECK_EQ` 打印两边的值**：只知道 `m == 9` 失败没什么用，知道「实际是 0」才能马上想到是初值写错了。
- **计数器放在 `static inline` 函数的局部静态变量里**：如果在头文件里写 `static int failed;`，没用到它的 `.c` 会报 unused 警告，违反零 warning 的要求。

### 复杂度计数实验
把真题程序段原样抄下来，只在基本语句旁加 `cnt++`。n 取 10、100、1000，每次扩大 10 倍，看次数的增长倍数：

| 阶 | n 扩大 10 倍时次数约 |
|---|---|
| O(log n) | 只多 3 次左右（log₂10 ≈ 3.3） |
| O(√n) | ×3.16 |
| O(n) | ×10 |
| O(n log n) | 明显多于 ×10（本关实测 ×14~×20，n 越大越接近 ×10） |
| O(n²) | ×100 |

## 实测结果与手推对照

真题均已核实原题与答案（第 1 题，单选）。

| 编号 | 程序段 | n=10 | 100 | 1000 | 手推 | 答案 |
|---|---|---|---|---|---|---|
| 2011-1 | `x=2; while(x<n/2) x=2*x;` | 2 | 5 | 8 | 2^(t+1) ≥ n/2 ⇒ t ≈ log₂n − 2 | O(log n) |
| 2012-1 | `fact(n)` 递归求阶乘 | 10 | 100 | 1000 | T(n) = T(n−1) + 1 = n | O(n) |
| 2014-1 | 外层 `k*=2`，内层 `j<=n` | 40 | 700 | 10000 | (⌊log₂n⌋+1) · n | O(n log n) |
| 2017-1 | `while(sum<n) sum+=++i;` | 4 | 14 | 45 | k(k+1)/2 ≥ n ⇒ k ≈ √(2n) | O(√n) |
| 2019-1 | `while(n>=(x+1)*(x+1)) x=x+1;` | 3 | 10 | 31 | ⌊√n⌋ | O(√n) |
| 2022-1 | 外层 `i*=2`，内层 `j<i` | 15 | 127 | 1023 | 1+2+…+2^(r−1) = 2^r − 1 < 2n | O(n) |
| square | 两层 `1..n` | 100 | 10000 | 1000000 | n² | O(n²) |
| triangle | 内层 `j<=i` | 55 | 5050 | 500500 | n(n+1)/2 | O(n²) |
| halve | `T(n)=2T(n/2)+n` | 34 | 672 | 9976 | 每层 n，共 log₂n 层 | O(n log n) |

（halve 取 n=8 时恰为 8×3 = 24，与 n·log₂n 完全吻合。）

## 易错点
1. **2022-1 不是 O(n log n)**：内层上界是外层变量 i，**内外层相关时不能直接相乘**，要逐项求和。2014-1 的内层上界是 n、与外层无关，才能用乘法规则。两题放在一起对照最清楚：实测 2014-1 每次 ×14~×18，2022-1 每次只有 ×8 左右，且始终小于 2n。
2. **递归看「每层工作量 × 层数」**：fact 每层 O(1)、n 层，所以 O(n)；halve 每层合计 n、log₂n 层，所以 O(n log n)。只看递归深度会把 halve 误判为 O(log n)。
3. **求最大值的初值用 `a[0]`，不用 0**：全负数组会得到错误的 0。`tests/max_io/practice-all-negative` 专门抓这个错误。
4. **空表要单独处理**：没有任何 int 能当「没有最大值」的标记，所以用 `bool` 返回值 + 指针输出参数。这正是王道 `int &e` 在 C 里的写法：参数写 `int *out`，调用处传 `&m`。
5. **复杂度只取最高阶、忽略系数**：2011-1 精确次数是 log₂n − 2，2017-1 是 √(2n)，写成 O(log n)、O(√n)。
6. **`unsigned` 溢出**：`fact(1000)` 的乘积早已溢出。有符号溢出是未定义行为，所以 `segments.c` 里用 `unsigned long long`（无符号溢出有定义，按 2^64 回绕）；这里只数调用次数，不关心乘积。

## CLion 操作（小步骤 ②）
1. 在 `code/` 下运行 `./lab.sh`，选「新建尝试」，建一次尝试 `lib/00-warmup/mine/<日期>-<说明>/`；里面的文件和答案同名，已经是能编译运行的空模板
2. CLion 菜单 **File → Reload CMake Project**；右上角运行配置下拉框里就会出现 `lib00_<尝试名>_max_test` 等目标
3. 选中目标点 ▶ 运行；在 `max.c` 的 `if (a[i] > best)` 行号旁单击设断点，点 🐞 调试，单步观察 `i` 和 `best` 的变化
4. 跑全部测试：CLion 的 CTest 运行配置，或终端 `ctest -L mine -L lib00 --output-on-failure`
5. **输出比对用例按入口文件名查找**：`tests/max_io/` 对应入口文件 `max_io.c`。自己的入口文件要起同样的名字，才能共用这些用例；输出格式必须完全一致（行尾空白和首尾空行会被忽略）
6. 全部写完、测试通过后运行 `./lab.sh done lib 00 <尝试>`：之后所有关卡改用你自己写的 `test.h`

## test.h 接口速查（后续所有关卡）

| 宏 | 含义 |
|---|---|
| `CHECK(cond)` | 条件为假时报告失败 |
| `CHECK_EQ(actual, expected)` | 两边转 `long long` 比较，失败时打印两个值 |
| `CHECK_STR(actual, expected)` | `strcmp` 比较，允许 `NULL` |
| `TEST_SUMMARY()` | 打印汇总；全部通过返回 0，否则返回 1。写成 `return TEST_SUMMARY();` |

## 概念卡片参考答案

### 卡片一：四种逻辑结构 vs 四种存储结构

| 逻辑结构 | 元素间关系 | 例子 |
|---|---|---|
| 集合 | 同属一个集合，别无其他关系 | 一组学号 |
| 线性结构 | 一对一 | 线性表、栈、队列、串 |
| 树形结构 | 一对多 | 二叉树、文件目录 |
| 图状（网状）结构 | 多对多 | 交通网、路由拓扑 |

| 存储结构 | 怎么体现元素关系 | 优点 | 缺点 |
|---|---|---|---|
| 顺序存储 | 物理位置相邻 | 随机存取，存储密度高 | 只能用整块连续空间，插删要移动元素 |
| 链式存储 | 指针 | 不要求连续，插删只改指针 | 只能顺序存取，指针占额外空间 |
| 索引存储 | 另建索引表（关键字，地址） | 检索快 | 索引表占空间，插删要改索引 |
| 散列存储 | 由关键字算出地址 | 存取极快 | 可能冲突，需要冲突处理 |

区别在哪：逻辑结构是**数据本身**的关系，与计算机无关；存储结构是逻辑结构**在计算机中的映像**。同一种逻辑结构可以有多种存储结构（线性表既可以用顺序表，也可以用链表），运算的实现依赖于存储结构（定义看逻辑结构，实现看存储结构）。数据结构三要素 = 逻辑结构 + 存储结构 + 数据的运算。

易混：「有序表」是逻辑概念（与存储无关）；「顺序表」「链表」「散列表」是存储概念；「循环队列」是用顺序表实现的队列，属于存储概念。

### 卡片二：算法的五个特性 vs 好算法的四个目标

| 五个特性（缺一个就不是算法） | 含义 |
|---|---|
| 有穷性 | 有穷步后结束，每步在有穷时间内完成 |
| 确定性 | 每条指令含义确定，相同输入得到相同输出 |
| 可行性 | 每个操作都能通过有限次基本运算实现 |
| 输入 | 零个或多个输入 |
| 输出 | 一个或多个输出 |

| 四个目标（越满足越好） | 含义 |
|---|---|
| 正确性 | 能正确解决问题 |
| 可读性 | 便于人理解 |
| 健壮性 | 输入非法时能恰当处理，不会莫名其妙地出错 |
| 高效率与低存储量需求 | 时间复杂度、空间复杂度低 |

区别在哪：五个特性是「**是不是**算法」的判据（程序可以不满足有穷性，例如操作系统一直运行；而算法必须有穷）；四个目标是「算法**好不好**」的标准。本关的 `max_find` 对空表返回 `false` 而不是越界读 `a[0]`，就是健壮性的体现。
