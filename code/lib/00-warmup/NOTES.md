#### C语言：

.h和.c的区别

如果使用C#来编码，例如

```c#
public int Demo(){......};
```

这一句在C#里保存后，既写了函数内容，又把函数声明为了public，而到了c中，声明和函数实现是分开的

.c 函数实现 源文件

.h 函数声明 头文件

但是在这里并非说我要是不在.h中写声明，编译器就不知道，我不声明别人也不会访问到我的函数中，在现代语言中这个意思可以算是对，但是在C就有另外一种情况，C的两个不同编译阶段：

1. 编译 编译期：编辑器只检查单个.c文件的语法对不对，参数类型有没有问题
2. 链接 链接期：链接器把所有.c生成的目标文件拼在一起，把函数真正调用起来

那，如果不写声明，其他真的绝对访问不到吗？

错，可以调用，只需要添加一个`extern`关键字，这个关键字是告诉编译器，远方有这个函数，在第二步的链接期时就会把他们强行连在一起，那有没有不添加然后也调用不了的呢？那就是在源文件函数上添加static这个关键字，当添加了这个关键字后，这个函数彻彻底底的变成了私有函数，无法调用了，即便加入了extern，编译期也找不到这个函数

而static关键字在两个语言中是有区别的，在C#中，static的意思为静态的，全局只有一份的，不需要再次实例化函数，而在了C中，这个static关键字是强调私有，不允许其他文件进行调用的

那如果我既写了static又在.h写了声明呢？

编译器会直接报错，因为这样就相当于既表明我是公开，又强调我是私有，关系矛盾了

那如果我的函数既没有声明.h，也没有强调是static，那还能被其他文件进行调用吗？

可以，在别人文件直接把声明复制一份就好，例如

```c
// math.c
int add(int a, int b) {
    return a + b;
}


// main.c
// 甚至不需要 #include 任何东西，他只要告诉编译器：“远方有一个函数叫 add”
int add(int a, int b); 

int main(void) {
    int result = add(3, 5); // 👈 毫无阻碍，成功调用！result = 8！
    return 0;
}
```

可是为什么没有声明也没有引用也能调用呢，很奇怪

```c#
第一步：编译（单兵作战）
   math.c  ─── 编译成 ───>  math.o （里面包含一个对外公开的符号标签：_add）
   main.c  ─── 编译成 ───>  main.o （编译器看到顶部有函数声明，放下戒心，编译通过）

第二步：链接器出场（大拼装）
   链接器把 math.o 和 main.o 拿在手里：
   “咦，main.o 里说需要一个叫 _add 的函数；”
   “巧了，math.o 刚好导出了一个叫 _add 的函数符号！”
   于是链接器用一根线把它们俩接在一起，生成了最终的运行程序！
```

其实.h并不是硬性规定的隔离，而是一个君子协议，只是让使用者直接看这份声明，就相当于点菜一样，不需要再去看函数的详细实现了，如果我都自己写了声明，那我还需要include吗？

不需要，也都不用写，因为include其实就是复制粘贴，其实就是相当于直接把包含的内容复制到当前文件，和自己直接声明的效果是一模一样的，但是，如果有多个文件都有同名、同形参的函数，链接期会直接报错，因为有多个的是情况下，链接期不知道该选哪一个

那如果我有两个文件里有两个函数名和形参都一样，且我在main中只引用包含了其中一个，然后执行引用的那个能正常运行吗？

不能，因为引用包含其实就是一个复制粘贴，也就是直接复制的函数声明

void function(){};

那为什么C#的这种不会报错，即便多个文件里有相同函数和参数一样也不会报错呢，因为命名空间，就比如

1. ProjectA.Tool.functionNum()
2. ProjectB.Tool.functionNum()

他们前面还有一个前缀进行区分，而到了C语言中，没有这种概念，全局只有一个函数名，

```
假设 a.c 和 b.c 都有一个实现：int functionNum() { ... }（都没加 static）： 即使你在 main.c 规规矩矩地写了 #include "a.h"，你以为你是在调 a 的函数。 但在第二步链接器去全项目找 _functionNum 的时候： 链接器手里拿着 a.o 和 b.o，它看到的依然是两个完全相同的名字撞车了！ 依然会当场无情报错：duplicate symbol _functionNum！
```

那也就是C语言中，没有这种概念，全局只有一个函数名，全编译就只有一个functionNum这个函数

**在整个编译链接生成的最终程序（可执行文件）里，全局公开符号表中，同一个函数名永远只能有且仅有一个！**

在规范的C语言函数中

1. 公开函数
   在.h中进行声明，在.c中进行函数实现
2. 私有函数
   不用在.h进行声明，只在.c里写相关函数实现，并且必须加上static关键字来强调这个函数是私有化的
