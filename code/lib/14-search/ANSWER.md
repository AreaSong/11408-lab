## 思路

### 有序性只帮失败，哨兵只省判断

无序表从头扫，第 i 个记录比 i 次，等概率成功 ASL 是 (n+1)/2。表排成升序之后，成功时还是要比到它才停，这个平均数不变。有序的好处是失败可以提前停：当前元素已经比待查关键字大，后面只会更大。

n 个不同关键字把数轴切成 n+1 段。小于第一个，比 1 次；落在第 i 个和第 i+1 个之间，比 i+1 次；大于最后一个，把 n 个都比完就停，还是 n 次，没有第 n+1 次。所以

ASL失败 = (1+2+…+n+n) / (n+1) = n/2 + n/(n+1)

`tests/practice-seq` 的 10…60 是 n=6。成功都是 7/2。失败：无序无哨兵是 6，有序是 27/7。27/7 ≈ 3.857，输出写成 3.86，做题写 27/7。把最后一项误写成 n+1，就会得到 28/7 = 4。

哨兵是王道 `Search_Seq` 的写法：待查关键字放进 0 号，从 n 往 0 扫，循环里只判断相不相等。0 号不是记录，返回 0 就是失败。它省掉的是「下标有没有越界」这一次判断，关键字比较一次都没少。失败时还要和哨兵再比一次，所以失败 ASL 从 n 变成 n+1。题目没给代码时，按教材的哨兵版，失败是 n+1。本关 `plain` 是不带哨兵的 n，`guard` 是带哨兵的 n+1，两行放在一起看这个差。

成功 ASL 与从哪头扫无关。`guard` 的 `cmp` 是 6 5 4 3 2 1，平均仍是 7/2。

### 判定树的层数就是比较次数

折半查找要求两件事同时成立：记录按关键字有序，并且能用下标在 O(1) 里拿到中点。王道的 C 代码是 `mid = (low + high) / 2`，整数除法向下取整。`ceil` 用 `(low + high + 1) / 2`，只为了看镜像。

判定树里每个内部结点是一次比较，层数从 1 起。空孩子不比较，它代表一个失败入口，比较次数等于父结点的层数。n 个内部结点有 n+1 个空孩子，所以失败 ASL 的分母是 n+1，不是 n。

树高 h = ⌈log2(n+1)⌉ = ⌊log2 n⌋ + 1。成功最多比 h 次，失败最多也是 h 次：失败只是走到某个空孩子，路径上的内部结点不会比树高更多。不要写成 h+1。

`tests/practice-bin` 用的是长度 11 的那棵教材树，根是 29（下标 6）。层数和是 33，成功 ASL = 33/11 = 3。12 个空孩子里 4 个比 3 次、8 个比 4 次，失败 ASL = 44/12 = 11/3。只剩两个元素的区间，向下取整的中点是左边那个，单独的孩子全在右边：下标 1、4、7、10 都是 `left=0`。

向上取整把左右对调。`tests/practice-ceil` 的 n=5，两棵树成功都是 11/5、失败都是 8/3，但下标 1 的层数一个是 2、一个是 3。问某个具体关键字比几次，必须先看取整方向；问 ASL，两种取整是同一个数。2017 年那道图题要求整棵树只用一种取整，不能左边独子朝右、右边独子朝左。

形态只由 n 和取整方向决定，和关键字具体是几无关。所以「长度 16」「600 个元素」不必把表填出来，`worst` 只建下标树。

### 比较序列看的是还剩哪一段

2015 年给的是比过的关键字，不是下标。每比完一个数，待查关键字的合法范围就收成一个开区间。下一个关键字必须落在这个开区间里。

A：500 之后往左，上界变成 500；200 之后往右，下界变成 200。区间是 (200, 500)。180 不在里面，所以 A 不可能。B、C、D 的每一步都还在当时的区间里。程序只做这个区间检查，这也是这道题的判法。它不要求你真的造出一张表，使这些数恰好是各步的中点。

能不能直接折半，还是那两个前提。有序链表有序，但不能 O(1) 取逻辑中点。无序数组能取中点，但无序。静态链表的存储池是数组，逻辑次序靠游标，下标相邻不等于逻辑相邻，仍然不能把「第 mid 个」写成 `a[mid]`。无序静态链表两个都不满足。2024 年四个都要排除，选 D。`fit array order` 才会是 `yes`。

### 分块是两段比较加起来

块间有序，块内可以无序。索引里存每块的最大关键字。先在索引上确定块，再进块里查。两段的比较次数相加。最大关键字在索引里比过一次之后，块内还要再比，公式不把这一次扣掉。

等长、每块 s 个、共 b 块、n = b·s 时，王道的成功 ASL：

- 索引和块内都顺序：(b+1)/2 + (s+1)/2
- 索引折半、块内顺序：折半成功 ASL(b) + (s+1)/2
- 块内改成折半，就把 (s+1)/2 换成折半成功 ASL(s)

`rough` 就是这几条。索引折半的「折半成功 ASL」有个简化：每一块都按它的最大关键字在索引判定树上的层数计费，块里别的关键字也收这个价。

真实路径不一定是这个价。三块最大关键字 3、6、9，索引折半的根是 6，层数 1。查 6 自己，索引比 1 次。查 4：4 小于 6、大于 3，要比 2 次才知道落在第 2 块。六个关键字里只有这 1 次差别，所以 `exact` 是 20/6 = 10/3，`rough` 是 19/6，`match=no`。见 `tests/practice-block` 的 `blk bin seq`。

索引改成顺序之后，第 i 块的每个关键字都恰好比 i 次，和 (b+1)/2 一致，`match=yes`。2025 年用的就是顺序索引加块内顺序，公式和真实路径是同一个数。块长不齐时没有这条公式，`rough=-`，只留 `exact`。`add 11 1 8` 再 `add 20 30` 是 16/5：块内乱序不改变顺序查找的 ASL，只改变某个具体关键字的 `j`。

最优块长对 s 看 (n/s + s)/2，两项相等时最小，s = √n。n=400 时 s=20，b=20，ASL = 21/2 + 21/2 = 21。四个选项里 8、10、20、25 的 ASL 是 30、26、21、21.5，最小是 20，选 C。25 已经过了谷底。

2013 年第 42 题的折半表必须按升序放，也就是题面的 do、for、repeat、while。n=4 的层数是 2、1、2、3。

0.35×2 + 0.15×1 + 0.15×2 + 0.35×3 = 2.20

这就是题干里的 2.2。等概率则是 2/1 = 2.00，`weight=no` 那一行。概率不同时，不能再除以 n 就完事。

要更短，就把概率大的放在比较次数小的位置，然后顺序查找。do 和 while 都是 0.35，放在前两位；for 和 repeat 都是 0.15，谁先谁后一样。

0.35×1 + 0.35×2 + 0.15×3 + 0.15×4 = 2.10

比 2.2 小。排完之后表不再有序，只能顺序查找。有序性帮不到成功 ASL，这里用它没有好处。

第（2）问如果用单链表，还是这个顺序、还是顺序查找，ASL 仍是 2.1。链表上做不了折半。官方也承认二叉排序树，for 或 repeat 当根时 ASL 可以到 2.0，那棵树在第 10 关算过。本关的用例只核对题干的 2.2 和第（1）问的 2.1。

2017 年第 8 题没有 `.in`。折半判定树是一棵二叉排序树，而且整棵树的中点取整方向必须相同。官方解答：B 在一处向上、另一处向下；C 同样混用；D 的根是左 4 右 5，这是向下取整，它的左子树却是左 2 右 1，又变成向上取整。A 从头到尾只用一种。选 A。`bin floor 10` 打出的是全程向下取整的那棵，用来和试卷上的 A、D 比形状。

## 易错点

- 看到「有序表的顺序查找」就把成功 ASL 写成比 (n+1)/2 更小。有序只减少失败的比较。
- 有序失败的分子是 (1+…+n)+n。最后一段是 n，不是 n+1。
- 无序失败到底是 n 还是 n+1，看有没有把关键字写入 0 号。没给代码就按哨兵版 n+1。哨兵不改变时间复杂度，只少了越界判断。
- 折半失败的最多比较次数等于树高，不是树高加 1。2010 年 n=16 是 5，2023 年 n=600 是 10。
- 成功 ASL 的分母永远是记录个数。失败分母是入口数：基于比较的查找是 n+1。散列的失败分母是散列函数的值域，那是第 16 关的事，不要提前除以 n+1。
- 向上取整和向下取整的 ASL 相同，某个关键字的比较次数可以不同。同一棵判定树不能两种取整混用。
- 静态链表不是「数组就能折半」。游标把逻辑次序和下标拆开了。
- 分块的王道公式在索引折半时，按最大关键字的层数给整块计价。块里不是最大关键字的记录，真实路径可能多比一次。2025 年索引是顺序的，没有这个差。
- 2025 年 s=25 的 ASL 是 21.5，比 s=20 的 21 大。√n 左右才是谷底，不是越大越好。

## 概念卡片

做完写进 `NOTES.md`。下面是对照用的，先自己写。

**查找表。** 同一类型记录的集合。静态查找表只做查找；动态查找表在查找过程中还可能插入、删除。折半查找维护有序顺序表的代价高，适合静态表。又要快又要经常插删，用后面的树或散列表。

**ASL。** 查找过程中关键字比较次数的期望 Σ Pi·Ci。等概率时 Pi = 1/n，成功 ASL = (Σ Ci) / n。Ci 只数关键字比较。成功和失败分开算，分母不一定相同。概率已知时，把概率大的记录放到比较次数小的位置，成功 ASL 会下降；2013 年因此用顺序查找胜过了折半查找。

**三种静态查找。** 顺序查找任何能逐个访问的结构都能用，成功 ASL 是 (n+1)/2。折半查找要有序并且能随机取中点，最多次数是 ⌈log2(n+1)⌉。分块查找要求块间有序、块内可以无序。索引和块内都顺序、并且等长时，块大小取 √n；n 正好是平方数时，成功 ASL 是 √n + 1。
