## 思路

### 两套下标差 1，说的是同一次失配

王道和严蔚敏把串从 1 编起：`next[1] = 0`，`next[2] = 1`。`0` 表示模式串第一个字符也对不上，主串、模式串一起前进一格。2015、2019 的题干把位序从 0 编起：`next[0] = -1`，`-1` 是同一个哨兵。

换算是整表减 1，再把下标左移一格：

```text
next0[j] = next1[j + 1] - 1
```

`abaabc` 的两行就是这个关系。`pm` 与编号无关，两套打印的是同一行：

```text
pm 0 0 1 1 2 0
row 0 1 1 2 2 3
row -1 0 0 1 1 2
```

上一行是从 1 起，下一行是从 0 起。`0 1 1 2 2 3` 每一项减 1，得到 `-1 0 0 1 1 2`。`nextval` 也这样减。比较次数、右滑距离不变，因为下标和哨兵一起平移了。

从 1 起先看两个校验位：`next[1]` 必须是 0，`next[2]` 必须是 1。从 0 起则是 `next[0] = -1`、`next[1] = 0`。对不上，就是两套混用了。

### 先写 pm，再右移得到 next

`pm[k]` 是前 k 个字符的最长真前后缀长度。真前后缀不能取整段，也不能从中间挑一段。`abaabc` 的前缀：

| 前 k 个 | 串 | 最长真前后缀 | pm |
|---|---|---|---|
| 1 | a | 没有 | 0 |
| 2 | ab | 没有 | 0 |
| 3 | aba | a | 1 |
| 4 | abaa | a | 1 |
| 5 | abaab | ab | 2 |
| 6 | abaabc | 没有 | 0 |

`abaa` 的前后缀只能是开头连续的一段对上结尾连续的一段，所以是 `a`，不是把两个 `a` 跳着取出来。

从 1 起：`next[1] = 0`，后面 `next[j] = pm[j - 1] + 1`，得到 `0 1 1 2 2 3`。整个模式串自己的 `pm[6] = 0` 不进 next，因为失配发生在某个字符上时，用的是它左边那一段。从 0 起：左边补 `-1`，后面直接放 `pm[1]` 到 `pm[5]`，得到 `-1 0 0 1 1 2`。

严蔚敏书上的 `abaabcac` 就是这条规则：`pm 0 0 1 1 2 0 1 0`，从 1 起的 next 是 `0 1 1 2 2 3 1 2`。书上写成 `01122312`。

`ababaa` 的 `pm` 是 `0 0 1 2 3 1`，从 1 起的 next 是 `0 1 1 2 3 4`。第 6 格是 `pm[5] + 1 = 4`，用的是 `ababa` 的前后缀 `aba`，不是整个串的 `pm[6] = 1`。

代码里 `border_len` 按这个定义从长到短试，`fill_next` 是王道的递推。`pattern_build` 要求两份结果逐项相同，所以 `ell` 和 `row` 不会各算各的。递推停在最后一个下标：`aba` 写完 `next[3] = 1` 就 `build done`，没有再拿 `a` 去比一次。

### 2015-8：i 不动，j 变成 2，选 C

模式串 `abaabc` 从 0 起的 next 是 `-1 0 0 1 1 2`。主串 `abaabaabacacaabaabcc` 和它比，前 5 个字符 `abaab` 都相等，第 6 个是主串的 `a` 对模式串的 `c`。下标从 0 数，这一次就是 `i = j = 5`。题干把失配位置写成 5，用的就是这一套。

```text
first_miss i=5 j=5 next_i=5 next_j=2
jump i=5 from=5 to=2 slide=3
```

`next[5] = 2`，所以下一次还是主串的第 5 格，模式串改到第 2 格。选项 C。

四个选项各自对应一种走法：

- A 的 `i=1, j=0` 是两个指针都拉回开头
- B 的 `j=0` 是主串没动，但 j 退到了起点旁边，不是 `next[5]`
- D 的 `i=6` 是主串也加了 1。KMP 里主串只有比较成功，或者 j 落到哨兵时，才会前进

同一时刻若改用从 1 起的编号，失配在 `i = j = 6`，`next[6] = 3`。`3` 和 `2` 指的是模式串里同一个 `a`（从 0 数是下标 2，从 1 数是下标 3）。这次匹配最后在从 0 起的下标 13 成功，那里是子串 `abaabc`；从 1 起的位置是 14。题只问第一次失配之后的下标，看 `first_miss` 就够了。

### 2019-9：比较 10 次，选 B

还是 `abaabc`，主串换成 `abaabaabcabaabc`。从 0 起：

```text
cmp k=1 i=0 j=0 S=a T=a eq=1
cmp k=2 i=1 j=1 S=b T=b eq=1
cmp k=3 i=2 j=2 S=a T=a eq=1
cmp k=4 i=3 j=3 S=a T=a eq=1
cmp k=5 i=4 j=4 S=b T=b eq=1
cmp k=6 i=5 j=5 S=a T=c eq=0
first_miss i=5 j=5 next_i=5 next_j=2
cmp k=7 i=5 j=2 S=a T=a eq=1
cmp k=8 i=6 j=3 S=a T=a eq=1
cmp k=9 i=7 j=4 S=b T=b eq=1
cmp k=10 i=8 j=5 S=c T=c eq=1
found pos=3 compares=10
```

第一段 6 次，含失配的那一次。`jump` 只查表，不算比较。第二段从 `j = 2` 接到 `j = 5`，4 次，主串从 5 走到 8。`6 + 4 = 10`。选项 B。从 1 起的 `compares` 仍是 10，成功位置是 4，也就是 `3 + 1`。

`next[5] = 2` 的意思是：失配时左边 5 个字符里，有长度为 2 的前后缀已经相等，这 2 个字符不用再比。若第二段仍从模式串头把 6 个字符都比一遍，就是 `6 + 6 = 12`，多出来的 2 正好是这段前后缀。选项 C 是这 12 次。只保留两段里比成功的 `5 + 4 = 9`，把失配漏掉，是选项 A。

同一对串用 BF，比较 15 次，位置同样是 4。主串退了三次：

```text
back i=6 j=6 -> i=2 j=1
back i=2 j=1 -> i=3 j=1
back i=4 j=2 -> i=4 j=1
found pos=4 compares=15
```

第一次从第 6 格退回第 2 格，后面两格又因为对不上再挪。KMP 的主串停在失配的那一格，没有这三次回退。15 是选项 D。

### nextval：相同的字符不要再比一次

`next[j]` 若指着一个和 `T[j]` 相同的字符，主串这个位置刚刚和 `T[j]` 不等，跟 `T[next[j]]` 也必然不等。`nextval` 在求表时就把这一跳提前做完：

- 起点固定是哨兵
- `T[j] == T[next[j]]` 时，`nextval[j] = nextval[next[j]]`
- 否则 `nextval[j] = next[j]`

相等时要顺着 `nextval` 走，不能改成 `next[next[j]]`。`next` 只退一截，`nextval` 已经是退到底的结果。`aa` 就看得出差别：next 是 `0 1`，第 2 个 `a` 和 `next[2]` 指向的 `a` 相同，`nextval[2] = nextval[1] = 0`。表变成 `0 0`。

`aaaab` 把这条链压平。从 1 起，next 是 `0 1 2 3 4`，nextval 是 `0 0 0 0 4`。只有最后一个 `b` 和它前面的 `a` 不同，保留 4；前面每一格都和第 1 格的 `a` 相同，全部收成哨兵。从 0 起就是各减 1：`-1 -1 -1 -1 3`。

`abc` 每个字符都不同，`j > 1` 时 `T[j]` 和 `T[1]` 不相等，修正条件一次也不发生，两张表都是 `0 1 1`。`ababaa` 会改掉其中几格：next `0 1 1 2 3 4`，nextval `0 1 0 1 0 4`。

严蔚敏用 `aaaab` 去配 `aaabaaaab`，把少掉的比较数出来了。用 next，失配后还要跟 `j = 3, 2, 1` 各比一次，这三次的模式串字符都是 `a`，结果事先就知道：

```text
cmp k=4 i=4 j=4 S=b T=a eq=0
jump i=4 from=4 to=3 slide=1
cmp k=5 i=4 j=3 S=b T=a eq=0
jump i=4 from=3 to=2 slide=1
cmp k=6 i=4 j=2 S=b T=a eq=0
jump i=4 from=2 to=1 slide=1
cmp k=7 i=4 j=1 S=b T=a eq=0
jump i=4 from=1 to=0 slide=1
found pos=5 compares=12
```

用 nextval，同一次失配直接落到哨兵，中间三格被跳过。`pass` 不是字符比较：

```text
cmp k=4 i=4 j=4 S=b T=a eq=0
jump i=4 from=4 to=0 slide=4
pass i=4 j=0 -> i=5 j=1
found pos=5 compares=9
```

`12 - 3 = 9`。匹配位置都是 5。`nextval` 不改变能不能配上，只少做注定失败的比较。2019 那一题的失配点上，next 和 nextval 都是 3，次数仍是 10；表在这一格没有被改掉。

递推填表时，回退也用已经写好的 `nextval`，所以 `build back` 的 `via` 是 `nextval[j]`。手算的 `j=` 行则是先把 next 求完再修正。`row_nextval` 跟这两条路都相同。

### 2024-6：修正后的最长右滑是 5，选 A

右滑距离是模式串开头相对主串前进了几格，等于 `j - nextval[j]`。哨兵比起点小 1，第一个字符失配时距离是 1：从 1 起 `1 - 0 = 1`，从 0 起 `0 - (-1) = 1`。

`aabaab` 从 0 起：

```text
row_next -1 0 1 0 1 2
row_nextval -1 -1 1 -1 -1 1
slide_next 1 1 1 3 3 3
max_next=3 j=3 ch=a
slide_nextval 1 2 1 4 5 4
max_nextval=5 j=4 ch=a
```

下标 4 是倒数第二个 `a`，`nextval[4] = -1`，距离 `4 - (-1) = 5`。从 1 起同一格是 `j = 5`，`nextval = 0`，距离 `5 - 0 = 5`。两套的 `j` 差 1，距离一样。选项 A。

另外三个选项都能在这张表上找到：

- 未修正的 next 最长是 3，三处并列，取最左边的 `j`。选项 C 就是拿 next 去回答「修正后」
- 修正后再短一档是 4，出现在下标 3 和最后一个 `b`。若从 0 起却把哨兵当成 0，`4 - 0 = 4`，也会得到这一档。选项 B
- 第二格的距离是 2。只看这一格，就是选项 D

`max_nextval` 取的是最长的那一档；同一档有多格时取最小的 `j`。`aa` 的 `slide_next` 是 `1 1`，所以 `j` 是 1 而不是 2。

## 易错点

1. **先看题干的编号。** 2015 写出第一次失配 `i = j = 5`，这只在从 0 起时成立。从 1 起同一次失配是 `i = j = 6`，next 是 3。3 和 2 是模式串里的同一个字符。校验位：从 1 起开头是 `0 1`，从 0 起开头是 `-1 0`。
2. **pm 右移时丢掉的是整个模式串那一项。** `abaabc` 的 `pm` 最后是 0，不出现在 next 里。`ababaa` 的第 6 格来自 `pm[5] + 1 = 4`，不是 `pm[6] = 1`。
3. **真前后缀必须从两端连续取。** `abaa` 的最长真前后缀是 `a`。从中间挑两个 `a`，长度会算成 2，后面的 next 整表错位。
4. **失配时主串下标不动。** 2015 的 D 把 `i` 加成了 6。主串前进只有两种情况：这一格比成功，或者 `j` 落到哨兵之后的 `pass`。
5. **失配算一次比较，查表和哨兵不算。** 2019 去掉失配是 `5 + 4 = 9`（选项 A）；把 next 已经保证相等的 2 个字符再比一遍是 `6 + 6 = 12`（选项 C）；BF 退回主串重比是 15 次（选项 D）。KMP 是 10 次。
6. **相等时取 `nextval[next[j]]`。** 写成 `next[next[j]]` 只退一截。`aaaab` 就要退到哨兵，匹配才会从 12 次变成 9 次。`abc` 这种字符互不相同的串，两张表相同，修正条件一次也不发生。
7. **2024 用的是修正后的表。** `aabaab` 未修正的最长右滑是 3，那是选项 C。距离 5 在从 0 起时落在 `j = 4`，从 1 起时落在 `j = 5`，都是倒数第二个 `a`。并列时取最小的 `j`，所以未修正的 3 记在最左边那一格。
8. **失败位置也差 1。** 从 1 起失败是 0，从 0 起失败是 -1。`ababa` 里找 `abc`，KMP 打 `fail pos=-1`，BF 打 `fail pos=0`。从 0 起的下标 0 是第一个字符，不是失败。成功时同样是「从 1 起 = 从 0 起 + 1」，2019 的位置是 3 和 4。
9. **哨兵不是字符。** `xabc` 对 `abc`，第一格失配后 `j` 变成 0，接着 `pass` 到 `i = 2, j = 1`，然后才比较 `a`。`pass` 没有 `cmp`。这次一共 4 次比较，位置是 2。同一对串的 BF 则是 `back i=1 j=1 -> i=2 j=1`，主串同样落到第 2 格，但走的是退回公式。两条输出都在 `tests/practice-bf.in`。
10. **BF 的主串会退，式子是从 1 起的。** `i = i - j + 2`，`j` 回到 1。2019 从第 6 格退到第 2 格。把这套式子套到从 0 起的下标上，退回的位置会偏一格。KMP 不使用这个式子。

## 概念卡片参考

- **模式匹配**：在主串中找模式串第一次出现的起始位置。BF 最坏要做约「主串长度 × 模式串长度」次比较，因为失配后主串退回，同一段会反复看。KMP 把退回需要的信息做成一张只和模式串有关的表，主串每个字符的前进次数有限，预处理和匹配合在一起是 O(主串长度 + 模式串长度)。一般文本里 BF 往往也很快，KMP 卡住的是最坏情况。
- **next**：失配后，模式串下一次拿哪一格来比。它等于「失配字符左边那段」的最长真前后缀长度，再按编号换成下标。从 1 起要加 1，从 0 起不加。整张表在看到主串之前就能算完。
- **nextval**：next 指出的那一格若和当前格是同一个字符，比较结果可以预知，表里就直接写成再退一步的结果。匹配成功的位置不变，少掉的是注定失败的比较。问「最长真前后缀是多少」时仍看 next；nextval 已经把这个长度改掉了。
- **两套编号怎么认**：题干给了定义，或像 2015 那样把失配下标写进了句子，就按题干的那一套算。王道教材从 1 起，`next[1] = 0`。只记得另一套的数字，每个值都会差 1。
