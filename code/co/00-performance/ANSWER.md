## 思路

三条时间公式先分清，后面每道题都是在问其中一条：

- **CPU 时间** = IC × CPI × T = IC × CPI / f。只含 CPU 真正执行指令的时间
- **响应时间**（执行时间、等待时间）还要加上 I/O 等待。2012 年的 100 s 是响应时间，其中 90 s 是 CPU 时间、10 s 是 I/O
- **MIPS** = f / (CPI × 10⁶)。分母的 10⁶ 是「百万」的定义，不是 2²⁰。主频先换成 Hz 再除，和「主频的 MHz 数 / CPI」是同一件事：1.2 GHz = 1200 MHz，1200 / 3 = 400

加速比一律是 **改进前的时间 / 改进后的时间**，大于 1 才是变快了。只改进一部分时，没改进的那段时间原样留下，这就是 Amdahl 定律：加速比不超过 1/(1−F)。

打印前先把 double 收成十进制（`snap`）。1.2×10⁹ 在二进制里不一定是精确的整数，时钟周期又只有 10⁻¹⁰ s 这一量级；要是用「离 0 很近就算 0」的容差，1 ns 会印成 0 s。不足 0.1 s 的时间同时写出 ms / us / ns，是为了和选项里的单位对上：2.8×10⁻⁵ s = 28 μs，不是 28 ms。

## 易错点

1. **M 有两套**。性能里 M = 10⁶，存储里 M = 2²⁰ = 1048576。2013 年若把 M 当成 2²⁰，1.2×10⁹ / (3×1048576) ≈ 381，和 400 对不上。另一条岔路是 CPI 没加权、只用了 A 类的 2：1200/2 = 600，正好是选项 D。
2. **提高 50% 不是时间减半**。S = 1.5，CPU 时间变成 90/1.5 = 60 s，加上没动的 I/O 10 s，是 70 s。把 90 s 砍半会得到 55 s，那是 2012 年的选项 A。I/O 那 10 s 不参与加速，所以总加速比只有 100/70 ≈ 1.43，到不了 1.5。
3. **2014 年两个变化要相乘**。时间与 IC×CPI 成正比，主频没变：0.7×1.2 = 0.84，20×0.84 = 16.8 s。只乘 0.7 得到 14 s（选项 C）；把 CPI 变大当成变快、改成除以 1.2，得到约 11.7 s（选项 B）。
4. **主频高不一定更快**。2017 年 M1 的主频 1.5 > 1.2，但 CPI 是 2 比 1，时间比是 1.6，M1 更慢。比值写反是 0.625（选项 B）。把主频放到分子上，(2/1)×(1.5/1.2) = 2.5，是选项 D。
5. **μs 和 ms 差 1000 倍**。2022 年 2.8×10⁻⁵ s = 0.028 ms = 28 μs。看成 28 ms 就是选项 C。2023 年 4×10⁻⁴ s = 0.4 ms，不是 0.4 μs（选项 D）。0.8 GIPS 是把 CPI/f 当成了速度（选项 A），速度是 f/CPI。
6. **占比用小数**。80% 写成 0.8。程序读到大于 1 的占比会报错，避免把 80 和 0.8 悄悄乘出两个 CPI。
7. **2016 年的「编译程序」和 2022 年的四步不是同一问**。编译程序负责高级语言到汇编或机器级目标代码；预处理、汇编、链接是另外的程序。2022-20 问的是整条流水，答案才是四步全写上。

## 概念卡片参考答案

### 卡片一：冯·诺依曼结构的特点

1. 硬件由五大部件组成：运算器、控制器、存储器、输入设备、输出设备。运算器和控制器合起来是 CPU，存储器通常指主存
2. 指令和数据以同等地位存放在存储器里，按地址访问，靠 CPU 在不同阶段的解释来区分「这是指令」还是「这是数据」
3. 指令和数据都用二进制表示
4. 指令由操作码和地址码组成
5. **存储程序**：程序事先放进主存，计算机运行时自动逐条取出指令并执行。这是冯·诺依曼结构的核心
6. 早期以运算器为中心；现在的机器以存储器为中心。题目问「冯·诺依曼计算机的结构特点」时，存储程序和五大部件是必答的，不要把「以存储器为中心」写成冯·诺依曼原始结构的特点

软件和硬件逻辑上等价：同一功能可以用硬件做，也可以用软件做。硬件快、成本高、改起来死；软件灵活、速度慢。指令系统是软硬件的交界面。

### 卡片二：计算机系统的层次结构

自底向上，上一层是下一层功能的扩展：

| 层次 | 谁在执行 | 本关实验里能看见的 |
|---|---|---|
| 微程序机器层 | 硬件直接执行微指令。硬布线控制器没有这一层 | 看不到，要到控制器那一关 |
| 传统机器层 | 机器指令 | 链接之后的可执行文件 |
| 操作系统层 | 机器指令，再加上系统调用这种广义指令 | `printf` 最终会进系统调用，本关先不拆 |
| 汇编语言层 | 汇编程序把助记符译成机器指令 | `clang -S` 得到的 `.s`，`clang -c` 得到的 `.o` |
| 高级语言层 | 编译程序翻译，或解释程序逐句执行 | `hello.c` |

从高级语言源程序到可执行文件是四步（2022-20，选 A）：

1. **预处理**：去注释、展开 `#include`、替换宏。`clang -E` → `.i`
2. **编译**：高级语言译成汇编。`clang -S` → `.s`。这一步的程序才是 2016-12 说的编译程序（选 C）
3. **汇编**：汇编译成机器语言目标文件。`clang -c` → `.o`。本文件里的符号有地址，外部函数（如 `printf`）还没有
4. **链接**：把目标文件和库拼起来，解析外部符号、重定位，得到可执行文件

硬件能直接执行的只有机器语言（2015-12，仅 I）。汇编语言要先汇编，硬件描述语言是给设计硬件用的，都不是 CPU 取出就能执行的指令。

解释程序是译一句、执行一句，不生成目标程序。它和编译程序都是翻译程序，但 2016-12 问的是「转换成机器级目标代码文件」，所以是编译程序，不是解释程序。

### 卡片三：吞吐量 vs 响应时间

| | 响应时间 | 吞吐量 |
|---|---|---|
| 问的是 | 一个任务从提交到做完要多久 | 单位时间能做完多少任务 |
| 方向 | 越短越好 | 越大越好 |
| 用户能感到的 | 是 | 机房、服务器更关心这个 |

缩短响应时间通常会提高吞吐量。用多道程序提高吞吐量时，单个任务可能要排队，响应时间反而变长。所以这两个指标不是永远同向的。

CPU 时间只是响应时间的一段。2012 年把 100 s 拆成 90 s CPU + 10 s I/O：CPU 快了 1.5 倍，I/O 的 10 s 一点不动，总时间是 70 s 而不是 60 s。这就是 Amdahl 定律在这道题里的样子——优化的收益被「没优化到的那部分」封了顶。

2023 年问的用户 CPU 时间没有另给 I/O，就是 IC × CPI / f。不要把它叫成整机的响应时间。
