## 一、本关任务

- **产出**：一个带单位的性能计算器。输入主频、CPI、指令条数等，按考纲公式打印推导过程和结果：执行时间、MIPS、加速比，以及 MFLOPS 到 ZFLOPS 的换算。另做一次「从 `hello.c` 到可执行文件」的实验，记录写在 `EXPERIMENTS.md`（本机输出，不进 `tests/`）
- **小步骤**：
  ① 基本公式：时钟周期、CPU 时间、MIPS / GIPS、IPC
  ② 多类指令的加权平均 CPI
  ③ 改进前后的加速比（指令条数和 CPI 同时变化、只改进一部分、两台机器比时间）
  ④ FLOPS 单位换算（M、G、T、P、E、Z 依次是 10⁶ 到 10²¹）
  ⑤ 用 `clang -E`、`-S`、`-c` 和链接，分别得到 `.i`、`.s`、`.o` 和可执行文件，用 `nm` 看 `.o` 里哪个符号还没解析
- **通过标准**：给定各类指令占比与 CPI，能算出平均 CPI、执行时间或 MIPS（**M 是 10⁶，不是 2²⁰**）；能说出高级语言程序变成可执行文件要经过哪几步
- **概念卡片**（写进 `NOTES.md`）：冯·诺依曼结构的特点；计算机系统的层次结构；吞吐量 vs 响应时间

本关有两个程序：`main.c` 编出的主程序（如 `performance_answer`）、`test.c` 编出的单元测试（`performance_answer_test`）。

王道第 1 章。性能指标里的 k / M / G / T 是 10³ / 10⁶ / 10⁹ / 10¹²；存储容量里的 K / M / G 才是 2¹⁰ / 2²⁰ / 2³⁰。本关全程用前者。

## 二、主程序题目（`main.c`）

读入命令，直到输入结束。每条命令打印一块推导，**每个数都带单位**，最后一行以 `结果：` 开头。`tests/` 里每组 `<用例>.in` 的输出必须与同名 `.out` 一致（行尾空白和首尾空行会被忽略）。

读之前用 `prompt(...)` 提示（`prompt` 在 `deps/prompt.h`，用法同 `printf`，跑测试时自动不打印）。可以连续输入多条命令，Ctrl+D 结束。

### 单位

- 主频：`Hz`、`kHz`、`MHz`、`GHz`、`THz`
- 时间：`s`、`ms`、`us`、`ns`、`ps`。`us` 就是微秒 μs
- 占比：0 到 1 的小数，80% 写成 `0.8`，不要写 `80`
- 加速比：正数（如 `1.5`），或 `+50%` 这种写法。`+50%` 表示速度提高 50%，部件加速比 S = 1 + 50/100 = 1.5
- FLOPS：`MFLOPS`、`GFLOPS`、`TFLOPS`、`PFLOPS`、`EFLOPS`、`ZFLOPS`

### 公式（输出里要把代入的数打出来）

- 时钟周期 T = 1/f
- CPU 时间 = 指令条数 IC × CPI / f
- 平均 CPI = Σ（该类占比 × 该类 CPI）
- MIPS = f / (CPI × 10⁶) = IC / (CPU 时间 × 10⁶)
- GIPS = f / (CPI × 10⁹)
- IPC = 1/CPI
- 主频不变时，新时间 = 原时间 × IC 的倍数 × CPI 的倍数；加速比 = 原时间 / 新时间
- 只改进一部分：新时间 = 不可改进部分 + 可改进部分 / S；总加速比 = 1 / ((1−F) + F/S)，F 是可改进部分占原时间的比例
- 两台机器指令条数相同：T1/T2 = (CPI1 × f2) / (CPI2 × f1)
- MFLOPS = 浮点运算次数 / (执行时间 × 10⁶)

打印 MIPS 或 GIPS 时要写明：这里的 M、G 是 10⁶、10⁹，不是 2²⁰、2³⁰。

### 命令

| 命令 | 输入 | 结果行里要有 |
|---|---|---|
| `basic` | 主频、单位、CPI、指令条数 | GIPS 和 CPU 时间 |
| `cpi` | 主频、单位、指令条数、类数；接着每行「占比 CPI」。指令条数未知填 `0` | 平均 CPI；给了指令条数再加 CPU 时间和 MIPS，否则只加 MIPS |
| `scale` | 原时间、单位、IC 倍数、CPI 倍数 | 新的执行时间和加速比 |
| `amdahl` | 总时间、单位、可改进部分时间、单位、加速比 | 新的执行时间和加速比 |
| `ratio` | f1、单位、CPI1、f2、单位、CPI2 | T1/T2 |
| `flops` | 数值、单位 | 换成 MFLOPS 的数 |
| `rate` | 浮点运算次数、时间、单位 | MFLOPS |

`cpi` 最多 16 类，输出里用 A、B、C… 称呼。某一类的占比不在 0 到 1 之间，或者单位认不出，程序向 stderr 报错并以非 0 退出。

### 样例

输入：

```
basic 2 GHz 2 4000000
```

输出：

```
【基本公式】
主频 f = 2000000000 Hz = 2000 MHz = 2 GHz
时钟周期 T = 1/f = 5e-10 s = 0.5 ns = 500 ps
CPI = 2 周期/条
指令条数 IC = 4000000 条
总时钟周期数 = IC × CPI = 4000000 × 2 = 8000000 周期
CPU 时间 = 总时钟周期数 / f = 8000000 / 2000000000 = 0.004 s = 4 ms
指令执行速度 = f / CPI = 2000000000 / 2 = 1000000000 条/s = 1000 MIPS = 1 GIPS
MIPS = f / (CPI × 10^6) = 2000000000 / 2000000 = 1000
核对：MIPS = IC / (CPU 时间 × 10^6) = 4000000 / (0.004 × 10^6) = 1000
IPC = 1/CPI = 0.5 条/周期
（性能指标里的 M、G 是 10^6、10^9，不是存储容量的 2^20、2^30）
结果：指令执行速度 = 1 GIPS，CPU 时间 = 0.004 s = 4 ms
```

## 三、编译实验（小步骤 ⑤）

写一个调用 `printf` 的 `hello.c`，里面放一个 `#define` 和一行注释。然后：

```
clang -std=c11 -Wall -Wextra -E hello.c -o hello.i
clang -std=c11 -Wall -Wextra -S hello.c -o hello.s
clang -std=c11 -Wall -Wextra -c hello.c -o hello.o
clang -std=c11 -Wall -Wextra hello.o -o hello
nm hello.o
./hello
```

看这四样东西分别是谁的产物：`.i` 有没有还留着注释和宏名，`.s` 里有没有对 `printf` 的调用，`.o` 里 `printf` 有没有地址，`.o` 能不能直接运行。本机是 arm64，汇编不是 408 卷面上的 32 位 Intel 语法；那部分在第 08 关。本机实际输出见 `EXPERIMENTS.md`，行数和符号前缀会随系统变化，不要写进 `tests/`。
