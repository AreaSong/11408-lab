## 思路

机器里没有负号这个符号。真值是人写的带正负的数，机器数是把符号也编进位串之后的 0/1。四种编码的差别只在负数和零；正数的原码、反码、补码是同一串位。

位宽 n 算进符号位。整数的补码把最高位的权当成 −2^(n−1)，所以范围是 −2^(n−1) ～ 2^(n−1)−1，比原码多一个最小负数。移码是在补码上把符号位取反，整数的偏置是 2^(n−1)，小数的偏置是 1。两种偏置做的是同一件位运算。IEEE 754 的阶码偏置是 2^(k−1)−1，单精度才是 127，不要提前用。

定点小数的小数点卡在符号位后面。数值位有 n−1 位，真值必须是 2^(1−n) 的整数倍，否则这道题的机器表示不了它。−1 只有补码和移码能表示，机器数是 `1.000…0`。

字节怎么进内存，是另一件事。小端把低字节放在低地址，大端反过来。结构体再加一条：每个成员的偏移要是它自己对齐数的倍数，结构体末尾再补到最大对齐数的倍数。`char name[10]` 的对齐数是 1，不是 10。

C 语言改变宽度时，补位看源类型，读数看目标类型。源是有符号就复制符号位，源是无符号就补 0。变窄只留低位，丢掉的高位不会四舍五入回来。

## 易错点

1. **−45 的 8 位原码是 ADH，不是 A5H**。45 = 0101101，符号位接上去是 10101101。A5H 是 10100101，那是 −37。反码 D2H，补码 D3H，移码 53H。定义式 2^8 + (−45) = 211，211 就是 D3H。
2. **−128 不是“符号位 1、数值位全 0 的原码”**。那一串位在原码里是 −0。补码里它才是 −2^7，移码里是全 0。全 0 的移码是最小真值，不是零；移码的零是 80H。
3. **小数的 −1 和整数的 −128 是同一串位 `100…0`，单位不同**。8 位定点小数的数值位是 1/128，−128 个单位就是 −1。原码到不了 −1。
4. **移码的偏置看的是整数还是小数，不是看是不是阶码**。整数加 2^(n−1)，小数加 1。IEEE 754 单精度阶码加的是 127，比 2^7 少 1。第 04 关再动那个偏置。
5. **加宽时先看源类型的声明**。`unsigned short` 65530 变成 `unsigned int` 是 0000 FFFAH（2012-13 的 B）。若把它当有符号扩展，会得到 FFFF FFFAH，那是 D。`short` −32767 赋给 `unsigned int` 时，源是有符号的，先复制符号位得到 FFFF 8001H，再按无符号读。先按无符号解释再补 0，会得到 32769，和真值差了约 2^32。
6. **−32767 = −(2^15 − 1)，不是 −2^15**。所以无符号值是 2^32 − 2^15 + 1，不是 2^32 − 2^15 − 1。差在那个 +1 上，正是 2025-12 的 C 和 D。−2^15 本身的 16 位补码是 8000H，−32767 是 8001H。
7. **截断不四舍五入**。32777 = 0000 8009H，低 16 位 8009H 的最高位是 1，按 short 读是 −32759，不是 −32777，也不是 32777 的低 15 位。再扩回 32 位，高位补的是 1，回不到原来的 32777。
8. **原码扩展不复制符号位**。8 位原码 10000011 是 −3，扩到 16 位是 8003H：符号位挪到新的最高位，中间补 0。把最高位的 1 照补码那样铺开，得到 FF83H，按原码读是 −32643。
9. **2009 年的 y 是 FFF7H，不是 FFF9H**。−9 的 16 位补码：9 是 0009H，取反加 1 得 FFF7H。FFF9H 是 −7。和 int 相加之前，short 会临时符号扩展成 FFFF FFF7H，加上 0000 007FH，丢掉进位后是 0000 0076H。y 存在内存里仍然是 16 位的 FFF7H，不会变成扩展后的样子。这次加法没有溢出，标志位留到第 02 关。
10. **同一串位，无符号和补码的顺序相反**。2021 年 FFFDH、FFDFH 最高位都是 1。当无符号读，它们比 7FFCH 大，而且 FFFD > FFDF。当补码读，它们是 −3 和 −33，都比正的 7FFCH 小，而且 −33 < −3。
11. **小端是低字节在低地址**。2016 年若从高位往低地址放，00008046H 会落到别的选项。2012 年 273 = 00000111H，低字节 11H 在 0xC008；放反了就是选项 A/B 里的 00H。
12. **填充算在成员前面，也算在结构体末尾**。2012 年 `short` 不能从奇数地址 0xC00D 开始，所以 `c` 在 0xC00E，那一字节是内部填充，不是末尾。2020 年 `short` 后面要空 2 字节，`int` 才到 4 的倍数；不空的话 34H 会落在 2020FE04H（选项 B）。按大端读又会落在 2020FE05H（选项 C）。
13. **`char[10]` 的对齐数是 1**。2025 年 id 4 字节、name 10 字节，接下来的 int 要从偏移 16 开始，中间空 2 字节，元素大小 20。有的解析只说“18 向上取整到 20”，元素起点碰巧还是对的，所以 56H 的地址一样；但 salary 会被放到偏移 14，那不是边界对齐。若完全不补、元素按 18 字节排，employee[1] 在 0000A0C2H，56H 在 0000A0C3H，是选项 A。大端则会把 56H 放在 0000A0C6H，是选项 D。
14. **本机的 `long` 不是卷面的 `long`**。计算器里 long 是 4 字节、对齐 4。本机 `sizeof(long)` 是 8，`char` 后面要空 7 字节。三道只含 int/short/char 的真题，本机的 `sizeof` 和卷面一致；一出现 long 或指针就不一致。`double` 在本机也按 8 对齐，和王道相同。有争议的是 32 位 Linux 的 System V ABI：那里的 double 只按 4 对齐。本机测不到那种环境，计算器按王道的 8。

## 小步骤对应的代码

| 步骤 | 函数 | 在算什么 |
|---|---|---|
| ① | `radix_parse`、`radix_result`、`radix_print` | 先按源进制收成整数部分加一个分数，再按目标进制写出来。2/8/16 的分组结果要和这个分数一致，对不上就报错 |
| ② | `code_encode`、`code_decode`、`code_extend`、`code_extend_orig` | 补码用“负数转无符号再取低位”。移码把补码符号位取反。原码扩展把符号位单独挪到新的最高位 |
| ③ | `code_comp_min`、`code_print_range`、`code_frac_units` | 整数范围直接用 2 的幂。小数先问它是不是 2^(1−n) 的整数倍，再套同一套编码 |
| ④ | `mem_byte`、`mem_print_endian`；`native.c` 里的指针 | 小端的第 i 个字节是机器数的第 i 个低字节。本机看的是真实内存，不进 `tests/` |
| ⑤ | `mem_layout`、`mem_print_align`；`native.c` 里的 `sizeof` | 偏移先补到对齐数的倍数，末尾再补。`native.c` 用编译器的结果核对三道真题的结构体 |

## 概念卡片参考答案

### 四种编码的对比

n 是字长，含 1 位符号位。下表是整数。定点小数把“数值”换成小数点后的 n−1 位，补码多出来的那个值是 −1，不再是 −2^(n−1)。

| | 负数怎么来 | 零 | 范围 | 主要用在 |
|---|---|---|---|---|
| 无符号 | 不表示负数 | 一个：全 0 | 0 ～ 2^n−1 | 地址、个数、位串本身 |
| 原码 | 符号位取 1，数值位是绝对值 | 两个：+0 全 0，−0 只有符号位为 1 | −(2^(n−1)−1) ～ 2^(n−1)−1 | 直观，乘除时符号位单独处理；浮点尾数也用原码 |
| 反码 | 原码的数值位取反 | 两个：+0 全 0，−0 全 1 | 与原码相同 | 求补码的中间步骤。自己做加减要循环进位，很少直接用 |
| 补码 | 反码末位加 1。负数也等于 2^n + 真值的低 n 位 | 一个：全 0 | −2^(n−1) ～ 2^(n−1)−1 | 整数的通用表示。减法可以变成加法，符号位参加运算 |
| 移码 | 补码的符号位取反。整数等于真值 + 2^(n−1) | 一个：最高位 1、其余 0 | 与补码相同 | 需要“位串越大、真值越大”的时候。全 0 是最小真值 |

8 位、真值 −45 的四个机器数：原码 ADH，反码 D2H，补码 D3H，移码 53H。−128 只有补码 80H 和移码 00H。

选型就一件事：要让符号位参加加法，用补码；要让位串的大小顺序和真值一致，用移码。整数用前者，阶码用后者。
