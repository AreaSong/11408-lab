## 思路

五段每拍流一次。没有冒险时，第 i 条指令的 IF 在第 i 拍，WB 在第 i+4 拍。n 条指令的最后一拍是 k+n−1。k=5 时就是 n+4。

三个指标都用这个总拍数 T：

- 顺序执行每条指令自己走完 k 段，T0 = n×k×Δt
- 加速比 S = T0 / (T×Δt) = nk / T
- 吞吐率 TP = n / (T×Δt)，最大吞吐率是 1/Δt
- 效率 E = 有效格 / 总格 = (n×k) / (k×T) = n/T

各段时间不等时，同步时钟取最长的一段。段与段之间还有流水段寄存器，2018 年要把这 20ps 加上。2009 年题目写了忽略段间缓存，锁存就是 0。

数据相关只计 RAW：后面的指令读寄存器，前面有指令写同一个寄存器。WAW、WAR 在按序五段里写回不会反序，2016 年那一对都写 R5 的不是答案。

两种读寄存器的约定差一拍，必须看题目原话：

| 约定 | 谁在用 | 相邻 RAW | 隔一条 |
|---|---|---|---|
| WB 前半写、ID 后半读 | 没特别声明时，含 2014 | 停 2 拍 | 停 1 拍，常常被前一条的停顿盖住 |
| 同一拍不能又读又写 | 2012 年原文 | 停 3 拍 | 再多 1 拍 |

转发以后，ALU 结果在 EX 末就有，下一条 EX 能直接用，相邻加法停 0 拍。load 的数在 MEM 末才从存储器出来，下一条若在 EX 就要用，必须再停 1 拍。store 要写进存储器的那个数可以晚到 MEM 段才用，所以紧跟在 ALU 或 load 后面的 store，转发后自己不必再停。

结构冒险：load/store 的 MEM 和别人的 IF 抢同一个存储器。五段里，第 1 条的 MEM 在第 4 拍，正好是第 4 条的 IF。指令 Cache 和数据 Cache 分开，这一拍就不再撞。分开不改变命中率，也不改变缺失损失。

控制冒险按题目给的办法，不另发明：

- 硬件阻塞到 MEM 结束：下一条的 IF 比正常晚 3 拍。分支自己若还因数据多停了几拍，那几拍算在分支头上，不再加进这 3 拍
- 预测不转移、EX 段才知道：猜对则后面的指令照做；猜错则冲刷 IF 和 ID 里已经进来的两条，惩罚 2 拍
- 延迟槽：分支下一条总是执行，ID 段末改 PC，惩罚 0 拍

2012 年第（1）问：−513 的 16 位补码是 FDFFH，算术右移 1 位得 FEFFH。过程在第 02 关。第（4）问的 `ADD R1, R2` 把和写入 R2，所以最后是 `STORE R2, [x]`，不是存 R1。

2013 年 A 的 0.25×10^9 是按 CPI=4、主频 1 GHz 去除。B 的 0.97×10^9 接近 100/103×10^9，主频误用了 1 GHz。D 就是 1.03 GHz 本身。

2014 年第 16 题有的转载把 C 印成「降低 CPU 平均访问时间」。正确项都是 D，分离的目的是减少流水线资源冲突。

2023 年有的转载把选项印乱，并写成只阻塞 I3。题面四个选项是「仅 I3 / 仅 I2 和 I4 / 仅 I3 和 I4 / 仅 I2、I3 和 I4」，答案是 C。beq 在 MEM 段才改 PC，I4 的取指要等。

## 易错点

1. **先看题目允不允许同拍读写**。不声明时按先写后读，相邻 RAW 停 2 拍。2012 年写了不能同拍读写，停 3 拍。用 2 拍去画 2012 的图，x=x*2+a 得不到 17。
2. **2012 年加法的目的寄存器在后面**。`ADD Rs, Rd` 是 (Rs)+(Rd)→Rd。`x=a+b` 的和在 R2，`x=x*2+a` 也是先把 2x 放进 R1，再 `ADD R1, R2` 把和写入 R2。
3. **前一条停在 ID，后一条的 IF 会重复**。这是按序发射，不是后一条自己的数据相关。2012 问的就是 I4 的 IF。2014 的 I5 也这样，但 I5 不在「因数据相关而阻塞」的名单里。
4. **转发不是所有 RAW 都变 0 拍**。load 紧跟着一条要在 EX 用该数的指令，仍停 1 拍。2024 年 C 错在「所有」。store 要存的数可以晚到 MEM 再用，所以 2019 年 I3 到 I4 转发后 I4 不再为数据停。
5. **隔得远的 RAW 可能被别人的停顿盖住**。四条都读 I1 所写的 R1 时，I2 停 2 拍已经把 I3 推开，I3 自己的 ID 不再多停。不能把「每对相关各算一次」再加起来。
6. **2014 年下一轮的第一条和 I5 仍是 RAW，只是不再阻塞**。I5 写 R2，下一条 sll 读 R2。中间有 bne 自己的 2 拍，再加上分支固定的 3 拍，I5 的 WB 已经过去。
7. **结构冒险不是每条指令的 MEM 都访存**。只有 load/store。四条里只有第一条 load 会在第 4 拍和第 4 条的 IF 相撞，所以只多 1 拍。
8. **时钟周期两道题的口径不同**。2009 年明确忽略段间缓存，答案 90ns。2018 年给出锁存 20ps，80+20=100ps。只写 80ps 是漏了寄存器。
9. **吞吐率的分母是总拍数，不是段数，也不是主频**。100 条、4 段是 103 拍。1.03×10^9 × 100/103 正好是 1.0×10^9。
10. **理想 CPI=1 不包括超标量**。基本流水线理想情况每拍流出一条。超标量一拍多条，CPI 小于 1。多周期 CPI 大于 1。
11. **超标量不缩短功能段时间**。缩短段时间、把一个时钟再拆开，是超流水线。动态流水线说的是同一时间各段可以做不同运算；动态调度是硬件重排没有相关的指令。2017 年Ⅲ只要求知道超标量可以配动态调度。

| 步骤 | 函数 | 在做什么 |
|---|---|---|
| ① | `metric_ideal`、`metric_freq`、`metric_clock` | T=k+n−1。加速比 nk/T，效率 n/T。时钟 = 最长段 + 锁存 |

## 概念卡片参考答案

### 卡片：超标量、超流水线、动态流水线

| | 在做什么 | 换什么 | 理想 CPI |
|---|---|---|---|
| 基本流水线 | 一条指令拆成多段，段与段重叠 | 时间重叠 | 1 |
| 超标量 | 多套功能部件，一个时钟发射多条 | 空间换时间 | 小于 1 |
| 超流水线 | 把功能段再细分，时钟更短 | 时间换空间 | 仍可按每拍一条理解，但拍更短 |
| 静态流水线 | 同一时间各段只能按同一种功能连接 | — | — |
| 动态流水线 | 同一时间有的段在做一种运算，有的段在做另一种 | 多功能 | — |

动态调度是另一层：硬件发现后面的指令和前面没有相关，就让它先执行。超标量常和动态调度一起用，所以 2017 年Ⅱ和Ⅲ都对，Ⅰ不对。记分牌、Tomasulo 的具体表不在 408 的计算范围里。

三种冒险的处理也可以放在这张卡片旁边：结构冒险靠重复资源或停一拍；数据冒险靠阻塞、转发或编译器重排；控制冒险靠阻塞、预测或延迟槽。预测错了要把已经取进来的指令冲掉。
