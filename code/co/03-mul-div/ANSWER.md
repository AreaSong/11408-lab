## 思路

三位算法都是「加法器再加一个移位器」。差别在看哪一位、右移还是左移、符号进不进运算。

### 原码一位乘

符号单独异或：同号为正，异号为负。数值位当成无符号数。

部分积用双符号位，初值 0。乘数寄存器只放 |y| 的数值位。从最低位看：是 1 就加上 |x|，是 0 就加 0。然后部分积和乘数一起逻辑右移，空出的高位补 0。做 n 次。右移之后，乘数寄存器里不再是原来的乘数，而是积的低 n 位；部分积的数值位是积的高 n 位。

双符号位是为了接住进位。两个 n 位正数相加，和可能到 n+1 位。01 的那个 1 是进位，右移补 0 之后会回到 00。它不是「部分积变成了负数」。

加 0 也算一次加法。n=4 的 `-0.1101 × +0.1011`，规则上 4 次加法，其中末位真是 1 的只有 3 次。数值位 `0.10001111`，加上符号是原码 `1.10001111`，真值 −143/256。

原码有负零。`-0.0000` 的真值是 0，符号位仍是 1，异或之后积的原码可以是 `1.000…0`。

### Booth

补码乘法让符号参加运算，不用先取绝对值。n 仍是数值位数，不含符号。

被乘数和部分积用双符号位。[y]补 用单符号位，最低位右边再放一个附加位，初值 0。每步看「乘数当前最低位、附加位」：

| 末两位 | 操作 |
|---|---|
| 00 | 部分积 + 0 |
| 01 | 部分积 + [x]补 |
| 10 | 部分积 + [-x]补 |
| 11 | 部分积 + 0 |

然后算术右移：空出的高位补当前部分积的符号。一共判断 n+1 次，只右移 n 次。最后一次已经对准位权，再移就会把积移错一位。

乘数寄存器里装的是 [y]补，不是原码。正数两者相同。`y = -0.1101` 的原码数值位是 1101，补码是 `1.0011`。

乘积的拼法：部分积留下一位符号和 n 位数值，再接乘数寄存器去掉最低位之后的 n 位。那最低位是 [y]补 的符号一路右移走到底的，不算进乘积。经典例子最后乘数是 `0.0010`、附加位是 1，积的低 4 位是 0001，拼出来是 `1.01110001`，真值仍是 −143/256。

00 和 11 不用真加。一串连续的 1 只在两头各做一次加减，这是 Booth 比逐位加少做加法的原因。上面这个例子判断 5 次，真正加减 4 次。

### 原码加减交替

商的符号仍是异或。余数的符号与被除数相同。数值位要求 |x| < |y|，否则商至少是 1，n 位小数放不下。除数为 0 时商和余数都没有定义。

寄存器：R 放余数，Q 放商，Y 放 |y|。机器做减法是加上 [-|y|]补。

先用 |x| 试减一次。余数为负，说明没有溢出。这一位不写入商，也不把除数加回去。

之后每一步：先记住余数的符号，再把 R 左移，然后才加或减。上一步余数为正，左移后减 |y|，够减则商 1；上一步为负，左移后加 |y|，不够减则商 0。正、1、减，负、0、加。看的是左移之前的符号。单符号位左移会把原来的符号顶掉，`0.1011` 左移可以变成 `1.0110`，这时最高位已经不能当符号用。

末位若余数仍为负，要加回 |y|，商不变。中间那些负余数不用加回：下一步的左移会把这笔账带过去。最后一步后面没有左移，所以这一次省不掉。

R 被左移了 n 次，真实余数 = 机器余数 × 2^(−n)。`+0.1001 ÷ +0.1101` 的商是 `+0.1011`，机器余数是 `+0.0001`，真实余数是 +1/256。验算用分子：11×13+1 = 9×2^4。

### 整数乘法和补码除法器

2020 年的 ALU 只会加减和逻辑运算。乘法可以拆成循环：看乘数的一位，是 1 就把被乘数的移位结果加进去。没有乘法指令时，这个循环由很多条普通指令完成，最慢。一条乘法指令若内部仍用 ALU 和移位器，控制逻辑负责数循环次数，并决定这一拍加不加、移不移；一条指令，多个时钟周期。阵列乘法器把各位部分积同时做出来，一个时钟周期，最快。

n 位乘 n 位得到 2n 位。C 语言的 `umul`、`imul` 只留下低 n 位。无符号溢出看高 n 位是不是全 0。有符号溢出看高 n 位是不是低 n 位的符号扩展。

2025 年的 `idiv` 是 64 位被除数除以 32 位除数。`scov` 把 d[i] 按符号扩展成 64 位：高 32 位是 R 的初值，低 32 位是 Q 的初值。Y 装 32 位除数。计数器在控制逻辑里，数 32 轮。加减交替的每一轮，ALU 只做加法或减法；左移是移位器的事。

d[i]=87654321H 的最高位是 1，所以 R=FFFF FFFFH，Q=8765 4321H。上一题的 `x` 是 `int`，`0xff` 就是 255，Y=0000 00FFH。

除法异常有两种。除数是 0：x=0000 0000H，d[i] 任意。商溢出：d[i]=8000 0000H（−2^31），x=FFFF FFFFH（−1），商是 2^31，32 位补码放不下。响应时关中断，进入内核态，保存断点（PC 和 PSW），跳到异常处理程序。异常的分类留到第 10 关。

补码除法的上商和原码不是同一句口诀：被除数与除数同号先减，异号先加；余数与除数同号商 1、下一步减，异号商 0、下一步加；商的末位恒置 1，商本身就是补码。本关的分步表是原码。2025 没有要求把 32 轮走完，两套收尾不能混着套。

2020 年第 43 题里 x=2^31−1=7FFF FFFFH，y=2。乘积是 4294967294，64 位写成 0000 0000 FFFF FFFEH。两个操作数都是正数，有符号和无符号的 64 位模式相同。低 32 位 FFFF FFFEH 按无符号读仍是 4294967294，高 32 位为 0，`umul` 不溢出。同一串低 32 位按 `int` 读是 −2，高 32 位也不是符号扩展，`imul` 溢出。

2024 年的 A、B、C 都对，和 2020 年的三种做法是同一件事。D 错在「无法」。没有乘法指令时，编译器就是把两个变量的乘法编成那个循环。

2025 年的 Y 有几份回忆答案写成 FFFF FFFEH，或把 `0xff` 当成 8 位补码的 −1。题面里 `x` 的类型是上一题的 `int`，`0xff` 的值是 255，高位是 0。R 才是因为 d[i] 为负而符号扩展成全 1。

## 易错点

1. **Booth 的 n 不含符号，最后一次不移位。** 数值位 4 位就要判断 5 次、右移 4 次。把最后一次也右移，积会多移一位。有的书写法把符号算进位数、每步都移位，步数可以凑齐，表格的最后一行不一样。本关按王道的定点小数。
2. **乘数寄存器装 [y]补。** `+0.1011 × -0.1101` 的 [y]补 是 `1.0011`，不是原码 `1.1101`。用原码的数值位去套末两位，第一步的 10/01 就错了。正数看不出来，因为原码和补码相同。
3. **乘积丢掉乘数寄存器的最低位。** 经典例子结束时乘数是 `0.0010`，附加位是 1。低 4 位要取 0001。把 `0010` 或附加位一起拼进去，会得到 `1.01110010` 之类的错补码。
4. **原码逻辑右移，Booth 算术右移。** 部分积是 `11.0110` 时，Booth 右移高位补 1，变成 `11.1011`。这里若补 0，符号就被右移吃掉了。
5. **原码双符号位的 01 是进位。** `-0.1101 × +0.1011` 的第 2 步，加上 |x| 之后是 `01.0011`。把它当成负数，下一步的右移就会补错。
6. **原码有负零，补码没有。** `-0.0000 × +0.1101` 的原码积是 `1.00000000`，真值仍是 0。Booth 里负零就是 0，符号位不会单独留下来。
7. **加减交替看左移之前的符号。** `+0.0011 ÷ +0.1101` 的第 4 步，左移前余数是正的，左移后最高位变成 1。这一步仍然减 |y|。按左移之后的最高位去选择加或减，商会从这一位开始全错。
8. **末位负余数要加回 |y|，中间的不用。** `+0.0001 ÷ +0.0110` 最后余数是 `1.1110`，加回之后机器余数是 `+0.0100`，商仍是 `+0.0010`。中途出现的负余数如果也加回去，就退回了恢复余数法，步数也不再固定。
9. **真实余数要乘 2^(−n)。** 机器余数 `+0.0001` 不是 1/16。它被左移过 4 次，真实值是 +1/256。用机器余数直接去验算 `商×除数+余数`，等式对不上。
10. **余数与被除数同号。** `-0.1001 ÷ +0.1101` 的数值过程和正被除数相同，商是 `-0.1011`，真实余数是 −1/256。余数跟着除数走，验算会差一个符号。
11. **2020 年两份 64 位乘积相同，是因为操作数都是正数。** 8 位 `FFH×2` 立刻分开：无符号积 `01FEH`，低 8 位当 254，高 8 位不是 0，`umul` 溢出；补码积 `FFFEH`，低 8 位是 −2，高位是符号扩展，`imul` 不溢出。看见 2020 年「两份相同」就以为有符号和无符号乘法的位永远一样，下一题就会错。
12. **无符号溢出只看高 n 位。** 低 n 位即使是全 1，只要高 n 位全 0，也还在 0～2^n−1 里面。2020 年的低 32 位是 FFFF FFFEH，高 32 位是 0，所以 `umul` 不溢出。
13. **2025 年的 Y 是 0000 00FFH。** `x` 是 `int`，`0xff` 等于 255。把 `FFH` 当成 8 位的 −1，Y 会写成 FFFF FFFFH；再左移一位会写成 FFFF FFFEH。R 的全 1 来自 d[i] 的符号扩展，不是来自除数。
14. **ALUop 不含左移。** 除法器每轮要左移，但那是 R、Q 两个移位寄存器做的。ALU 这一拍只在加法和减法里选一个。计数器在控制逻辑里，不在 ALU 里。
15. **补码除法的末位恒置 1，原码是末位为负才加回除数。** 两套收尾换着用，最后一位商和最终余数都会错。2025 问的是初值和 ALU 做哪几种运算，没有要求按补码规则把商一位一位算完。

## 概念卡片参考答案

### 乘法电路

n 是数值位数。原码的部分积多一位进位，印出来是双符号位；移位仍是逻辑右移。

| 寄存器 | 开始时装什么 | 每一步 | 结束时 |
|---|---|---|---|
| 被乘数 | \|x\|，Booth 则是 [x]补（双符号位） | 不动 | 仍是被乘数 |
| 部分积 | 0 | 加上被乘数、[-x]补或 0，再右移 | 积的高位 |
| 乘数 | \|y\| 的数值位；Booth 是 [y]补，另有附加位 0 | 最低位决定本步操作，然后右移 | 积的低位 |
| 计数器 | 原码为 n；Booth 的判断次数为 n+1 | 每步减 1 | 到 0 结束 |

原码还有一个异或门，专门算积的符号。Booth 的符号已经在补码里，不再单设这个门。加法器的宽度和部分积一样。阵列乘法器把这 n 步展开成组合逻辑，里面没有计数器，也没有逐拍移位。

### 除法电路

原码定点小数：R 的初值是 |x|，Q 的初值是 0，Y 放 |y|。先试减一次，用来判断商会不会 ≥ 1。

| 寄存器 | 每一步 |
|---|---|
| R | 先左移，再按左移前的符号加 Y 或减 Y |
| Q | 和 R 一起左移，最低位写上这一步的商 |
| Y | 不动 |
| 计数器 | 初值 n，每步减 1 |

2025 年是 32 位补码整数除法，被除数先扩成 64 位。R 的初值是高 32 位，Q 的初值是低 32 位，Y 是 32 位除数。计数器在控制逻辑里。ALU 每轮只做加法或减法。

补码的上商换成：余数与除数同号商 1、下一步减；异号商 0、下一步加。末位商恒置 1。这和原码「末位为负才把除数加回去」是两套收尾。
