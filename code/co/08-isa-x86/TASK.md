# co/08 · 指令系统与 x86 汇编 · 题目

> 本文件只写题目，不含思路和代码，做题前可以放心看；答案讲解在 `ANSWER.md`，做完再看。

## 一、本关任务

- **产出**：扩展操作码能不能排下；各种寻址方式的有效地址；用 `clang` 读 32 位 x86，并和 arm64 的反汇编对照
- **小步骤**：
  ① 零地址、一地址、二地址、三地址指令各自把结果和下一条指令地址放在哪
  ② 给定指令字长、地址码位数和各类条数，检查扩展操作码是否可行，或求字长至少多少位
  ③ 计算有效地址。相对寻址用的 PC 是取指之后的值
  ④ 写 `if`、循环和函数调用，看栈帧、参数和条件转移用的标志
  ⑤ 同一个 C 函数分别编成 i386 和 arm64，对照指令长度和访存方式
- **通过标准**：能算出扩展操作码最多还有多少条、某种寻址方式的有效地址，并能根据一段 x86 说出对应的控制结构，或某条指令做完后寄存器里的值
- **概念卡片**（写进 `NOTES.md`）：指令集体系结构 ISA 规定什么；基址寻址和变址寻址怎么分

本关有两个程序：`main.c` 编出的主程序（如 `isa_x86_answer`）、`test.c` 编出的单元测试（`isa_x86_answer_test`）。

王道第 4 章指令系统。小步骤 ④⑤ 依赖本机的 `clang` 和 `objdump`，命令和一次实际输出在 `EXPERIMENTS.md`，不进 `tests/`。

输出里的地址写成 `0x` 开头。括号里的 `2008H` 是考卷写法，末尾的 H 表示十六进制。

扩展操作码要求短操作码不能是更长操作码的前缀：上一级没用完的操作码入口，才用来区分下一级。位移量按补码读。直接寻址的地址是无符号的。按字节编址时，指令字长要向上取整到 8 的倍数。

## 二、主程序题目（`main.c`）

读入命令，直到输入结束。每条命令打印一块推导，最后一行以 `结果：` 开头。`tests/` 里每组 `<用例>.in` 的输出必须与同名 `.out` 一致（行尾空白和首尾空行会被忽略）。

读之前用 `prompt(...)` 提示（`prompt` 在 `deps/prompt.h`，用法同 `printf`，跑测试时自动不打印）。可以连续输入多条命令，Ctrl+D 结束。

整数可以写成十进制、`0x` 开头，或末尾加 `H`。负号只出现在真值上，`90H` 这种带 H 的数是位模式，不是已经取过补的真值。

参数不合法时向 stderr 报错，并以非 0 退出。

### 命令

| 命令 | 输入 | 结果行里要有 |
|---|---|---|
| `kind` | 地址个数，0 到 4 | 结果写到哪，下一条指令地址从哪来 |
| `ext` | 字长、地址码位数、最高地址个数，然后从这一级往下每级一条数 | 可行，或不可行。最后一级写成 `-1` 时，给出这一级最多多少条 |
| `minlen` | 地址码位数、对齐位数、最高地址个数，然后各级条数 | 指令字长至少多少位。对齐位数填 `8` 表示按字节向上取整，填 `1` 表示不取整 |
| `direct` | 字长、指令条数、寻址方式种数 | 直接寻址的无符号范围。操作码位数和寻址方式位数都固定，各取能装下的最短位数 |
| `disp` | 字长、操作码位数、通用寄存器个数、指令里寄存器字段的个数 | 补码偏移量的最小值和最大值 |
| `rel` | 本条指令地址、指令字节数、位移位模式、位移位数、比例 | 目标地址。比例是一个位移单位里有几个编址单位 |
| `reloff` | 本条指令地址、指令字节数、目标地址、位移位数，后面可以再给机器码里的各字节 | 下一条指令的地址和偏移量。给了字节就判断大端还是小端 |
| `span` | 首字节地址、末字节地址 | 这段代码多少字节。末字节也算进去 |
| `iset` | 若干条指令各自的字节数 | 定长还是变长 |
| `arr` | 数组首址、元素地址、元素字节数 | 变址寄存器里的下标 |
| `operand` | 方式，再加该方式需要的数 | 有效地址和操作数。没有有效地址时只写操作数 |
| `jump` | 一条助记符 | 条件转移还是一定跳转。条件转移要写用哪些标志 |
| `x86` | 后面逐行写汇编，标签单独成行，最后一行只有一个 `.` | `eax` 和 ZF、SF、CF、OF，以及这段代码的结构 |

`ext` 的最高地址个数是 3、2、1 或 0。后面的条数依次是这一级、少一个地址的一级，直到你给出的最后一级。例如只有二地址、一地址、零地址时，最高地址个数填 `2`。

`operand` 的方式：

| 方式 | 后面的数 |
|---|---|
| `imm` | 立即数 |
| `reg` | 寄存器里的值 |
| `direct` | 形式地址 A，Mem[A] |
| `indirect` | A，Mem[A]，Mem[EA] |
| `regind` | 寄存器里的地址，Mem[EA] |
| `stack` | SP，Mem[SP] |
| `base` | 基址寄存器，形式地址（可负），Mem[EA] |
| `index` | 变址寄存器，形式地址，Mem[EA] |
| `both` | 基址，变址，形式地址，Mem[EA] |
| `rel` | 已经自增过的 PC，位移真值（可负），Mem[EA] |

`rel` 这条命令自己会先把 PC 加上指令长度。`operand rel` 认为你给的 PC 已经是下一条指令的地址。

`jump` 接受 `jmp`、`call`、`ret`、`je`、`jne`、`jz`、`jnz`、`jl`、`jle`、`jg`、`jge`、`jb`、`jbe`、`ja`、`js`、`jo`。

`x86` 是一台 32 位玩具机，寄存器有 `eax ecx edx ebx esp ebp esi edi`。栈向低地址增长，`dword` 按 4 字节对齐存放。每条指令在玩具机里占 4 字节，只为了让 `call` 有一个返回地址；真题里的 x86 是变长的，字节数用 `span` 和 `iset` 算。方括号里不要加空格。能写的形式：

```
mov eax, 5
mov eax, ecx
mov eax, dword ptr [ebp+8]
mov dword ptr [ebp-4], eax
add eax, ecx
add eax, 1
sub eax, 1
cmp eax, 3
cmp dword ptr [ebp+8], 1
shl edx, 1
imul eax, ecx
push eax
push 7
pop ebp
jmp label
jle label
call label
ret
label:
```

标签必须单独占一行，而且下一行得是指令。结构行只区分顺序、条件分支、循环、过程调用。向前的条件跳转记成条件分支，向后的跳记成循环。

### 样例

输入：

```
rel 2000H 2 06H 8 1
```

输出：

```
【相对寻址】
本条指令地址 0x2000（2000H），长度 2 字节。取指时 PC 按指令长度增加
取指后的 PC = 0x2002（2002H）
位移是 8 位补码，位模式 0x06，真值 6。比例 1：一个位移单位含 1 个编址单位
目标 = 取指后的 PC + 真值×比例
结果：目标地址 0x2008（2008H）
```

这就是 2009 年第 16 题的数据。

### 2009-17

相对 CISC，RISC 的特点是：指令条数少，指令长度固定，指令格式和寻址方式种类少；只有取数、存数指令访问存储器；通用寄存器多；大部分指令在一个时钟周期内完成；以硬布线控制为主。据此判断「RISC 普遍采用微程序控制器」这一说法是否成立。

某程序中有如下循环代码段 P：「`for (int i=0; i<N; i++) sum += A[i];`」。假设编译时变量 sum 和 i 分别分配在寄存器 R1 和 R2 中，常量 N 在寄存器 R6 中，数组 A 的首地址在寄存器 R3 中。程序段 P 起始地址为 08048100H，对应的汇编代码和机器代码如下表所示。
