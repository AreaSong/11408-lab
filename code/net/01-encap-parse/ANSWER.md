## 思路

上层的 PDU 到了下层就是 SDU。下层加上自己的首部（协议控制信息），得到本层的 PDU。这一关的四层是：

| 层 | PDU | 本关加上的首部 |
|---|---|---|
| 应用层 | 报文 | HTTP 请求本身，不再加首部 |
| 传输层 | 报文段 | TCP 20 字节。数据偏移的单位是 4 字节，5 就是 20 |
| 网络层 | IP 数据报（分组） | IPv4 20 字节。IHL 的单位也是 4 字节 |
| 数据链路层 | 帧 | 以太网 14 字节：目的 MAC、源 MAC、类型。FCS 4 字节本关不写 |

链路上先出现的是目的 MAC。目的 IP 若在别的网络，这一跳的目的 MAC 填默认网关，不填目的主机。源 MAC 是发出这一帧的接口；路由器转发时两头的 MAC 都换成新的一跳，普通转发不改 IP 地址。

多字节字段不能把主机上的整数直接叠进结构体。这台机器是小端，`0x0800` 若按主机序放进内存会变成字节 `00 08`。`write_be16` 把高字节放在低地址，和 `htons` 的结果相同，单测里对过。

IP 首部校验和只覆盖 IP 首部：校验和字段先当 0，16 位一组做反码求和，进位折回低 16 位，再按位取反。TCP 还要加 12 字节伪首部（源 IP、目的 IP、0、协议 6、TCP 长度）。伪首部不出现在线上。算出 0 时 TCP 改记成 `0xffff`，因为全 0 留不出“这个字段有意义”和“没算”的区别；UDP 才用 0 表示不算。

以太网数据字段最少 46 字节，整帧加 FCS 最少 64 字节。IP 总长度小于 46 时，0 填在 IP 数据报后面，不放进总长度，解析时也不能当成应用层数据。给出的字节若正好比“不含 FCS 的完整帧”多 4 字节，多出来的按 FCS 看待，本关不校验 CRC。

pcap 的魔数 `0xa1b2c3d4` 用小端写入时，文件前 4 字节是 `d4 c3 b2 a1`。这和帧的大端相反。链路类型 1 才是以太网；macOS 上 `lo0` 是 0，前面有 4 字节地址族，不能按 MAC 去拆。

## 真题对照

### 2011-47

80 字节的布局：以太网 14 + IP 20 + TCP 20 = 54，应用层只露出 26 字节。IP 总长度 `0x01ef` = 495，所以不含 FCS 的完整帧是 14 + 495 = 509 字节，缺的 429 字节全是 `GET /rfc.html` 后面的报文。

| 问 | 从帧里读到的 | 答案 |
|---|---|---|
| （1）Web 服务器 IP | 目的 IP，偏移 30，`40 aa 62 20` | 64.170.98.32 |
| （1）默认网关 MAC | 目的 MAC，前 6 字节 | 00-21-27-21-51-ee |
| 源 IP | `0a 02 80 64` | 10.2.128.100，和题干一致 |
| 端口 | TCP 前 4 字节 `04 ff`、`00 50` | 源 1279，目的 80 |
| TTL、协议 | IP 首部第 9、第 10 字节 `80`、`06` | TTL 128，协议 TCP |
| 首部校验和 | 重算得到 `0xba9d` | 与字段一致 |

数到目的 IP 的方法和标准解答相同：以太网首部 6+6+2 = 14，IP 首部里目的 IP 前面还有 16 字节，14+16 = 30。从第 1 个字节向后数完这 30 个，下一个才是目的 IP，也就是第 31 个字节。图左侧的 `0000` 不是帧。

（2）确定目的 MAC 用 ARP。请求要让本网段上所有接口都收到，以太网目的 MAC 是 `FF-FF-FF-FF-FF-FF`。主机要解析的是默认网关 10.2.128.1，不是 Web 服务器：服务器不在这根链路上，ARP 出不去。

（3）6 个 RTT。这帧的标志是 PSH+ACK，不是 SYN，题目又说从发出这个 Web 请求开始，三次握手不要加进去。HTTP/1.1 持续非流水线：先用 1 个 RTT 取回 rfc.html，之后 5 个 JPEG 各用 1 个 RTT，必须等前一个响应回来才能发下一个请求。1+5 = 6。流水线才是把多个请求接连发出去。

（4）经过 R 时一定改的字段：

- 源 IP：`10.2.128.100`（`0a 02 80 64`）改成 R 的公网地址 `101.12.123.15`（`65 0c 7b 0f`）
- TTL：128 减 1
- 首部校验和：源 IP 和 TTL 都变了，必须重算

目的 IP 不变，它已经是公网地址。本题的标准答案不改端口；端口一起变的是 NAPT，第 08 关再做。IP 总长度 495，小于以太网 MTU 1500，所以总长度、标志、片偏移这次不变。标准解答仍写了一句：若分组长过输出链路的 MTU，这三个字段也要改。

`tcpdump -r` 对本关自己构造的那一帧给出 `cksum 0x49f9 (correct)`，和程序印的 TCP 校验和相同。见 `EXPERIMENTS.md`。

## 易错点

1. **目的 MAC 不是 Web 服务器的 MAC**。2011 的前 6 字节是默认网关。把目的 IP 的主机当成这一跳的接收者，第（1）问的 MAC 就错了。
2. **图的偏移列不要算进帧**。把 `0000` 当成第一组字节，后面的 IP 和端口全部错位。
3. **第 31 个字节和偏移 30 是同一个位置**。从 0 起是偏移，从 1 起是“第几个”。标准解答说“数 30 字节，得目的 IP”，指的是数完 30 个之后的那个字节。
4. **大端**。`01 ef` 是 495，不是 `0xef01`。端口 `04 ff` 是 1279，不是 0xff04。
5. **IHL 和 TCP 数据偏移的单位是 4 字节**。写成“IHL = 5 所以首部 5 字节”，TCP 首部的起点就错了。
6. **校验和的一个字常常跨两个字段**。样例里 `4006` 是 TTL `0x40` 和协议 `0x06` 拼出来的，标志是它前面的 `4000`。2011 里对应的字是 `8006`：TTL 128，协议 6。
7. **IP 校验和不加伪首部，TCP 要加**。伪首部不传输。把 IP 的算法套到 TCP 上，和字段对不上。
8. **填充不在 IP 总长度里**。`Hi` 那一帧总长度 42，帧长 60：多出来的 4 个 0 是以太网填充。把它读成应用层数据，报文就变长了。
9. **FCS 也不在 IP 总长度里**。给出的长度比不含 FCS 的帧正好多 4，才把末尾当 FCS。2011 只给了 80 字节，里面没有 FCS。
10. **类型和协议不是同一个字段**。`0x0800` 在以太网首部，表示里面是 IPv4。`6` 在 IP 首部，表示里面是 TCP。
11. **端口在 TCP 首部**。IP 首部只有地址，没有端口。
12. **2011 的两个 429 是同一段**。完整帧 509 减给出的 80 是 429；应用层 455 减看见的 26 也是 429。首部已经齐了，缺的全是报文尾部。
13. **第（3）问不要加握手，也不要按非持续连接来算**。从 GET 起算，持续非流水线是 6。答 7 是把建立连接算进去了；答 2 是记成了流水线。
14. **第（4）问不要改目的 IP，也不要主动改端口**。变的是私有源 IP、TTL、校验和。
15. **`lo0` 抓到的不是以太网帧**。链路类型 0，前面是地址族。要看 MAC，用 `en0` 这类以太网接口。

## 概念卡片参考答案

### 卡片一：分层

分层是为了把一个大问题拆开：每一层只使用下层提供的服务，只通过服务访问点（SAP）交数据，某一层内部怎么实现可以换，只要上下的接口不变。

数据从上往下走叫封装，从下往上走叫拆封装。第 n 层的 PDU 到了第 n−1 层，变成第 n−1 层的 SDU，再添上第 n−1 层的首部。

### 卡片二：协议、接口、服务

| | 协议 | 接口 | 服务 |
|---|---|---|---|
| 谁和谁 | 同一层的对等实体 | 相邻层 | 下层对上层 |
| 方向 | 水平 | 垂直 | 垂直 |
| 是什么 | 通信规则：语法、语义、同步 | 交换信息的地点和格式 | 下层能替上层完成的功能 |

协议是水平的，服务是垂直的。服务访问点在传输层体现为端口，在网络层体现为用来交付的地址。OSI 的服务原语有请求、指示、响应、证实。服务可以是面向连接的，也可以是无连接的；这是服务的性质，不是协议报文本身。

### 卡片三：三种模型

| OSI 七层 | 五层（王道用来讲） | TCP/IP 四层 | 本关看到的 |
|---|---|---|---|
| 应用层 | 应用层 | 应用层 | HTTP 报文 |
| 表示层 | 并进应用层 | 并进应用层 | |
| 会话层 | 并进应用层 | 并进应用层 | |
| 传输层 | 传输层 | 传输层 | TCP 报文段 |
| 网络层 | 网络层 | 网际层 | IP 数据报 |
| 数据链路层 | 数据链路层 | 网络接口层 | 以太网帧 |
| 物理层 | 物理层 | 网络接口层 | 比特 |

五层模型是把 TCP/IP 的网络接口层拆开，又把 OSI 上面三层合成应用层。考试问“TCP/IP 有几层”时答四层；问各层 PDU、设备工作在哪一层时，按五层来答和王道一致。

### 卡片四：PDU 和设备

| 层 | PDU | 拆到这一层的设备 |
|---|---|---|
| 应用层 | 报文 | 应用层网关 |
| 传输层 | TCP 叫报文段；UDP 叫用户数据报 | 传输层网关能看端口 |
| 网络层 | 分组，IP 的分组也叫数据报 | 路由器。转发时看 IP，TTL 减 1 |
| 数据链路层 | 帧 | 网桥、交换机。转发时看 MAC |
| 物理层 | 比特 | 中继器、集线器。不看地址，只放大信号 |

设备拆到哪一层的头，就工作在哪一层。交换机不看 IP，路由器不根据 MAC 选择下一条链路（它只是在选好的出口上重新填 MAC）。
