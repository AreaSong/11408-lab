> 王道第 1 章。帧里的多字节整数是网络字节序（大端）。以太网 II 的类型字段：大于等于 `0x0600` 是类型，小于等于 1500 是 IEEE 802.3 的长度。本关构造的帧不含 4 字节 FCS。

## 一、本关任务

- **产出**：把一句 HTTP 请求封装成 TCP 报文段、IP 数据报、以太网帧，逐字段、逐字节打印；再把一段帧的十六进制从外向里拆开。另有一个程序读经典 pcap 文件
- **小步骤**：
  ① 用结构体表示以太网首部、IPv4 首部、TCP 首部，多字节字段按字节写入
  ② 封装：应用层报文外面依次加上 TCP 首部、IP 首部、以太网首部
  ③ 解析：给出帧的十六进制，读出源/目的 MAC、源/目的 IP、端口、TTL、协议
  ④ 读 pcap。抓真实的包依赖本机网卡，步骤和本机输出写在 `EXPERIMENTS.md`，不进 `tests/`
- **通过标准**：能说出每层首部的关键字段和长度；2011-47 这帧的目的 IP、目的 MAC、源 IP、端口、TTL、协议与标准答案一致
- **概念卡片**（写进 `NOTES.md`）：分层结构；协议、接口、服务（协议水平，服务垂直）；OSI 七层、TCP/IP 四层、五层模型；各层 PDU 的名称

每个项目有三个程序：`main.c` 编出的主程序（与项目同名，如 `encap_parse_first`）、`test.c` 编出的单元测试（`encap_parse_first_test`）、`pcap.c`（`encap_parse_first_pcap`）。

读入前用 `prompt(...)` 打印提示（`prompt` 在 `deps/prompt.h`，用法同 `printf`，跑测试时自动不打印）。可以连续输入多条命令，Ctrl+D 结束。命令之间的输出空一行。

## 二、主程序题目（`main.c`）

### 命令

| 命令 | 接着读什么 |
|---|---|
| `encap` | 四行：应用层报文；目的 MAC、源 MAC；源 IP、目的 IP、TTL、标识；源端口、目的端口、序号、确认号、标志、窗口 |
| `parse` | 一行字节数，再是恰好这么多个两位十六进制字节 |

`encap` 固定这些值，输入里不要给：版本 4，IHL = 5，区分服务 0，协议 6（TCP），DF = 1、MF = 0、片偏移 0，TCP 数据偏移 5，紧急指针 0，以太网类型 `0x0800`。FCS 不计算。IP 总长度小于 46 字节时，帧的数据字段用 0 填到 46 字节；填充不算进 IP 总长度。

应用层报文占一整行。这一行里的 `\r`、`\n`、`\t`、`\\`、`\xHH` 会转义，所以 HTTP 的回车换行写成 `\r\n`。空行表示报文长度是 0。

MAC 写成 `00-11-22-33-44-55` 或冒号分隔，先目的、后源。IP 用点分十进制。TTL 是 0 到 255。标识、端口、窗口是 0 到 65535。序号和确认号是 0 到 2³²−1，可以写成十进制或 `0x` 开头的十六进制。标志用逗号隔开：`fin` `syn` `rst` `psh` `ack` `urg`，全都不置写 `none`。

`parse` 的每个字节必须是两位十六进制，中间用空白隔开。题目图里行首的 `0000`、`0010` 是偏移，不是帧的内容，不要输入。字节数要在 14 到 1600 之间。

### 样例

输入：

```
encap
GET / HTTP/1.1\r\n
00-11-22-33-44-55 00-aa-bb-cc-dd-ee
192.168.1.2 192.168.1.1 64 1
50000 80 1 0 psh,ack 8192
```

输出：

```
【分层封装】
应用层 PDU 是报文。这次的报文 16 字节，交给传输层。
传输层 PDU 是报文段。TCP 首部 20 字节，报文段 = 20 + 16 = 36 字节。
网络层 PDU 是 IP 数据报（分组）。IPv4 首部 20 字节，总长度 = 20 + 36 = 56 字节。
数据链路层 PDU 是帧。以太网首部 14 字节：目的 MAC 6 + 源 MAC 6 + 类型 2。
物理层 PDU 是比特。帧在链路上先写目的 MAC，再写源 MAC。
FCS 4 字节由网卡按 CRC 填写，本关不计算，第 03 关再做。
以太网数据字段最少 46 字节。IP 总长度 56 字节，已经够长，填充 0 字节。
不含 FCS 的帧长 = 14 + 56 = 70 字节。含 FCS 的最短帧是 64 字节。
【以太网首部】14 字节，帧内偏移 0（第 1 个字节起）
目的 MAC = 00-11-22-33-44-55（6 字节）
目的 MAC 是同一条链路上的下一跳。目的 IP 在别的网络时，下一跳是默认网关，这里填的就不是目的主机的 MAC。
源 MAC = 00-aa-bb-cc-dd-ee（6 字节，帧内偏移 6，第 7 个字节起）
源 MAC 是发出这一帧的接口。路由器转发时换成自己出接口的 MAC。
类型 = 0x0800（IPv4）。大于等于 0x0600 是以太网 II 的类型，小于等于 1500 是 IEEE 802.3 的长度。
【IPv4 首部】20 字节，帧内偏移 14（第 15 个字节起）
版本 = 4，首部长度 IHL = 5，即 5 × 4 = 20 字节
区分服务（旧称 TOS）= 0
总长度 = 56 字节。这是 IP 首部加数据，不含以太网首部，也不含后面的填充。
标识 = 0x0001
标志与片偏移 = 0x4000：保留 = 0，DF = 1，MF = 0，片偏移 = 0
片偏移的单位是 8 字节。分片的长度和偏移在第 07 关再算。
TTL = 64，帧内偏移 22（第 23 个字节）。每经过一个路由器减 1。
协议 = 6（TCP），帧内偏移 23（第 24 个字节）。6 是 TCP，17 是 UDP，1 是 ICMP。
源 IP = 192.168.1.2（c0 a8 01 02），帧内偏移 26（第 27 个字节起）
目的 IP = 192.168.1.1（c0 a8 01 01），帧内偏移 30（第 31 个字节起）
数到目的 IP：以太网首部 14 + IP 首部里它前面的 16 字节 = 30，所以它从第 31 个字节开始。
首部校验和：字段先按 0000 参加求和，不加伪首部。
4500 + 0038 + 0001 + 4000 + 4006 + 0000 + c0a8 + 0102

【TCP 首部】20 字节，帧内偏移 34（第 35 个字节起）
源端口 = 50000，目的端口 = 80（HTTP）。端口在 TCP 首部，不在 IP 首部。
序号 = 0x00000001，确认号 = 0x00000000
数据偏移 = 5，即 5 × 4 = 20 字节
标志字节 = 0x18：保留高 2 位 = 0，URG=0 ACK=1 PSH=1 RST=0 SYN=0 FIN=0
窗口 = 8192 字节，紧急指针 = 0

伪首部：c0a8 + 0102 + c0a8 + 0101 + 0006 + 0024

## 三、pcap 程序（`pcap.c`）

| 命令 | 接着读什么 |
|---|---|
| `pcap` | 一行字节数，再是整个 pcap 文件的十六进制 |
| `file` | 一行文件路径，读 `tcpdump -w` 写成的文件 |

只认经典 pcap（魔数 `0xa1b2c3d4` 或纳秒精度的 `0xa1b23c4d`），不认 pcapng。链路类型是 1 时，每个数据包按以太网帧交给和主程序一样的拆帧。最多打印 8 个数据包。

`tests/pcap/practice-one` 是把 `practice-pad` 那一帧装进 pcap 之后的 100 个字节。真实抓包见 `EXPERIMENTS.md`。

## 四、真题题面

### 2011-47（9 分）

某主机的 MAC 地址为 00-15-C5-C1-5E-28，IP 地址为 10.2.128.100（私有地址）。题 47-a 图是网络拓扑，题 47-b 图是该主机进行 Web 请求的 1 个以太网数据帧前 80 个字节的十六进制及 ASCII 码内容。

图 47-a（文字转写，原题是图）：主机接在路由器 R 的局域网一侧，默认网关是 10.2.128.1。R 的公网地址是 101.12.123.15，另一侧经因特网连到 Web 服务器。

```

请参考图中的数据回答以下问题。

（1）Web 服务器的 IP 地址是什么？该主机的默认网关的 MAC 地址是什么？

（2）该主机在构造题 47-b 图的数据帧时，使用什么协议确定目的 MAC 地址？封装该协议请求报文的以太网帧的目的 MAC 地址是什么？

（3）假设 HTTP/1.1 协议以持续的非流水线方式工作，一次请求-响应时间为 RTT，rfc.html 页面引用了 5 个 JPEG 小图像，则从发出题 47-b 图中的 Web 请求开始到浏览器收到全部内容为止，需要多少个 RTT？
