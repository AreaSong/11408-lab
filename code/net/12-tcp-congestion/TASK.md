> 王道第 5 章。超时重传时间用加权平均往返时间 RTTs 和偏差 RTTD。发送窗口 = min(拥塞窗口, 接收窗口)。慢开始每个新确认加 1 个 MSS，一轮发满就看起来翻倍；拥塞窗口达到门限后每个 RTT 加 1 个 MSS。超时把门限减半、拥塞窗口重置为 1 个 MSS。连续 3 个重复确认走快恢复：门限减半，拥塞窗口设成新门限。

## 一、本关任务

- **产出**：超时重传时间计算器；流量控制模拟（含零窗口和持续计时器）；拥塞控制模拟器，每个 RTT 打印拥塞窗口和慢开始门限
- **小步骤**：
  ① 超时重传。第一次样本：RTTs 取样本，RTTD 取样本的一半。之后 α = 1/8，β = 1/4，RTO = RTTs + 4 × RTTD。重传过的样本不更新估计，RTO 翻倍
  ② 流量控制。发送窗口还要扣掉已发送未确认的字节。接收窗口变成 0 就启动持续计时器，到期发 1 字节探测
  ③ 拥塞控制。慢开始、拥塞避免、超时、3 个重复确认和快恢复。trace 里每一轮都有 cwnd 和 ssthresh
  ④ 发送窗口 = min(接收窗口, 拥塞窗口)
- **通过标准**：下面真题的结果行与标准答案一致
- **概念卡片**（写进 `NOTES.md`）：可靠传输靠什么；流量控制和拥塞控制；四个计时器；慢开始、拥塞避免、快重传、快恢复

每个项目有四个程序：`main.c`（如 `tcp_congestion_first`）、`test.c`（`tcp_congestion_first_test`）、`rto.c`（`tcp_congestion_first_rto`）、`flow.c`（`tcp_congestion_first_flow`）。

## 二、主程序题目（`main.c`，拥塞窗口）

一次运行里只有一条连接。`mss` 先设，而且只能设一次。窗口和缓存都要是 MSS 的整数倍。

| 命令 | 作用 |
|---|---|
| `mss <长度>` | 最大段长 |
| `rtt <时间>` | 往返时间。算「至少要多久」时才需要 |
| `buf <长度>` | 接收缓存。应用不读，通告窗口 = 缓存 − 已用。和 `rwnd` 只能设一个 |
| `rwnd <长度>` | 固定通告窗口。每个确认都报这个值，不随缓存变小 |
| `seq <序号>` | 下一个待发送数据字节的序号。2016 的第一段数据是 101 |
| `init <拥塞窗口> <门限>` | 设初始 cwnd 和 ssthresh。只能设一次 |
| `timeout` | 超时。门限改为 cwnd 的一半（按 MSS 个数向下取整，不足 2 个 MSS 时抬到 2 个），cwnd 改为 1 个 MSS |
| `round [n]` | 连续 n 个成功的 RTT，缺省 1。一轮开始时在途数据必须已经确认完 |
| `send` | 把当前发送窗口里能发的整段 MSS 放进在途，先不确认 |
| `ack [n]` | 确认 n 个在途 MSS，缺省 1。慢开始时每个确认加 1 个 MSS |
| `dup` | 一个重复确认。第 3 个触发快重传和快恢复 |
| `until cwnd <长度>` | 做成功的 RTT，直到拥塞窗口达到目标 |
| `until swnd <长度>` | 直到发送窗口达到目标 |
| `stall` | 一直发到发送窗口为 0。要先有 `buf`、`rtt` 和 `seq` |

一轮开始时，cwnd < ssthresh 走慢开始：这一轮发出去多少，cwnd 就加多少，但不超过门限。cwnd 已经大于或等于门限时走拥塞避免：这一轮只要发出了数据，结束时 cwnd 加 1 个 MSS。发送窗口每轮都重新取 min(cwnd, 接收窗口)。接收窗口不限时，发送窗口等于拥塞窗口。

`tests/practice-cap` 用自编数据看门限如何截住翻倍。`tests/practice-fast` 看 3 个重复确认。真题在 `tests/2009-39`、`2014-38`、`2015-39`、`2016-41`、`2016-41-rate`、`2017-39`、`2020-38`、`2022-38`。

2017-39 的题面没有初始门限，`tests/2017-39` 把门限设成和接收缓存一样的 64 KB。2020-38 问的是最长时间，`tests/2020-38` 让门限等于当时的拥塞窗口。为什么这样设，见 `ANSWER.md`。

结果行：

| 命令 | 结果行 |
|---|---|
| `init` / `round` | `结果：拥塞窗口 9 KB，发送窗口 9 KB` |
| `timeout` | `结果：门限 8 KB，拥塞窗口 1 KB` |
| `until` | 有 RTT 时 `结果：5 RTT，25 ms`，否则 `结果：11 RTT` |
| `ack` | `结果：接收窗口 12 KB，拥塞窗口 9 KB，发送窗口 9 KB` |
| `dup` 未满 3 个 | `结果：重复确认 2 个` |
| `dup` 满 3 个 | `结果：门限 8 KB，拥塞窗口 8 KB` |
| `stall` | `结果：序号 20581，5 RTT，速率 20 KB/s（163.84 kbit/s）` |

## 三、超时重传程序（`rto.c`）

α 固定 1/8，β 固定 1/4。时间用秒打印，0.75 s 不要写成 750 ms。

| 命令 | 作用 |
|---|---|
| `init <时间>` | 还没有样本时，超时重传时间先取这个值 |
| `sample <时间>` | 一个新的 RTT 样本 |
| `rexmit` | 发生一次超时重传。RTO 翻倍，下一个 `sample` 不更新 RTTs 和 RTTD |

第一次 `sample` 把 RTTs 设成样本，RTTD 设成样本的一半，RTO = RTTs + 4 × RTTD。连接开始时先放的那个值被这次测量换掉。以后先更新 RTTs，再用新的 RTTs 和样本的差去更新 RTTD。

`tests/rto/practice-sample` 用谢希仁习题 5-33 的 6 s、1.5 s、2.5 s。统考没有直接考这组小数。`tests/rto/practice-karn` 在同一组数之后再重传一次。

结果行是超时重传时间，例如 `结果：4.5 s`。

## 四、流量控制程序（`flow.c`）

| 命令 | 作用 |
|---|---|
| `mss <长度>` | 最大段长。零窗口那组用来对齐段长，2010-39 可以不参与窗口计算 |
| `cwnd <长度>` | 拥塞窗口 |
| `buf <长度>` | 接收缓存。设了之后，发送方一开始就知道窗口等于缓存 |
| `seq <序号>` | 下一个发送序号 |
| `send <长度>` | 发出这么多字节，进入在途。接收窗口是 0 时拒绝 |
| `ack <长度> [rwnd <长度>]` | 确认这么多在途字节。写了 `rwnd` 就采用通告值；没写而且有缓存，就用缓存剩的空位 |
| `read <长度> [lose]` | 应用读走缓存。`lose` 表示新的窗口通告丢了，发送方仍用旧窗口 |
| `probe` | 持续计时器到期，发 1 字节探测 |

还能发送 = 发送窗口 − 已发送未确认。发送窗口 = min(拥塞窗口, 接收窗口)。接收窗口还没通告时，先只受拥塞窗口限制。

`ack` 的结果行是还能发送的字节数，例如 `结果：1000 字节`。`probe` 的结果行是探测之后通告的接收窗口。

`tests/flow/2010-39` 是真题。`tests/flow/practice-zero` 和 `tests/flow/practice-probe` 是自编的零窗口：缓存 300 字节，三段 100 字节把它填满。前者应用读走 300 字节但通告丢失，探测被收下；后者探测时窗口仍是 0。
