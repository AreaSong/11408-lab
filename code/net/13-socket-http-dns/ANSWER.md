## 思路

### 一个对象为什么是 2 个 RTT

客户发 SYN，服务器回 SYN+ACK，这一个来回把连接建立起来。客户的第三个 ACK 可以夹着 GET 一起走，所以握手不要算成 1.5 个 RTT，更不要把四次挥手算进「收完内容」。对象很小的时候，发出请求到收完响应再算 1 个 RTT。一个对象就是 2 个 RTT。

HTML 自己也是一个对象。没拿到它，不知道后面还有几张图，所以图不能和 HTML 并行，也不能跟 HTML 挤在同一次请求里。

N 是引用对象的个数：

| 方式 | 从建立连接算起 |
|---|---|
| 非持久，串行 | 2(1+N) |
| 非持久，最多 M 条并行 | 2 + 2⌈N/M⌉ |
| 持久，非流水线 | 2 + N |
| 持久，流水线 | 有引用对象时是 3，没有时是 2 |

`from request` 表示时钟从那个已经发出的 GET 开始。HTML 只剩响应的 1 个 RTT，上面各式里开头的 2 改成 1。2011 就是这种算法。

`dns` 写在最前面，和 HTTP 的 RTT 相加。解析还没做完时，主机一直在等，这段时间要算进去。

### 2022 的图像为什么要两个 RTT

HTTP/1.1 默认持久、非流水线，题目又没说流水线。连接只建一次。王道的慢开始从 1 个 MSS 起，不采用 RFC 6928 的初始窗口 10。每个新确认让窗口加 1 个 MSS；这一轮把整个窗口都发出去时，看起来才是翻倍。

| 轮 | 发生的事 | 窗口 |
|---|---|---|
| 1 | 建立连接 | 还没有数据，窗口 1 MSS |
| 2 | HTML 1 MSS | 1 个确认，窗口变成 2 |
| 3 | 图像先发 2 MSS | 2 个确认，窗口变成 4 |
| 4 | 图像剩下 1 MSS | 只有 1 个确认，窗口变成 5，不是 8 |

4 个 RTT × 10 ms = 40 ms。最后一轮没发满，不能按「翻倍」把它写成 8。这一轮结束时窗口是多少，题目没有问，时间已经由 4 个 RTT 决定了。

就算第三个 ACK 不夹带 GET，握手 1 个 RTT、HTML 1 个 RTT、图像仍然要 2 个 RTT，总数还是 4。这道题的差别在 3 MSS 发不完，不在捎带。

### 递归和迭代

实际系统里，主机到本地域名服务器几乎总是递归：主机发 1 条，然后干等。本地域名服务器再到根，通常改成迭代，自己一跳一跳问。2010 考的不是这个混合过程，题干写的是「采用递归方法」，本地也只向上发 1 条，根再替它问顶级，顶级再问权威。

谢希仁那张图是根、顶级、权威三级。两种方式都是 4 个来回、8 条 UDP 报文。差在箭头连在谁身上：迭代是星形，每条查询都从本地发出去；递归是一条链，本地只接触根。

| 缓存 | 主机发出 | 本地发出 | 三级时的报文总数 |
|---|---|---|---|
| 无，递归 | 1 | 1 | 8 |
| 无，迭代 | 1 | 3 | 8 |
| 主机自己有记录 | 0 | 0 | 0 |
| 本地已有 IP | 1 | 0 | 2 |

2016 的名字有四截：`www`、`abc`、`xyz`、`com`。最坏时每一截都单独成区，本地要迭代问根、com、xyz.com、abc.xyz.com，共 4 条。`www` 是区内的主机记录，没有第五台服务器。加上主机和本地之间的一来一回，查询 5 条、响应 5 条，共 10 条。题目问的只是这台域名服务器自己发出的次数。

### HTTP 报文和 Cookie

请求报文分四段：请求行（方法、路径、版本），首部行，一个空行，然后才是实体。2015 这份没有实体。`Host` 指出站点，`Connection: close` 表示这份响应之后把 TCP 拆掉，`Cookie` 是浏览器主动带回来的。

HTTP 本身无状态，服务器不记得你是谁。`Set-Cookie` 让浏览器下次把 `visit=N` 放进请求，次数才加得上去。状态在客户端那张纸条上，不在协议里。`Path=/` 是为了下一次访问这个站点的页面时仍然带上它；取 `/a.txt` 时就算带上了，服务器也不改这个数。

## 真题对照

### 2010-40

选 A。用户主机 1 条，本地域名服务器 1 条。

无缓存、递归、名字在另一个网络，所以本地自己答不了，但它只向根发 1 条递归查询，后面的顶级和权威由根这条链去问。主机不会自己改去问根。选项 B 是把「实际的迭代」当成了题干里的递归。

`tests/dns/2010-40` 的结果行是 `主机 1 条，本地域名服务器 1 条，共 8 条`。前两个数是选项，8 是三级服务器的查询加响应，题目没问。

### 2011-47（3）

6 个 RTT。

那一帧的标志是 PSH+ACK，数据里已经是 `GET /rfc.html`，三次握手在这之前。持续、非流水线：页面响应 1 个 RTT，5 个 JPEG 必须等前一个响应回来才发下一个，各 1 个 RTT。1+5 = 6。第 01 关的讲解是同一个数，那里没有程序去算。

### 2015-40

错误的是 C。

`Connection: close` 是非持续，持续连接要写 `keep-alive`。HTTP/1.1 默认虽然持续，这行首部把它改掉了。A 看请求行的路径，B 看 `Host`，D 看 `Cookie`：这张纸条是服务器以前发给浏览器的，请求里带着，说明以前来过。`tests/req/2015-40` 的结果行是 `非持续连接，有 Cookie`。

### 2016-40

选 C。最少 0 次，最多 4 次。

问的是域名服务器 201.1.1.1 发出的查询。主机缓存里已经有记录时，这台服务器收不到查询，是 0。它自己的缓存里已经有 IP 时，也是 0。两种「最少」都对得上选项里的 0。

无缓存、迭代、四个标号都可能成区：根、com、xyz.com、abc.xyz.com，是 4。问到 xyz.com 就停，会得到 3，那是选项 A、B 的「最多」。

有的解析把 4 次理解成「主机问本地 1 次，本地再问 3 次」，并且把 xyz.com 当成最后一站。选项碰巧仍是 C，但主机发出的那 1 次不能算在 201.1.1.1 头上。`tests/dns/2016-40` 的两个结果行是本地 0 条和本地 4 条。

### 2022-40

选 B。40 ms。

域名已经解析完，DNS 不加。持久连接，初始窗口 1 MSS。建立连接 1 个 RTT，HTML 1 个 RTT，图像 3 MSS 分成 2 MSS 和 1 MSS 两个 RTT。4 × 10 ms = 40 ms。

30 ms 是把 3 MSS 当成一轮就能发完，初始窗口若按 10 也会得到这个数。50 ms 是 3 个 MSS 各占 1 个 RTT，再加握手和 HTML。本关按王道，窗口从 1 开始，每个确认加 1 个 MSS。

### 2024-40

选 D。16 个 RTT。

1 个 HTML 加 7 个小图像，共 8 个对象。非持久、不能并行，每个对象 2 个 RTT，8 × 2 = 16。从建立连接算起，DNS 不在这段里。

9 是持久非流水线的 2+7，14 是只算了 7 张图、漏了 HTML 的 2 个 RTT。有的回忆解析把 16 拆成「8 次建连加 8 次关闭」。题干收到内容为止，挥手不算。数字碰巧相同，过程不是这一关用的算法。`tests/practice-modes` 对同一页打出 16、9、3：非持久、持久非流水线、流水线。

## 易错点

1. **收完内容不算挥手。** 2024 的 16 来自 8 个对象各 2 个 RTT。把 FIN 再数一遍，过程就和王道不一致了。
2. **第三个 ACK 可以夹着 GET。** 一个对象是 2 个 RTT，不是 3 个。本机这次 curl 把 GET 放在了空 ACK 后面的另一个段里，见 `EXPERIMENTS.md`。考场仍按 2 个 RTT，不把那个空 ACK 再加进去。
3. **图不能和 HTML 一起并行。** 非持久开 M 条连接，先单独花 2 个 RTT 取 HTML，再按 ⌈N/M⌉ 批。把 HTML 也塞进第一批，2024 这种「不并行」看不出来，一批能塞满的时候就会少算。
4. **2022 的初始窗口是 1 个 MSS。** 按 10 来，图像一轮发完，总时间变成 30 ms，那是选项 A。
5. **没发满的一轮不是翻倍。** 窗口 4、只发出 1 个 MSS 时，只有 1 个确认，窗口变成 5。和第 12 关「每个新确认加 1 个 MSS」是同一条规则。
6. **2011 不要再加握手。** 题干从已经在路上的 Web 请求算起。加上握手会得到 7，题目里没有这个选项，但和「持续非流水线是 2+N」混在一起时很容易加上。
7. **2010 的递归里，本地只发 1 条。** 混合方式（主机递归、本地迭代）才是本地发 3 条。题干写了「递归方法」。两种方式的报文总数都可以是 8，2010 不问总数。
8. **2016 的主语是那台域名服务器。** 最多 4 次全是它自己发出的。`www` 不再单独占一台服务器。
9. **`Connection: close` 压过 HTTP/1.1 的默认持续。** 只看版本号会把 2015 的 C 当成正确叙述。
10. **Cookie 没有让 HTTP 变成有状态。** 服务器不保存客户。下一次的次数是浏览器把 `visit` 再送回来之后加 1。

## 概念卡片

### 层次域名空间和服务器

名字是树。最右边是顶级域，往左一级比一级低，最左边通常是主机名。点的个数不固定，也不跟 IP 的点对齐。域名和地理、子网没有对应关系。

服务器按区，不按整个域。区可以等于域，也可以更小，不能更大，区里的节点要连得上。改数据只在主服务器上做，再复制给辅助服务器，区传送用 TCP。

| 种类 | 知道什么 | 在不在这棵树里 |
|---|---|---|
| 根 | 所有顶级服务器的名字和地址 | 在，最高 |
| 顶级 | 该顶级下面注册的二级域 | 在 |
| 权限 | 自己那个区里的域名到 IP | 在 |
| 本地 | 缓存，并替主机去问 | 不在 |

根有 13 个名字，不是 13 台机器，各地有镜像。根一般只指路，不直接给主机的 IP。查询常用 UDP 的 53 端口；响应太大，或要做区传送，改用 TCP 的 53。

### WWW

WWW 是这三样一起：URL 指出要哪一台主机上的哪一个对象，HTTP 负责把对象搬过来，HTML 描述页面里还有哪些对象。浏览器先取 HTML，再按里面的引用继续取。

### HTTP 报文

请求的第一行是请求行：方法、路径、版本。响应的第一行是状态行。后面都是首部，一个空行，然后是实体。报文是文本，端口是 TCP 的 80（HTTPS 是 443）。

HTTP 面向事务，也无状态：一次请求配一次响应，服务器不记得上一次。无连接说的是发 HTTP 之前不必先建立「HTTP 连接」；底下的 TCP 连接该握手还是要握手。持久连接只是这条 TCP 先留着，协议仍然无状态。

`Host` 在 1.1 里必须有，因为一个 IP 上可以放多个站点。`Connection` 决定这条 TCP 响应之后还留不留。`Cookie` 和 `Set-Cookie` 是补无状态的应用手段，不是 HTTP 自己记住了用户。
