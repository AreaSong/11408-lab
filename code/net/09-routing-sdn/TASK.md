# net/09 · 路由算法与 SDN · 题目

> 本文件只写题目，不含思路和代码，做题前可以放心看；答案讲解在 `ANSWER.md`，做完再看。
>
> 王道第 4 章。OSPF 是链路状态：每台路由器掌握全图，用 Dijkstra 算最短路径树。RIP 是距离向量：只和邻居交换「我到各网络有多远」，直连记 1，16 表示不可达。坏消息要一跳一跳加到 16，所以传得慢。SDN 把算路挪到控制器，交换机只查已经下发的流表。

## 一、本关任务

- **产出**：链路状态（Dijkstra，对应 OSPF）与距离向量（Bellman-Ford，对应 RIP）模拟器；一个迷你 SDN 控制器
- **小步骤**：
  ① 对一台源跑 Dijkstra，得到最短路径树。算法用数据结构第 13 关的实现
  ② 距离向量每一轮交换之后，能看出各路由器的距离和下一跳
  ③ 把直连网络断开，看距离怎样一跳一跳涨到 16
  ④ 收到邻居的一条距离向量后更新本表：先加 1，到 16 封顶
  ⑤ 控制器掌握全网拓扑，算出路径，给每台交换机下发「匹配-动作」流表。数据平面只查这张表。链路断开后由控制器重算再下发
- **通过标准**：给定拓扑和链路代价，能写出某路由器的路由表；RIP 收到邻居通告后的距离和下一跳与下面的规则一致；说得清 SDN 里数据平面和控制平面各做什么
- **概念卡片**（写进 `NOTES.md`）：静态路由和动态路由；层次路由与自治系统

每个项目有四个程序：`main.c`（如 `routing_sdn_first`）、`test.c`（`routing_sdn_first_test`）、`ripmain.c`（`routing_sdn_first_rip`）、`sdnmain.c`（`routing_sdn_first_sdn`）。

读入前用 `prompt(...)` 打印提示（`prompt` 在 `deps/prompt.h`，跑测试时自动不打印）。一行一条命令，可以连续输入，Ctrl+D 结束。空行跳过。命令之间不插空行。输入不合法时向 stderr 写原因，并以非 0 退出。

结点、路由器、网络、交换机、主机的名字不超过 31 个字符。图上结点最多 12 个（第 13 关的上限）。RIP 最多 8 台路由器、8 个网络。SDN 主机最多 16 台。链路代价是正整数；Dijkstra 不处理 0 和负数。

## 二、主程序题目（`main.c`，链路状态）

路由器和子网都是无向图上的结点。两边费用相同才能用这条边；OSPF 允许两个方向费用不同，那种题不要用本程序。子网用 `node <名字> net` 标记，它只出现在路由表里，不作为中转。

`from` 按 Dijkstra 确定顶点的次序输出，源自己不输出。费用相等时留下编号较小、也就是先建的那个前驱。路由表要的下一跳是离开源的第一台，不是最短路树上的父亲。

| 命令 | 作用 |
|---|---|
| `init` | 清空图 |
| `node <名字>` | 加一台路由器 |
| `node <名字> net` | 加一个子网 |
| `link <甲> <乙> <代价>` | 加一条无向边，代价是正整数 |
| `from <源>` | 打印源到其余每个结点的下一跳、代价和路径 |
| `from <源> net` | 只打印到子网的行 |
| `default <Metric>` | 记录 R1 的 LSI 增加一条到互联网的特殊链路。不改已经算出的子网路径 |

`from` 的表头是两行：`【链路状态】源 <名字>`，然后 `目的 下一跳 代价 路径`。直连子网写 `<子网> 直连 <代价> 直接到达`。其余写 `<目的> <下一跳> <代价> <源>><下一跳>…`。不可达写 `<名字> - - 不可达`。`default` 只打印一行 `LSI 增加 Prefix 0.0.0.0/0 Metric <数>`。

### 样例

输入：

```
init
node 0
node 1
node 2
node 3
link 0 1 1
link 0 2 1
link 1 3 1
link 2 3 1
from 0
```

输出与 `tests/practice-tie.out` 一致。3 的两条路费用都是 2，下一跳留先松弛到的 1。

## 三、RIP 程序（`ripmain.c`）

直连网络的距离是 1，不是 0。16 表示不可达，不是「第 16 跳」。邻居通告的是它自己的距离，本机使用前先加 1，加出来 ≥ 16 就记 16。

三条规则：

- 本表没有到该网络的路由，且加 1 之后仍小于 16：添加，下一跳是发来的邻居
- 本表的下一跳就是这个邻居：无条件换成新距离，变大也换
- 下一跳是别的邻居：只有严格更短才换。距离相等不换下一跳

`converge` 和 `spread` 按回合同步：这一轮用回合开始时的距离生成通告，本轮新学到的下一轮才继续往外传。`slow` 不这么做，它一次只让一台把整张表告诉另一台，先开口的是还握着旧路由的那台。这是王道上两台路由器的那张表。水平分割默认关闭。`split on` 之后，下一跳是对方时，这一项按「没有通告」处理，表上的效果和毒性逆转一样，都是对方看到 16。

| 命令 | 作用 |
|---|---|
| `init` | 清空 |
| `router <名字>` | 加一台路由器 |
| `net <名字>` | 加一个网络，开始时大家都不可达 |
| `rlink <甲> <乙>` | 两台路由器相邻 |
| `nlink <路由器> <网络>` | 这台路由器直连该网络，距离 1 |
| `split on` / `split off` | 开或关水平分割 |
| `set <路由器> <网络> <距离> <下一跳>` | 直接写入一条路由。下一跳写 `direct` 时距离必须是 1 |
| `learn <本机> <邻居> <网络> <邻居自己的距离>` | 邻居通告这一项，按上面三条规则更新 |
| `converge` | 同步交换到距离和下一跳都不再变 |
| `down <路由器> <网络>` | 这台路由器的直连接口断开，距离立刻变成 16，先不采用旧通告 |
| `hear <本机> <邻居>` | 本机收到该邻居当前的整张距离向量 |
| `tables` | 打印全部路由器的全部网络 |
| `tables <路由器>` | 只打印这一台 |
| `show <路由器> <网络>` | 打印一行 |
| `as <台数>` | 路径上可能经过这么多台路由器时，选 RIP 还是 OSPF |
| `ttl <台数>` | 分组要穿过这么多台路由器，初始 TTL 至少是多少 |
| `spread <网络> <周期秒>` | 从「大家同时交换初始距离向量」的 t=0 起，每隔这么多秒同步一轮，打印每台路由器第一次拿到正确距离的时刻 |
| `slow <路由器> <网络>` | 这台路由器的直连网络断开，按王道的交替通告打印到两边都是 16。只允许正好两台路由器 |

路由行是 `<路由器> <网络> <距离> <下一跳>`。直连的下一跳写 `直连`，不可达写 `-`。`as` 在超过 15 台时打印「RIP 距离会到 16，选 OSPF」，否则打印「RIP 的最大距离仍够用，选 RIP」，最后一行 `结果：OSPF` 或 `结果：RIP`。`ttl` 打印「初始 TTL 至少 <台数+1>」，最后一行 `结果：<这个数>`。

`spread` 先打印 `【<网络>】周期 <秒>s`。交换开始前就已经正确的，写 `一开始 <路由器> <距离> <下一跳>`。其余写 `t=<秒>s <路由器> <距离> <下一跳>`。同一时刻按路由器加入的次序。最后一行 `结果：<秒>s`，是最后一台变正确的时刻；若在 t=0 就全部正确，结果是 `0s`。

`slow` 先打印 `轮 0` 和断开后的两行。之后每一轮写 `轮 <k> <发送方> 到 <接收方>`，被水平分割挡住时后面再加 ` 水平分割`。然后是这一轮之后两台的路由行。最后一行 `收敛 <轮数>`，轮数不含「轮 0」。

`init`、`router`、`net`、`rlink`、`nlink`、`split`、`set`、`learn`、`converge`、`down`、`hear` 没有标准输出。

## 四、SDN 程序（`sdnmain.c`）

交换机是图上的结点，主机不是。主机只记录接在哪台交换机上。端口从 1 起，按 `link` 的先后在每一端各自编号。

`install` 由控制器对每台交换机跑 Dijkstra，写下流动作。交换机自己不交换路由。`go` 只顺着已经写下的动作走，途中不重算。`fail` 先拆链路，再由控制器重算并下发，只打印动作有变化的那些行。

| 命令 | 作用 |
|---|---|
| `init` | 清空 |
| `switch <名字>` | 加一台交换机 |
| `host <主机> <交换机>` | 主机接到这台已经存在的交换机上 |
| `link <甲> <乙> <代价>` | 两台交换机之间加一条正代价的链路，并分配端口 |
| `install` | 控制器计算并下发流表 |
| `go <源主机> <目的主机>` | 数据平面按流表走一遍 |
| `fail <甲> <乙>` | 这条链路断开，控制器重算并下发 |
| `south` | 回答控制器下发流表用的是哪个接口 |

`install` 的前两行固定是：

```
控制平面：控制器掌握全网拓扑，用 Dijkstra 计算路径，经南向接口下发流表。
数据平面：交换机只查流表做匹配-动作，不互相交换路由。
```

然后每个交换机、每台主机一行：`<交换机> 匹配 <主机> 动作 交付`，或 `动作 输出端口 <N>（到 <下一跳>）`，或 `动作 丢弃`。先按交换机加入的次序，再按主机加入的次序。

`go` 先写 `数据平面从 <源> 到 <目的>`，沿途每一跳一行，到达目的交换机后写交付。动作是丢弃就停。`fail` 先写 `控制平面发现 <甲>—<乙> 断开，重新计算并下发。`，再写 `<交换机> 到 <主机> 的动作由<旧动作>改为<新动作>`。「改为」两边不空格。`south` 的最后两行是 `结果：南向接口` 和 `选项 B`。

`init`、`switch`、`host`、`link` 没有标准输出。`install`、`go`、`fail` 之前要先把设备建好；`go` 和 `fail` 之前要先 `install`。
