- **小步骤**：

- **通过标准**：CDMA 求某站发送的数据；最短帧或最远距离；冲突后的退避时间范围。结果与真题一致。ALOHA 的 S 与最大吞吐率、三种坚持的发送时隙、2020 的最长帧间间隔、2024 的 NAV 也与口径一致

## 二、主程序题目（`main.c`，CDMA）

码片的每个分量只能是 `1` 或 `-1`。各站码片等长。一次运行里，已经写入的码片和收到的信号会保留，下一条命令接着用。

发比特 1 时发原码片，发比特 0 时每位取反，`x` 表示这一位不发（信道上是全 0）。规格化内积 = 这一段与码片的内积 / 码片长度。结果是 +1 表示比特 1，-1 表示比特 0，0 表示没发。不是这三个数就报错。

| 命令 | 作用 |
|---|---|
| `chip <站名> <1 或 -1> ...` | 登记一个站的码片。站名以字母开头 |
| `ortho` | 检查目前所有站是否两两正交 |
| `recv <整数> ...` | 写入信道上的叠加信号。长度必须是码片长度的整数倍 |
| `send <站名> <比特串>` | 记下这一站要发的比特。比特串只含 `1` `0` `x` |
| `mix` | 按各站的 `send` 算出叠加信号，并当成随后 `decode` 的输入。各站比特数要相同 |
| `decode` | 解出每一个站 |
| `decode <站名>` | 只解这个站 |

`decode` 不带站名时，每个站各有一段过程，最后一行把各站的比特串写在一起，例如 `结果：A=101，B=110，C=xxx`。`x` 是没发，不是比特 0。

### 样例

输入：

```
chip A 1 1 1 1
chip B 1 -1 1 -1
ortho
recv 2 0 2 0
decode A
```

输出：

```
【码片 A】
发比特 1 时发出这串，发比特 0 时每位取反，不发则是全 0。
A：1 1 1 1
结果：站 A，码片长度 4

【码片 B】
发比特 1 时发出这串，发比特 0 时每位取反，不发则是全 0。
B：1 -1 1 -1
结果：站 B，码片长度 4

【正交】
码片长度 4。不同站内积为 0，各自和自己的内积等于码片长度。
A·A = 1×1 + 1×1 + 1×1 + 1×1 = 4
B·B = 1×1 + -1×-1 + 1×1 + -1×-1 = 4
A·B = 1×1 + 1×-1 + 1×1 + 1×-1 = 0
结果：两两正交

【叠加信号】
共 4 个数，码片长度 4，所以是 1 个比特。
结果：收到 1 个比特

【解码 A】
规格化内积 = 内积 / 码片长度。+1 是比特 1，-1 是比特 0，0 是没发。
第 1 位 (2 0 2 0) · (1 1 1 1) = 2×1 + 0×1 + 2×1 + 0×1 = 4，4 / 4 = 1，发送 1
结果：1
```

`tests/2014-37` 是三个站、三个比特的真题，只解 A。`tests/practice-stations` 把同一段信号三个站都解出来。`tests/practice-mix` 先正交，再由各站的比特叠加，然后解回去。

## 三、争用期程序（`csma.c`）

最短帧的发送时间要盖住争用期。争用期 = 2 × 单程预算。单程预算 = 单程传播 + 单程经过的设备时延。`dev` 不写就是没有设备。设备时延先从单程预算里扣，剩下的才用来算距离；不要先从整个争用期里扣一次再除以 2。

10 Mbps 以太网的标准最短帧是 64 B（512 bit），争用期 51.2 us。题目写了不考虑前导码，就不要再加 8 字节前导码。给了别的帧长，就按给的算，不要改成 64 B。

二进制指数退避按王道，并且和 2023 年的题一致：已经连续冲突 n 次时，k = min(n, 10)，退避时隙数 r 从 0～2ᵏ−1 里取，等待 r 个争用时间片。n = 16 时不再重传，放弃这一帧。

| 命令 | 作用 |
|---|---|
| `frame bw <速率> dist <距离> speed <速度> [dev <时间>]` | 由距离求最短帧 |
| `reach frame <帧长> bw <速率> speed <速度> [dev <时间>]` | 由最短帧求最远距离 |
| `tau frame <帧长> bw <速率>` | 单向传播最多多久 |
| `delta less\|more <帧长变化> bw <速率> speed <速度>` | 帧变短或变长时，最远距离减少或增加多少 |
| `backoff n <次数> slot <时间>` | 这一次冲突之后，退避范围和最长等待 |
| `picks slot <时间> r <整数>...` | 按给出的 r 逐次打印范围和等待。r 必须落在当次范围内，最多 15 个 |
| `detect dist <距离> speed <速度>` | 两台主机都检测到冲突的最短时间和最长时间 |
| `goodput frame <帧长> data <有效数据> ack <确认帧> bw <速率> dist <距离> speed <速度>` | 一个周期里的有效数据速率。分子用 `data`，分母含整帧发送、确认帧发送和往返传播 |

关键字顺序不能换。`less` 表示帧变短，`more` 表示帧变长。

### 样例

输入：

```
frame bw 10 Mbps dist 2500 m speed 200000 km/s
```

输出：

```
【最短帧】
带宽 10 Mbps（M = 10^6），距离 2500 m，速度 200000000 m/s = 200000 km/s = 200 m/us。
单程传播 = 距离 / 速度 = 12.5 us。
争用期 = 2 × 单程传播 = 25 us。
最短帧 = 争用期 × 带宽 = 250 bit。
帧的发送时间至少要盖住争用期，否则发完了才发现冲突。
结果：250 bit
```

`tests/csma/practice-cable` 在这一问之后，再问 64 B、10 Mbps、没有设备时延时的最远距离。`tests/csma/2009-37`、`2016-36`、`2019-36`、`2023-36`、`2010-47` 是真题。`tests/csma/practice-picks` 自己指定每次抽中的 r。`tests/csma/practice-cap` 看 k 封顶和放弃。

## 四、模拟程序（`sim.c`）

时间分成时隙，1 个时隙 = 1 个争用期。这里比的是时隙数，不换算成比特。

CSMA/CD 按 1-坚持：

- 退避减到 0 的站，信道一空闲就发送
- 只有一个站发送：成功，占用 `length` 个时隙，这些时隙算有用
- 两个及以上站同时发送：冲突，只浪费这 1 个时隙。强化冲突的干扰信号已经算在这个争用期里，不再单列
- 没参与这次发送的站，退避照样减。减到 0 时如果信道还忙，就等到空出来再抢
- 大家都还在退避：信道空等

选中的时隙不用真随机数，否则每次结果不一样，没法对测试。公式是

r = (17 × 站号 + 29 × 冲突次数 + 3) mod 2ᵏ

站号从 0 起。k = min(这一站已经发生的冲突次数, 10)。第 16 次冲突放弃这一帧，放弃的帧不算有用。冲突次数按站分开计，发送成功后清零。

令牌从站 0 开始，沿 0、1、2……转：

- 持有令牌且还有帧：发 1 帧，占用 `length` 个时隙
- 然后把令牌交给下一站，走过 `walk` 个时隙。最后一帧发完就停，不再多走一次
- 没有帧的站也要把令牌传下去，同样走 `walk` 个时隙

利用率 = 有用时隙 / 总时隙，百分数保留两位小数，四舍五入。`compare` 里每站的帧数和帧长相同，这就是两边的同一负载。令牌多出来的是 `walk`，总线上没有这一项。

| 命令 | 作用 |
|---|---|
| `trace csma stations <n> frames <每站帧数> length <帧长>` | 打印 CSMA/CD 的每一次冲突、空等和成功 |
| `trace token stations <n> frames <每站帧数> length <帧长> walk <时隙>` | 打印令牌的发送和传递 |
| `compare from <n1> to <n2> frames <每站帧数> length <帧长> walk <时隙>` | 站点数从 n1 到 n2，每档都打 CSMA/CD 和令牌 |

站点数 1～32。本关要看的实验是 2 到 20。

### 样例

输入：

```
trace csma stations 2 frames 1 length 4
```

输出的结果行是：

```
结果：8/9 = 88.89%
```

前面要有规则，以及每次冲突的 k、范围和选中的 r。`tests/sim/practice-trace` 是 3 个站的 CSMA/CD 和令牌。`tests/sim/practice-compare` 是 2～20 站的对照。

## 五、随机访问程序（`access.c`）

这一节不改前面的最短帧和二进制指数退避。CSMA/CD 的多站模拟仍在 `sim.c`。这里的 CSMA 只按给定的忙闲序列决定发不发，不检测冲突，也不抽退避随机数。

G 是一个帧时内全网平均尝试发送的帧数，含重传，范围 0～20。S 保留四位小数。除不尽不必报错，吞吐率本来就不是整数。

纯 ALOHA 不听信道，随时能发。易受攻击时间是 2 个帧时，S = G*e^(-2G)。G = 0.5 时最大，Smax = 1/(2e)，约 18.4%。时隙 ALOHA 只能在时隙起点发，易受攻击时间是 1 个帧时，S = G*e^(-G)。G = 1 时最大，Smax = 1/e，约 36.8%。两种都不听信道。时隙 ALOHA 要对齐时钟。两个最大点相比，时隙是纯 ALOHA 的两倍；同一个 G 下不是这个倍数。

信道序列里 1 是忙，0 是空闲，时隙从 0 编号，最多 32 个。

- 1-坚持：空闲立刻发；忙就继续听，变空闲的那个时隙立刻发
- 非坚持：空闲立刻发；忙就停止听，等待 `wait` 个时隙再听。等待的那些时隙即使变空闲也不发。再听的时隙必须还在序列里
- p-坚持：用于时隙信道。忙就继续听，这次不抽签。空闲时看下一张抽签：1 发送，0 推迟到下一时隙。抽签只含 0 和 1，用来代替随机的 p

CSMA/CA 的顺序是：DIFS、退避、RTS、SIFS、CTS、SIFS、数据帧、SIFS、ACK。DIFS 必须长于 SIFS。退避时隙数是 0～1023，这里按信道一直空闲把给定的时隙数一次减完，并注明信道再忙时剩余值要冻住。`line` 里的 `data` 是已经算好的传输时间。`nav` 里的 `data` 是帧长，发送时延要整除，规则和第 ② 步一样。

隐藏站收到 CTS 时，CTS 已经发完。NAV = SIFS + 数据帧发送时延 + SIFS + ACK。DIFS、RTS 和 CTS 的传输时间不加进去。

| 命令 | 作用 |
|---|---|
| `pure G <负荷>` | 纯 ALOHA 的 S |
| `slot G <负荷>` | 时隙 ALOHA 的 S |
| `max` | 两个最大吞吐率 |
| `one <0 或 1> ...` | 1-坚持 |
| `non <0 或 1> ... wait <时隙数>` | 非坚持。等待至少 1，至多 31 |
| `p <0 或 1> ... draw <0 或 1> ...` | p-坚持 |
| `ifs` | 2020 年那张图上四个帧间间隔谁最长 |
| `line difs <时间> sifs <时间> slot <时间> backoff <时隙数> rts <时间> cts <时间> data <时间> ack <时间>` | 一轮 RTS/CTS 的时间线，结果是总时间 |
| `nav difs <时间> sifs <时间> rts <时间> cts <时间> ack <时间> data <长度> bw <速率>` | CTS 结束时的 NAV |

关键字顺序不能换。时间单位仍是 `ns` `us` `ms` `s`。

`pure` / `slot` 的结果行是四位小数，例如 `结果：0.1839`。`max` 的结果行是 `结果：1/(2e) ≈ 18.4%，1/e ≈ 36.8%`。坚持策略发出去时是 `结果：时隙 2 发送`，序列走完还没发是 `结果：未发送`。`ifs` 的结果行是 `结果：IFS1`。`line` 的结果行是总时间。`nav` 的结果行是 NAV，例如 `结果：354 us`。

### 样例

输入：

```
pure G 0.5
```

输出：

```
【纯 ALOHA】
不听信道，随时能发。前后各一个帧时都会撞上，易受攻击时间是 2 个帧时。S = G*e^(-2G)。
G = 0.5。S = 0.5*e^(-1) = 0.1839。
最大在 G = 0.5，Smax = 1/(2e) ≈ 0.1839（18.4%）。
这个 G 就是最大点。
结果：0.1839
```

`tests/access/practice-aloha` 再看 G = 1、G = 2 和时隙 ALOHA。`tests/access/practice-persist` 是三种坚持。`tests/access/practice-ca` 是一条自编时间线，总时间 211 us，其中 NAV 是 124 us。`tests/access/2020-37` 和 `tests/access/2024-36` 是真题。

## 六、同步时分和统计时分

`mux.c` 只比同一帧里两种时分的利用率。用户数 1～32，有数据的用户不能超过用户数，数据位 1～4096，地址位 1～64。

同步 TDM 每帧固定给每个用户一个时隙，时隙里只有数据。位置就是用户的名字，所以不带地址。有用位数 = 有数据的用户 × 数据位，总位数 = 用户数 × 数据位。没数据的时隙也算进总位数。

STDM 这一帧只发出有数据的那些时隙。每个时隙是地址加数据。有用位数仍是有数据的用户 × 数据位，总位数 = 有数据的用户 ×（数据位 + 地址位）。有数据的用户为 0 时，这一帧没有时隙。

利用率是有用位数 / 总位数，百分数保留两位小数，四舍五入。人少时 STDM 通常更高。人人都有数据时，地址变成纯开销，同步 TDM 更高。两种相等时结果行写「这一帧两种一样」。

| 命令 | 做什么 |
|---|---|
| `stdm users <用户数> busy <有数据的用户> data <数据位数> addr <地址位数>` | 比较这一帧的两种利用率 |
| `card` | 打印 FDM、TDM、STDM、WDM、CDM |

`stdm` 的结果行是 `结果：这一帧 STDM 更高`、`结果：这一帧同步 TDM 更高`、`结果：这一帧两种一样` 或 `结果：这一帧没有数据`。`card` 的结果行是 `结果：五种划分`。

`tests/mux/practice-stdm` 用 4 个用户、8 位数据、2 位地址。只有 1 个用户有数据时 STDM 是 80.00%，同步 TDM 是 25.00%。4 个用户都有数据时反过来：同步 TDM 100.00%，STDM 80.00%。
