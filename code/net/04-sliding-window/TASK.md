# net/04 · 可靠传输：停等、GBN、SR · 题目

> 本文件只写题目，不含思路和代码，做题前可以放心看；答案讲解在 `ANSWER.md`，做完再看。
>
> 王道第 3 章 数据链路层。带宽里的 k / M / G 是 10³ / 10⁶ / 10⁹，1 B = 8 bit。时间用 `s`、`ms`、`us`、`ns`。
>
> 本关的确认号按王道：ACK n 表示 n 号帧已经正确收到。GBN 里这是累计确认。有的教材把 ACK n 定义成「下一帧期待 n」，两种差 1，这里不用那一套。

## 一、本关任务

- **产出**：滑动窗口模拟器，能走停等、后退 N 帧（GBN）、选择重传（SR），并能表示丢帧、确认丢失和超时；另有一个带单位的计算器，算信道利用率和序号位数
- **小步骤**：
  ① 停等协议，以及窗口为 1 时的信道利用率
  ② GBN：累计确认；超时后把窗口里已发送、还没确认的帧全部重传
  ③ SR：逐帧确认；接收窗口里的失序帧先缓存；超时只重传点名的那几帧
  ④ 序号位数和窗口的关系：GBN 发送窗口最大 2ⁿ−1；SR 在收发窗口相等时每个最大 2ⁿ⁻¹，一般是 Ws + Wr ≤ 2ⁿ 且 Wr ≤ Ws
- **通过标准**：信道要达到某个利用率时，发送窗口至少多大、序号至少几位；n 位序号时 GBN 和 SR 的最大窗口；丢失或超时之后要重传哪些帧。结果与真题一致
- **概念卡片**（写进 `NOTES.md`）：流量控制和可靠传输；停等、GBN、SR 对比

每个项目有三个程序：`main.c` 编出的主程序（与项目同名，如 `sliding_window_first`）、`test.c` 编出的单元测试（`sliding_window_first_test`）、`util.c`（`sliding_window_first_util`）。

读入前用 `prompt(...)` 打印提示（`prompt` 在 `deps/prompt.h`，用法同 `printf`，跑测试时自动不打印）。一行一条命令，可以连续输入，Ctrl+D 结束。空行跳过。命令之间的输出空一行。算不出来或命令不合法时向 stderr 写原因，并以非 0 退出。

发送窗口用数据结构第 04 关的循环队列（`deps/cycq.h`）。`front` 是最早未确认的帧，`rear` 指向下一空位，空一格用来区分队空和队满，所以队列容量是发送窗口加 1。确认从队头出队，新帧从队尾入队。模拟器的序号只有 1～6 位，窗口才放得进这个队列。只问最大窗口或序号位数时用 util 程序，位数可以到 16。

`arrive` 只作用在接收方，`ack` 只作用在发送方，两边不会自动把确认送过去。确认要丢失，就不要写对应的 `ack`。`loseack` 只是在输出里记一笔，不改窗口。

## 二、主程序题目（`main.c`）

| 命令 | 作用 |
|---|---|
| `proto stop\|gbn\|sr bits <n> [window <Ws>] [recv <Wr>]` | 建立协议。`window`、`recv` 不写就用该协议的默认窗口 |
| `send` 或 `send <k>` | 不写 k 就把窗口里的空位填满；写了 k 就最多发 k 帧 |
| `arrive <序号>` | 这一帧到达接收方 |
| `ack <序号>` | 这一份确认到达发送方 |
| `drop <序号>` | 这一份数据帧在去的路上丢失。帧必须已经在发送窗口里，窗口不删它 |
| `loseack <序号>` | 记一笔：这份确认没有回到发送方 |
| `timeout` | 停等和 GBN：重传当前窗口里已发送、还没确认的全部帧 |
| `timeout <序号...>` | 只给 SR 用：只重传写出来的这些帧 |
| `show` | 打印发送窗口和接收方缓存 |

停等的窗口只能是 1。GBN 的接收窗口只能是 1，发送窗口最大是 2ⁿ−1。SR 的接收窗口不能大于发送窗口，两者之和不能超过 2ⁿ。默认时 SR 两边相等，各是 2ⁿ⁻¹。

每一条命令的最后一行是 `结果：...`。重传的结果写成 `结果：重传 4 帧：4 5 6 7` 这种。

### 样例

输入：

```
proto stop bits 1
send
arrive 0
ack 0
```

输出：

```
【停等】
序号 1 位就够：窗口里永远只有 1 帧，0 和 1 交替，重传不会和新帧撞号。
发完一帧必须停下等确认。超时只重传这一帧。
信道利用率 U = Td / (Td + Ta + 2×单向传播)。窗口大于 1 的算法在 util 程序里算。
发送窗口用循环队列装着，容量 2，最多放 1 帧。空出的一格用来区分队空和队满。
front 是最早未确认的帧，rear 指向下一空位。确认从 front 出队，新帧从 rear 入队。
循环队列 [_ _] front=0 rear=0 个数=0
窗口左边界 0，下一帧序号 0，上限 1。
结果：停等，序号 1 位，发送窗口 1，接收窗口 1

【发送】
这次发送 1 帧。发出去的帧留在队列里，等确认。
发出帧 0。
循环队列 [0 _] front=0 rear=1 个数=1
窗口左边界 0，下一帧序号 1，上限 1。
结果：发送 0

【到达 0】
接收方正在等 0，序号相同，收下并交给上层。
累计确认记到这一帧。ACK 0 先留在接收方，要另写 ack 才会送到发送方。
结果：收下 0，准备 ACK 0

【ACK 0】
ACK 0 确认的就是窗口左边界。
滑出 0。
左边界 0 → 1。
循环队列 [_ _] front=1 rear=1 个数=0
窗口左边界 1，下一帧序号 1，上限 1。
结果：确认到 0，窗口左边界 1
```

`tests/practice-stop` 在这之后把下一帧丢掉再超时。`tests/2009-35` 是 GBN 的累计确认。`tests/2011-35` 和 `tests/2024-37` 是 SR。`tests/practice-gbn-loss` 里失序帧被丢掉。`tests/practice-sr-fill` 里缓存的帧在缺口补上之后一起上交。

## 三、利用率程序（`util.c`）

一个确认周期 = 数据帧发送时延 Td + 确认帧发送时延 Ta + 2 × 单向传播时延。窗口为 W、还没把信道用满时，利用率 U = W × Td / 周期。W × Td 不小于周期之后，U 封顶为 1，平均速率等于带宽。

单位和 `net/00` 相同：`bit` `B` `kbit` `kb` `Mbit` `Mb`，`bps` `kbps` `Mbps` `Gbps`，`ms` `s` 等。不认识的单位报错。

| 命令 | 作用 |
|---|---|
| `need <协议> frame <长度> <单位> [to <长度> <单位>] bw <带宽> <单位> prop <时延> <单位> ack <same\|长度 单位> [util <百分比>]` | 要达到这个利用率，发送窗口至少多大，序号至少几位。`util` 不写就是 100。协议可以是 `stop` `gbn` `sr` `slide` |
| `rate <协议> window <W> frame <长度> <单位> bw <带宽> <单位> prop <时延> <单位> ack <same\|长度 单位>` | 这个窗口实际能达到的平均速率。协议是 `stop` `gbn` `sr` |
| `limit <协议> bits <n> [send <Ws>]` | n 位序号时窗口最大是多少。`send` 只给 SR 用，用来求接收窗口 |
| `compare <位数>` | 停等、GBN、SR（收发窗口相等）最大利用率的大小关系 |

`ack same` 表示确认帧和当前这一档数据帧一样长。`ack 0 B` 表示忽略确认帧的发送时延。`frame ... to ...` 给出帧长范围，两档都要算。`slide` 表示题面只说滑动窗口，没有点名 GBN 或 SR。

最后一行仍是 `结果：...`。

### 样例

输入：

```
rate stop window 1 frame 1000 bit bw 10 kbps prop 200 ms ack 0 B
```

输出的结果行是：

```
结果：2 kbps
```

前面要有 Td、Ta、往返传播、周期、满载需要的窗口和利用率。`tests/util/practice-stop` 是这一问，再问 GBN 要多少窗口才用满，以及 1 位序号的停等窗口。`tests/util/2012-36`、`2014-36`、`2015-35`、`2019-35`、`2023-35` 是真题。

## 四、真题题面

### 2009-35

数据链路层采用后退 N 帧（GBN）协议，发送方已经发送了编号为 0～7 的帧。当计时器超时时，若发送方只收到 0、2、3 号帧的确认，则发送方需要重发的帧数是（ ）。

A. 2　B. 3　C. 4　D. 5

### 2011-35

数据链路层采用选择重传协议（SR）传输数据，发送方已发送了 0～3 号数据帧，现已收到 1 号帧的确认，而 0、2 号帧依次超时，则此时需要重传的帧数是（ ）。

A. 1　B. 2　C. 3　D. 4

### 2012-36

两台主机之间的数据链路层采用后退 N 帧协议（GBN）传输数据，数据传输速率为 16 kbps，单向传播时延为 270 ms，数据帧长度范围是 128～512 字节，接收方总是以与数据帧等长的帧进行确认。为使信道利用率达到最高，帧序号的比特数至少为（ ）。

A. 5　B. 4　C. 3　D. 2

### 2014-36

主机甲与主机乙之间使用后退 N 帧（GBN）协议传输数据，甲的发送窗口尺寸为 1000，数据帧长为 1000 字节，信道带宽为 100 Mbps，乙每收到一个数据帧就立即利用一个短帧（忽略其传输延迟）进行确认，若甲乙之间的单向传播延迟是 50 ms，则甲可以达到的最大平均数据传输速率约为（ ）。

A. 10 Mbps　B. 20 Mbps　C. 80 Mbps　D. 100 Mbps

### 2015-35

主机甲通过 128 kbps 卫星链路，采用滑动窗口协议向主机乙发送数据，链路单向传播延迟为 250 ms，帧长为 1000 字节。不考虑确认帧的开销，为使链路利用率不小于 80%，帧序号的比特数至少是（ ）。

A. 3　B. 4　C. 7　D. 8

### 2019-35

对于滑动窗口协议，如果分组序号采用 3 比特编号，发送窗口大小为 5，则接收窗口最大是（ ）。

A. 2　B. 3　C. 4　D. 5

### 2023-35

假设通过同一信道，数据链路层分别采用停等协议、GBN 协议和 SR 协议（发送窗口和接收窗口相等）传输数据，三个协议数据帧长相同，忽略确认帧长度，帧序号位数为 3 比特。若对应三个协议的发送方最大信道利用率分别是 U1、U2 和 U3，则 U1、U2 和 U3 满足的关系是（ ）。

A. U1 ≤ U2 ≤ U3

B. U1 ≤ U3 ≤ U2

C. U2 ≤ U3 ≤ U1

D. U3 ≤ U2 ≤ U1

### 2024-37

主机甲通过选择重传（SR）滑动窗口协议向主机乙发送帧的部分过程如下图所示。F 为数据帧，ACKx 为确认帧，x 是位数为比特的序号。乙只对正确接收的数据帧进行独立确认。发送窗口与接收窗口大小相同且均为最大值。甲在 t1 时刻和 t2 时刻发送的数据帧分别是（ ）。

A. F1、F3　B. F1、F4　C. F3、F1　D. F4、F1

图本身没有贴在这里。从图上能读出的事件是：序号 3 位，所以收发窗口都是 4；甲先把 F0～F3 发出去，F1 在去的路上丢失；乙对收到的帧单独确认，ACK3 在回来的路上丢失；t1 是甲收到 ACK0 的时刻，t2 是 F1 超时的时刻。ACK2 在超时前回到甲，但窗口左边界还停在 F1。`tests/2024-37` 按这个顺序写。
