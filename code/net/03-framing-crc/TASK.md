## 一、本关任务

- **产出**：组帧器（字符计数、PPP 字节填充、零比特填充）；奇偶校验；CRC 计算器，把模 2 除法的每一步打出来；海明码编码与纠错器
- **小步骤**：
  ① 组帧：字符计数法；字节填充（PPP 的 `0x7E`、`0x7D`，以及小于 `0x20` 的控制字符）；零比特填充（连续 5 个 1 后插 0）及接收端删除
  ② 奇偶校验
  ③ CRC 发送端：补 0、求余数、拼到数据后面
  ④ CRC 接收端：对整串做除法，看余数
  ⑤ 海明码：由不等式求校验位个数，确定位置并编码；人为翻转一位，接收端定位并纠正
- **通过标准**：零比特填充后的比特串、CRC 余数或实际发送的比特串、海明码校验位个数与出错位置，都与真题一致
- **概念卡片**（写进 `NOTES.md`）：数据链路层的功能；四种组帧方法对比；检错编码和纠错编码

每个项目有四个程序：`main.c` 编出的主程序（与项目同名，如 `framing_crc_first`）、`test.c` 编出的单元测试（`framing_crc_first_test`）、`crc.c`（`framing_crc_first_crc`）、`hamming.c`（`framing_crc_first_hamming`）。

读入前用 `prompt(...)` 打印提示（`prompt` 在 `deps/prompt.h`，用法同 `printf`，跑测试时自动不打印）。一行一条命令，可以连续输入，Ctrl+D 结束。空行跳过。命令之间的输出空一行。算不出来时向 stderr 写原因，并以非 0 退出。

## 二、主程序题目（`main.c`）

| 命令 | 输入 |
|---|---|
| `count send` | 数据字节，两位十六进制，可以连写。计数字段不要写进来 |
| `count recv` | 已经带计数字段的字节流，里面可以有多帧 |
| `byte send` | 信息字段的原始字节 |
| `byte recv` | 填充后的信息字段；若首尾都是 `7E`，先当整帧剥掉标志 |
| `bit send` | 只含 0 和 1 的数据。空格可以用来分组，不占位 |
| `bit recv` | 填充后的数据；首尾都是 `01111110` 时先剥掉标志 |
| `bit frames` | 一串用 `01111110` 隔开的帧。相邻帧可以共用一个标志 |
| `parity even` 或 `parity odd` | 数据比特，校验位由程序补在最后 |
| `parity check even` 或 `parity check odd` | 已经带校验位的码字 |

字节最多 128 个，比特串最长 256 位。字符计数的计数字段是 1 字节，所以一帧最多 255 字节。

规则：

- 字符计数：帧首那一字节是本帧的总字节数，包含它自己。数据字节数 = 计数 − 1。计数是 0，或者后面的字节不够这一帧，就报错退出
- PPP 异步字节填充。三种字节都写成 `7D` 再跟「原字节异或 `20`」：`7E → 7D 5E`，`7D → 7D 5D`，小于 `20` 的控制字符同样转义（`01 → 7D 21`）。其余字节原样。还原时看见 `7D` 就删掉，下一字节再异或 `20`
- 零比特填充：从左往右，一遇到连续 5 个 1，立刻在后面插一个 0，然后重新开始数。接收方看见连续 5 个 1 后面的 0，就删掉这个 0。连续 6 个 1，或结尾刚好 5 个 1 却没有填充位，都报错
- 标志 `01111110` 只加在帧的两端，标志本身不再填充。两个标志紧挨着表示帧间填充，中间没有数据，`bit frames` 跳过
- 偶校验：加上最后一位之后，1 的个数是偶数。奇校验则是奇数。校验只回答通过或发现错误

`bit send`、`byte send` 的结果行只写填充之后的数据，不含首尾标志。整帧另起一行打印。

### 样例

输入：

```
bit send 11111
```

输出：

```
【零比特填充】
定界标志是 01111110。数据里不能出现这 8 位，否则接收方会把它当成帧界。
发送方从左往右数 1：一遇到连续 5 个 1，立刻在后面插一个 0，然后重新开始数。
这个 0 是填充的。接收方看到连续 5 个 1 后面的 0，就把这个 0 删掉。
数据：11111
读完第 5 位时已经连续 5 个 1，在它后面插入 0
填充后的数据：111110
整帧：0111111011111001111110
结果行只写填充后的数据。首尾标志另外加上，标志本身不再填充。
结果：111110
```

`tests/2013-37` 是 HDLC 的零比特填充。`tests/practice-byte` 同时用到标志、转义字节和控制字符。`tests/practice-count` 里有一帧的计数字段被改过，字节仍能切完。`tests/practice-parity` 里有一次两位同时翻转。`tests/practice-bit` 把填充删回去，并切两帧。

## 三、CRC 程序（`crc.c`）

数据比特可以按空格分组。生成多项式写在 `gen` 后面，两种写法都可以：二进制 `10011`，或 `x^4+x+1`、`x^4 + x + 1`、`x4+x+1`。最高次项和常数项都必须是 1。最高次数记为 r，除数有 r+1 位，余数只有 r 位。

| 命令 | 含义 |
|---|---|
| `send <比特> gen <多项式>` | 数据后面补 r 个 0，模 2 除法求 FCS，再拼回数据 |
| `check <比特> gen <多项式>` | 对收到的整串做除法，不再补 0。余数写满 r 位 |

模 2 除法里，加减都是异或。窗口最高位是 1 才和除数异或；是 0 就商 0。每一步都要打印。商不用发送。余数高位的 0 也要留下。

### 样例

输入：

```
send 101001 gen x^3 + x^2 + 1
```

输出的结果行是：

```
结果：FCS = 001，发送 101001001
```

前面要有生成多项式、除数、补 0 后的被除数，以及每一步窗口。`tests/crc/practice-send` 是这道发送，再对正确帧和错一帧各验一次。`tests/crc/2023-37` 是四条接收串，余数为 0 的那条就是未检出错误。

## 四、海明码程序（`hamming.c`）

位号从左往右、从 1 开始。校验位放在 1、2、4、8…… 数据按给出的顺序从左到右填进其余位置。缺省偶校验；命令最后可以写 `odd`。

纠正 1 位错时，校验位数 r 满足 `2^r >= m + r + 1`。右面这个 1 表示「哪一位都没错」。

| 命令 | 输入 |
|---|---|
| `need <m>` | 只求最少校验位数。m 从 1 到 4096 |
| `encode <比特>` | 编码。数据最长 64 位 |
| `correct <码字>` | 按最多错一位来定位，并把那一位取反 |
| `flip <数据> <位号>` | 先编码，再翻转码字里的这一位（从 1 数），然后纠正 |

`flip` 的位号是码字里的位置，不是数据里的第几位。它写在比特串后面；`odd` 或 `even` 若出现，要放在最后。

### 样例

输入：

```
need 4
```

输出：

```
【海明码校验位数】
数据 m = 4 位。纠正 1 位错要满足 2^r >= m + r + 1。
右面这个 1 是「哪一位都没错」。另外 m + r 个数分别对应码字里的一个位置。
r = 1：2^1 = 2，m + r + 1 = 6，2 >= 6？否
r = 2：2^2 = 4，m + r + 1 = 7，4 >= 7？否
r = 3：2^3 = 8，m + r + 1 = 8，8 >= 8？是
结果：3
```

`tests/hamming/2013-15` 的输入是 `need 8`。`tests/hamming/practice-need` 用来看 r 刚好够和刚好不够的边界。`tests/hamming/practice-flip` 编码 `1010`、翻转第 5 位再纠正，并给出同一数据的奇校验码字。
