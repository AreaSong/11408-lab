## 思路

### 三段邮件，两种方向

用户代理、邮件服务器，再加上发送协议和读取协议，这是电子邮件系统的三块。发送协议是 SMTP，读取协议是 POP3 或 IMAP。方向看谁发起连接，不看字节往哪流。

| 这一跳 | 谁发起 | 协议 |
|---|---|---|
| 用户代理 → 自己的邮件服务器 | 用户代理，推 | SMTP，端口 25 |
| 发件服务器 → 收件服务器 | 发件服务器，推 | SMTP。TCP 直接连过去，不找第三台邮件服务器转发 |
| 用户代理 ← 自己的邮件服务器 | 用户代理，拉 | POP3 端口 110，或 IMAP 端口 143 |

2012 的 ③ 画成从服务器指向用户，字节确实是往用户走的。连接仍是用户拨过去的，所以协议是 POP3，不是再来一次 SMTP。IMAP 也是这一跳，只是信留在服务器上；2012 的选项写的是 POP3。

POP3 在一条 TCP 上可以连续取多封，所以 2025 的 I 和 IV 成立。它不负责发信，也不负责两台服务器之间的传送。

用浏览器打开网页邮箱时，人和自己的服务器之间换成 HTTP。两台邮件服务器之间仍是 SMTP。Web 邮箱换掉的是两端，不是中间。

### SMTP 为什么吃不下「你好」

SMTP 的正文按 NVT ASCII，每个字节的最高位是 0。`你好` 的 UTF-8 是 `E4 BD A0 E5 A5 BD`，六个字节的最高位都是 1。JPEG、MPEG、EXE 同样不是 7 位 ASCII。2018-40 里唯一能直接送的是 ASCII 文本。

MIME 不改 SMTP 的命令和应答，只改信的组织方式。Base64 把 3 个字节收成 4 个 `A–Z`、`a–z`、`0–9`、`+`、`/`，不够 3 个就用 `=` 补齐。`你好` 编出来是 `5L2g5aW9`。主题放在 `=?UTF-8?B?5L2g5aW9?=` 里，这样主题那一行本身也是 ASCII。

`DATA` 以单独一行的句点结束。正文里真有一行只有一个句点时，客户多写一个句点，服务器删掉行首的那一个。这和组帧时的填充是同一件事：结束符不能在内容里原样出现。

信封是 `MAIL FROM` 和 `RCPT TO`，内容首部是 `From:` 和 `To:`。两套可以不一致。密送就是这样：收件人在信封上，不在 `To:` 里。`practice-envelope` 的 `c@lab.local` 只出现在信封上。

迷你服务器不拒绝最高位为 1 的字节。规范限制的是客户可以交给 SMTP 的内容；编码要在 `DATA` 之前做完。`EHLO` 是 ESMTP 的问候。本程序不广告 `8BITMIME`，所以仍然按 7 位来准备正文。

### FTP 的两条连接

控制连接由客户连到服务器的 21，从登录一直开到 `QUIT`。`USER`、`PASS`、`PORT`、`PASV`、`RETR`、`STOR` 都走它。命令不夹在文件里，这叫带外传送。

数据连接每次传输单独建立，传完就关。下一个文件再建立一条。2009 问的是命令，所以是 TCP 上的控制连接。2017 里错误的是 C：端口 20 只属于主动模式下的服务器。客户的数据端口是它在 `PORT` 里报上去的临时端口，不是 20。被动模式下服务器另开一个临时端口，客户去连，两边都不用 20。

2023 的第（1）问：登录时还没有文件，建立的是控制连接，而且它是持久的。真正传 F 的那条数据连接是非持久的。一次上传就是 1 条控制连接加 1 条数据连接。

第（2）（3）（4）问是这条数据连接上的 TCP，算法在第 11、12 关。标准答案记在下面的真题对照里，本关程序不算它们。

### 两个分发时间

文件长度 F 比特，服务器上传 `us`，第 i 个对等方下载 `di`、上传 `ui`，最慢下载 `dmin`。

客户-服务器里，文件只从服务器出去。服务器至少送出 `NF` 比特，最慢的那个人至少要花 `F/dmin`。两件事都得做完，取较大的：

`Dcs = max(NF/us, F/dmin)`

P2P 里，一个比特只要被服务器送进网络一次，别的对等方就可以转发。系统一共仍要交付 `NF` 比特，能用来上传的是 `us` 加上全体 `ui`：

`Dp2p = max(F/us, F/dmin, NF/(us+Σui))`

N = 1、每个对等方下载 10 Mbps、上传 3 Mbps、服务器 30 Mbps、文件 300 Mbit 时，两个模型都是 30 s。P2P 的第三项只有 `100/11 s`，被下载时间挡住了。人少的时候 P2P 并不更快。

同样的速率、N = 10 时，C/S 是 100 s，瓶颈在服务器上传；P2P 是 50 s，瓶颈在总上传。N = 1000 时 C/S 是 10000 s，P2P 是 `10000/101 s`，大约 99.010 s。每个对等方上传都是 u 时，第三项趋近 `F/u`。这里 `F/u = 100 s`。时间随 N 变大，但有上界。C/S 的 `NF/us` 没有这个上界。

所有对等方上传都是 0 时，`us+Σui` 变回 `us`，P2P 的第三项和 C/S 的第一项相同。自扩展来自 `Σui`。

下载比服务器更慢时，两个模型会被 `F/dmin` 一起卡住。15 Gbit、服务器 30 Mbps、每人下载 2 Mbps 时，无论 N = 10 时别人能上传多少，最短时间都是 7500 s。

### 2023-47

第（1）问：控制连接持久，数据连接非持久，登录建立的是控制连接。主动上传一次时，控制连接 1 条，数据连接 1 条。

第（2）问：初始序号 100 用在 SYN 上，SYN 占一个序号，F 的第一个字节是 101。18000 字节占 101 到 18100。第一次挥手的 FIN 序号是 18101，第二次挥手确认它，ACK 是 18102。写成 18101，是把 FIN 占用的那个序号漏了。

第（3）问：确认序号 2101 表示从 101 起已经确认 2000 字节，即 2 个 MSS，还没到门限 4 MSS，慢开始，拥塞窗口调整为 3 MSS。确认序号 7101 表示已经确认 7000 字节，即 7 个 MSS，已经过了门限，拥塞避免，拥塞窗口调整为 5 MSS。

第（4）问：从请求建立数据连接到收齐确认，是 6 个 RTT，60 ms。18000 B / 60 ms = 300000 B/s = 2.4 Mbps（M = 10⁶）。300 kB/s（k = 10³，B 是字节）是同一个量。评分答案写成 2.4 Mbps。

## 易错点

1. 读取邮件的那一跳是 POP3 或 IMAP。把三段都写成 SMTP，是把数据方向当成了发起方向。
2. SMTP 直接传输的是 7 位 ASCII，不是 8 位，也不是「所有二进制只要 Base64 以外的办法」。MIME 是在交给 SMTP 之前把内容变成 ASCII。
3. 主动模式的端口 20 在服务器一侧。被动模式的数据连接由客户发起，不使用 20。控制连接两种模式都是客户连 21。
4. 控制连接持久，数据连接非持久。登录建立的是控制连接。
5. N = 1 时 P2P 不一定更短。`Σui = 0` 时，P2P 的总上传退回成服务器的上传。
6. P2P 的时间随 N 增大，上界大约是 `F/u`。它不是人数越多下载越快。
7. 2023 第二次挥手的 ACK 是 18102。FIN 占一个序号。
8. 网页邮箱只把用户和自己的服务器换成 HTTP。服务器之间仍是 SMTP。
9. 信封收件人和 `To:` 可以不同。密送写在信封上。

## 概念卡片

**电子邮件系统的组成。** 用户代理、邮件服务器、发送协议 SMTP、读取协议 POP3 或 IMAP。邮件服务器 24 小时在线，信先落在收件人的邮箱里。同一台服务器对发件人是 SMTP 服务器，对下一台邮件服务器又是 SMTP 客户。

**SMTP 与 POP3。** SMTP 推，用于用户代理到自己的服务器，以及服务器到服务器，只直接送 7 位 ASCII。POP3 拉，用于用户代理到自己的服务器，一条 TCP 可以收多封，取走之后本地和服务器不再同步。IMAP 也是拉，信留在服务器上。

**邮件格式。** 信封是 `MAIL FROM`、`RCPT TO`。内容是首部、一个空行、正文。`To:` 属于内容首部。非 ASCII 用 MIME 说明类型和传输编码，Base64 是其中一种编码。结束正文的是单独一行的句点。

**FTP 的两条连接。** 控制连接端口 21，整个会话保持打开，命令带外传送。数据连接在需要传文件或目录时建立，传完关闭。主动模式由服务器从端口 20 连向客户报告的端口。被动模式由客户连向服务器给出的临时端口。

**C/S 与 P2P。** C/S 里服务器一直在线，客户主动发起，客户之间不直接通信。分发时间是 `max(NF/us, F/dmin)`，N 大了以后随人数线性变长。P2P 里结点既能下载也能上传。分发时间是 `max(F/us, F/dmin, NF/(us+Σui))`。对等方的上传使第三项随 N 趋近 `F/u`，所以通常更短；上传为 0 时就和 C/S 一样。
