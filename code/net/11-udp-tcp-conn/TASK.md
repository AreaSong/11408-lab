> 王道第 5 章。UDP 首部 8 字节，校验和把 12 字节伪首部算进去，伪首部不传输。TCP 按字节编号：SYN 和 FIN 各消耗 1 个序号，不带数据的 ACK 不消耗。确认号是期望收到的下一字节。三次握手之后才是 ESTABLISHED；主动关闭的一方最后进入 TIME_WAIT。

## 一、本关任务

- **产出**：UDP 校验和计算器；TCP 连接状态机（三次握手、四次挥手）；序号与确认号计算器
- **小步骤**：
  ① UDP 首部 8 字节。校验和是伪首部、UDP 首部和数据的 16 位反码求和，接收端再验一遍
  ② 三次握手、四次挥手。trace 里要有双方每一步的状态，以及这一段的序号、确认号
  ③ 由数据长度推出序号和确认号。中间有段没收到时，确认号停在空洞之前
- **通过标准**：下面真题的结果行与标准答案一致；UDP 检验能区分「收下」「丢弃」和「字段为 0 时不检验」
- **概念卡片**（写进 `NOTES.md`）：传输层的功能；端口和熟知端口号；无连接服务和面向连接服务；UDP 和 TCP

每个项目有四个程序：`main.c`（如 `udp_tcp_conn_first`）、`test.c`（`udp_tcp_conn_first_test`）、`tcp.c`（`udp_tcp_conn_first_tcp`）、`seq.c`（`udp_tcp_conn_first_seq`）。

读入前用 `prompt(...)` 打印提示（`prompt` 在 `deps/prompt.h`，跑测试时自动不打印）。一行一条命令，可以连续输入，Ctrl+D 结束。空行跳过。会出内容的命令之间空一行。输入不合法时向 stderr 写原因，并以非 0 退出。每条会出内容的命令，最后一行以 `结果：` 开头。

状态名用下划线：`CLOSED`、`LISTEN`、`SYN_SENT`、`SYN_RCVD`、`ESTABLISHED`、`FIN_WAIT_1`、`FIN_WAIT_2`、`CLOSE_WAIT`、`CLOSING`、`LAST_ACK`、`TIME_WAIT`。王道图里的连字符写法是同一个状态。

## 二、主程序题目（`main.c`，UDP）

IP 写成点分十进制，每一段 0～255。端口是 0～65535 的整数。十六进制不带空格，大小写都可以，位数必须是偶数。`build` 没有数据时，数据那一项写 `-`。

| 命令 | 作用 |
|---|---|
| `sum <16位二进制> <16位二进制>` | 两个 16 位字做反码求和再取反 |
| `build <源IP> <目的IP> <源端口> <目的端口> <数据十六进制或 ->` | 生成 UDP 数据报并计算校验和 |
| `recv <源IP> <目的IP> <UDP十六进制>` | 接收端检验。报文必须完整，长度字段要和字节数一致 |
| `header <UDP十六进制>` | 只解析首部。可以只有 8 字节 |
| `demux` | 回答分用看哪个字段 |
| `eff <应用层字节数>` | UDP 和 TCP 的最大传输效率，应用层字节数 1～65535 |

`build` 的数据最长 256 字节。校验和字段在计算时先当 0。奇数长度要在说明里写明补了 0，补的字节不出现在「线上的 UDP 数据报」里。

结果行：

| 命令 | 结果行 |
|---|---|
| `sum` | `结果：1110 0000 1000 0011`，二进制每 4 位空一格 |
| `build` | `结果：校验和 0x97b6` |
| `recv` 通过或未检验 | `结果：收下` |
| `recv` 检验失败 | `结果：丢弃` |
| `header` | `结果：目的端口 69，数据 20 字节` |
| `demux` | `结果：目的端口号` |
| `eff` | `结果：60.0%，37.5%`，先 UDP 后 TCP，保留一位小数 |

### 样例

输入：

```
sum 1011100110110110 0110010111000101
```

输出：

```
【16 位反码求和】
  1011 1001 1011 0110
+ 0110 0101 1100 0101
= 1 0001 1111 0111 1011
最高位的进位要加回最低位，不能丢掉。丢掉进位会停在选项 A 那种中间结果。
回卷后：0001 1111 0111 1100
再取反：1110 0000 1000 0011（0xe083）。
选项 B 是回卷后、取反前的数。题目要的是取反之后的校验和。
这一步只加了题目给出的最后两个 16 位数，还不是整份伪首部。
结果：1110 0000 1000 0011
```

`tests/practice-check` 覆盖带伪首部的计算、奇数补 0、算出 0 时改记 `0xffff`、回卷进位，以及收下、丢弃、字段为 0。`tests/practice-tftp` 只给 8 字节首部。

## 三、连接程序（`tcp.c`）

一次运行里只有一条连接。`open` 只能做一次。`send` 和 `close` 都要求双方已经是 `ESTABLISHED`。序号是 0～4294967295 的整数。`data` 和 `send` 的字节数是 1～65535。

客户从 `CLOSED` 主动打开，服务器一开始在 `LISTEN`。第三次握手可以带数据，前两次不能。`close` 把这一侧的挥手一次做完，半关闭期间不再插入数据。`close both` 表示两个 FIN 在路上交错。

| 命令 | 作用 |
|---|---|
| `open <客户初始序号> <服务器初始序号>` | 三次握手，第三段不带数据 |
| `open <客户初始序号> <服务器初始序号> data <字节数>` | 第三段携带数据 |
| `send client <字节数>` | 客户发数据，服务器立刻累积确认 |
| `send server <字节数>` | 服务器发数据，客户立刻累积确认 |
| `close client` | 客户主动四次挥手 |
| `close server` | 服务器主动四次挥手 |
| `close both` | 同时关闭 |

挥手停在 `TIME_WAIT`，不自动再等 2MSL。结果行：

| 命令 | 结果行 |
|---|---|
| `open` 不带数据 | `结果：第二次握手确认号 2019，第三次握手确认号 2047` |
| `open` 带数据 | 上面的结果后面再加 `，下一序号 1201` |
| `send` | `结果：发送方下一序号 5001，接收方确认号 5001` |
| `close` | `结果：客户 TIME_WAIT，服务器 CLOSED`，以 trace 最后的两个状态为准 |

### 样例

输入：

```
open 2018 2046
```

输出与 `tests/tcp/2019-39.out` 一致。第三次握手的确认号是 2047。

## 四、序号程序（`seq.c`）

`cum` 的段数是 1～6。段号从 1 开始。每段长度 1～65535 字节。`at` 给出其中一段的序号，其余段按前后相接推出来。`miss` 可以写多个段号，表示这些段没收到。

| 命令 | 作用 |
|---|---|
| `cum <长度>... at <段号> <序号> [miss <段号>...]` | 累积确认号 |
| `reply <序号> <确认号> <载荷字节>` | 收到一段纯数据后，立即回复的序号和确认号 |
| `app syn <序号> fin <序号>` | SYN 和 FIN 之间的应用层字节数 |

结果行是 `结果：确认号 1000`、`结果：序号 2046，确认号 2013` 或 `结果：4000 字节`。

### 样例

输入：

```
reply 1913 2046 100
```

输出：

```
【立即回复】
收到序号 1913，确认号 2046，载荷 100 字节。
本段字节 1913～2012。
我方序号 = 对方确认号 = 2046。
我方确认号 = 1913 + 100 = 2013。
这是纯数据段，没有 SYN 或 FIN，确认号不要再额外加 1。
结果：序号 2046，确认号 2013
```
