## 二、主程序题目（`main.c`，以太网帧）

构造一帧。关键字顺序不能换。`type` 和 `len` 二选一，`bytes` 和 `data` 二选一。`vlan` 和 `pri` 可以不写。

| 命令 | 作用 |
|---|---|
| `frame dst <MAC> src <MAC> type <十六进制> bytes <n>` | 以太网 II。数据是 n 个 0。n 是 0～1500 |
| `frame dst <MAC> src <MAC> type <十六进制> data <字节> ...` | 数据用两位十六进制给出，最多 64 字节 |
| `frame ... len <十进制> bytes <n>` 或 `data ...` | IEEE 802.3。长度必须等于数据字节数，并且 ≤ 1500 |
| 上面任一命令再加 `vlan <编号> [pri <0～7>]` | 插入 802.1Q 标签。VLAN 号用 1～4094。不写 `pri` 就是 0 |

`type` 要 ≥ `0x0600`。小于等于 1500 的值是长度，不要塞进 `type`。`0x8100` 是标签的类型，不要把它写成帧的类型字段，用 `vlan`。

数据字段最少 46 字节。不够就在数据后面补 0。补上去的字节算进帧长，不算进 `len` 给出的长度。标签不占用这 46 字节。FCS 4 字节盖住从目的 MAC 到填充为止的全部内容，标签也算在里面。前导码 7 字节和帧开始定界符 1 字节不要放进帧里。

帧不超过 80 字节时，把整帧的十六进制印出来。更长就只印首部和 FCS。

### 样例

输入：

```
frame dst ff-ff-ff-ff-ff-ff src 00-11-22-33-44-55 type 0x0800 data 68 69
```

输出的结果行是：

```
结果：帧长 64 字节，数据 2 字节，填充 44 字节
```

前面要有类型或长度的判断、每个字段从第几个字节开始、填充了多少、FCS，以及十六进制。`tests/practice-pad` 是上面这一帧再加一帧带长度字段的。`tests/practice-vlan` 插标签。`tests/practice-mtu` 是 1500 字节的数据，整帧 1518 字节。

## 三、模拟程序（`sim.c`）

一次运行里的设备、链路和转发表会保留，下一条命令接着用。`clear` 全部清空。

交换机的端口号按 `link` 的先后从 1 编号。`link` 不写 `vlan` 时，交换机端口属于 VLAN 1。只有交换机的端口能写 VLAN。一台主机只能接一条链路。

| 命令 | 作用 |
|---|---|
| `host <名字> <MAC> [IP]` | 增加一台主机。名字以字母开头。IP 可省略 |
| `dev hub\|switch\|router <名字>` | 增加集线器、交换机或路由器 |
| `link <甲> <乙> [vlan <编号>]` | 把两端连起来。编号是 1～4094 |
| `domains` | 数当前拓扑的冲突域和广播域，并列出每个域里有谁 |
| `share <主机> <主机>` | 这两台主机在不在同一个冲突域、同一个广播域 |
| `send <主机> <目的 MAC>` | 这台主机发出一帧。源 MAC 用它自己的 |
| `table <交换机>` | 只打印这台交换机的转发表 |
| `compare <n>` | n 台主机分别全接在一台集线器、一台交换机、一台路由器上，各数一次。n 是 2～8 |
| `delay cut bw <数> <单位>` | 直通交换的最少转发延迟 |
| `delay store bw <数> <单位> frame <字节数> B` | 存储转发要收完这一整帧 |

名字最长 15 个字符。带宽单位用 `bps`、`kbps`、`Mbps`、`Gbps`。除法要除尽，不四舍五入。

数域的口径：

- 一台集线器，连同它上面的主机和它到交换机或路由器的那条上联线，算 **1** 个冲突域
- 交换机或路由器的一个端口直接接一台主机，这条链路算 **1** 个冲突域
- 交换机和交换机之间、交换机和路由器之间的全双工链路 **不算** 冲突域
- 广播帧过得了集线器，也过得了同一 VLAN 的交换机端口，过不了路由器。VLAN 把广播域切开，不把冲突域切开

`send` 要印出：从哪个端口进来、源地址记到了哪个端口、是泛洪、单播转发还是过滤、谁收到了、当时的转发表。收到帧的主机按名字排序。转发表按 VLAN、端口、MAC 排序，不要按散列表内部的槽位顺序印。

### 样例

输入：

```
dev switch SW
host a 02-00-00-00-00-01
host b 02-00-00-00-00-02
link a SW
link b SW
send a 02-00-00-00-00-02
```

输出：

```
【转发】
a 发出，目的 02-00-00-00-00-02。
转发决策看目的 MAC，自学习看源 MAC 和进入的端口。
交换机 SW 从端口 1 收到，VLAN 1。源 02-00-00-00-00-01，目的 02-00-00-00-00-02。
学习：把源地址记到端口 1。
目的不在这个 VLAN 的转发表里，向端口 2 泛洪。
b 收到。
转发表 SW：
02-00-00-00-00-01  端口 1  VLAN 1
结果：SW 转发端口 2；收到 b
```

`delay cut bw 10 Mbps` 的结果行是 `结果：4.80 us`。前面要有比特数、带宽和纳秒。

`tests/sim/2014-34` 是三台主机的自学习和泛洪。`tests/sim/2016-35` 是交换机下面再接一台集线器。`tests/sim/practice-filter` 是目的主机和源主机在集线器的同一侧。`tests/sim/2024-35` 按端口划分 VLAN 之后发广播。`tests/sim/2020-35` 和 `tests/sim/2022-47` 是数域。`tests/sim/practice-compare` 是 4 台主机的三种接法。`tests/sim/2013-38` 是直通交换和存储转发。

## 四、802.11 程序（`wifi.c`）

地址按王道填写。输出里要写明「去往 AP」和「来自 AP」各是 0 还是 1，再逐个写出地址字段表示谁。最后一行把这些 MAC 按地址 1、2、3（有地址 4 就带上）连起来。

| 命令 | 场景 |
|---|---|
| `sta-ap sta <MAC> ap <MAC> dest <MAC>` | 站点把帧发给 AP。`dest` 是这一帧真正要交给的目的 MAC |
| `ap-sta ap <MAC> dest <MAC> src <MAC>` | AP 把帧发给站点。`dest` 是接收这帧的站点，`src` 是真正的源 |
| `adhoc src <MAC> dest <MAC> bssid <MAC>` | 自组网，没有 AP |
| `wds ra <MAC> ta <MAC> dest <MAC> src <MAC>` | 一个 AP 把帧转给另一个 AP |

`tests/wifi/practice-modes` 是自组网和四个地址的格式。`tests/wifi/2017-35`、`tests/wifi/2022-47` 是真题里的三个地址。
