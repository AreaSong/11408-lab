## 一、本关任务

- **产出**：路由表的最长前缀匹配（Trie）；路由器转发；NAPT 转换表；ARP 请求和响应；IPv6 地址的压缩和展开
- **小步骤**：
  ① 用 Trie 做最长前缀匹配，包含默认路由
  ② 查到下一跳后把 TTL 减 1，重算首部校验和；TTL 减成 0 就丢弃并产生 ICMP
  ③ NAPT：内网地址加端口和公网地址加端口互换
  ④ ARP 缓存、请求、响应；目的不在本网段时解析的是网关
  ⑤ 用 `ping` 和 `traceroute` 看 ICMP，理解 traceroute 怎样利用 TTL。这一步不进 `tests/`，写在 `EXPERIMENTS.md`
  ⑥ IPv6 地址的零压缩和展开
- **通过标准**：给定目的地址得到下一跳；NAT 之后的地址和端口与真题一致；转发后说得清首部哪些字段变了
- **概念卡片**（写进 `NOTES.md`）：网络层的功能（异构网络互连、路由与转发、拥塞控制）；DHCP 的四步；ICMP 报文类型；IPv6 的主要特点与首部（对照 IPv4）；路由器的组成、路由表和转发表

## 二、主程序题目（`main.c`，查表和转发）

目的网络必须是网络地址，主机位不是 0 就拒绝。前缀是 0～32。直连路由不写 `via`。有下一跳时不能写 `0.0.0.0`。接口只由字母和数字组成。同一条前缀再插入一次，就替换下一跳和接口。

默认路由是前缀长度 0，挂在 Trie 的根上。查找从地址的高位往低位走，沿途每一个写了前缀的结点都是候选，留下最长的那条。一条都不中，就丢弃，ICMP 类型 3、代码 0（网络不可达）。

`pkt` 在路由表非空时先查目的地址。查不中就不再改首部。查中之后把 TTL 减 1。减完是 0，丢弃，ICMP 类型 11、代码 0（传输期间生存时间超时）。否则重算首部校验和。`nat` 同时改源地址，校验和仍只算这一次。总长度大于 1500 字节时，分片还会改总长度、标志和片偏移；本程序不切分片。

`ttl` 不看路由表。发出时的 TTL 减去路径上的路由器台数，就是终点收到的 TTL。减完不是正数，分组在中途被丢掉。

| 命令 | 作用 |
|---|---|
| `route <网络>/<前缀> dev <接口>` | 插入一条直连路由 |
| `route <网络>/<前缀> via <下一跳> dev <接口>` | 插入一条有下一跳的路由 |
| `default via <下一跳> dev <接口>` | 插入 `0.0.0.0/0` |
| `lookup <目的 IP>` | 最长前缀匹配 |
| `ttl <1～255> hops <0～255>` | 经过这么多台路由器之后的 TTL |
| `pkt <两位十六进制> ...` | 转发这一份首部：TTL 减 1，重算校验和 |
| `pkt nat <新源地址> <两位十六进制> ...` | 同上，并改源地址 |
| `reset` | 清空路由表 |

直连的下一跳印成 `直连`。首部至少 20 字节，版本是 4，IHL 至少为 5，给出的字节要盖住首部，校验和要和重算一致。

结果行：

| 命令 | 结果行 |
|---|---|
| `route` / `default` | `结果：已插入 194.17.20.128/25` |
| `lookup` 查中 | `结果：下一跳 直连，接口 E0` 或 `结果：下一跳 10.1.1.2，接口 L0` |
| `lookup` 查不中 | `结果：没有匹配的路由，ICMP 终点不可达，类型 3，代码 0` |
| `ttl` 到得了 | `结果：TTL 61` |
| `ttl` 到不了 | `结果：丢弃，ICMP 时间超过，类型 11，代码 0` |
| `pkt` 转发了 | `结果：改变了 TTL、首部校验和`。路由表非空时前面加上下一跳和接口。做了 NAT 则写成 `改变了源地址、TTL、首部校验和` |
| `pkt` 因 TTL 丢掉 | `结果：丢弃，ICMP 时间超过，类型 11，代码 0` |
| `pkt` 查不中 | `结果：丢弃，ICMP 终点不可达，类型 3，代码 0` |

## 三、NAT 程序（`nat.c`）

一台路由器先写名字，再写动作。名字是字母和数字，最长 7 个字符。最多同时记 4 台。`emit` 不建表，只把主机发出时的分组印出来。

`basic` 只替换 IP，端口留着。`pool` 从端口池里分配公网端口，多个内网主机可以共用一个公网地址。`map` 是静态的公网地址加端口到内网地址加端口。协议写 `tcp` 或 `udp`。端口是 1～65535。

出站按（协议，内网地址，内网端口）查表，没有就新建。入站按（协议，目的地址，目的端口）查公网侧的键，把目的改成内网那一端。源在入站时不变，目的在出站时不变。

| 命令 | 作用 |
|---|---|
| `<名字> map <tcp\|udp> <外网 IP> <外网端口> <内网 IP> <内网端口>` | 静态映射 |
| `<名字> basic <公网 IP>` | 基本 NAT，只改 IP |
| `<名字> pool <公网 IP> <起始端口> <结束端口>` | NAPT 的端口池 |
| `<名字> emit <tcp\|udp> <源 IP> <源端口> <目的 IP> <目的端口>` | 主机发出，还没进路由器 |
| `<名字> out ...` | 出站转换。四个地址参数和 `emit` 一样 |
| `<名字> in ...` | 入站转换。四个地址参数和 `emit` 一样 |

`basic` 和 `pool` 不能在同一台路由器上各设一次。公网地址加端口已经被占用就拒绝。

结果行带着端口，例如 `结果：源 201.1.3.10:49152，目的 130.18.10.1:80`，静态映射是 `结果：外网 203.10.2.2:80，内网 192.168.1.2:80`。

### 样例

输入：

```
gw pool 172.16.0.1 40000 40007
gw out tcp 192.168.0.2 1234 1.2.3.4 80
```

```
结果：公网地址 172.16.0.1，端口 40000-40007
结果：源 172.16.0.1:40000，目的 1.2.3.4:80
```

## 四、ARP 程序（`arp.c`）

MAC 写成 `00-15-c5-c1-5e-28`，六段十六进制，用减号分开。输出用小写。

`ask` 的 `<网关>/<前缀>` 同时给出默认网关和本网段前缀。目的和本机落在同一个网络里，就解析目的自己；否则解析网关。缓存里有就不再广播。没有就发请求：以太网目的 MAC 是 `ff-ff-ff-ff-ff-ff`，操作码 1，目标 MAC 先填 0。

`reply` 必须回答当前这个请求。响应是单播，操作码 2。响应方从请求里学到请求方的映射；请求方记下响应方的映射。

`observer`、`vlan`、`which` 用来判断一条表项会不会出现在观察者的 ARP 表里。ARP 请求是广播，出不了观察者所在的 VLAN。

| 命令 | 作用 |
|---|---|
| `host <IP> <MAC>` | 本机 |
| `ask <最终目的 IP> gw <网关 IP>/<前缀>` | 决定解析谁，必要时广播请求 |
| `reply <IP> <MAC>` | 对当前请求给响应 |
| `observer <VLAN 号>` | 观察者在哪个 VLAN |
| `vlan <VLAN 号> <IP> <MAC>` | 登记一台主机的 VLAN |
| `which <IP>` | 这台主机会不会出现在观察者的 ARP 表里 |

结果行：

| 情形 | 结果行 |
|---|---|
| 发出请求 | `结果：ARP，目的 MAC ff-ff-ff-ff-ff-ff` |
| 缓存里已有 | `结果：缓存命中，MAC 00-21-27-21-51-ee` |
| 收到响应 | `结果：10.2.128.1 的 MAC 是 00-21-27-21-51-ee` |
| 同一 VLAN | `结果：192.168.3.81 在 VLAN 1，可以出现` |
| 不同 VLAN | `结果：192.168.3.129 在 VLAN 3，不会出现在 VLAN 1 的 ARP 表` |

`tests/arp/practice-cache` 在收到响应之后再问一次同一个网关，然后问一台本网段上的主机。

## 五、IPv6 程序（`ipv6.c`）

地址 8 段，每段 1～4 位十六进制。`::` 最多出现一次，而且至少代表一段 0。压缩时省略前导零；连续 0 至少两段才用 `::`，有好几处一样长就压最左边的。全 0 写成 `::`。展开把每一段补成 4 位。

| 命令 | 作用 |
|---|---|
| `compress <地址>` | 压成 RFC 5952 的写法 |
| `expand <地址>` | 展开成 8 段、每段 4 位 |

结果行就是这一条地址，例如 `结果：2001:db8::1` 和 `结果：2001:0db8:0000:0000:0000:0000:0000:0001`。
