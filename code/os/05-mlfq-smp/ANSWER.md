## 思路

处理机调度仍然只回答一句：现在让谁跑，跑到什么时候停。第 04 关的停法是运行完、时间片用完、来了严格更合适的进程。本关加上阻塞，并且「更合适」在反馈队列里写成「更高的那一级队列里有人」。

甘特图仍是左闭右开。`0-1 P1` 是时刻 0，时刻 1 已经交给下一段。

### 反馈队列的级

王道的多级反馈队列是若干条就绪队列，第 1 级优先级最高，时间片最小。新进程先到第 1 级队尾。轮到它时给一个本级时间片：这段里跑完了就离开；时间片用完还没完，就降到下一级队尾。最后一级不再降，在本队列里按时间片轮转。只有更高的队列空了，才轮到较低的队列。正在较低队列里运行时，若有进程进入更高的队列，就把正在运行的进程放回它现在这一级的队尾，CPU 让给更高的队列。

程序里队列从 0 编号，0 就是王道的第 1 级。`run mlfq 3 1` 的时间片是 1、2、4。输出头上的 `quantum=1,2,4` 和 `idle=yes` 把这两条约定写死：时间片翻倍，而且始终有一个闲逛进程。

同一时刻的次序写在 `mlfq_step.c` 的 `drive` 里，和单级 RR 对齐：先让新进程进入第 0 级，再处理时间片用完。新进程因此排在「刚用完时间片、仍留在本队列」的进程前面。结束或阻塞先于降级。进程在这一刻已经不想再占 CPU，不能再记一次降级。

被抢占之后放回本队列队尾。王道没有写「没用完的那半个时间片还留不留」。本关每次上 CPU 都把 `used` 清零，重新拿满本级时间片。半片不累计。这是本关的约定，写在 `rule fresh-slice`。

`practice-mlfq` 是 3 级、第 0 级时间片为 1，三个进程 P1(0, 4)、P2(1, 2)、P3(3, 1)：

```
0-1 P1   1-2 P2   2-3 P1   3-4 P3   4-5 P2   5-7 P1
```

时刻 1，P1 用完第 0 级的 1，降到 q1；P2 刚刚到达，在 q0，所以下一拍是 P2。时刻 3，P1 正在 q1 上跑，时间片是 2，才用了 1；P3 进入 q0。q0 比 q1 高，P1 被放回 q1 的队尾，trace 是 `preempt P1 stay q1`。P3 只有 1 个单位，跑完就结束，不降级。完成时刻是 P1 = 7、P2 = 5、P3 = 4。平均等待 `5/3`。

P3 结束时所在的级是 0。它没被降过。P1 和 P2 都在 q1 里跑完，表上的 `level` 是 1。

只有一个进程、时间片用完后队列里还是它自己时，调度程序会再选中它，但不用换成别人。`practice-keep` 里 P 在时刻 1 从 q0 降到 q1，下一行是 `from=P to=P switch=no`，甘特图连成 `0-3 P`。时间片到了会引起调度；切换要等选中的是另一个进程。`claim slice-always-switch` 因此是 `false`。

同一级里后来的进程也不抢占。`practice-same` 只有一级，时间片是 4。P2 在时刻 1 到达，P1 的时间片还没用完，P1 继续跑到时刻 3 才结束。若误把「同级的新进程」也当成抢占，P1 的完成时刻就不会是 3。

### 2019-27 不是「时间片翻倍」

这道题的 Q2 是短进程优先，不是再给一个翻倍的时间片。`run fb2` 单独做这套规则：q0 时间片 10，用完降到 q1；q1 比剩余 CPU，时间片记 0，所以不会因为时间片再降一次。只有 q0 非空才抢占 q1。

P1 需要 30，P2 需要 20，都在时刻 0 创建，P1 先入队：

```
0-10 P1   10-30 P2   30-50 P1
```

时刻 10，P1 降到 q1，还剩 20。时刻 20，P2 也降到 q1，还剩 10。q1 选更短的 P2。P2 自己刚从 q0 下来，q1 里它又是最短的，所以 `from=P2 to=P2 switch=no`，甘特图把 10 到 30 连成一段。P2 在时刻 30 结束，P1 再跑 20，时刻 50 结束。

等待时间：P1 是 50 − 30 = 20，P2 是 30 − 20 = 10，平均 `(20+10)/2 = 15`。输出是 `avg wait=15/1`。选项 A 到 D 是 25、20、15、10，对应 C。

P2 的响应时间是 10：它在时刻 10 才第一次上 CPU。题目问的是平均等待，不是响应。

### 闲逛进程和阻塞

没有用户进程就绪时，CPU 不能没有归属。王道设一个优先级最低、永远就绪的闲逛进程，调度程序就总能选出一个进程。它不参加周转时间的平均。`idle=yes` 每行输出都有。有空隙时甘特图画 `idle`，例如 `practice-idle` 的 `1-3 idle`：P1 在时刻 1 结束，P2 要到时刻 3 才到。最后一个用户进程结束之后，trace 里还有一次 `to=idle`，甘特图不再往后画，因为后面没有要度量的时刻。

阻塞是主动让出 CPU。`practice-block` 里 P1 先跑 1，再阻塞 2，唤醒后再跑 1。时刻 1 的原因是 `block`，不是 `slice`。阻塞时不降级，时刻 3 唤醒后仍回 q0。等待时间要减去 I/O：P1 的周转是 4，CPU 合计 2，I/O 是 2，等待是 0。P2 没有 I/O，等待是 1。时间片用完时队列里只有 P2，所以有一行 `switch=no`，甘特图仍是连续的 `1-3 P2`。

### 现在能不能换人

会引起调度的事件，王道分成主动放弃和被动放弃。主动：运行结束、异常结束、自己阻塞。被动：时间片用完、来了更高优先级的进程。2012-30 还把「创建新进程之后」和「系统调用完成、返回用户态」算进可以调度的时机。题目的前提是系统里还有别的就绪进程，所以这些事件都是 `want=yes`。

不能在三处马上切换：正在处理中断、正处在操作系统内核程序临界区、正在执行要屏蔽中断的原语。内核临界区碰的是内核自己的数据结构，例如就绪队列。还没解锁就换人，调度程序也要碰这条队列，会拿不到锁。普通临界区碰的是打印机这类临界资源。打印机很慢，这段时间若不许换人，CPU 就空等。所以「进程处于临界区就不能调度」这句是错的，2012-30 选 C。`claim user-cs-cannot` 是 `false`。`claim kernel-cs-cannot`、`interrupt-cannot`、`atomic-cannot` 是 `true`。

`hold` 把这件事拆开。`hold interrupt exit` 打出 `switch=defer`，再加一行 `after leave switch=now`：中断处理过程中不换人，中断返回时可以换。`hold user-cs slice` 是 `switch=now`。`hold interrupt return` 也是 `switch=now`，因为 `return` 本身就是回到用户态的那一刻，2012-30 的 D 说这时能调度。

### 两颗 CPU

多处理机调度是 2025 考纲写进来的。本关只做对称的两颗 CPU，进程可以放到任意一颗上，再比较队列怎么组织。

共享一条就绪队列时，哪颗 CPU 空了就自己取队头。负载自然被拉平，不必再写一次「负载均衡」。所以命令里的 `off` 和 `balance` 对共享队列是同一套算法，输出固定写 `balance=shared`。代价是进程容易换 CPU，上次留在那颗核缓存里的数据用不上。这就是迁移。

私有队列是每个 CPU 一条。进程到达时放到当时更空的那条，人数相同放 CPU 0。不做均衡时，一个 CPU 跑完了也不会去拿另一个 CPU 队列里的进程，迁移少，但可能一边闲着一边还有人等。做均衡时，只在自己已经空闲、自己的就绪队列也空，而对方还忙的时候，从对方队尾拉一个就绪进程。不把正在运行的进程拽下来，也不把对方唯一的那个就绪进程抢走，否则两个空闲 CPU 会把同一个进程推来推去。

`practice-balance` 用 A、B、C 三个进程，都在时刻 0 到达，服务时间都是 4，时间片 2，亲和都不指定：

| 组织 | 迁移 | 全部完成 |
|---|---|---|
| 共享队列 | 3 | 6 |
| 私有队列，不均衡 | 0 | 8 |
| 私有队列，从队尾拉 | 1 | 6 |

共享队列的甘特图是：CPU 0 上 `0-2 A`、`2-4 C`、`4-6 B`；CPU 1 上 `0-2 B`、`2-4 A`、`4-6 C`。A、B、C 各换了一次 CPU。私有队列不均衡时，C 一直跟在 CPU 0 上，CPU 1 从时刻 4 到 8 是 `idle`，所以要到时刻 8 才全部结束，迁移是 0。打开均衡后，时刻 4 CPU 1 已经空了，CPU 0 的就绪队列里有 A 和刚用完时间片的 C，把队尾的 C 拉走。C 的 CPU 序列是 `0,1`，迁移合计 1，时刻 6 结束。

亲和和均衡是对着干的。硬亲和：指定了 0 或 1 的进程只能在那颗 CPU 上跑。`practice-affinity` 里 A、B 都指定 CPU 0，硬亲和下 CPU 1 从 0 到 6 全是 `idle`，迁移 0，A 要到时刻 6 才结束。软亲和仍优先把它们放在 CPU 0 上，但 CPU 1 没有自己的进程可跑时可以拿走 B。B 的第一次运行就在 CPU 1 上，迁移记 1，全部完成提前到时刻 4。软亲和在共享队列里允许这种「第一次就没跑在指定 CPU 上」；私有队列做均衡时，软亲和和硬亲和都不把指定了另一颗 CPU 的进程拉走。

还没运行过的进程，只是在就绪队列里换了一条队，先不计迁移。等它真的在一颗新的 CPU 上开始跑，再按「上次的 CPU」或「指定的亲和」加 1。缓存要等它跑起来才热。

### 切换时保存什么

进程切换要保存旧进程的 CPU 现场，再恢复新进程的现场。现场在进程不运行时放在 PCB 里：程序计数器、程序状态字、通用寄存器、栈的位置。支持页式存储时，还要把页表基址寄存器改成新进程的页表。代码和数据本来就在内存里，不用在切换时再复制一份。2024-25 的 I、II、III 都要做，答案是 D。`claim switch-only-ptbr` 是「只更新页表基址」这句，它是错的。

同一进程的两个线程共用地址空间，切换时不改页表基址，TLB 也可以留着。用户级线程的切换在用户态完成，内核看不到这些线程，调度单位仍是进程；一个线程阻塞，整个进程都阻塞。内核级线程由操作系统调度，切换要进内核，但只要还是同一个进程，仍然不换页表。2019-23 里错误的是 B：操作系统并不为每个用户级线程各建一个线程控制块。那是一对一的内核线程才有的事。这道题在第 02 关用来看线程的实现，本关看的是调度由谁做。

2025-25 问的是优先级就绪队列用单链表、高优先级放在队头时的复杂度。插入要沿链表找到位置，是 O(n)；选出队头是 O(1)。答案是 C。本关的反馈队列按级分开，级内是队头或按剩余时间挑，不把所有进程串成一条按优先数排序的链表。这句话放在 `queue prio-list`，用来记住调度程序自己的数据结构也有代价。

基本的多级反馈队列没有「等太久就抬回最高级」。更高的队列若一直有新进程，最低级里的长进程会一直轮不到。最低级内部的时间片轮转，只保证轮到这一级之后大家按片转，不保证这一级进得去。`claim mlfq-starve-without-boost` 是 `true`。王道说它能照顾长作业，指的是高优先级队列会空出来的时候；不断有短进程到来时，这句不能说死。

## 易错点

1. **2019-27 的第二级是短进程优先。** 时间片逐级翻倍是 `run mlfq`。用翻倍的时间片去跑这道题，平均等待对不上 15。
2. **队列从 0 编号。** 输出里的 q0 是题目里的 Q1。`level` 是进程结束时所在的级，不是它到过的最高级。
3. **更高的队列才抢占。** 同一级的新进程要等这次时间片结束。`practice-same` 专门看这个。
4. **结束和时间片边界撞在一起，算结束或阻塞。** 进程已经不再要 CPU，不能再降一级。
5. **被抢占不降级，而且下次重新拿满时间片。** 王道写了「放回本队列末尾」，没写半个时间片留不留。本关不留。
6. **阻塞不降级。** 等待时间还要减 I/O。只减 CPU，会把阻塞的那段算进等待。
7. **调度不等于切换。** 时间片用完一定调度；选中的还是自己时 `switch=no`，甘特图合并。
8. **闲逛进程不进平均。** 有空隙才在甘特图里出现。最后一个进程结束时的 `to=idle` 不再往右画。
9. **共享队列的迁移可以比私有队列多，完成时刻可以更早。** `practice-balance` 里是 3 次对 0 次，时刻 6 对时刻 8。打开私有队列的均衡后，迁移是 1，完成时刻回到 6。
10. **硬亲和可以让另一颗 CPU 空转。** 软亲和在共享队列里仍可能把进程第一次就放到别的核上，那一次也算迁移。
11. **均衡不抢占正在运行的进程。** 只拉就绪队列队尾。对方只剩一个就绪进程、自己又没在跑时，不拉，避免两颗空闲 CPU 对推。
12. **同进程的线程切换不改页表基址。** 2024-25 的页表基址是进程切换才要的。用户级线程的切换可以不进内核。
13. **管道测到的纳秒数不是考点。** 它随机器变，而且多核上常常是往返延迟。进程版和线程版在这台机器上只差零点几微秒，见 `EXPERIMENTS.md`。

## 概念卡片参考答案

### 卡片：抢占 vs 非抢占

| | 非抢占 | 抢占 |
|---|---|---|
| 谁让出 CPU | 运行结束、阻塞、自己放弃 | 再加上时间片用完、更高优先级到达 |
| `way` | `nonpreempt` | `preempt` |
| 典型算法 | FCFS、SJF、HRRN | RR、SRTN、多级反馈队列、抢占式优先级 |
| 适合 | 早期批处理，实现简单 | 分时、实时 |

狭义的调度是从就绪队列里选一个进程。切换是这个进程和正在运行的不是同一个，要把现场换掉。时间片用完时总会调度；队列里只有自己，就不再切换。`when slice` 的 `switch=if-other` 说的就是这件事。

不能马上切换的三处：处理中断的过程中、内核程序临界区、原语。普通临界区可以切换。

### 卡片：两类线程的调度

| | 用户级线程 | 内核级线程 |
|---|---|---|
| 谁调度 | 用户态线程库 | 操作系统 |
| 切换 | 用户态，不陷入内核 | 要进内核 |
| 内核看见什么 | 只看见进程 | 看见每一个线程 |
| 一个线程阻塞 | 整个进程阻塞 | 同进程的其他线程还能跑 |
| 页表基址 | 同进程，不换 | 同进程也不换；换成另一个进程才换 |
| `thread` | `ult` | `klt` |

用户级线程可以在内核不支持线程的系统上做。操作系统不为每个用户级线程建立线程控制块，2019-23 的 B 错在这里。用户级切换少一次进内核，所以通常比内核级线程切换便宜；这和 `EXPERIMENTS.md` 里「进程对线程的管道往返几乎一样贵」不矛盾，那次测的是管道系统调用，不是纯线程切换。

进程切换另外要更新程序计数器、栈的位置和页表基址寄存器。代码段不用在切换时复制。
