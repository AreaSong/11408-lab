# os/05 · 本机实验记录

> 2026-10-25，macOS 26.6.2，arm64。`uname -a` 给出 Darwin 25.6.0，`xnu-12377.161.14~5/RELEASE_ARM64_T6041`。下面的纳秒数是这一台机器上的两次运行。进程是否把字节送回来，以 `tests/switch/` 为准，不随这次计时变化。

## 1. 一对管道来回 10 万次

交互运行 `switch`（设置了 `LAB_TEST`，所以没有提示），输入：

```
process 100000
thread 100000
```

第一次：

```
kind=process rounds=100000 switches=200000 elapsed-ns=491643000 per-ns=2458
kind=thread rounds=100000 switches=200000 elapsed-ns=453376000 per-ns=2266
```

紧接着再跑一次：

```
kind=process rounds=100000 switches=200000 elapsed-ns=498115000 per-ns=2490
kind=thread rounds=100000 switches=200000 elapsed-ns=467451000 per-ns=2337
```

一次来回记 2 次切换：父方（或主线程）写一个字节再读回复，读不到就停在管道上；对方读到之后写回，再去读下一个字节时也会停住。10 万次来回是 20 万次这样的停顿。`per-ns` 用总纳秒除以 20 万，整数除法。

两次里，进程大约 2.5 微秒，线程大约 2.3 微秒。差的是零点几微秒，不是一个数量级。读和写都要进内核，这份开销盖过了「换不换地址空间」。

## 2. 这个数不是同核切换的常数

两颗可运行的执行体在这台多核机器上可以并行。父方阻塞在读上时，子方可能已经在另一颗核上跑，测到的是一次往返的墙钟时间，里面有唤醒，不保证是同一颗核上把寄存器换下来再换上去。

所以 `per-ns` 用来看进程版和线程版谁更贵、贵在哪里，不用来背「上下文切换就是多少纳秒」。进程切换比同进程的线程切换多更新页表基址寄存器，还可能让 TLB 失效；这次实验里那一项没有单独露出来。

`check process` 和 `check thread` 只来回 3 次，确认字节 `A` 原样回来。那两行在 `tests/switch/practice-pipe.out` 里，和这次的纳秒数无关。
