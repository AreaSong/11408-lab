# os/12 · 页面置换与工作集 · 题目

> 本文件只写题目，不含思路和代码，做题前可以放心看；答案讲解在 `ANSWER.md`，做完再看。

王道第 3 章，页面置换。请求分页在第 11 关。本关比较 OPT、FIFO、LRU、CLOCK、改进型 CLOCK，并算工作集。缺页次数按题目约定：装进空页框算缺页，不算置换。

## 一、本关任务

- **产出**：页面置换模拟器。按王道的表，打印每一步内存里有哪些页、这次是缺页还是命中。另有工作集计算器
- **小步骤**：
  ① FIFO 与 OPT
  ② LRU，用双向链表记使用顺序，用拉链散列表判断这一页在不在
  ③ CLOCK 与改进型 CLOCK
  ④ 用程序去找 Belady 异常，不要把例子写死在代码里
  ⑤ 给定访问串和窗口，求某一时刻的工作集；减少页框，看缺页率在哪一档陡增
  ⑥ 分别改页面大小、页框数、置换算法、访问串的局部性，看缺页率怎么变
- **通过标准**：给定访问串和页框数，能求出缺页次数、缺页率，或某次访问淘汰了哪一页；能求出某时刻的工作集；能说出改进型 CLOCK 的淘汰顺序
- **概念卡片**（写进 `NOTES.md`）：抖动的原因与对策

每个项目有两个程序：`main.c` 编出的主程序（与项目同名，如 `page_replace_first`）、`test.c` 编出的单元测试（`page_replace_first_test`）。本关的实验都由输入决定，不读本机时间，没有 `EXPERIMENTS.md`。

## 二、主程序题目（`main.c`）

每条命令占一行，读到输入结束为止。空行跳过。`#` 开头的行是注释，跳过。每次读取前用 `prompt(...)` 打印「请输入命令，Ctrl+D 结束：」。第一条错误就停，退出码为 1。算完的缺页、命中、淘汰都是正常结果，退出码为 0。

页号、页框数、地址都是十进制。`010` 是 10，不是八进制。页号可以写 `7` 或 `7r`，都表示读；`7w` 表示写。页号从 0 到 1000000。一次 `run` 最多 48 次访问，页框数是 1 到 8。

| 命令 | 含义 |
|---|---|
| `run <算法> <页框数> <页...>` | 内存一开始是空的 |
| `run <算法> <页框数> warm <页...> ref <页...>` | `warm` 里的页已经在内存，从旧到新，不算进访问串，也不算缺页 |
| `preset <clock\|clock2> <页:访问位.修改位> ... ref <页>` | 环已经装满，指针指着第一页，然后只访问这一页 |
| `ws <窗口> <页...>` | 访问串走完之后的工作集 |
| `thrash <算法> <页...>` | 页框从多到少，看缺页从哪一档开始跳 |
| `size <算法> <页框数> <页字节> <地址...>` | 先把字节地址换成页号，再只印合计 |
| `sweep frames <算法> <页...>` | 页框从 1 画到 6（访问串更短就画到串长），只印合计 |
| `sweep algos <页框数> <页...>` | 按 opt、lru、clock、clock2、fifo 的顺序各跑一次，只印合计 |
| `locality <页框数>` | 同一页框数上，循环访问和顺序扫一遍 |
| `belady` | 在指定范围内搜索第一组 Belady 异常 |
| `exam <题号>` | 打印该题的结论 |
| `claim <名字>` | 打印一条判断 |
| `card` | 按固定顺序打概念卡片 |

算法名：`fifo`、`lru`、`opt`、`clock`、`clock2`。`clock` 是简单 CLOCK，`clock2` 是改进型 CLOCK。

命令拼错、参数个数不对、`warm` 后面没有 `ref`、`sweep` 的种类不是 `frames` 或 `algos`，是 `bad-command`。整数读不出来、越界、页字节不是不小于 2 的 2 的幂、访问位或修改位不是 0 或 1、读写后缀不是 `r` 或 `w`，是 `bad-number`。算法名不认识是 `bad-algo`。`warm` 或 `preset` 里同一页出现两次是 `duplicate`。一行超过缓冲区是 `bad-line`。未知题号是 `bad-exam`。未知判断是 `bad-claim`。

`warm` 里的页是普通整数，不带 `r` 或 `w`，个数是 1 到页框数，不能有重复。它们按从旧到新装入：写在前面的更老。

`preset` 的每一格写成 `页号:访问位.修改位`，例如 `2:0.1`。至少 1 格，最多 8 格。`ref` 后面正好一个页。

### 一步的打印

页框是稳定的槽。淘汰谁，就盖掉谁的那一格，其他格不动。空槽印 `-`。没有淘汰时 `victim=-`。

FIFO 另印队列，队头（最老）在左。LRU 另印栈，最近使用的在左。OPT 只有槽。CLOCK 和 CLOCK2 另印每位的 `访问位.修改位`，以及指针正指着的页号。改进型 CLOCK 发生淘汰时再印扫了几轮，`passes` 从 1 数起。

装进空页框：`result=fault`，`victim=-`。这次计入缺页，不计入置换。真正选出被淘汰页时，缺页和置换都加 1。缺页率是缺页次数除以访问次数，不约分。

```
algo=fifo frames=3 refs=5
t=1 page=1 rw=r result=fault victim=- slots=1 - - queue=1
t=4 page=1 rw=r result=hit victim=- slots=1 2 3 queue=1 2 3
t=5 page=4 rw=r result=fault victim=1 slots=4 2 3 queue=2 3 4
summary faults=4 replaces=1 rate=4/5
```

写一次时 `rw=w`。简单 CLOCK 淘汰后的一行带 `bits` 和 `hand`。改进型 CLOCK 再带 `passes`：

```
t=1 page=9 rw=r result=fault victim=1 slots=0 9 2 bits=1.0 1.0 0.1 hand=2 passes=1
```

`size` 先印页号，再印合计：

```
page-bytes=256 algo=lru frames=2
pages=0 0 0 0 1 1 0 0
summary algo=lru frames=2 faults=2 replaces=0 rate=2/8
```

页号等于字节地址除以页字节，余数丢掉。

`ws` 的窗口是已经完成的最近这么多次访问，含最后一次。集合按页号从小到大印。

```
t=10 window=6
recent=6 0 3 2 3 2
set=0 2 3 6
size=4
```

`thrash` 从不同页的个数往下减页框，最多从 6 开始。`jump-below` 是缺页第一次变多时、上一档的页框数。

`locality` 固定用 LRU。`loop` 把 0、1、2 重复到 24 次。`scan` 把 0 到 7 重复到 24 次。

`belady` 不带参数。它在页号 1 到 5、长度 8 到 12、字典序下，找第一组「FIFO 用 3 个页框的缺页少于 4 个页框」的访问串，再把五种算法在 3 个和 4 个页框上的缺页都印出来。`note` 由算出来的升降拼成，不写死。

`sweep` 的合计行是 `summary algo=... frames=... faults=... replaces=... rate=...`。

其余命令的整段输出以 `tests/` 里的同名 `.out` 为准。

## 三、真题题面

**2014-30** 在页式虚拟存储管理系统中，采用某些页面置换算法，会出现 Belady 异常现象，即进程的缺页次数会随着分配给该进程的页框个数的增加而增加。下列算法中，可能出现 Belady 异常现象的是（ ）。

I. LRU 算法　　II. FIFO 算法　　III. OPT 算法

A. 仅 II　　B. 仅 I、II　　C. 仅 I、III　　D. 仅 II、III

**2015-27** 系统为某进程分配了 4 个页框，该进程已访问的页号序列为 2，0，2，9，3，4，2，8，2，4，8，4，5。若进程要访问的下一页的页号为 7，依据 LRU 算法，应淘汰页的页号是（ ）。

A. 2　　B. 3　　C. 4　　D. 8

有的转载把 `8,4,5` 印成 `8,5`。希赛和 2015 年题面写的是 `2,4,8,4,5`，本关用这一条。

**2016-26** 某系统采用改进型 CLOCK 置换算法，页表项中字段 A 为访问位，M 为修改位。A=0 表示页最近没有被访问，A=1 表示页最近被访问过。M=0 表示页没有被修改过，M=1 表示页被修改过。按 (A, M) 所有可能的取值，将页分为四类：(0,0)、(1,0)、(0,1) 和 (1,1)，则该算法淘汰页的次序为（ ）。

C. (0,0)，(0,1)，(1,1)，(1,0)

D. (0,0)，(1,1)，(0,1)，(1,0)
