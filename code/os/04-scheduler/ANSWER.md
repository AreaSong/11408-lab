## 思路

处理机只有一个。调度算法要回答的只有一句：现在让谁跑，跑到什么时候停。停的原因在本关有三种：它运行完了，时间片用完了，或者来了严格更合适的进程。

### 时间怎么走

模拟按整数时刻推进。时刻 t 的开头先处理「谁在这一刻进入就绪」，再决定 CPU 上下一个单位时间跑谁。甘特图 `a-b P` 是区间 [a, b)。`7-11 P2` 表示 7、8、9、10 是 P2，11 不是。

没有就绪进程时画出 `idle`。这不是闲逛进程，第 05 关再把空闲做成一个真正的进程。

周转时间 = 完成时刻 − 到达时刻。带权周转时间 = 周转时间 / 服务时间，纯 CPU 下它至少是 1。等待时间 = 周转时间 − 服务时间。响应时间 = 第一次拿到 CPU 的时刻 − 到达时刻。响应时间只看第一次，等待时间把后来被抢占、在就绪队列里耗掉的时间也算进去。2023-29 的 P1 响应时间是 0，等待时间是 55：它在 0 时刻就上了 CPU，但中间被抢占，一共有 55 个单位没在跑。

到达时刻写成负数，是为了 2018-24。表里的「等待时间」是 T 时刻之前已经等过的，程序里写成到达时刻 = −等待时间。周转时间用完成时刻减去这个负数，那段历史等待还在。

### 先来先服务和两个「短」

FCFS 非抢占，按到达顺序。对长作业有利，不会饥饿。王道那组进程是 P1(0, 7)、P2(2, 4)、P3(4, 1)、P4(5, 4)：

| 进程 | 完成 | 周转 | 带权周转 | 等待 |
|---|---|---|---|---|
| P1 | 7 | 7 | 1/1 | 0 |
| P2 | 11 | 9 | 9/4 | 5 |
| P3 | 12 | 8 | 8/1 | 7 |
| P4 | 16 | 11 | 11/4 | 7 |

平均周转 35/4 = 8.75，平均带权 7/2 = 3.5，平均等待 19/4 = 4.75。

SJF 也非抢占，当前进程结束时，在已经到达的进程里选服务时间最短的。题目没写「抢占」时，短作业优先就是这一种。上面那组在时刻 7 才重新选择，P3 的服务时间是 1，所以顺序是 P1、P3、P2、P4。P2 和 P4 服务时间都是 4，P2 到得更早。平均周转 8/1，平均带权 41/16 = 2.5625，平均等待 4/1。

SRTN 是 SJF 的抢占版，也叫最短剩余时间优先。新进程的剩余时间必须严格更短才抢占，相等就让正在跑的继续。同一组的甘特图是：

```
0-2 P1  2-4 P2  4-5 P3  5-7 P2  7-11 P4  11-16 P1
```

时刻 2，P1 还剩 5，P2 是 4，P2 抢占。时刻 4，P2 还剩 2，P3 是 1，P3 抢占。时刻 5，P3 刚好结束，P4 到达，剩余时间里 P2 的 2 最短。平均周转 7/1，平均带权 169/112，平均等待 3/1。比 SJF 更小。所以「SJF 的平均等待时间一定最少」这句话过严：到达时刻不同时，SRTN 可以更短。所有进程同时到达时，没有后来者可以抢占，SRTN 和 SJF 是同一种选法，这时 SJF 在非抢占算法里平均等待最少。

SJF 和 SRTN 都会饥饿：短进程不断到来，长进程一直轮不到。而且服务时间要事先知道，用户报的数也可以作假。

### 高响应比

响应比 = (等待时间 + 要求服务时间) / 要求服务时间 = 1 + 等待时间 / 要求服务时间。非抢占，只在当前进程结束时重算。短作业的分母小，响应比容易高；长作业等久了，分子变大，响应比也会爬上去，所以不会饥饿。等待时间相同且大于 0 时，服务时间短的响应比一定更高，这是公式本身的结果。

等待时间都是 0 时，响应比都是 1/1，公式分不出长短。本关这时按先来先服务：先到的优先，同时到达则按输入顺序。`practice-tie` 里 P1(0, 10) 和 P2(0, 2) 同时到达，HRRN 先跑 P1，SJF 先跑 P2。王道那组四进程的等待时间在重新选择时都大于 0，HRRN 和 SJF 的顺序碰巧一样，都是 P1、P3、P2、P4。时刻 7 的响应比是 P2 = 9/4，P3 = 4/1，P4 = 3/2。

2017-23 若在 t = 2 用 HRRN，J1 的响应比是 5/3，J3 是 3/2，J1 更高。这道题问的是 FCFS 和 SJF，不是 HRRN。

### 时间片轮转

RR 只用于进程调度：时间片是 CPU 上的时间。就绪队列仍按到达顺序，队头运行一个时间片；没跑完就到队尾。时间片还没用完就运行结束的，主动放弃 CPU，不把剩下的时间片留给别人。

王道约定写在 `rule rr-join`：同一时刻新进程先入队，时间片刚用完的进程跟在后面。`practice-rr` 第一组在时刻 2 的记录是 `ready 2 queue P2 P1 -> P2`。P1 的时间片用完，P2 刚好到达，下一拍是 P2。时刻 4 则是 `P1 P3 P2`：P1 本来就在队列里，P3 是新到的，P2 是刚用完时间片的。

时间片用完时队列里没有别人，进程继续跑，再拿一个时间片。第二组 P4 在时刻 14 就是这样，记录是 `keep 14 P4`，甘特图连成 `12-16 P4`。剩余时间小于时间片时按剩余时间结束，例如 P3 只跑了 `6-7`。

这组 q = 2 的完成时刻是 P1 = 16、P2 = 9、P3 = 7、P4 = 15。平均周转 9/1，比 FCFS 的 8.75 还大一点。RR 要的是响应时间，不是把平均周转压到最小。时间片大到每个进程都能在自己的时间片里跑完，RR 就退化成 FCFS。时间片太小，切换次数上去，开销变大。

2017-27 里错误的是 B。时间片用完，进程回到就绪态，不是阻塞态。阻塞是在等 I/O 或等资源。时钟中断里会改这个时间片还剩多少，时间片的长短要看响应时间、切换开销和进程数量。

### 静态优先级

`large` 数字大的优先，`small` 数字小的优先。2018-24 和 2023-29 都是数字大的优先。相等不抢占。`practice-prio` 里优先数都是 5 的两个进程，抢占式也不会在中途换人。

非抢占：当前进程一直跑完。`P1(0, 6, 优先数 1)` 和 `P2(2, 2, 优先数 5)` 在 `large` 下，P1 先把 6 跑完，P2 从 6 跑到 8。抢占式则是 `0-2 P1`、`2-4 P2`、`4-8 P1`。

静态优先数会饥饿。2016-46 第（1）问就是这个：就绪队列里总有优先数更小的进程时，优先数大的进程一直上不去。第（2）问要自己设计公式，评分看三项的方向，不要求唯一的式子。优先数小的先运行时，一种能得分的写法是：

```
priority = nice + k1 × cpuTime − k2 × waitTime    （k1 > 0，k2 > 0）
```

cpuTime 变大，优先数变大，刚跑过的进程暂时让开。waitTime 变大，优先数变小，等得久的进程会被选中。waitTime 的作用就是避免饥饿。本关的 `prio-np` / `prio-p` 是静态优先级，没有把 cpuTime 和 waitTime 算进去。

`compare` 用优先数 1、2、3、4 时，`prio-np` 的三个平均值和 FCFS 都是 35/4、7/2、19/4，但顺序不同：FCFS 是 P1、P2、P3、P4，非抢占优先级是 P1、P4、P3、P2。完成时刻的总和碰巧一样。看顺序要用 `run` 的甘特图，不能只看平均值。

### 切换开销

2018-24 每次调度并切换花 1μs。程序用 `switch 1`，在选中之后、第一拍运行之前插入 `dispatch`。三个进程的到达时刻写成 −30、−15、−18。甘特图：

```
0-1 dispatch  1-25 P2  25-26 dispatch  26-62 P3  62-63 dispatch  63-75 P1
```

周转时间是 P2 = 40、P3 = 80、P1 = 105，平均 75/1。表里的「等待时间」已经通过负的到达时刻算进周转，输出列 `wait` 还把这 1μs 开销算进去，所以 P2 的 `wait` 是 16，不是表上的 15。开销不是服务时间。

## 易错点

1. **周转时间减的是到达时刻。** 带权周转再除以服务时间。等待时间还要减服务时间；进程里若另有 I/O，王道还要再减 I/O。本关没有 I/O。
2. **响应时间不是等待时间。** 响应时间到第一次上 CPU 为止。被抢占之后的等待只进 `wait`。
3. **短作业优先默认不抢占。** 抢占的名字是 SRTN。剩余时间相等不抢占。
4. **「SJF 平均等待最少」要加前提。** 同时到达时，它和 SRTN 一样，并且在非抢占算法里最少。到达时刻错开时，SRTN 可以更小，见 `compare` 里的 `4/1` 和 `3/1`。
5. **响应比为 1/1 时按先来先服务。** 等待时间都是 0 就分不出长短。等待时间相同且大于 0，短作业的响应比才更高。
6. **RR 在同一时刻先排新进程，再排时间片用完的进程。** 已经在队列里的仍在这两类前面。队列空了就 `keep`，甘特图不断开。
7. **时间片用完进入就绪，不是阻塞。** 2017-27 的 B 错在这里。
8. **RR 的平均周转可以比 FCFS 大。** 它照顾的是响应。时间片过大就退化成 FCFS。
9. **优先级相等不抢占。** `large` 和 `small` 方向相反。2018、2023 都是数字大的优先；2016-46 的优先数是数字小的先跑。
10. **静态优先级会饥饿。** 把等待时间算进优先数，等得越久越容易被选中，饥饿才会消失。本关的优先级命令不算 cpuTime 和 waitTime。
11. **平均值相同，顺序可以不同。** `compare` 里 `prio-np` 和 FCFS 的三个分数一样，甘特图不一样。
12. **2018-24 的 1μs 是切换，不是服务。** 用 `switch 1`。到达时刻用等待时间的相反数。输出的 `wait` 含这段历史等待和切换，大于表里原来的等待时间。
13. **甘特图左闭右开。** 问「时刻 7 谁在运行」，要看起点是 7 的那一段，不能算进 `0-7`。
14. **2023-29 的 P3 用 13ms。** 写成 15ms 时，平均周转对不上选项。

## 概念卡片参考答案

### 卡片：调度的三个层次

| | 作业调度 | 中级调度 | 进程调度 |
|---|---|---|---|
| 别名 | 高级调度、长程调度 | 内存调度 | 低级调度、短程调度 |
| `level` | `job` | `mid` | `low` |
| 队列 | 外存上的后备队列 | 挂起队列 | 就绪队列 |
| 做的事 | 选作业装入内存，创建进程 | 挂起和激活，在内存与外存之间换入换出 | 选就绪进程占用 CPU |
| 频率 | 低 | 中 | 高 |

`card` 里三行的字段是 `en`、`queue`、`move`、`freq`。

### 卡片：目标与评价指标

| 系统 | 主要看 | `goal` |
|---|---|---|
| 批处理 | 周转时间、系统吞吐量、CPU 利用率 | `batch` |
| 分时 | 响应时间 | `interactive` |
| 实时 | 截止时间 | `realtime` |

| 指标 | 算法 | 本关输出 |
|---|---|---|
| 周转时间 | 完成时刻 − 到达时刻 | `turn` |
| 平均周转时间 | 周转时间之和 / 进程数 | `avg turn` |
| 带权周转时间 | 周转时间 / 服务时间，纯 CPU 下 ≥ 1 | `weight` |
| 平均带权周转时间 | 带权周转时间之和 / 进程数 | `avg weight` |
| 等待时间 | 周转时间 − 服务时间；有 I/O 时再减 I/O | `wait` |
| 响应时间 | 第一次开始运行的时刻 − 到达时刻 | `response` |
| 响应比 | (等待时间 + 要求服务时间) / 要求服务时间 | HRRN 的 `ratio` |

### 算法对照

| 算法 | 抢占 | 饥饿 | 偏向 | 用于 |
|---|---|---|---|---|
| FCFS | 否 | 不会 | 长作业 | 作业和进程 |
| SJF | 否 | 会 | 短作业 | 作业和进程 |
| SRTN | 是 | 会 | 剩余时间短的 | 进程 |
| HRRN | 否 | 不会 | 等待和服务时间一起看 | 作业和进程 |
| RR | 是 | 不会 | 响应时间 | 进程 |
| 静态优先级 | 两种都有 | 会 | 紧急的 | 作业和进程 |

`algo` 的一行把优先级写成 `preempt=either`、`starve=static`。动态优先级可以把等待时间算进去，从而不饥饿，见 2016-46。
