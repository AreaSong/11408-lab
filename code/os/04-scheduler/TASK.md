# os/04 · CPU 调度算法 · 题目

> 本文件只写题目，不含思路和代码，做题前可以放心看；答案讲解在 `ANSWER.md`，做完再看。

王道第 2 章，处理机调度。本关是单处理机上的进程调度模拟，不做多级反馈队列，也不做上下文切换的实测，那两件事在第 05 关。

## 一、本关任务

- **产出**：主程序按命令跑 FCFS、SJF、SRTN、HRRN、RR、静态优先级（非抢占 `prio-np`、抢占 `prio-p`）。每次打印调度记录、甘特图，以及每个进程的周转时间、带权周转时间、等待时间、响应时间。`compare` 用同一批进程把七种算法的三个平均值打成一张表
- **小步骤**：
  ① `run fcfs`
  ② `run sjf` 与 `run srtn`
  ③ `run hrrn`
  ④ `run rr <时间片>`。同一时刻新到达的进程先入队，时间片用完的进程随后入队
  ⑤ `run prio-np` 与 `run prio-p`，`large` 表示数字大的优先，`small` 表示数字小的优先
  ⑥ `compare <时间片> <large|small>`
- **通过标准**：给定进程表，能读出某算法的平均周转时间、平均带权周转时间，以及某时刻正在运行的是谁。主程序测试全部通过
- **概念卡片**（写进 `NOTES.md`）：
  1. 调度的三个层次。列：队列、做的事、发生频率
  2. 调度的目标与评价指标。列：批处理、分时、实时各看什么；周转、带权周转、等待、响应时间怎么算

每个项目有这些程序：`main.c` 编出的主程序（与项目同名，如 `scheduler_first`）、`test.c` 编出的单元测试（`scheduler_first_test`）。

## 二、主程序题目（`main.c`）

每条命令占一行，读到输入结束为止。空行跳过。命令行每次读取前用 `prompt(...)` 打印提示，如「请输入命令，Ctrl+D 结束：」。`run`、`pick`、`compare` 接下来逐行读进程，每次读取前用 `prompt(...)` 打印「请输入进程（名字 到达 服务 [优先数]），end 结束：」，读到单独一行 `end` 为止。

名字以字母开头，后面可以是字母、数字、下划线，最长 15，不能叫 `end`。到达时刻、服务时间、优先数都是整数。服务时间必须是 1 到 100000。到达时刻和优先数的绝对值不超过 1000000。优先数可以不写，缺省是 0。最多 16 个进程。名单里第一个错误先记下来，仍读到 `end` 再输出；没写 `end` 就到了文件末尾，输出 `missing-end`（名单里已经有错误时，输出那个错误）。

| 命令 | 含义 |
|---|---|
| `run fcfs [switch <开销>]` | 先来先服务，非抢占 |
| `run sjf [switch <开销>]` | 短作业优先，非抢占。进程调度里也叫短进程优先 |
| `run srtn` | 最短剩余时间优先，抢占 |
| `run hrrn [switch <开销>]` | 高响应比优先，非抢占 |
| `run rr <时间片>` | 时间片轮转。时间片是 1 到 100000 的整数 |
| `run prio-np <large\|small> [switch <开销>]` | 静态优先级，非抢占 |
| `run prio-p <large\|small>` | 静态优先级，抢占 |
| `pick <fcfs\|sjf\|hrrn\|prio-np> <时刻> [large\|small]` | 不往下跑。只在该时刻已经到达的进程里选一个。`prio-np` 必须带 `large` 或 `small` |
| `compare <时间片> <large\|small>` | 七种算法各跑一遍，只打平均值。时间片给 RR，优先级方向给两种优先级算法。不计切换开销 |
| `card` | 不带参数。按固定顺序打层次、目标、指标、算法、规则 |
| `level` `goal` `metric` `algo` `rule` | 各带一个名字，打出 `card` 里对应的那一行 |
| `claim <名字>` | `<名字> true` 或 `<名字> false` |

`switch` 的开销是非负整数，不超过 100000，缺省 0。只有 `fcfs`、`sjf`、`hrrn`、`prio-np` 可以带大于 0 的开销。选中一个进程之后、它开始跑之前，插入一段这么长的 `dispatch`。这段时间不再改选别人。开销不算进服务时间。

时间是整数。甘特图的区间是左闭右开：`0-7 P1` 表示时刻 0、1、2、3、4、5、6 在跑 P1，时刻 7 已经不是 P1。某时刻正在运行的进程，就是包含这个时刻的那一段；`dispatch` 和 `idle` 不是进程。

计算用这些式子。本关每个进程都是纯 CPU，没有单独的 I/O 时间：

- 周转时间 = 完成时刻 − 到达时刻
- 带权周转时间 = 周转时间 / 服务时间
- 等待时间 = 周转时间 − 服务时间
- 响应时间 = 第一次开始运行的时刻 − 到达时刻
- 响应比 = (等待时间 + 服务时间) / 服务时间。这里的等待时间是「当前时刻 − 到达时刻」，因为非抢占算法选中之前进程还没运行过

到达时刻可以是负数，表示时刻 0 之前已经等过的时间的相反数。周转时间仍然用完成时刻减这个到达时刻。

选择规则：

- FCFS、RR 用就绪队列，队头先跑。进程在自己的到达时刻入队；时刻 0 之前已经到达的，按到达时刻从早到晚入队。到达时刻相同，按输入顺序
- 同一时刻既有新进程到达，又有进程时间片用完：新进程先入队，时间片用完的进程排在它们后面。队列里原来已经在等的进程仍排在这两类前面
- 进程在时间片用完之前运行结束，不再入队。时间片用完时剩余时间是 0，同样不再入队
- 时间片用完时，把这一时刻的新进程入队之后队列仍是空的，这个进程继续运行，再给它一个完整时间片，输出一行 `keep`，不再付切换开销。甘特图上这前后两段连成一段
- SJF 选服务时间最短的。SRTN 选剩余时间最短的。只有新进程的剩余时间**严格小于**正在运行的进程，才抢占；相等则正在运行的继续
- HRRN 选响应比最高的。响应比用整数交叉相乘比较。响应比相等时按先来先服务，不按谁更短。大家的等待时间都是 0 时，响应比都是 1/1
- 优先级相等时不抢占。要抢占，必须严格更高：`large` 是数字更大，`small` 是数字更小
- 上面几种「谁更优」比完仍一样，就选到达更早的；到达也一样，选输入里更靠前的
- 当前进程结束、或处理机空着，才做非抢占算法的下一次选择。空闲区间输出 `idle`

`run` 的输出：

```
algo=<算法> q=<时间片或 0> switch=<开销> order=<none|large|small>
trace
ready <时刻> <queue|service|remain|ratio|prio> ... -> <选中>
keep <时刻> <名字>
gantt
<起>-<止> <名字|dispatch|idle>
table
name arrive service prio start finish turn weight wait response
<名字> <到达> <服务> <优先数> <开始> <完成> <周转> <带权> <等待> <响应>
avg turn=<分数> weight=<分数> wait=<分数>
```

`trace` 里每一行 `ready` 是一次选择，发生在切换开销之前。队列算法从队头写到队尾，名字不带等号。其余算法按输入顺序列出当时就绪的进程，等号后面是这次比较用的数：服务时间、剩余时间、响应比或优先数。`->` 后面是选中的进程。带权周转、响应比和三行平均值都写成最简分数 `分子/分母`，能整除也保留分母，例如 `8/1`。`table` 按输入顺序，不按完成顺序。

`pick` 的输出：

```
pick <算法> at=<时刻>
ready <名字> <名字> ...
chosen <名字>
```

`ready` 只含到达时刻小于等于 `at` 的进程，按输入顺序。一个都没有时输出 `no-ready`。

`compare` 的输出第一行是 `compare q=<时间片> switch=0 order=<large|small>`，然后固定按 fcfs、sjf、srtn、hrrn、rr、prio-np、prio-p 各一行：

```
<算法> avg-turn=<分数> avg-weight=<分数> avg-wait=<分数>
```

`card` 以及 `level`、`goal`、`metric`、`algo`、`rule` 打出的词是稳定的，用来填概念卡片、对照算法性质。`claim` 的句子按王道判断真假，和第四节的题面对得上。不认识的名字输出 `<名字> unknown`，这一行不算失败。`card` 多了参数、其他命令参数个数不对，输出 `bad-command` 或 `missing-arg`，程序最终退出码为 1。进程或参数不合法时输出 `bad-job`、`bad-service`、`bad-arrive`、`bad-prio`、`bad-quantum`、`bad-switch`、`bad-order`、`dup-name`、`too-many`、`no-job`、`bad-pick`、`too-long`、`stuck` 之一，退出码为 1。

甘特图片段超过 512，或调度记录超过 128 条，输出 `too-long`。真题规模到不了这个上限。

  输入：
