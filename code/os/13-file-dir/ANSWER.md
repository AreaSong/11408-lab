## 思路

文件在使用前要先按名字找到它的文件控制块。树形目录里，这个名字是一条路径。每次读盘都按块来，所以路径有几级、目录项落在第几块，直接决定打开要读几次。打开做完这一次查找，把控制块放进内存的打开文件表，后面的 `read` 只用文件描述符。

### ② 三种逻辑结构，比的是关键字

`practice-asl` 里 10000 条记录、100 组，各组 100 条。

顺序文件从前往后比。第 k 条比 k 次，等概率平均是 `(n+1)/2 = 10001/2`，也就是 5000.5 次。王道那句「大约比较 5000 次」就是这个数。

索引文件每个记录一个索引项，折半。判定树把 10000 个关键字逐个算比较次数，加起来是 123631，平均 `123631/10000`。最多会比到第 14 层，所以有的书说「大约 14 次」。14 是这一棵树的高度，成功查找的平均不是 14。n=10 时平均是 `29/10`，可以手算：关键字 5 比 1 次，2 和 8 比 2 次，1、3、6、9 比 3 次，4、7、10 比 4 次，合计 29。

索引顺序、索引表顺序查：100 组，先在索引里平均比 `(100+1)/2` 次，组内再平均比 `(100+1)/2` 次，加起来正好 101。这就是王道「分块查找大约 101 次」那个例子，这里是整数，不用大约。

索引表改成折半：100 个最大关键字的成功折半平均是 `580/100`，组内仍是 `101/2`，合起来 `563/10`，也就是 56.3。各组一样大时，可以先写「折半 ASL + (s+1)/2」，再通分。

10 条切成 3 组时，组的大小是 4、3、3，索引项的最大关键字是 4、7、10。关键字 6 落在第 2 组：顺序查索引先碰到 4，再碰到 7；组内先碰到 5，再碰到 6。一共 4 次。折半查索引时，`mid` 直接落在 7 上，索引只比 1 次，组内仍是 2 次，一共 3 次。平均则是 `41/10` 和 `39/10`。组大小不一样，所以输出里有 `size=4+3+3`。

只有 1 条记录、1 组时，索引顺序要比 2 次：索引上 1 次，组里再 1 次。顺序文件只比 1 次。两条都算进比较次数，是这个公式的口径。

### ③ 打开文件，读盘次数按路径一截一截加

`practice-open` 的文件是 `/a/b/c`，索引结点方案，根的索引结点已经在内存，别的都在磁盘上，每个目录占 1 块，目录项在第 0 块。

从根打开它：读根目录找到 a，读 a 的索引结点，读 a 的目录找到 b，读 b 的索引结点，读 b 的目录找到 c，读 c 的索引结点。6 次。三个分量，每次一块目录加一个索引结点，是 `2k`。

然后用 fd 读第 0 块，只多 1 次 `read-data`，没有目录步骤。再读一次还是 1 次。`readpath` 把路径重走一遍再读数据，是 7 次。两次按路径读是 14 次，一次打开加两次 fd 读是 8 次。多出来的就是重复的目录查找。2024-29 选 A：按名查找在 `open`。`read` 和 `close` 用的是已经打开的描述符。

`cd /a/b` 自己要 4 次，因为还得从根走到 b。走到之后，b 的索引结点留在内存。再 `open c` 只读 b 的目录和 c 的索引结点，2 次。当前目录省的是以后每次相对路径少读的那几级。2010-31 选 C。它不改变磁盘读写一块有多快，所以 `claim cwd-io` 是 `false`，选项 D 不成立。`cd` 那 4 次是到达这个目录的花费，省下来的是后面的打开。

`fcb` 方案里，目录项已经带上文件控制块。`practice-fcb` 打开 `/d/b` 只有两次读目录，没有 `read-inode`。同样两级，索引结点方案是 4 次。2022 年的目录项就是「文件名 + 索引结点号」，走的是索引结点这一套，找到名字之后还要再读索引结点。

目录跨块时读到就停。`practice-span` 把 `b` 放到 `/d` 的第 1 块。在 `/d` 里打开 `a`（第 0 块）是 1 次目录加 1 次索引结点。打开 `b` 要先读第 0 块再读第 1 块，再加索引结点，一共 3 次。

### 2022-45 的两块

图里的对应关系：stu 的目录项是 `course,2` 和 `doc,10`。course1 的索引结点号也是 10，数据在 30 号块。doc 和 course1 是同一个索引结点上的两个名字，所以 doc 的块号 x 就是 30。这是硬链接：两个目录项，一份数据。

第（3）问假定 course 的目录内容已经在内存。模拟器里先 `cd /stu/course`（这 4 次是走到 course，题目不算在这一问里），再 `cache data .`，然后 `load course1`。目录数据不再读。course1 的索引结点要读 1 次，数据块再读 1 次，`reads=2`。打开并不把数据读进来；题目写的是「打开并读入」，所以要加上那一块数据。

第（4）问：6MB / 4KB = 1536 块。直接地址 10 块，一级间接 4KB/4B = 1024 块，合计 1034 块，小于 1536。二级间接是 1024×1024 块，够用。所以间接地址用到一级和二级。题目问的是哪几级间接，输出是 `indirect=1+2`。直接地址一定会用到，但不算在「间接」里。三级要到 1024³ 块才需要。这个结构的一般算法在第 14 关，本关只核这一个文件长度。

### ④ 硬链接共享索引结点，软链接保存路径

2009-31 的过程在 `2009-31` 这组输入里。

F1 刚建立，链接计数 1。符号链接 F2 是新文件，自己的计数是 1，F1 仍是 1。硬链接 F3 和 F1 是同一个索引结点，计数变成 2。删掉 F1 这个名字，计数减到 1，文件控制块还在，`fcb=kept`。F2 的计数一直是 1。再 `stat /F2` 要跟随路径 `/F1`，目标已经没了，`result=dangling`。F3 仍是普通文件，计数 1，数据还在。所以 F2 和 F3 的引用计数是 1、1，选 B。

`practice-sym` 把读盘也算上。直接打开 `/a/b` 是 4 次。硬链接 `/h` 的目录项直接指向同一个索引结点，从根打开它只要读根目录和这个索引结点，2 次。符号链接 `/s` 先读到链接自己的索引结点和数据块，再按 `/a/b` 重走一遍，一共 7 次。软链接慢，是因为它存的是路径，不是索引结点号。

自己指向自己的 `/loop`，跟随超过 8 次，`result=loop`。建立的时候目标也解析不成一个结点，所以 `target-nlink=absent`。

硬链接不能跨文件系统，因为索引结点号只在本卷里有意义。软链接存的是路径，可以跨。本关只有一卷，这两条在 `claim` 里。硬链接也不能指向目录，避免目录成环。

本机程序不打印 inode 号，只打印是否相同。某一次 `stat` 看到的号在 `EXPERIMENTS.md`：F1 和 F3 号相同、计数一起变成 2，F2 号不同、计数保持 1。删掉 F1 之后 F3 的计数变成 1，内容仍能读到；`cat` 软链接得到 “No such file or directory”。软链接这个名字还在，失败的是它里面那条路径。

### 打开文件表和关闭

2020-23 选 B。`tables` 里 `/F` 只有一项 `sys`，计数 2，权限和块数抄在这一项上。两个进程的用户表项：一个是读、偏移 1，一个是写、偏移 0。所以 C 不成立。A 不成立，写打开是允许的。进程 0 关闭之后计数变成 1，系统表项还在，所以 D 不成立。D 要改成：打开计数减到 0 才删除。`claim close-always-drop` 因此是 `false`。

写打开的那个 fd 再去 `read`，是 `eacces`，偏移不变。读写方式记在用户表项上，不记在系统表项上。

2023-31 选 B。只打开一次再关闭：`mem=dropped`，链接计数仍是 1，`lstat` 还能看到这个文件。关闭不去掉目录项，那是 `unlink` 的事；也不把磁盘索引结点的链接计数减一。减的是内存里的打开计数。公开回忆里 B 有「内存的文件索引结点」和「内存的文件目录」两种写法，选项位置都是 B，说的都是丢掉内存里的那一份。

`practice-busy` 把两套计数分开。文件还开着就把最后一个名字删掉：链接计数到 0，`fcb=busy`，名字已经 `not-found`。数据要等 `close` 才释放，那一行是 `disk=freed`、`nlink=0`。链接计数管磁盘上的文件还在不在，打开计数管内存里的表项还在不在。

### ⑤ 权限位，以及删除时目录还在

2013-23 选 A。`unlink /d/a` 之后 `/d` 还在，里面的 `b` 还在，`rmdir /d` 因为不空而失败。父目录不会跟着一个文件一起删。这一次 a 的链接计数到 0，文件控制块释放了，所以选项 C 在「没有别的硬链接」时确实会发生。还有硬链接时是 `fcb=kept`，2013 把「删除文件控制块」写成可能做的操作，指的是计数降到 0。

2009-30 选 A。谁能读、谁能写，记在文件控制块里。UNIX 的文件控制块是索引结点，文件名留在目录项里，所以硬链接才能让两个名字共用一份权限和一份数据。文件分配表只串磁盘块。用户口令表是登录用的。注册表不是这个文件的访问控制表。

权限按主人、同组、其他人三组查。本关的用户号 0 只是一个编号。若把它当成超级用户，`chmod 400` 之后主人仍能写，实验就看不出这一位。

`practice-perm` 和本机 `perm` 对得上的部分：

- 文件 `400` 能读，不能写，也不能执行。`200` 相反。`100` 只有执行位，`access` 的 `X_OK` 成功。本机没有真的去 `exec` 这个数据文件。
- 目录 `100`（只有 x）：按名字打开里面的文件成功，列目录失败，新建失败。
- 目录 `400`（只有 r）：列目录成功，按名字打开失败，新建失败。
- 目录 `500`（r 和 x）：能列、能进，不能新建。
- 目录 `300`（w 和 x）：能新建。没有 r，列目录失败。
- 目录 `200`（只有 w）：新建失败。

王道的句子是：目录的 w 表示可以增删目录项。本机只有 w、没有 x 时，加不了文件。模拟器因此要求父目录同时有 w 和 x。只背「有 w 就能改目录」会在 `0200` 上出错。

本机这次 `opendir` 在只有 r 时成功了，只有 x 时失败。按名字打开里面的文件则必须有 x。模拟器的 `ls` 只查 r，`open` 沿途只查 x，和这次的结果一致。

### 概念卡片

文件控制块保存除了「这个名字叫什么」以外的元数据：权限、主人、长度、地址、链接计数。早期目录项就是一整份文件控制块。索引结点把名字拆出去，目录项只留文件名和索引结点号。好处是同一个索引结点可以有多个名字。`card` 的前两行就是这个拆分。

保护有三种。口令：访问时核对系统里存着的口令，口令存在系统中，改口令要改系统保存的那一份。密码：对文件内容加密，密钥不由系统保存，读的时候要解密。访问控制：访问控制表或 rwx 位，放在文件控制块里。2009-30 考的是第三种的存放位置。

## 易错点

1. 顺序文件 10000 条的平均是 `10001/2`，也就是 5000.5。写成 5000 或 5001 都少了「+1 再除 2」。
2. 折半「大约 14 次」说的是 10000 个关键字时树的高度。等概率成功平均是 `123631/10000`。
3. 索引顺序要加两段：查索引的次数，加上组内顺序的次数。只有 1 条记录时这两段都有，平均是 2，不是 1。
4. 各组不能整除时，前面的组多 1 条。10 条 3 组是 4、3、3，最大关键字是 4、7、10。
5. 索引结点方案下，k 个分量、根索引结点已在内存、每级目录一块并且名字在第 0 块，打开是 `2k` 次。文件控制块方案是 `k` 次。
6. `open` 不读文件数据。2022 第（3）问的 2 次是「索引结点一块 + 数据一块」。
7. `close` 减打开计数。`unlink` 减链接计数。打开着删掉最后一个名字，要等关闭才释放磁盘索引结点。
8. 软链接的引用计数是它自己的，建立和删除都不改目标。目标删掉之后，软链接的名字还在，跟随才会失败。
9. 相对路径的符号链接，从它所在的目录接着找。
10. 删文件不会删除所在目录。目录里还有别的名字时，`rmdir` 失败。
11. 目录只有 w、没有 x 时，不能新建。`practice-perm` 里 `chmod /d 200` 之后 `create` 是 `eacces`。
12. 用户号 0 不是超级用户。权限位按主人、同组、其他人查。
13. 本关默认只有根的索引结点在内存。根目录的数据块仍要读。题目说「已经在内存」时用 `cache`，这次标记不计读盘。
14. 2022 第（4）问问的是间接地址项。6MB 要一级和二级。直接地址也用，但不写进「间接」。
