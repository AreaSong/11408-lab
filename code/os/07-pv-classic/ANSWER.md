## 思路

临界资源用互斥信号量，初值 1。前后关系用同步信号量，初值是已经具备的资源数；还没有的那一份，初值是 0，先做的人 V，后做的人 P。

最小编号调度会让同一个人一直走到自己阻塞。所以 `pc 1 1` 里生产者把唯一的空位填上之后，消费者才出现。这不是「必须先生产」，只是编号小的人先走。`order right` 把消费者编号设成 0，第一步就是他在 `full` 上阻塞，而且手里没有 `mutex`。生产者随后能拿锁、放入、`V(full)` 把他叫醒。

### ① 生产者-消费者

`empty` 是空位数，`full` 是已放入的件数，`mutex` 保护缓冲区下标。容量为 1 时，`empty` 和 `full` 已经保证两边不会同时碰缓冲区；`mutex` 仍然要留着，因为容量大于 1 时，多个生产者会改同一个 `head`。本关主程序只有一对，真线程的容量是 3，所以代码里一直带着 `mutex`。

`pc 2 3` 的第 11 步：生产者第三次 `P(empty)`，值变成 -1，`state=block`。消费者 `V(empty)` 时值回到 0，`state=wake`，`wake=P`。这就是记录型信号量：V 发生时有人等，就从队头叫醒，不会把这次 V 丢掉。

### ② 读者-写者

读者优先：`readcount` 从 0 变成 1 时，这个读者代表全体去 `P(wmutex)`；减回 0 时，最后一个读者 `V(wmutex)`。中间进来的读者不再申请 `wmutex`。`rw reader-cut` 里写者停在 `wmutex=-1`，读者 1 的 `readcount` 仍能加到 2。写者要等两个读者都离开。新读者可以插在已经等待的写者前面，所以写者可能饥饿。

写者优先用王道那一组四个信号量。`r` 是门，不是文件。读者进门时 `P(r)`，登记完、真正读之前就 `V(r)`，所以读的过程中不占着门。第一个写者 `P(r)` 之后，后来的读者进不了门；写者再去 `P(file)`，如果里面还有读者，他就等文件，但门已经关上了。`rw writer-cut` 的第 12 步写者阻塞在 `file`，第 13 步读者 1 阻塞在 `r`。这就是「新读者不能插队」。

`rw readers` 没有写者，两个人的 `readcount` 会到 2。读者之间不互斥。

### ③ 哲学家

先写会死锁的版本，是为了看见环，不是为了让最小编号调度碰巧撞上。最小编号会让 P0 把左右两根都拿完并吃完，根本排不出「五个人各拿一根」。`phi dead` 因此改成强迫次序：五个人先各 `P` 自己的左边，再各 `P` 右边。右边正好是下一个人的左边。

```
wait who=P0 sem=chop1 holder=P1
wait who=P1 sem=chop2 holder=P2
...
wait who=P4 sem=chop0 holder=P0
```

这是一个环。每人拿着一根，等着邻居手里的那一根。

三种改法破的是不同的地方：

| 命令 | 在破什么 |
|---|---|
| `limit` | `room=n-1`。最多 n-1 个人来抢，至少剩一根没被当作「某人的左边」拿走，就有人能拿到第二根 |
| `odd` | 偶数先右后左，奇数先左后右。编号从 0 起。两边的人第一下抢的不是同一圈方向，环断了 |
| `both` | `pick` 把两根筷子的 P 包成一段。拿齐就 `V(pick)`，吃饭时别人可以来拿。不会出现「每人只拿到一根」 |

`both` 的第 1 步是 `P(pick)`，第 4 步在 `eat` 之前 `V(pick)`。吃饭期间不占这把锁，否则整桌同时只能有一个人在吃，违反「只是让拿筷子这一小段互斥」。

题目若从 1 编号，奇偶会和这里对调。要紧的是左右两批方向相反，不是「0 一定先拿右」。

`limit` 和 `odd` 的主程序 trace 经常是一个人吃完才轮到下一个人。那是最小编号造成的，不能用来证明「他们真的会同时吃」。同时性看 `live`：`limit` 和 `odd` 各吃 10 顿，`bad=no` 表示相邻的人没有同时处于进餐。

### ④ 互斥 P 放在同步 P 前面

`order wrong`：缓冲区是空的，消费者编号更小。他先 `P(mutex)` 成功，再 `P(full)` 阻塞，锁还在他手里。生产者 `P(mutex)` 也阻塞。消费者等的 `full` 只有生产者能 V，生产者要的锁在消费者手里。

```
wait who=C sem=full holder=-
wait who=P sem=mutex holder=C
```

`full` 的 holder 是 `-`，因为它是同步信号量，不是「谁 P 成功了就一直拿着」。环在另一行：P 等的锁，holder 是 C。

`order wrong-full` 把角色换过来。缓冲区一开始是满的，生产者先拿到锁，再在 `empty` 上等待。消费者进不了锁，也就不能把东西取走、`V(empty)`。

`order right` 用同一组初值、同样让消费者先走，但消费者第一下是 `P(full)`。他阻塞时 `mutex` 仍是 1。生产者能做完放入并 `V(full)`，`wake=C`。

`order plant` 是 2025 年那道题的同一种错法。已经有 3 个坑时 `pits=0`。甲若先拿铁锹再等名额，乙拿不到铁锹，名额就不会被 V 回来。

### ⑤ 吸烟者

三种原料各设一把信号量时，供应者 `V(tobacco)`、`V(paper)` 表示「这一份是烟草加纸」。有纸的人只需要烟草，会把烟草取走；有烟草的人只需要纸，会把纸取走。真正需要这两样的人（手里有胶水）两样都没拿到。`smoke-split` 把这次交错固定下来：

```
wait who=glue sem=tobacco holder=paper
```

有纸的人拿着烟草，有胶水的人永远等不到烟草。所以信号量要按**组合**设，不按原料设。`smoke 1 2 3 1` 里，供应者先 `V(glue)` 再去等 `finish`。有胶水的人抽完 `V(finish)`。第四次代号又是 1 时，有胶水的人已经停在 `P(glue)` 上，供应者的 V 是 `state=wake`。V 会把值留下，也会叫醒已经在等的人。

### ⑥ 四道真题

**2019-43。** 碗用来限制同时来抢筷子的人数，所以要在拿筷子之前 `P(bowl)`。`bowl = min(n-1, m)`。

- m < n 时，碗本身就不到 n 个，初值用 m，至多 m 个人来抢。
- m ≥ n 时，若初值仍用 m，n 个人都能拿到碗，再各拿一根筷子，又是 `phi dead` 那个环。初值要收成 n-1。

`exam 2019 5 4` 的 `bowl=4`。`exam 2019 5 6` 的 m 比 n 大，`bowl` 仍是 4，不是 6。`exam 2019 3 1` 只有一个碗，`bowl=1`，三个人都吃到，`meals=3`。同时进餐的上限还要再和筷子一起看：n 根筷子、每人两根，最多 `n/2`（向下取整）人。碗若更少，就以碗为准。trace 里常常一个人吃完再换人，那是调度，不是这个上限。

**2022-46。** 同一条线程里的先后不用信号量。T1 自己会先做 A 再做 E 再做 F，T2 自己会先做 B 再做 C 再做 D。跨线程只剩两处：C 要等 A，E 要等 C。

```
AC = 0    /* A 做完才允许 C */
CE = 0    /* C 做完才允许 E */
```

T1：`A; V(AC); P(CE); E; F`。T2：`B; P(AC); C; V(CE); D`。B 在 C 前面是 T2 的程序顺序，不必再设一把从 B 到 C 的信号量。

最小编号下 T1 先做 A、V(AC)，然后在 `CE` 上阻塞。T2 做完 B 和 C，`V(CE)` 叫醒 T1。T1 编号更小，所以接着做 E 和 F，T2 的 D 排在后面。`order=A,B,C,E,F,D`。D 和 E 都在 C 之后就符合题图，D 不必在 E 前面。`check=yes` 查的就是这几条边，不是某一种全序。

若给 D 和 E 共用同一把「C 已经完成」的信号量，谁先 P 谁把值拿走，另一个就永远等。两个后继要各用各的信号量，或者像这里一样只给需要跨线程的那一个后继设信号量。

**2024-46。**

（1）是临界区。P1 和 P2 都执行 C1，也就是都写共享缓冲区 B。`reason=both-write-B`。

（2）`empty=1`，`full=0`。P1：`P(empty); C1; V(full)`。P2：`P(full); C2; V(empty)`。不再加 `mutex`。两人各只做一次，`full` 把 C2 挡在 C1 完成之后，两次访问碰不到。输出里的 `mutex=none` 就是这个意思。

只设一把 `full=0`、让 P1 直接做 C1 再 `V(full)`，在「各一次、B 初始为空」时也能把顺序守住，而且更少。有的评分把这一写法也算对。本关的标准输出仍用 `empty` 和 `full` 这一对，因为题干把「为空才能 C1」和「非空才能 C2」写成了并列的两个条件。多出来的是互斥信号量，不是这一对里的 `empty`。

（3）B 一开始非空，两人各改一次，谁也不把缓冲区变空，也没有先后。只要 `mutex=1`。`sync=none`。

**2025-45。** 四把就够：

| 信号量 | 初值 | 作用 |
|---|---|---|
| `pits` | 3 | 甲还能挖的名额。未填的坑到 3 个，甲就不能再挖 |
| `empty` | 0 | 已经挖好、乙还没填的坑 |
| `water` | 0 | 乙已经填好、丙还没浇的树 |
| `mutex` | 1 | 铁锹。甲挖和乙填都要用 |

水桶只有丙一个人用，不是临界资源。`bucket=none`。给它再设初值 1 不算错，但不符合「尽可能少」。

```
甲：P(pits); P(mutex); 挖; V(mutex); V(empty);
乙：P(empty); P(mutex); 放苗并填土; V(mutex); V(pits); V(water);
丙：P(water); 浇;
```

`pits` 的 P 必须在 `mutex` 前面。`exam 2025 4` 里甲先挖满 3 个并在第 4 个名额上阻塞，乙填掉一个并 `V(pits)`，甲被叫醒后再挖。`max_open=3`，没有第 4 个未填的坑。`order plant` 就是把甲的两个 P 对调之后的死锁。

## 易错点

1. **同步在前，互斥在后。** `order wrong` 和 `order plant` 是同一条规则。先拿了锁再去等对方，对方就进不来 V。
2. **V 不会丢。** 没人等时值加 1，`state=inc`。条件变量的 signal 没人等就会丢，那是第 06 关的 `cond`，不是信号量。
3. **读者优先会饿死写者。** `reader-cut` 里第二个读者不用等写者。写者优先关的是门 `r`，不是把正在读的人赶出去。
4. **哲学家从 0 编号。** `phi odd` 里 P0 的第一根是 `chop1`（右边）。题目从 1 编号时，这句话要改成「奇数先左还是先右」，方向相反即可。
5. **`both` 的锁不覆盖吃饭。** `V(pick)` 在 `eat` 之前。
6. **2019 的碗在 m≥n 时不是 m。** `5 6` 仍是 `bowl=4`。
7. **同一线程里的箭头不要再设信号量。** 2022 年多设、又让两个后继去 P 同一把，会把一个人饿死。
8. **2024 年第（2）问不要再加 mutex。** 第（3）问也不要再加 empty/full。
9. **水桶不是信号量。** 铁锹才是。
10. **吸烟者按组合，不按原料。** `smoke-split` 里 `holder=paper` 就是原料被拆开。
11. **最小编号调度看不出死锁环。** 会死锁的哲学家必须用 `phi dead` 那种强迫次序，或者用 `live` 的真线程。

## 概念卡片

| | 信号量 | 条件变量 | 管程 |
|---|---|---|---|
| 信号留不留得住 | V 把值加回去，没人等也不丢 | signal 时没人等就丢 | 等在条件上，由管程过程去 signal |
| 什么时候阻塞 | P 之后值小于 0 | 调用 wait | 条件不成立 |
| 还要不要另一把锁 | 互斥和同步都可以直接用它 | 必须另有一把互斥锁，wait 时把锁放开 | 锁在管程里面，外面只调用过程 |

`card` 的三行就是这张表。条件变量那一行的 `saved=no`，对应第 06 关 `cond` 脚本里的 `state=lost`。
