## 思路

这一关把「进程是什么」拆成两件能对上的事：控制块里记着它现在处于哪种状态、它和别的执行流共用哪一块内存。

### 五种状态里，阻塞不能直接上 CPU

考纲用的是五态。平时画图，真正来回走的是这四条：

| 转换 | 谁引起 | `trans` 的 how |
|---|---|---|
| 就绪 → 执行 | 调度 | `dispatch` |
| 执行 → 就绪 | 时间片用完，或被更高优先级抢走 | `preempt-or-yield` |
| 执行 → 阻塞 | 等一个处理机以外的事件 | `block` |
| 阻塞 → 就绪 | 等待的事件发生 | `wakeup` |

另外三条和进程的出生、死亡有关：创建 → 就绪（`admit`），执行 → 终止（`exit-or-revoke`），以及撤销把就绪或阻塞的进程直接收走（`revoke`）。

阻塞 → 执行不在表里。进程被唤醒之后只是重新有资格竞争 CPU，还要再被调度一次。就绪 → 阻塞也不在表里：只有正在运行的进程才会去申请资源、启动 I/O。处理机被抢走，进程回到就绪，不是阻塞。

`state` 把这些做成命令。`ok=no` 时 `to` 仍写成这次想去的状态，队列打印的是没改过的原样。2015-25、2018-27、2019-24、2023-27 都是在问「这个事件走上面哪一条」。

创建原语在王道里有四步：申请空白 PCB，分配资源，初始化，插入就绪队列。资源不够才会停在创建态。本关每次创建都当资源够用，所以一行 trace 的终点是 `ready`，`via=new` 表示中间经过了创建态。`trans new running` 仍然不合法，创建完不能越过就绪直接跑。

### PCB 用链接串成队列

PCB 是进程存在的唯一标志。撤销和 `exit` 都把槽位清掉，名字可以再用。字段按王道分成四类，`fields` 那一行就是这四类：

| 类 | 本关记下的 | 王道里还有 |
|---|---|---|
| 标识 | `pid` | 用户标识 uid |
| 处理机状态 | 切换时要保存的现场 | PC、通用寄存器、PSW、栈指针 |
| 调度 | `state`，阻塞时还有 `reason` | 优先级、等待事件 |
| 控制 | 队列的 `link` | 程序和数据地址、打开文件、同步信息 |

组织方式用的是链接：同一状态的 PCB 用 `link` 串起来。就绪一条链。阻塞按原因分链，I/O 和磁盘不是同一条队。空了的原因不打印，下一次同一原因再阻塞时还排在原来的位置上。

四个原语：

1. **创建**：空白槽 → 创建态 → 就绪队尾。
2. **阻塞**：运行进程把自己放进对应原因的队尾，CPU 空出来。阻塞是进程自己请求的。
3. **唤醒**：别的进程或中断处理把等待者移到就绪队尾。阻塞和唤醒成对使用。唤醒不是调度。
4. **撤销**：从就绪、运行或阻塞队列摘下，回收 PCB。`exit` 只允许运行进程自己结束；就绪进程要结束，用 `revoke`。

本关的进程都由输入直接创建，没有记录父子关系，所以撤销不会连带收走别的进程。调度策略也不在这里：`dispatch` 可以点名就绪队列里的任何一个，谁先跑留给第 04 关。抢占和主动出让都把进程放到就绪队尾。

单处理机同时只有一个 `running`。已经有人在跑时再 `dispatch`，`why=cpu-busy`。

### fork 复制的是调用这一刻的地址空间

`isolate` 里父进程的 `x` 从 1 开始。`fork` 之后子进程执行 `x = x + 1`，得到 2，从管道送回来。父进程的 `x` 仍是 1，所以 `isolated=yes`。

两边打印出来的指针经常是同一个虚拟地址。`fork` 先让父子看见同一套虚拟地址，页被写到的那一刻才真正分开，这是写时复制。虚拟地址一样，不表示变量还是同一份。看值，不看指针字面是不是相同。实测见 `EXPERIMENTS.md`。

`exec` 把子进程的程序换成新映像。本关换的是同一个可执行文件，参数 `--child 7`，新映像不再读标准输入，直接以退出码 7 结束。父进程从 `wait` 拿到这个码，`replaced=yes`。`exec` 成功之后，子进程里 `fork` 之后写的代码不会再执行。

打印次数考的是用户空间缓冲区，不是进程个数本身。循环固定两轮：

```c
for (i = 0; i < 2; i++) {
    fork();
    printf(...);
}
```

每一轮，父进程和当时已经存在的每个进程都会再 `fork` 一次，然后自己也执行 `printf`。两轮之后有 4 个进程。

`line` 和 `flush` 在 `fork` 之前把缓冲清空，子进程复制不到旧字符。第一轮 2 个进程各打 1 个，第二轮 4 个进程各打 1 个，一共 6 个。

`nolf` 不刷新。第一轮之后两个进程的缓冲里各有 1 个 `-`。第二轮 `fork` 时，新进程把这 1 个也复制走，然后 4 个进程再各放进 1 个。结束时各刷出 2 个，一共 8 个。

这个 6 和 8 按「终端上是行缓冲，没有换行就不刷出」来算。本机如果把标准输出接在管道上，C 库会改成全缓冲，`printf("-\n")` 也会得到 8。`forkrun` 因此自己管一块缓冲，测试结果才和考法一致。管道上的实测也在 `EXPERIMENTS.md`。408 统考没有一道可以核对年份的原题，所以用例名用 `practice-`。

子进程用 `_exit` 结束。`exit` 会把继承来的 stdio 缓冲再刷出去，父进程已经 `printf` 过的提示或结果会被子进程再写一遍。

### 线程共享地址空间，不共享栈

2011-25 和 2024-28 问的是同一件事。同一进程的线程共用代码、全局变量、堆、打开的文件和文件描述符。每个线程自己带一套执行现场：程序计数器、寄存器、栈、栈指针。

`threadrun` 让一个线程把原子整数写成 42，另一个线程等到看见 42。看得见，说明这块内存在两个线程之间是同一份。两个局部变量的地址不同，说明栈是分开的。地址每次运行都变，只打到标准错误。

`share stack-pointer` 是 2011-25 的 D，`shared=no`。`share stack` 是 2024-28 的第Ⅱ项，也是 `no`。地址空间和 `fd` 是 `yes`，所以 2024-28 选「仅Ⅰ、Ⅲ」。

### 三种模型差在内核看不看得到这些线程

用户级线程由线程库管理，切换在用户态完成，内核不给每个用户线程单独建控制块。内核级线程的创建、撤销和切换由操作系统完成，内核里有线程控制块。

| 模型 | 映射 | 一个线程阻塞 | 多 CPU 上并行 | 内核控制块 |
|---|---|---|---|---|
| 多对一 `many-one` | n 个用户线程 → 1 个内核线程 | 整个进程停住 | 不能 | 只有进程那一个 |
| 一对一 `one-one` | n → n | 只停这一个 | 能 | 每个用户线程一个 |
| 多对多 `many-many` | n → m，m ≤ n | 内核还可以调度同进程的另一个内核线程 | 能 | 按 m 个内核线程建，不是每个用户线程一个 |

2019-23 的 B 把「每个用户级线程都有内核线程控制块」说成普遍事实。这只在一对一里成立，多对一和多对多都不是，所以这句是错的。A 对：内核级线程由操作系统调度。C 对：用户级切换不必陷入内核。D 对：多对一可以在没有内核线程的系统上做出来。

本机 pthread 是一对一。`ps -M` 能看到每个 pthread 各占一行。`uctx` 是多对一：`swapcontext` 不进入内核，实验进程在 `ps -M` 里只有一行。

2024-24 问终止进程时哪一步不一定做。回收内存、设备，并释放 PCB，这三步都要做。子进程不一定被杀掉，它可以变成孤儿，由 init 收养。王道的终止原语写了「应当终止其所有子孙进程」。教材说的是一种实现步骤，2024-24 的标准答案是这一步并不是必须的。本关的 `revoke` 只回收被点名的那一个 PCB，和这道题一致，不按「子孙一起杀掉」来做。

## 易错点

1. **阻塞不能直接变成执行。** 唤醒只到就绪。`dispatch` 一个还在阻塞队列里的进程，`why=not-ready`。
2. **就绪不能直接变成阻塞。** 申请资源、启动 I/O、P 操作，都是运行进程自己做的。时间片用完、CPU 分给高优先级进程，走的是执行 → 就绪。
3. **时间片用完不是唤醒。** 2019-24 的第Ⅲ句把运行进程送回就绪队列。唤醒的对象是已经阻塞、正在等某个处理机以外事件的进程。
4. **主动出让和被抢占都回到就绪，原因不同。** `yield` 是线程自己让出，`preempt` 是时间片或更高优先级把它赶下来。`trans running ready` 因此写成 `preempt-or-yield`。两条都不是阻塞。
5. **缺页、键盘输入、信号量 wait 都不会把执行态变成就绪态。** 缺页后要等页面调入，进程阻塞。当前线程如果为了读键盘而等待，也是阻塞。`wait` 在资源不够时阻塞；资源够时它继续执行，也不会因此进入就绪。2023-27 要选的是主动出让 CPU。
6. **有的解析把「键盘输入」理解成外设中断，说它不一定改变当前线程的状态。** 两种理解的共同点是：它不是执行 → 就绪。本关按「当前线程为了等输入而阻塞」来归类。
7. **`fork` 之后虚拟地址可以相同。** 相同的是地址空间布局。子进程改过的那一页已经和父进程分开。`isolate` 用值来判断，不用指针是否相等。
8. **不带换行的 `printf` 会把字符留到下一次 `fork`。** 两轮循环、结束时才刷新，是 8 个 `-`。每句都刷新，是 6 个。进程数两种都是 4。只数进程会把 8 做成 4 或 6。
9. **管道上的 `printf("-\n")` 在本机是 8，不是 6。** 终端才是行缓冲。接到管道会变成全缓冲，换行也不刷出。对答案时要先说清楚缓冲模式。
10. **子进程不要用 `exit` 来结束这段实验。** `exit` 刷新 stdio。父进程缓冲里还没写到内核的内容，会在子进程里再写一次。实验进程用 `_exit`。
11. **2019-23 的 B 只在一对一模型里成立。** 不能把「用户级线程」和「内核为它建了 TCB」画等号。多对一没有单独的内核线程控制块，一个线程阻塞，整个进程停住，也不能在多个 CPU 上并行。
12. **本机 pthread 不是 `uctx` 那种线程。** pthread 是一对一，内核看得到。`uctx` 用来看多对一：切换在用户态完成，`ps` 里仍然一个线程。
13. **线程共享打开的文件，不共享别人的栈。** 2024-28 的 fd 在进程打开文件表里，Ta 和 Tb 都能用。线程 T 的栈是 T 的私有现场。
14. **终止进程一定回收 PCB、内存和设备，不一定杀掉子进程。** 2024-24 的 A 是选出来的那一项。王道把「终止子孙」写进了终止原语的步骤，和这道题的标准答案不一致。孤儿进程交给 init。本关 `revoke` 只回收被点名的 PCB。
15. **引入线程之后，进程不是调度单位。** `entity process` 的 `schedule=no`，`entity thread` 的 `schedule=yes`。进程仍然是资源分配的基本单位。程序是放在文件里的静态指令和数据，既不占资源表，也不被调度。
16. **`exit` 和 `revoke` 不是一回事。** 自己结束只能从运行态发生。就绪或阻塞的进程被收走，是别的执行流调用撤销原语。

## 概念卡片参考答案

### 卡片一：程序、进程、线程

| | 程序 | 进程 | 线程 |
|---|---|---|---|
| 形态 | 静态的指令和数据，在文件里 | 动态的一次执行，PCB 是它存在的标志 | 进程里的一条执行流，有自己的 TCB |
| 资源 | 不占进程资源表 | 资源分配的基本单位 | 基本不占资源，只用一点栈、寄存器和 TCB |
| 调度 | 不被调度 | 引入线程之前是调度单位；引入之后不再是 | 调度的基本单位 |
| 并发 | 本身不并发 | 进程之间可以并发 | 同一进程的线程也可以并发 |
| 地址空间 | 还没有 | 每个进程一份 | 同一进程内的线程共用一份 |

`entity` 的三行就是这张表里「形态、资源、调度」三列。`schedule` 按引入线程之后填写。

### 卡片二：内核级线程、用户级线程，和三种模型

内核级线程：创建、撤销、切换都陷入内核，内核保存每个线程的控制块，一个线程阻塞不会挡住同进程的其他内核线程，多个 CPU 上可以并行。切换要保存内核现场，比用户态切换贵。

用户级线程：线程库在用户空间完成管理。切换不陷入内核，所以快。内核只认识进程（或多对多里的那几个内核线程）。一个用户线程如果自己陷入阻塞，多对一模型下整个进程都停。库可以在没有内核线程的系统上实现。

三种连接方式就是 `model` 的三行：

| | 多对一 | 一对一 | 多对多 |
|---|---|---|---|
| 输出里的名字 | `many-one` | `one-one` | `many-many` |
| 内核控制块 | `tcb=process` | `tcb=thread` | `tcb=partial` |
| 切换发生在 | 用户态 | 内核 | 两种都有 |
| 并行 | 否 | 能 | 能 |
| 一个线程阻塞是否拖住整个进程 | 是 | 否 | 否 |

两级模型是多对多的一种做法：多数用户线程仍映射到内核线程池，另允许把某个用户线程绑定到一个专用内核线程。考纲点名的是上面三种。本关 `model` 不单列两级模型。
