## 思路

逻辑地址是作业自己的编号，每道作业都从 0 编起。物理地址是内存单元的编号。连续分配里，一道作业占 `[基址, 基址+长度)` 这一段物理内存，作业里的地址 0 落到基址上。

### ① 两套保护

界地址寄存器存的是长度，不是最高物理地址。硬件先看逻辑地址是否小于这个长度，小于才做 `物理地址 = 逻辑地址 + 重定位寄存器`。等于长度已经越出这一块，`practice-bound` 里 500 和 600 都是 `bound`，400 得到 3400。

上下限寄存器圈的是物理地址，下限和上限都算在内。同一块内存写成上限时，上限 = 基址 + 限长 − 1。基址 3000、限长 500，对应下限 3000、上限 3499。物理地址 3500 越界，3499 还在里面。两套寄存器都只能由内核用特权指令装入，用户程序改不了，所以一道作业摸不到另一道的内存。

分区分配的主要保护就是这套界地址保护。2009-26 选 A。程序代码保护、数据保护、栈保护都不是分区方案的硬件措施。

### ② 空闲链按地址存放

表里每块空闲区只有起点和大小，按起点升序排。这样「前一块的终点是不是我的起点」一次扫描就能判断。最佳适应和最坏适应要的容量顺序，是 `show` 和挑选时另排的，不把这张地址表打乱，否则合并时找不到邻居。

`hole` 加进来的区间若和已有空闲首尾相接，立刻合成一块。`practice-merge` 最后一组输入的是 `[0,10)` 和 `[10,15)`，`show` 里只剩 `0 15`。回执仍打印输入的 `10 5`，合并后的样子看 `show`。

### ③ 四种算法都从低地址切

选中一块之后，作业拿走 `[起点, 起点+申请量)`，高地址剩下的仍是空闲。`left` 是这块剩余，它没有分给作业，所以成功行上 `internal=0`。

- 首次适应：地址从低到高，第一块够大的
- 最佳适应：容量从小到大，第一块够大的就是浪费最少的
- 最坏适应：容量从大到小，第一块就是当前最大的
- 邻近适应：地址序不变，从上次查找停住的那一块继续，那一块自己还要再比一次大小

容量相同时，更低的地址排在前面，输出才只有一种。

`practice-fit` 的空闲区按地址是 100、500、200、300、600。

- 首次适应：212 进 500，117 进剩下的 288，526 进 600，三块都放下
- 最佳适应：212 进 300，117 进 200，526 仍进 600。大块留住了，同时留下 88 和 83 两块小的
- 最坏适应：212 切掉 600，剩下 388。此时最大块是原来的 500，不是刚切出来的 388，所以 117 的起点是 1000。526 到来时最大块只剩 388，失败。空闲加起来是 1371，一次都用不上，`external=1371`

有的过程讲解把第二次写成去切 388。388 比 500 小，最坏适应不会选它。第三次失败这个结论倒是对的，中间那一步要按「重新找最大块」重算。

`practice-keep` 把同一组 120、200、120 交给首次适应和最佳适应。首次适应第二刀切掉 200，第三刀 150 失败。最佳适应第二刀去切另一块 120，200 还在，第三刀放得下。短序列里最佳适应可以更会留大块。2019-32 问的是长期最容易产生碎片：最佳适应每次都留下最小的边角，小空闲区会越积越多，选 C。循环首次适应是邻近适应的另一个名字，它让高低地址被用到的机会更匀，大块更容易被提前切掉，但碎片最多的仍是最佳适应。综合起来，王道认为首次适应通常更好，因为它实现简单，又把高地址的大空闲区留得更久。

邻近适应的指针留在刚切的那一块上，下一次从它开始，包括切剩的部分。`practice-nf` 第一刀把 1000 处的 100 切成作业 40 和空闲 60，指针停在 1040。第二刀 20 就从这 60 里拿，起点是 1040。同样的输入用首次适应，第二刀会回到地址 0 的那块 30。若把指针理解成「移到下一块、跳过剩余」，第二刀会落到 2000，和本关的输出对不上。王道的说法是从上次查找结束的位置开始，结束的位置就是刚分走的这一块。整块分完、结点消失时，没有剩余可指，指针才移到地址序的下一块，链尾则回到链头。第三组先把 `[0,100)` 整块分走，指针落到 500 处的 10；释放之后这块 100 又出现在指针前面，下一刀 50 绕回去，起点仍是 0。

### ④ 回收的四种相接

回收区 `[起点, 起点+大小)` 只和终点正好等于起点、或起点正好等于终点的空闲区合并。中间还隔着作业或其他空隙，就不并。

| 相接 | `merge` | 合并后的起点 |
|---|---|---|
| 只有低地址那侧 | `front` | 不变，仍是低地址那块的起点 |
| 只有高地址那侧 | `back` | 改成回收区的起点 |
| 两侧都有 | `both` | 仍是低地址那块的起点，高地址那条记录删掉 |
| 两侧都没有 | `none` | 新的一条，起点就是回收区 |

`practice-merge` 的前四组就是这四句，最后一组是用 `hole` 把两块首尾相接的空闲加进去，链上只剩一块。样例里释放 `[0,4)`，它高地址一侧紧挨着剩下的 `[4,10)`，所以是 `merge=back`，合成 `[0,10)`。

2017-25 的四块按容量已经是 40、80、100、200。回收 `[60K, 200K)`：低地址的 `[20K, 60K)` 和高地址的 `[200K, 400K)` 都接上，三块合成起点 20、大小 380。空闲块从 4 条变成 3 条。最佳适应按大小重排，最小的是原来的 80，起点 500。链首是 `500 80`，选 B。选项 A 是合并对了、忘记重排，把 380 那块留在了链首。

### ⑤ 两种碎片

内部碎片是分给这道作业的分区里没用完的部分。外部碎片是内存里的空闲区太小或太散，眼前这次申请用不上。

固定分区事先划死。作业进一个够大的分区，分区里多出来的是内部碎片。空着的分区还完整，可以给下一道合适的作业，不算外部碎片，所以放不下时也打印 `external=0`。分区大小可以不相等，小作业进小分区，就是为了少浪费内部。`practice-frag` 两个 50 的分区各放进 20，内部碎片合计 60。

单一连续把整个用户区分给唯一的一道作业。用户区 100 放进 20，内部碎片 80。第二道来的时候用户区正忙，不是碎片问题。

动态分区按申请量切割，分出去的那一段没有富余，内部碎片是 0。切剩的高地址部分仍在空闲链上。申请失败、同时空闲总和却够，这些空闲就是这次的外部碎片。`practice-frag` 里空闲 20 和 40 加起来是 60，最大块只有 40，申请 50 失败，`external=60`。紧凑把作业挤到低地址，空闲合成高地址的一块，才能让这种申请重新变得可满足。

紧凑会改变作业的物理起点。静态重定位在装入时已经把逻辑地址改成了物理地址，搬动之后指令对不上，`compact` 拒绝并保持原状。动态重定位的程序里仍是逻辑地址，物理地址每次用基址加上去，紧凑只改重定位寄存器。`practice-compact` 在静态时 C 仍在 50；改成动态后 C 从 50 挪到 20，空闲合成 `[30,100)`。

### ⑥ 共享和伙伴系统

两道作业可以有不同的逻辑地址，背后是同一块物理内存。`share` 在父子进程里分别映射同一个文件。子进程先做一块匿名映射，文件映射就会落在另一个虚拟地址。`MAP_SHARED` 时父进程和文件本身都能看见子进程写的 `SHARE408`。`MAP_PRIVATE` 时子进程写的 `PRIVATE1` 父进程看不见，父进程仍读到文件里的 `SHARE408`。用户态读不到页框号，能确认的是：虚拟地址不同，存储的效果却是同一份。本机页大小和这次的地址在 `EXPERIMENTS.md`。

2024-27 选 A。首次、最佳、最坏适应只要物理上相邻就合并，不管两块是不是一样大。伙伴算法把内存拆成 2 的幂，回收时只和「起点异或块大小」的那一块、并且大小相同的伙伴合并。`practice-buddy` 里 `[4,8)` 和 `[8,12)` 相邻，又都是 4，但 4 的伙伴是 0，8 的伙伴是 12。两块都空着也不合并。同样的布局交给普通动态分区，`free C` 是 `merge=front`，合成起点 4、大小 8。

单独分配一块 3，向上取整成 4。释放后伙伴一级级都空着，两次合并回到整块 16。

## 真题在对什么

**2009-26，选 A。** 分区分配用界地址寄存器挡住越界访问。

**2010-28，选 B。** 主存 55 一开始整段空闲，系统区没有另占一块。最佳适应每次切最小的够大块，从低地址切：

1. 15 从 55 里切走，剩 40
2. 30 从 40 里切走，剩 10，位于高地址
3. 释放 15 之后，低地址 15 和高地址 10 不相接
4. 8 小于 15，切的是那块 10，剩下 2
5. 6 大于 2，只能切 15，剩下 9

最大空闲区是 9。若在第 4 步误切了 15，会剩下 7 和 10，最大变成 10，那是选项 C。题目只问大小。从高地址切还是从低地址切，9 和 2 这两个大小不变；本关按王道从低地址切，最终空闲块的起点是 53 和 6。

**2011-30，选 B。** 官方答案是编译：编译产生目标模块，模块内部的地址是相对本模块的逻辑地址。链接把各模块收成一份相对整个装入模块的逻辑地址空间，装载（或运行时的动态重定位）才变成物理地址。`note=compile-module` 就是把这两件事分开。标准答案按编译，完整逻辑地址空间形成于链接。

**2017-25，选 B。** 回收区同时接上 20K 的 40KB 和 200K 的 200KB，合成 20K、380KB，空闲块剩 3 个。按大小升序，链首是 500K 的 80KB。地址和大小都用 K 做单位，20+40=60，不必再乘 1024。

**2019-32，选 C。** 最佳适应最容易留下难以利用的小空闲区。

**2024-27，选 A。** 只有伙伴算法把「大小相等并且互为伙伴」当作合并条件。相邻但不是伙伴的等大块不合并。

## 易错点

1. 限长和逻辑地址比，比过才加基址。合法逻辑地址含 0，不含限长。
2. 上下限比的是物理地址，上限是最后一个合法单元。同一分区的上限 = 基址 + 限长 − 1。
3. 从低地址切下来的剩余是空闲，成功分配的内部碎片是 0。
4. 最佳适应回收后要按大小重排。2017 的链首是 80KB，合并出来的 380KB 排到后面。
5. 最坏适应每次都重新找最大块。刚切出来的剩余常常已经不是最大。
6. 邻近适应的指针含着切剩的那一块。整块分完才移到下一块。
7. 固定分区放不下时，外部碎片仍记 0。空分区不是内部碎片。
8. 动态分区申请失败且空闲总和够用时，这些空闲都算这次的外部碎片。
9. 紧凑只在动态重定位下做。静态重定位拒绝搬动，作业的起点保持原样。
10. 2010 的 55MB 初始全部空闲。释放 15MB 是释放第一块申请，它和后来剩下的 10MB 不相接。
11. 2011 的官方选项是编译。完整逻辑地址空间在链接时形成，这两句回答的不是同一个问题。
12. 伙伴算法里，相邻、等大、但不是伙伴的两块保持分开。普通回收会把它们合成一块。
13. 共享看的是不同虚拟地址上的同一次写入。本机用户态拿不到页框号。

## 概念卡片

| | 逻辑地址空间 | 物理地址空间 |
|---|---|---|
| 编号 | 每道作业从 0 开始 | 内存单元的真实编号 |
| 谁产生 | 编译形成模块内的相对地址，链接形成完整逻辑地址空间 | 装入或运行时，由基址、页表、段表变换得到 |
| 会不会重复 | 不同作业可以都有地址 0 | 一个单元同时只属于一个物理地址 |

| 方式 | 内部碎片 | 外部碎片 | 同时几道 |
|---|---|---|---|
| 单一连续 | 有，整个用户区的富余都算 | 无 | 1 |
| 固定分区 | 有，分区里没用完的 | 无 | 多道，每区一道 |
| 动态分区 | 无，按申请量切 | 有，小空闲区散在作业之间 | 多道 |

| 装入 | 什么时候把逻辑地址变成物理地址 | 装入之后还能不能挪 |
|---|---|---|
| 绝对装入 | 编译时地址就是物理地址 | 不能 |
| 静态重定位 | 装入时一次改完 | 不能。紧凑做不了 |
| 动态重定位 | 每次访问加上重定位寄存器 | 能。紧凑只改寄存器 |

| | 覆盖 | 交换 |
|---|---|---|
| 对象 | 同一道作业里的程序段轮流用同一块区域 | 整个进程在内存和外存之间换入换出 |
| 谁安排 | 程序员 | 操作系统 |

| 算法 | 链怎么排 | 挑选 | 用久了的样子 |
|---|---|---|---|
| 首次适应 | 地址升序 | 从链头起第一块够大的 | 低地址碎，高地址容易留下大块 |
| 邻近适应 | 地址升序 | 从指针继续，含剩余块 | 高低地址更匀，大块更早被切 |
| 最佳适应 | 大小升序 | 够用的最小块 | 小碎片最多 |
| 最坏适应 | 大小降序 | 最大块 | 大块消耗得快 |
