## 一、项目定位与两层解耦架构

### 1.1 为什么传统考研 Prompt 经常失效？
在长周期的考研复习中，大多数考生直接向通用大模型提问往往会遇到以下痛点：
1. **直接泄露答案（秒杀思考）**：大模型倾向于一次性输出完整推导或代码，剥夺了考生的独立解题过程，陷入「看懂了但自己写不出来」的假性掌握。
2. **上下文漂移与规则遗忘（Context Drift）**：当对话超过 10 轮后，模型逐渐遗忘角色设定、公式排版规范和评分标准。
3. **大纲外知识污染（Hallucination & OOD）**：联网检索或检索非考研大纲教材，引入自命题超纲结论或已废弃的旧题型。
4. **评分虚高或空泛**：主观大题批改缺乏具体的步骤分（Rubric），无法定位具体丢分步骤。

### 1.2 两层解耦系统架构图
本项目采用**「指令层（System Instructions）+ 知识库层（RAG Knowledge Base）」两层解耦架构**，将静态教学行为准则与高密度动态学科考点完全分离：

### 1.3 核心设计优势
- **指令层轻量高敏（≤ 1250 汉字）**：严格控制在 Gemini 系统指令的最佳注意力加权窗口内，确保每一条教学逻辑都能被 100% 精确执行。
- **知识库层独立挂载（RAG 优化）**：大纲考点、细粒度 Rubric 评分表和易混对比卡片作为知识文件上传，不占用指令框字数预算，且支持独立迭代。
- **注意力首尾锚定（Bookend Effect）**：在指令开头设定角色与边界，在指令末尾建立 `【🔒 执行硬约束二次锚定】`，彻底根除多轮对话后的指令衰减。

## 三、Gemini Custom Gems 最佳部署指南

### 3.1 方式一：Google Gemini Custom Gems 官方最佳部署（推荐）

在 Google Gemini（Web 端或 App 端）中，使用 Custom Gems 功能可以获得最佳的解耦体验：

```
[Gemini 首页] ➔ [Gem 管理器 (Gem Manager)] ➔ [新建 Gem (New Gem)]
                                                     │
               ┌─────────────────────────────────────┴─────────────────────────────────────┐
               ▼                                                                           ▼
   【步骤 1：填写基本信息与 Instructions】                                     【步骤 2：上传 Knowledge 知识文件】
   • 名称：如「408 操作系统专属私教」                                            • 点击「+ Add Files」
   • 指令框 (Instructions)：                                                     • 上传本地对应的「408-操作系统-考点库.md」
     全文复制对应科目「408-操作系统-指令.md」内容并粘贴                             • 推荐直接使用原生 .md 文本格式
               │                                                                           │
               └─────────────────────────────────────┬─────────────────────────────────────┘
                                                     ▼
                                      【步骤 3：配置高级工具链开关】
                                      • 禁用 Google 搜索（Search Grounding）
                                      • 理工科启用 Python 代码解释器
                                      • 确认模型选用 Gemini 1.5 Pro / 2.0 Pro
                                                     │
                                                     ▼
                                            【步骤 4：保存并开始学习】
```

#### 详细操作步骤：
1. **登录平台**：访问 [Google Gemini 官网](https://gemini.google.com/)，在左侧侧边栏点击 **Gem 管理器 (Gem Manager)**，选择 **新建 Gem (New Gem)**。
2. **设置名称与头像**：
   - 名称建议保持标准清晰，例如：`考研数学一专属私教`、`408 操作系统私教`。
3. **注入指令层**：
   - 打开对应科目的 `*-指令.md` 文件（如 `数学一-指令.md`），全选并复制全部内容；
   - 粘贴至 Gem 配置界面的 **Instructions（指令）** 输入框中。
4. **挂载知识库层**：
   - 在 **Knowledge（知识）** 区域点击 **Add files（添加文件）**；
   - 上传本地对应的 `*-考点库.md` 文件（如 `数学一-考点库.md`）；
   - *提示：一门科目配置一个独立的 Gem，严禁将 7 门科目的考点库混杂上传至同一个 Gem，以免引发跨学科检索混淆。*
5. **保存 Gem**：点击右上角 **Save（保存）**。之后每次学习该科目，直接进入对应的 Gem 开启新对话即可。

#### 知识库文件格式特别说明：
- **强烈推荐原生 `.md` 或 `.txt`**：Markdown 的结构化标题（`#`、`##`、`###`）与代码块天生具备极高的语义切片亲和度，Gemini RAG 引擎能精准按小节检索召回。
- **避免转存为 `.pdf` 或 `.docx`**：转成 PDF 后容易因分页截断表格、双栏排版错位导致 RAG 切片断裂，降低检索命中率。

### 3.3 方式二：不想创建 Gem？在普通对话中使用单文件合并版（10 秒开箱即用）

如果你无法创建 Google Custom Gems（如使用免费版账号、移动端快捷使用），或者偏好在 **Gemini Advanced**、**Claude 3.5 Sonnet**、**ChatGPT (GPT-4o)** 普通对话窗口以及本地客户端（Cherry Studio、Chatbox、NextChat 等）中直接答疑，推荐使用项目预先编译好的 **`dist/` 单文件全功能版本**。

#### 为什么不建议手动 `cat` 粗暴合并？
传统简单的文件拼接（如 `cat 考点库.md 指令.md`）存在三大痛点：
1. **多级标题冲突**：多处一级标题 `#` 与同名二级标题 `##` 竞争，破坏模型层级理解；
2. **过时前言残留**：知识库顶部的「配合指令使用」废话白白浪费上下文注意力；
3. **末尾注意力失效**：若将包含负向约束的指令夹在中间，长上下文推理极易出现「中间遗忘（Lost-in-the-Middle）」。

本项目通过 `build_dist.py` 构建流水线，将指令层解构为【第一部分：核心系统指令】与【第三部分：🔒 执行硬约束终极锚定】，将知识库嵌套降级为【第二部分：专属考点与评测知识库】置于文档中部。**将最为关键的负向惩罚项与排版铁律锚定在全文最底端**，彻底激活现代大模型的末尾注意力（Recency Effect）。

### 💡 408 标准满分三段式重构示范

#### 1. 算法设计基本思想
采用空间换时间策略。申请大小为 $(n+1)$ 的辅助数组并初始化为 0。遍历链表，取结点值的绝对值查表，若首次出现则置 1 并保留前驱指针继续后移；若已出现则通过前驱指针删除该结点并 `free` 释放空间。

#### 2. 标准 C 语言核心代码
```c
void deleteSame(LinkList &L, int n) {
    int *visited = (int*)calloc(n + 1, sizeof(int));
    LNode *pre = L, *p = L->next;
    while (p != NULL) {
        int val = abs(p->data);
        if (visited[val] == 1) {
            pre->next = p->next;
            free(p);
            p = pre->next;
        } else {
            visited[val] = 1;
            pre = p;
            p = p->next;
        }
    }
    free(visited);
}
```

#### 3. 复杂度分析
- **时间复杂度**：$O(m)$（$m$ 为链表长度，仅需单次遍历）。
- **空间复杂度**：$O(n)$（$n$ 为数据绝对值上限，辅助数组开销）。

## 五、Gemini 底层模型特性与提示词工程优化原理

本项目不仅仅是简单的 Prompt 编写，而是深度结合了 Google Gemini 1.5/2.0 大模型底层架构特性的工程级优化：

### 5.1 首尾注意力锚定机制（Bookend Effect）
大模型在处理几千字上下文时，注意力机制（Attention Weights）呈现经典的 **U 型分布（Primacy and Recency Effect）**：
- **头部（Primacy）**：模型对最前方的角色定义和身份边界记忆深刻；
- **中部（Lost in the Middle）**：长文本中部的规则极易在多轮推理中被稀释；
- **尾部（Recency）**：模型对末尾的指令响应强度最高。

因此，本套指令在第 1 节定义身份边界，并在第 7 节构建 `【🔒 执行硬约束二次锚定】`，将「刚学模式禁止直接给答案」「严格遵循 LaTeX 规范」「真题不编造」等核心铁律在尾部强制复述，实现抗多轮衰减的双重锁定。

---

### 5.2 RAG 亲和度与抗断裂微对比卡片设计
在考点库（Knowledge Base）构建中，针对向量检索与切片机制进行了深度优化：
- **消除超长宽表**：传统 15+ 行的 Markdown 复杂对比大表在 RAG 分块时，极易从中间被硬性截断，导致召回内容失去表头信息。
- **高内聚微对比卡片**：全面重构为行数 ≤ 6 行的微型对比表或结构化无序列表（包含【核心差异】【判断口诀】【典型陷阱】），确保每一个知识切片在 512~1024 Token 的检索窗口内**绝对自包含**。

---

### 5.3 KaTeX / LaTeX 严格无空格渲染与公式规范
Gemini Web 端及移动端 App 内置的 KaTeX 渲染引擎对定界符空格极其敏感：
- **错误写法**：`$ x + y $` 或 `$$ f(x) $$`（定界符内侧带空格会直接导致渲染引擎失效，暴露出难看的源码字符）。
- **严格规范**：指令层强制约束行内公式为 `$x+y$`，独立公式为 `$$f(x)$$`，中文与公式之间保留空格，文本说明在公式内部强制使用 `\text{}` 包裹。

---

### 5.4 防幻觉与真题教材仲裁锚点
- **拒绝真题年份伪造**：指令层明确禁止模型虚构「这是 2018 年 408 统考第 42 题」等伪标签；无法 100% 确定真题出处时，仅标注「考研经典题型」。
- **权威教材争议仲裁**：当不同名师或教材对同一概念有冲突时（如计网中部分教材对物理层/数据链路层功能划分微调，或 OS 中关于死锁定理表述差异），知识库层明确以**教育部统考大纲**与**官方指定/主流权威教材（王道、武忠祥、肖秀荣等）**为唯一裁决基准。

## 七、常见问题与排错指南 (FAQ)

### Q1: 为什么有时候 Gemini 还是会忍不住把全套答案一下子发出来？
- **原因**：会话未成功读取自述行，或当前 Prompt 被用户提示词中的「怎么做」误导。
- **解决方法**：
  1. 新对话开头严格发送包含 `刚学` 关键词的自述行；
  2. 随时发送一句提示词：`让我先想，只给第一步引导`，私教会立刻纠偏并回归单步苏格拉底状态。

### Q2: 知识库文件需要转成 PDF 格式再上传吗？
- **解答**：**千万不要转 PDF**。原生 `.md`（Markdown）文件具有最清晰的文本层级，大模型的 RAG 引擎能实现最高精度的语义召回。转成 PDF 反而会因为分页截断造成表格断裂和公式错乱。

### Q3: 可以在同一个 Gem 里面把 7 门科目的考点库全传上去吗？
- **解答**：**不建议**。多学科知识库混杂会导致 RAG 检索跨领域召回干扰（如计网的「流量控制」与操作系统的「进程同步」概念串扰）。建议按照 1 门科目建 1 个专属 Gem（只需创建一次即可永久使用）。

### Q4: 手机端 Gemini App 是否完美支持？
